# 配装工坊

纯前端的 FFXIV 自动配装优化器。项目把游戏规则、属性公式和搜索算法放在 `src/domain` 中，UI 层只负责配置与结果展示，方便未来把领域层单独发布成库。

## 开发

```bash
npm install
npm run dev
```

## 验证

```bash
npm run build
npm run test:coverage
npm run test:data
```

领域纯逻辑层的语句、分支、函数和行覆盖率门槛均为 90%。搜索模型通过小规模穷举、整数伤害因子、因子签名复核和联合共享身份测试验证。法系 GCD 使用咏速，坦克、力量及灵巧职业使用技速；可行档位查询与正式搜索使用相同的候选和约束。

数据测试校验 MCP 查询版本、空名称物品排除，以及原生零伤害与缺失字段的区分。测试文件最多同时运行两个，避免重复加载完整生产数据造成资源竞争。

## 配装搜索

职业图标来自 XIVAPI v2 的游戏资产接口，作为本地图像随应用提供。刷新图标可运行 `node scripts/download-job-icons.mjs`；脚本使用已有 Lumina MCP 服务核对职业编号，下载并校验 PNG，来源与哈希保存在 `public/assets/jobs/source.json`，不更新装备或公式数据。

单职业入口先独立选择职业，随后在连续工作台配置指标与 GCD、装备品级与同步、食物及限制。职业等级固定使用当前职业数据定义的最高等级，不提供选择或单独展示；右侧全高条件摘要随配置更新，底部提供“开始搜索”。来源、排除装备和强制装备使用可搜索下拉列表，装备候选使用虚拟滚动，菜单按视口定位并在空间不足时向上展开。单职业参数页不显示魔晶石规则。指标根据 GCD 或自定义速度范围内的可行档位自动选择；坦克坚韧方式互斥。可从历史搜索记录载入旧条件或同数据版本的已完成结果，旧条件载入工作台后按当前职业最高等级执行；收起的搜索记录位于参数页底部，展开后页面可滚动。

单职业结果页在同一页展示目标值、耗时、原有突出指标行、装备逐行属性、食物、总属性和完整条件，并提供“修改条件”入口；不计算或展示单职业基线比例。桌面按装备表在左、汇总在右的方式优先保证可读性；装备属性列按 4 个数字的宽度分配并水平居中，部位列避免名称换行，装备名称列适当收窄，品级列可收窄，魔晶石列可容纳 5 项镶嵌信息，食物行与装备表头对齐。右侧来源、强制装备和排除装备限制可向左展开；点击外部或按 Esc 收起，长列表仅在浮窗内滚动，键盘焦点可进入列表并在关闭后返回触发按钮。每次单职业及联合搜索都记录时间、配置和完成状态，成功时保存完整结果；记录保存在当前浏览器的本地数据库，刷新、重置配置或离开页面不清除。职业选择页、参数工作台及联合页均可访问对应搜索记录；载入成功结果不启动新搜索，不同数据版本的结果不能作为当前数据的推荐载入。本轮所有页面按 1440×695 桌面视口验收，同时保留窄屏回退。

单职业搜索与多职业联合搜索使用独立页面。单职业页面支持装备品级、等级同步、来源和装备限制、食物、GCD 单档或多档、速度范围、坚韧及减伤约束；联合页面为各职业分别配置限制，并选择共享部位、共享或独立食物。共享装备包含同一装备及同一完整镶嵌方案，共享槽位中的“戒指1”和“戒指2”可分别选择，也可同时选择；全套配装始终满足戒指唯一性。普通装备必须填满全部可用镶嵌孔，可禁忌镶嵌装备必须填满五孔，页面不提供关闭禁忌镶嵌的选项。

当前支持 22 个战斗职业，包括青魔法师。职业等级上限和默认品级范围随职业数据导入；青魔法师上限为 80 级。`ClassJob` 提供职业名称与原生属性修正，GCD、特性及队伍加成公式由参考项目补齐。MCP 没有青魔法师按 INT 索引的魔法武器伤害加值表或字段，因此该映射使用参考项目原始导出，并逐值核验原始测量输入。

正式 TypeScript 求解器位于 `src/domain/search`，以 HiGHS 混合整数模型联合选择装备、食物和属性阶梯，用整数因子及 BigInt 有理数复核目标。可选择最大化“每威力伤害期望”或按 GCD 折算的目标；联合搜索最大化各职业目标与各自单独最优基线的比例之和。基线与联合结果采用相同目标及各职业约束。Node 验收与正式 UI 均使用 HiGHS；历史算法包对比记录在 [搜索基准记录](docs/搜索基准记录.md)。算法说明见 [最优装备算法](docs/最优装备算法.md) 和 [正确性与验收](docs/V3正确性与验收.md)。

搜索在浏览器工作线程中执行，支持进度和取消。超时或求解器未完成最优性复核时明确失败，不返回近似结果。最优性限定于输入的真实候选及约束；HiGHS 的浮点数值最优状态不是独立形式化有理数证书。浏览器无法取得进程 RSS，因此不将浏览器统计描述为进程峰值内存。
单职业搜索期间使用准备、求解、核验三个阶段，不显示估算整体进度、百分比或剩余时间。候选数来自领域层准备出的逐槽装备池与食物池；求解状态仅展示真实 HiGHS 回调中的当前模型数据，不表示整场搜索完成比例。单轮核验不显示候选组合计数；只有实际启动第二轮求解才显示已核验组合数及轮次。取消会立即中止搜索。
结果页使用中文固定文案（保留 GCD、原始装备名称和来源名称），同页展示推荐配装、每件装备的最终属性、魔晶石和配装总属性。装备原生副属性达到单件上限时会加粗；“每威力伤害期望”沿用参考项目的取整顺序和计算公式。

## 更新数据

配装结果保持固定单列，按武器、盾牌、防具、饰品的顺序展示，无盾牌时省略该行。多职业搜索的共享槽位选择分两列：左列为武器、头、身、手、腿、脚，右列为盾牌、耳坠、项链、手镯、戒指1、戒指2；无法共享盾牌时保留空白占位，不添加说明。

项目的数据来源是 MCP 优先、参考项目补缺：能从对应 MCP 服务器取得的目标版本游戏资料必须使用 MCP，只有确认 MCP 缺失的资料才使用 [Asvel/ffxiv-gearing](https://github.com/Asvel/ffxiv-gearing)。MCP 与参考项目的适用范围、回退条件和版本一致性要求见 [项目规则与实现记录](docs/PROJECT_RULES.md)。

名称为空的物品视为已移除，导入时排除，不参与配装或食物计算，也不会用参考项目中的旧名称恢复。

先由脚本启动环境提供的 `ffxiv-mcp-lumina` stdio 服务器并生成可复现快照，再由统一更新器合并参考项目中 MCP 未覆盖的领域常量：

```bash
npm run data:mcp
npm run data:update
```

`data:mcp` 默认查询参考项目中的全部装备（含唯一性）、战斗食物、职业分类、22 个受支持职业的 `ClassJob` 行、食物效果、属性上限、魔晶石和当前已确认的自定义参数武器表（`MandervilleWeaponEnhance`），并写入 `src/data/mcp-lumina.snapshot.json`。职业行通过 `ClassJob.Abbreviation` 搜索发现，再批量读取，不依赖记忆中的行 ID。它也会保存 `list_sheets` 与 `ClassJob` 字段描述，核对青魔法师武器伤害映射是否存在于 MCP。它要求本机配置的游戏目录、EXDSchema 和 Lumina MCP 可执行文件；可用 `FFXIV_MCP_LUMINA_COMMAND`、`McpLumina__GamePath`、`McpLumina__SchemaPath` 和 `FFXIV_MCP_LUMINA_CONCURRENCY` 覆盖默认值。仅在 MCP 明确声明通用查询不受版本警告影响时接受验证版本滞后，并保存警告；其他降级或任一批次重试失败会终止。

参考仓库默认位于 `reference/ffxiv-gearing`，可用 `FFXIV_GEARING_ROOT` 指向另一份本地检出。已有快照和本地参考数据时可运行 `node scripts/update-data.mjs --offline`，该模式不会访问网络，也不会直接启动 MCP。

生成数据记录 MCP 游戏/验证版本、查询时间、Sheet、字段和行范围，以及参考仓库 URL、精确 commit、导入时间和源文件。解析器会严格校验数量、重复 ID、职业、魔晶石及必需字段；当前快照覆盖 21964 件可用战斗装备、420 种战斗食物和 22 个职业；青魔法师伤害映射必须是完整的非负安全整数数据，并与参考项目原始测量文件逐项一致。MCP 缺失情况与使用的参考文件保留在数据来源记录中。`ItemFood` 行 1800 当前未被参考项目用作食物效果参数，导入器会记录该查询缺口但不把它作为必需效果行，并使用同一动作中其余 MCP 效果字段。源数据缺失或异常时直接失败，运行时没有演示数据或合成数据回退。
