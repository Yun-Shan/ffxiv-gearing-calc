### 热点一：伤害评估的动态对象路径（优化前）

最重的调用链是：

```text
#searchSuffixFrontier
  -> #upperDamageOfSum
    -> v1Damage
      -> equippedEffects
        -> addStats / Object.entries
          -> KeyedLoadIC_Megamorphic / KeyedStoreIC_Megamorphic
```

`#upperDamageOfSum` 在每次上界检查中创建新的属性数组并调用伤害函数，原始实现位于 `loadout-finder-v2-search.ts`；当时 `test.ts` 的 `v1Damage` 会把数组逐项转换成动态字段的 `EquippedStats` 对象，`equipped-effects.ts` 的 `addStats` 再使用 `Object.entries` 和动态键合并。这个路径解释了两个 Megamorphic IC 热点，以及 `addStats`、`calculateFromTotalStats` 的连续出现。

当前已通过 `createEquippedEffectsVectorEvaluator` 处理该问题：基础属性和固定形状的总属性对象在创建 evaluator 时预计算，搜索回调只更新已知属性索引并复用同一套 `calculateFromTotalStats` 公式。V2 的 `#foodAttributes` 与 `#upperAttributes` 也作为 scratch 数组复用，因此上界和食物评估不再走数组到 `addStats` 的转换路径。

需要特别注意：`Builtin: KeyedLoadIC_Megamorphic` 不是应用层 `damageCache` 的“缓存未命中”统计，而是 V8 对动态键访问的优化失败/退化提示。

### 热点二：支配索引查询

`DominanceIndex.#findDominator` 位于 `loadout-finder-v2-search.ts`，单次查询会先遍历全部维度检查节点包围盒，再遍历维度检查节点是否支配目标，最后递归访问左右子树。一次运行中 `支配比较` 达到 `225,549,341`；该计数只代表检查过的树节点，实际维度数组访问次数还要乘以属性维度和递归访问量。该结构在本次 V2 优化中保持不变，仍是后续最值得单独基准化的算法热点。

当前索引保留历史点，靠分层树合并维持结构，不删除已经被后续点支配的点。这个设计保证了传递性正确，但会扩大后续查询的节点集合。该函数是本次采样中最大的源码级算法热点。

### 热点三：后缀搜索的上界评估

`#searchSuffixFrontier` 位于 `loadout-finder-v2-search.ts`。本次执行检查了 `100,497,784` 个后缀树节点/状态，其中 `42,210,533` 个由上界剪掉，仍有大量节点需要继续展开或进行叶向量评估。`#upperDamageOfSum` 的上界函数仍直接调用 `this.damageFunction(attributes)`，但现在使用复用的上界 scratch 数组和数组原生 evaluator，不再产生动态属性合并对象。

因此后缀阶段的主要成本不是“递归函数自身”，而是：

1. 数千万次后缀包围盒判断。
2. 大量新的属性数组和食物应用。
3. 未缓存的完整伤害公式调用。
4. 后缀状态前沿在不同食物分支中重复构建和遍历。

## `damageCache` 的实际作用

`damageCache` 定义于 `loadout-finder-v2-search.ts`，本次日志显示命中率约 `48.7%`，缓存有 `312,296` 项，清空 `0` 次。它主要服务于搜索前的全局上界、贪心/局部改良、槽位排序和候选排序路径。

真正的 DFS 前缀和后缀热路径调用的是 `#upperDamageOfSum`，该函数直接调用 `damageFunction`，所以提高 `damageCache` 容量或命中率预计不会显著改善本次主搜索耗时。若要让缓存影响主搜索，必须先解决上界向量的键构造和内存成本，并验证重复向量比例；简单把所有上界调用塞入字符串 Map 可能会把字符串构造和 GC 成本转移回来。

## 优化优先级

### P0：提供数组原生的伤害评估入口（已完成）

为搜索保留一条与现有公式共用实现的数值向量入口，避免每次上界评估都经历“数组 -> 动态对象 -> `Object.entries` -> 数组/对象字段读取”。可以预计算等级、职业、基础属性和食物相关常量，并用固定索引读取 CRT、DET、DHT、速度、主属性和武器性能。不能在优化器中复制一份公式；取整顺序必须继续复用同一个规则实现。

当前实现为 `equipped-effects.ts` 的 `createEquippedEffectsVectorEvaluator`，由 `test.ts` 注入 V2。它继续复用 `calculateFromTotalStats`，没有在搜索器中复制公式；应使用新的 `--prof` 运行单独量化其收益。

### P0：重新评估 `DominanceIndex` 的查询结构（后续方向）

应以 `225,549,341` 次支配比较为基准，测试专用的低维、整数、阈值分层索引。例如可以分别按阈值类/速度档位分组，再在组内使用更紧凑的 Pareto 表示；后缀前沿也可以使用一次性批量 Pareto 算法，减少逐点递归 KD 树查询。任何替代结构都必须保留上限属性的相等约束和速度/坚韧可行性语义。

### P1：收紧后缀上界

当前后缀前沿已经剪掉 `65.41%` 的原始组合，但搜索仍进行超过一亿次上界检查。下一步可以评估分组 Pareto 上界、总属性预算约束和阈值感知的组合上界，重点减少“上界仍高于当前最优、只能继续展开”的状态，而不是单纯增加 `damageCache`。

### P1：减少搜索状态分配

`#sum`、`#upperDamageOfSum` 和后缀组合生成都会创建新数组；后缀生成还会复制候选列表。GC 采样为 `5.2%` 总 tick，已达到需要关注但不是第一优先级的程度。应在前两项算法优化后，再用复测确认使用预分配数组、紧凑 TypedArray 或父指针是否能降低 RSS 和 GC，同时不能破坏递归状态的生命周期。

## 结论

本次 V2 profiling 说明，V2 包装层不是瓶颈；在未启用最高坚韧模式时，V2 直接把约束转换后调用独立的 `LoadoutFinderV2Search`，见 `loadout-finder-v2.ts`。向量评估路径已经完成，当前最主要的源码级成本中心是：

1. `DominanceIndex.#findDominator` 的多维递归支配查询。
2. 后缀搜索的上界检查和剩余的完整伤害公式调用。

数组原生评估入口已经实现；下一步应单独替换/优化支配索引，再比较后缀上界和状态分配优化。当前 profiling 结果不支持先扩大伤害缓存作为主要优化方向。

当前实现使用 `createEquippedEffectsVectorEvaluator`、复用的食物/上界属性 scratch 数组，以及独立的 `loadout-finder-v2-search.ts`。V1 归档文件未修改，仅由归档回归测试显式引用。

验证命令：

```powershell
$env:DATA_TEST_GCD = "2.48"
npm run data:test
```

验证结果：进程退出码 `0`，最优每威力伤害期望 `91.07033391009733`，未发生 OOM；生成的 ffxiv-gearing 配置链接与既有基准方案一致。构建和单元测试也通过，V2 专项测试 `20/20`，项目测试 `31/31`。`scripts/test` 为脚本测试目录，不适用应用领域层覆盖率门槛。

后续将 `maxCombinedDamageFlat` 的每状态评分逻辑内联到批量循环后，RDM 无 GCD 短时采样吞吐约为 `39.5M` 后缀向量/秒，相比此前 `34--35M` 提升约 `14%`。该改动只消除闭包和参数传递开销，仍复用同一套属性查表与伤害公式。总属性数组索引的可行性采样显示，精确总属性和阈值签名均很快超过 `500,000` 个组合，暂不具备小型通用数组的内存/查询条件。

### 总属性索引实验结论

固定属性和确实将后缀划分为少量（本场景 `158` 个）预算组，但组内仍有 `38,886` 个不同属性向量。前缀、食物和当前下界会改变这些向量的相对优劣，因此不能预计算一个与前缀无关的“总属性 -> 最优后缀”数组。实验性的状态上界、连续小块和连续数组树均保留为显式开关，短测未超过默认连续块扫描；只有在 evaluator 明确对所有属性单调时才允许启用状态上界。

默认单线程路径运行 `60s` 的采样评估了约 `2.845e9` 个后缀向量，仍未完成全局搜索；因此当前实现不能声称在 `60s` 内得到严格全局最优，也没有提前启用四 worker。采样通过 `SharedArrayBuffer` 中止标志结束，保留了每秒调试日志和 CPU profile 所需的正常落盘路径。

新增的总属性必要阈值实验按单调性二分每个属性的必要后缀下限，并用排序数组跳过前缀；在目标下界附近没有跳过任何状态。块最大值精确评分和按前缀动态排序同样未改善吞吐，故均保持显式关闭。结论仍是：总属性可以作为固定和分组及安全包围盒的输入，但不能在当前前缀偏移和食物封顶规则下直接变为小型全局数组索引。

### 2026-09-16：总属性精确缓存复测

为验证“总属性组合少”能否直接替代后缀遍历，新增了 `suffixTotalDamageCache` 诊断开关。它以 `食物 + 前缀属性 + 后缀属性` 的精确总向量作为键，使用开放寻址的 TypedArray 存储；哈希冲突逐维比较，命中只复用已经计算的精确分数，不能改变最优性判定。后缀属性哈希在构建前沿时预计算，前缀哈希在每个块复用，避免把实验实现成字符串 Map。

RDM、730--795、同步 735、无 GCD、单线程采样中，2 槽后缀约 1,800 万向量/5 秒，缓存命中约 `9.8%`；4 槽短测约 500 万向量/3 秒，命中约 `42.6%`。作为对照，关闭缓存时同机同参数约为 3,000 万和 8,900 万向量。逐状态寻址、碰撞校验和缓存写入的成本远高于命中节省，因此该开关默认关闭，仅用于后续数据集诊断。它也说明“总属性可以缓存”不等于“后缀可以数组直接访问”：要用数组替代查询，仍需先为每个变化的前缀和食物建立对应的总属性索引，索引规模会重新接近实际搜索规模。

同一实验中还验证了固定总和块的逐槽容量包围盒：该严格上界在 5 秒采样中约 `187M` 向量，未启用时约 `191M`，剪枝率没有提高，故 `suffixPerSlotBounds` 也保持显式关闭。

### 2026-09-16：当前快照直接索引复核

为排除测试快照变化对结论的影响，重新运行了当前 MCP/参考数据快照。条件为赤魔法师 100 级、装备品级 730--795、同步品级 735、无 GCD、单线程，搜索阶段 5 秒后中止。默认连续数组路径评估 `308,533,509` 个后缀向量；开启 `sharedRawPrefixDominance` 后为 `306,157,133` 个，额外的共享支配查询没有收益；开启 `suffixTotalDamageCache` 后为 `11,241,844` 个，缓存命中 `2,446,069` 次（`21.8%`），但逐状态哈希和碰撞检查使吞吐约下降一个数量级。

精确总属性仍是 `prefix + suffix` 的平移：固定一个前缀时，后缀向量到总属性向量是一一映射；改变前缀或食物后，原有总属性键不再指向同一伤害值。因此不能把总属性缓存改造成一个与前缀无关的几万项数组。连续后缀数组、固定属性和分组及安全上界仍是当前默认实现；本次还修复了批量 DPS 路径对不存在 `speedReciprocal` 字段的引用，并用逐状态结果验证了除法顺序未变。

### 2026-09-16：固定总和前缀数组实验

在每个固定后缀属性和块内，为贪心优先级属性建立按属性升序的连续 `Int32Array` 视图，同时预计算该排序前缀的逐维最大值。给定当前下界时，逐块对“前缀状态集合的最大向量”做单调二分；被证明不可能超过下界的部分直接跳过，其余连续尾部交给批量 evaluator。这样后缀筛选从逐状态闭包检查变为数组访问，且不改变严格性条件：只对单调伤害 evaluator 启用，无约束时使用。

当前快照的 4 槽短测中，固定总和数组路径约 `2.45e8` 向量/5 秒，普通连续扫描约 `3.6e8` 向量/5 秒；跳过约 `8.5e6` 个状态。把固定总和上界函数用于每个属性的每次二分会增加调用开销，墙钟速度反而下降，因此当前实现只使用廉价组件最大值二分，块级总和上界仍保留。将后缀扩至 5 槽虽减少前缀触发次数，但前沿增至约 `2.0e5`，完整搜索超过 240 秒，不作为默认配置。

### 2026-09-16：总属性列式顺序校验

启用 `suffixStateUpperBound` 时，后缀状态会按“前缀逐维最大值 + 食物变换”的精确分数分别排序。此前列式最大值回调仍读取未重排的列，存在返回分数与状态索引错位的风险。现在为每个食物同步建立重排后的列视图，并在回映射时使用同一状态顺序；新增多食物、封顶食物和列式回调回归测试，普通扫描与重排列式路径的伤害及最终属性均一致。

同一采样将总属性诊断集合改为数值型开放寻址结构，避免字符串键和 GC 干扰。当前快照在约 `1.85M` 个后缀样本内就达到 `500,000` 个“食物 + 总属性”唯一组合上限，说明跨前缀的总向量并非几万规模；固定一个前缀时 `后缀向量 -> 总属性向量` 又是平移一一映射。因此总属性可以继续用于固定和分组、列式评估和安全上界，但不能在本数据集上把后缀遍历替换为一个通用的稠密数组索引。该诊断仍是显式开关，不进入默认热路径。

### 2026-09-16：复合总属性下标实验

伤害公式中的武器性能和主属性只以二维乘积出现。对这两个后缀分量预先编码为 `武器后缀 × 主属性表宽度 + 主属性后缀` 后，完整总属性的二维下标满足：

```text
pair(prefix + suffix) = pair(prefix) + pair(suffix)
```

因此 `maxFlatScore`/`maxFlatScoreColumns` 可以在热循环中直接读取 `pairPrefix + suffixPairIndex`，不改变食物封顶、属性档位或最终公式。该路径由 `suffixPairAttributes`、`suffixPairStride` 显式配置，没有配置时仍使用原始逐维计算；RDM 测试已覆盖普通、DPS、分段和批量评估的结果及状态索引一致性。

这只是常数项优化，不是把全部总属性压缩成一个数组：其余属性仍需按前缀偏移读取。当前快照中复合下标本身只有约 65 万种可能，适合放在 `Int32Array`，而六维总属性组合仍迅速超过 50 万种。

### 2026-09-16：前缀阈值等价类查找实验

进一步按 `#buildStateTierClasses` 生成的“所有可达后缀下都不会跨档”的前缀等价类建立后缀最优结果缓存，并保留未分档的武器性能精确值。该缓存理论上可将同类前缀变成一次数组/映射读取；但在当前 RDM 快照、4 槽后缀、无 GCD 的 5 秒采样中产生 `4,720` 个不同前缀键、命中 `0` 次，吞吐没有改善。因此它保持显式实验开关 `DATA_TEST_SUFFIX_PREFIX_TIER_LOOKUP=true`，不进入默认路径。`DATA_TEST_SUFFIX_FUTURE_TIER_COMPRESSION=true` 也已传递到 worker 诊断路径，但本快照的后缀前沿没有可合并状态。

结论是：总属性和前缀阈值确实可以用于安全的固定和分组、二维复合下标以及网格上界，但当前装备数据的前缀状态几乎没有可复用的完整等价类，不能据此承诺将后缀遍历改为 O(1) 的通用总属性数组。
