### 热点一：伤害评估的动态对象路径（优化前）

最重的调用链是：

```text
#searchSuffixFrontier
  -> #upperDamageOfSum
    -> v1Damage
      -> equippedEffects
        -> addStats / Object.entries
          -> KeyedLoadIC_Megamorphic / KeyedStoreIC_Megamorphic
```

`#upperDamageOfSum` 在每次上界检查中创建新的属性数组并调用伤害函数，原始实现位于 `loadout-finder-v2-search.ts`；当时 `test.ts` 的 `v1Damage` 会把数组逐项转换成动态字段的 `EquippedStats` 对象，`equipped-effects.ts` 的 `addStats` 再使用 `Object.entries` 和动态键合并。这个路径解释了两个 Megamorphic IC 热点，以及 `addStats`、`calculateFromTotalStats` 的连续出现。

当前已通过 `createEquippedEffectsVectorEvaluator` 处理该问题：基础属性和固定形状的总属性对象在创建 evaluator 时预计算，搜索回调只更新已知属性索引并复用同一套 `calculateFromTotalStats` 公式。V2 的 `#foodAttributes` 与 `#upperAttributes` 也作为 scratch 数组复用，因此上界和食物评估不再走数组到 `addStats` 的转换路径。

需要特别注意：`Builtin: KeyedLoadIC_Megamorphic` 不是应用层 `damageCache` 的“缓存未命中”统计，而是 V8 对动态键访问的优化失败/退化提示。

### 热点二：支配索引查询

`DominanceIndex.#findDominator` 位于 `loadout-finder-v2-search.ts`，单次查询会先遍历全部维度检查节点包围盒，再遍历维度检查节点是否支配目标，最后递归访问左右子树。一次运行中 `支配比较` 达到 `225,549,341`；该计数只代表检查过的树节点，实际维度数组访问次数还要乘以属性维度和递归访问量。该结构在本次 V2 优化中保持不变，仍是后续最值得单独基准化的算法热点。

当前索引保留历史点，靠分层树合并维持结构，不删除已经被后续点支配的点。这个设计保证了传递性正确，但会扩大后续查询的节点集合。该函数是本次采样中最大的源码级算法热点。

### 热点三：后缀搜索的上界评估

`#searchSuffixFrontier` 位于 `loadout-finder-v2-search.ts`。本次执行检查了 `100,497,784` 个后缀树节点/状态，其中 `42,210,533` 个由上界剪掉，仍有大量节点需要继续展开或进行叶向量评估。`#upperDamageOfSum` 的上界函数仍直接调用 `this.damageFunction(attributes)`，但现在使用复用的上界 scratch 数组和数组原生 evaluator，不再产生动态属性合并对象。

因此后缀阶段的主要成本不是“递归函数自身”，而是：

1. 数千万次后缀包围盒判断。
2. 大量新的属性数组和食物应用。
3. 未缓存的完整伤害公式调用。
4. 后缀状态前沿在不同食物分支中重复构建和遍历。

## `damageCache` 的实际作用

`damageCache` 定义于 `loadout-finder-v2-search.ts`，本次日志显示命中率约 `48.7%`，缓存有 `312,296` 项，清空 `0` 次。它主要服务于搜索前的全局上界、贪心/局部改良、槽位排序和候选排序路径。

真正的 DFS 前缀和后缀热路径调用的是 `#upperDamageOfSum`，该函数直接调用 `damageFunction`，所以提高 `damageCache` 容量或命中率预计不会显著改善本次主搜索耗时。若要让缓存影响主搜索，必须先解决上界向量的键构造和内存成本，并验证重复向量比例；简单把所有上界调用塞入字符串 Map 可能会把字符串构造和 GC 成本转移回来。

## 优化优先级

### P0：提供数组原生的伤害评估入口（已完成）

为搜索保留一条与现有公式共用实现的数值向量入口，避免每次上界评估都经历“数组 -> 动态对象 -> `Object.entries` -> 数组/对象字段读取”。可以预计算等级、职业、基础属性和食物相关常量，并用固定索引读取 CRT、DET、DHT、速度、主属性和武器性能。不能在优化器中复制一份公式；取整顺序必须继续复用同一个规则实现。

当前实现为 `equipped-effects.ts` 的 `createEquippedEffectsVectorEvaluator`，由 `test.ts` 注入 V2。它继续复用 `calculateFromTotalStats`，没有在搜索器中复制公式；应使用新的 `--prof` 运行单独量化其收益。

### P0：重新评估 `DominanceIndex` 的查询结构（后续方向）

应以 `225,549,341` 次支配比较为基准，测试专用的低维、整数、阈值分层索引。例如可以分别按阈值类/速度档位分组，再在组内使用更紧凑的 Pareto 表示；后缀前沿也可以使用一次性批量 Pareto 算法，减少逐点递归 KD 树查询。任何替代结构都必须保留上限属性的相等约束和速度/坚韧可行性语义。

### P1：收紧后缀上界

当前后缀前沿已经剪掉 `65.41%` 的原始组合，但搜索仍进行超过一亿次上界检查。下一步可以评估分组 Pareto 上界、总属性预算约束和阈值感知的组合上界，重点减少“上界仍高于当前最优、只能继续展开”的状态，而不是单纯增加 `damageCache`。

### P1：减少搜索状态分配

`#sum`、`#upperDamageOfSum` 和后缀组合生成都会创建新数组；后缀生成还会复制候选列表。GC 采样为 `5.2%` 总 tick，已达到需要关注但不是第一优先级的程度。应在前两项算法优化后，再用复测确认使用预分配数组、紧凑 TypedArray 或父指针是否能降低 RSS 和 GC，同时不能破坏递归状态的生命周期。

## 结论

本次 V2 profiling 说明，V2 包装层不是瓶颈；在未启用最高坚韧模式时，V2 直接把约束转换后调用独立的 `LoadoutFinderV2Search`，见 `loadout-finder-v2.ts`。向量评估路径已经完成，当前最主要的源码级成本中心是：

1. `DominanceIndex.#findDominator` 的多维递归支配查询。
2. 后缀搜索的上界检查和剩余的完整伤害公式调用。

数组原生评估入口已经实现；下一步应单独替换/优化支配索引，再比较后缀上界和状态分配优化。当前 profiling 结果不支持先扩大伤害缓存作为主要优化方向。
