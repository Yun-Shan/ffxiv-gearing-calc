# V3 联合搜索的正确性与验收

## 优化目标

各职业先在自己的完整输入候选集合中、按自己的 GCD 和坚韧约束计算单独最优值 `OPT_c`。联合搜索最大化 `Σ D_c / OPT_c`，等价于最小化百分比差距之和。默认 `damage` 目标使用每威力伤害期望，符合 V3 文档；显式 `dps` 目标使用每威力伤害期望除以 GCD，并且基线、上界和最终方案全部使用同一目标。两种目标都不能通过各职业对数目标相加来替代。

本次指定的性能验收为钐镰客＋武士、蝰蛇剑士＋机工士。两组均共享耳饰、项链、手镯和两枚戒指，食物全局共享，不限制 GCD，采用 `dps` 目标。

追加验收为赤魔法师＋绘灵法师：赤魔固定 2.48 GCD；绘灵允许 2.48 或 2.50，按联合 `dps` 目标搜索。除武器和戒指外全部共享，食物全局共享。允许的 GCD 由真实公式反查为速度闭区间并集，不能提前选定绘灵的档位，也不能把并集填成包含 2.49 的连续区间。

共享装备指同一物品和同一完整属性方案；戒指对还必须有相同的两枚戒指及各自属性方案。共享槽通过名称映射到各职业自己的槽位顺序。共享食物必须在所有职业的输入食物集合中存在，独立食物允许各职业分别选择。

最高坚韧模式先在原始候选集合中计算该职业可达到的最高坚韧；后续固定共享装备时仍要求达到这个值。不能通过缩小候选集合再降低最高坚韧要求来制造可行解。

## 分支限界

正权重职业且存在共享槽位时，使用包含各职业完整属性模型、共享装备和共享食物等式的联合 MIP。先构造并核验实际可行的共享方案作为下界。设归一化值为 `r_c`，单职业基线保证 `0 ≤ r_c ≤ 1`，因此 `Σr_c ≤ n−1+Πr_c`。任何超过当前总和 `S` 的方案都必须满足 `Πr_c > S−(n−1)`。模型的对数乘积只用于枚举这个必要集合；每个因子签名仍用 BigInt 有理数总和比较，不能把乘积最优直接当作总和最优。必要集合穷尽后，才返回最优结果。固定点下界采用 `ln(t) ≥ 1−1/t` 和因子取整误差界，并完全使用整数计算。

共享装备模型先把每个共享槽限制到完整身份交集，再让各职业的共享装备组合具有相同的通用属性贡献总和。通用向量覆盖每个职业的属性提取器和全部属性坐标，而不是只比较某个职业使用的副属性。求解后，把所有职业的共享槽同时替换为第一个职业选择的真实组合：每件装备属于对应槽的身份交集，各职业全部原始属性总和保持不变，因此食物、GCD、坚韧和伤害也保持不变。输出重新核验完整身份、属性和整数因子。这种可还原的表示消除了属性等价组合的重复分支，仍得到实际装备与魔晶石方案全部一致的共享结果。

存在零权重职业或没有共享槽位时，使用以下外层分支限界路径。

外层枚举共享装备；共享食物模式还枚举食物。每个节点允许各职业独立选择尚未确定的共享槽，得到单职业上界。这放宽了共享约束，因此所有真实联合扩展都包含在这个松弛集合中。

分支只选择当前各职业松弛最优装备不一致的未固定槽，并完整枚举该槽的共享候选。已经一致的槽仍保持自由，不能强行固定；所有槽都一致时，松弛最优方案已实际可行。若父节点某职业的最优方案也满足子节点新增限制，就直接复用：子集合的最优值不可能高于父集合，而这个可行方案已达到父最优值，所以也必定是子节点最优。

各职业单独最优值为正时，上界除以该值仍为上界。把各职业上界相加，是联合目标的上界。只有该上界不能超过已找到的真实联合方案时才可剪枝。联合比例使用整数因子构成的有理数比较，避免浮点加总误差剪掉更好的方案。

单职业沿用 HiGHS 混合整数模型：装备和食物是离散选择，食物取整、上限和属性约束进入模型；伤害阶梯因子以有误差界的固定点对数建目标，再按整数因子复核接近目标最优值的因子签名。求解器只有报告最优且复核结束后才能返回。HiGHS 使用浮点数求解，数值最优状态不是形式化有理数证明；小规模穷举对照能验证模型和算法，但不能替代所有大规模实例的形式化证书。

因子签名复核采用双向枚举并用 BigInt 比较伤害乘积和 GCD 分母。枚举的是实际装备可达因子的超集：如果超集中也没有更优组合，就可以结束复核；如果发现更优组合，仍需回到完整模型检查实际可行性。枚举规模或时间达到保护线时也回到完整模型，不能把未完成枚举当成最优证明。

超集可以按真实 GCD 区间和属性预算进一步缩小。对副属性的每个非空子集，任何方案的属性和都不超过“各槽位该子集最大贡献之和＋真实食物在各属性原始最大值处的最大加成”。因子所需属性下界若超过这个预算，该组合一定不可行。同一固定点对数值对应多个因子类时，下界取所有相关原始类的最小值；食物上界沿用模型的有理数比例并以 BigInt 取整。未知下界或无法安全判断的组合一律保留。

## 验收口径

搜索计时从全部职业的装备候选准备完成后开始，包含单独最优基线、联合搜索、食物选择和最优性复核。工作线程的启动及结果传输也由入口的总时限保护。候选生成不计入搜索时间。

不生成预先打表文件。运行时缓存必须有界，不能把本次搜索产生的缓存当作无需计时的离线预计算。

当前要求为四分钟内完成，尽量优化到两分钟；总保护时限取 235 秒，保留退出余量。在时限内停止且报告未完成，与时限内完成最优搜索是两种结果。验收记录必须列出真正完成的场景、候选数量、共享部位、食物策略、耗时及内存峰值；不能用超时保护代替性能通过。

入口同时读取进程 RSS 和操作系统报告的进程内存高水位，记录两者最大值；高水位不可用的平台退回采样测量。入口保留低于 4GB 的保护余量，并限制工作线程的 V8 堆；WASM 内存也计入进程 RSS。实测峰值描述本次运行，不能作为所有输入的静态内存证明。
