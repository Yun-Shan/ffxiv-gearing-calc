# 最优配装搜索基准记录

## 2026-09-29：精确 MIP 搜索

单 worker 执行 `npm run data:test` 时默认使用 HiGHS 精确 MIP。该模式把每个槽位和食物建成离散选择变量，按 V2 规则约束食物取整/封顶、GCD、坚韧及最高坚韧目标；伤害因子使用固定点对数作为 MIP 目标，并用 BigInt 精确复核候选，直到剩余因子签名低于可证明的误差界。求解器未证明最优、超过时限或触及 RSS 保护线时会停止且不返回近似结果。

- 搜索时限默认 `115000ms`，可通过 `DATA_TEST_EXACT_TIMEOUT_MS` 调低，最高不能超过 `115000ms`。
- 搜索进程 RSS 达到 `3.5 GiB` 时停止；MIP 在独立 worker 中运行，V8 老生代限制为 `2560 MiB`。
- 不生成或读取预先打表文件；候选因子区间在运行时构建。
- 显式设置 `DATA_TEST_ALGORITHM=v2` 会运行旧 V2 搜索；它仍是近似搜索，不能据此声称严格全局最优。多 worker 也仅支持 V2。

### 优化后 V1 真实搜索验证

运行命令：

```powershell
$env:DATA_TEST_ALGORITHM = 'v1'
npm run data:test
```

本次 V1 在相同输入和伤害函数下启用了以下优化：

- 单槽局部改良后继续进行双槽联合改良，使搜索下界在 DFS 前直接达到已知最优值。
- 前缀槽位按“逐属性独立最大值造成的上界虚高影响”排序，将上界最不准确的槽位优先确定。
- 将候选数最少的 5 个槽位合并为精确 Pareto 后缀，并使用包围盒树分组计算安全伤害上界。
- Pareto 状态按所有未来可达后缀下的伤害阈值等价类比较；未采用只比较当前档位的非安全剪枝。
- 普通 DFS 继续缓存相同“食物 + 完整属性向量”的伤害结果，几乎不重复的后缀树包围盒和叶向量改为直接计算。

分享建议中的“总属性预算约束”也已纳入推导，但没有作为独立剪枝实现。若用“最大属性总和减去其他维最小值”推导某一维上界，该上界必然不小于该维原本的真实最大值，无法收紧现有逐维包围盒；若人为继续压低则不再是安全上界，可能剪掉最优解。装备属性之间的互斥关系目前由多槽位联合 Pareto 前沿精确表达，而不是叠加一个无效或不安全的总量约束。

### 2026-09-15：后缀总属性块与扁平数组采样

V2 无 GCD 搜索新增了连续 `Int32Array` 后缀属性存储和范围批量 evaluator。后缀前沿按完整后缀属性和分为 `158` 个块；块内保存属性最小/最大向量及固定属性和上限，前缀查询先做安全上界，再仅扫描可能超过当前下界的块。该路径仍逐个精确评估未剪枝状态，没有把近似分数当作结果。

同一输入的短时单线程采样（保持调试日志开启）观察到约 `26--27M` 后缀向量/秒，块上界剪枝约 `28%`；此前无条件扁平扫描约 `27--29M` 向量/秒但没有块剪枝。按前两件装备切分的更细块上界只有约 `2%` 剪枝且吞吐下降，已回退。5 槽后缀前沿为 `202,143`、总和块 `302`，短测吞吐约 `24--26M` 向量/秒，未替换默认的 4 槽方案。

采样在完成全局最优性证明前通过 SIGINT 停止，因此这些数字不能作为完整搜索耗时或最优结果；当前单线程完整搜索仍未达到用户要求的 `240s` 门槛，尚未启用并发 worker。

### 2026-09-15：总和预算与食物查表复测

前缀层补齐剩余槽位的属性和预算参数，避免前缀上界继续使用逐属性独立最大值。扁平 evaluator 对每个稳定的食物变换数组构建“基础值 -> 食物后值”的 `Int32Array`，保持逐个变换的取整和封顶顺序。`RDM`、730--795、同步 735 的 10 秒单线程采样中，连续数组路径约评估 `3.0e8` 个后缀向量；与树路径的 `1.4e8` 个向量相比，树路径上界剪枝不足 1%，额外节点判断使墙钟吞吐更低。该查表只减少单向量公式成本，不改变后缀状态数量。

将后缀从 4 槽改为 5 槽（前沿约 `202,143`）或把总和组切成 32 状态小块，都未改善完整搜索：60 秒采样仍约 `1.9e9` 个向量，且小块上界检查开销显著增加。精确“前缀 + 食物 + 下界 + 后缀 -> 总属性”全局数组仍不可行，因为前缀偏移使同一后缀在不同前缀下对应不同伤害签名；现阶段保留连续属性数组和固定总和块上界，未启用并发 worker。

### 2026-09-15：扁平批量评分内联复测

将 `maxCombinedDamageFlat` 中每个后缀状态的评分从闭包调用改为批量循环内联，仍使用同一组食物查表、属性档位表和 GCD 公式。RDM、730--795、同步 735、无 GCD 的 5 秒单线程采样约为 `39.5M` 后缀向量/秒（此前约 `34--35M`），最优解和已有扁平 evaluator 等价测试均通过。该优化只降低单向量评估成本，不改变后缀状态集合或上界正确性。

总属性数组化仍需同时解决两个问题：其一，前缀偏移会让同一后缀向量对应不同的总属性；其二，实际采样的精确总属性和阈值签名在 `500,000` 个样本内即达到诊断上限。因此当前不能用一个小型通用数组直接替代后缀遍历；固定属性和分组仍作为可证明安全的索引边界。

### 2026-09-15：共享食物路径对比

在相同 RDM、730--795、同步 735、无 GCD、单线程和 5 秒中止条件下，共享前缀后按食物顺序独立扫描后缀约 `178.5M` 个向量，独立食物分支约 `194.8M` 个向量，前者快约 `8.5%`。共享批量（一次后缀扫描同时评估全部食物）约 `172.6M` 个食物--后缀向量，但会延迟不同食物之间的下界更新，反而失去剪枝收益。实际基准入口默认使用“共享前缀 + 顺序后缀”模式；批量共享和完全独立路径保留为实验开关及等价性测试。

开启总属性签名诊断时，扁平后缀路径会记录每个精确总属性和食物后阈值签名。一次约 3 秒的单食物采样已评估 `3,088,284` 个向量；两类唯一签名都达到诊断上限 `500,000`，说明总属性数组不能按几万项规模覆盖目标搜索空间。

### 2026-09-15：总属性必要阈值与动态块顺序实验

进一步测试了两种直接利用总属性/下界的安全路径。`suffixNecessaryLowerBound` 为每个前缀和食物按属性二分“其它后缀维取独立最大值时仍需达到的最小值”，并为每个属性建立连续排序视图；只有预计能跳过至少 35% 状态时才使用排序视图。该必要条件在真实 RDM 下界 `37.24890190074447` 附近始终过宽，5 秒采样跳过状态为 `0`，额外二分没有带来收益。

`suffixExactBlockUpperBound` 用块属性包围盒的精确单调 evaluator 值收紧现有上界，`suffixDynamicBlockOrder` 则按当前前缀重新排序块。两者在 5 秒采样中均未提高吞吐（约 `190M` 向量，和默认路径的运行间抖动相当），说明块最大值仍然过于虚高、动态排序也无法替代更紧的几何上界。这些路径保留为关闭的诊断开关，不改变默认搜索。

### 2026-09-15：总属性数组索引与连续树实验

针对“前缀 + 食物 + 当前下界 + 后缀 = 总属性”的想法，增加了三个可关闭实验开关：

- `suffixStateUpperBound`：用所有前缀各维最大值预计算每个后缀块的真实 evaluator 上界；该值只在明确声明 evaluator 对每个属性单调时启用。
- `suffixSubblockRefinement`：把固定属性和块切成连续小块，先比较小块包围盒。
- `suffixFlatTree`：在连续 `Int32Array` 上建立区间树，叶节点仍调用原有批量 evaluator。

RDM、730--795、同步 735、无 GCD、单线程、5 秒采样结果如下（向量数越高越快）：

| 路径 | 后缀向量/5 秒 | 后缀上界检查 |
| --- | ---: | ---: |
| 连续块扫描（状态上界关闭） | `175.0M` | `0.72M` |
| 连续块扫描 + 状态上界 | `174.2M` | `0.71M` |
| 连续小块（256 状态） | `161.6M` | `1.14M` |
| 连续数组树（256 状态叶） | `146.3M` | `1.82M` |
| 原有前沿树（32 状态叶） | `24.8M` | `2.90M` |

小块和连续树虽然能剪掉一部分区间，但额外包围盒计算超过了节省的 evaluator 调用；状态上界在该数据集上也没有稳定收益，默认均关闭。四种路径的专项测试结果一致。前缀等效状态集合则改为开放寻址 `Float64Array` 存储，哈希冲突仍逐维校验，减少了大量 JS 数组分配；该改动不改变支配语义。

同一默认路径延长到 `60s` 后，共评估约 `2.845e9` 个后缀向量，后缀包围盒上界检查 `11,628,030` 次、剪枝 `3,277,255` 次（约 `28.2%`），仍未完成全局搜索。该结果确认当前单线程耗时尚未低于并发前要求的 `240s`，因此没有启用四 worker；中止时只保留采样统计，不输出“严格最优”结果。

### 2026-09-16：总属性精确缓存复测

为验证“总属性组合少”能否直接替代后缀遍历，新增了 `suffixTotalDamageCache` 诊断开关。它以 `食物 + 前缀属性 + 后缀属性` 的精确总向量作为键，使用开放寻址的 TypedArray 存储；哈希冲突逐维比较，命中只复用已经计算的精确分数，不能改变最优性判定。后缀属性哈希在构建前沿时预计算，前缀哈希在每个块复用，避免把实验实现成字符串 Map。

RDM、730--795、同步 735、无 GCD、单线程采样中，2 槽后缀约 1,800 万向量/5 秒，缓存命中约 `9.8%`；4 槽短测约 500 万向量/3 秒，命中约 `42.6%`。作为对照，关闭缓存时同机同参数约为 3,000 万和 8,900 万向量。逐状态寻址、碰撞校验和缓存写入的成本远高于命中节省，因此该开关默认关闭，仅用于后续数据集诊断。它也说明“总属性可以缓存”不等于“后缀可以数组直接访问”：要用数组替代查询，仍需先为每个变化的前缀和食物建立对应的总属性索引，索引规模会重新接近实际搜索规模。

同一实验中还验证了固定总和块的逐槽容量包围盒：该严格上界在 5 秒采样中约 `187M` 向量，未启用时约 `191M`，剪枝率没有提高，故 `suffixPerSlotBounds` 也保持显式关闭。

### 2026-09-16：食物专属后缀数组与档位缓存复测

针对“前缀 + 食物 + 当前下界 + 后缀 = 总属性”的进一步尝试，后缀块在显式开启 `suffixStateUpperBound` 时按每个食物的全局前缀最大值评分排序，并保存连续属性数组及原始状态索引。块内评分单调时，数组首值可先于资源分配上界做安全预筛，二分确定只需评估的后缀范围；非单调块保留原有完整扫描。该排序只改变扫描顺序，不把近似评分当作最终结果。

RDM、730--795、同步 735、无 GCD、单线程短测中，开启 `suffixSubblockRefinement` 后，数组首值预筛与原有资源上界组合约评估 `14.7M` 个后缀向量/10 秒，细块上界检查约 `29.6M` 次；仅使用数组首值而跳过资源上界会退化到约 `86M` 向量/10 秒，按父固定和块扫描则约 `395M` 向量/10 秒且几乎没有剪枝。因此当前保留“父块预筛 + 细块严格上界”的结构，食物专属数组只作为显式分析开关。

新增 `suffixTotalDamageTierCache` 将食物变换后的、已配置阈值属性压缩为档位键，武器性能等未分档属性仍保留精确值。小型 RDM 回归与普通缓存结果一致；目标数据 5 秒采样命中率约 `40%`，但哈希/键构造开销抵消了吞吐收益，仍默认关闭。实际最终属性签名远超几万项，不能用单一通用数组替代后缀遍历，也不能据此声称已满足 `60s` 严格全局最优证明。

### 2026-09-16：总属性直接索引复核

在当前 MCP/参考数据快照下，以赤魔法师 100 级、装备 730--795、同步 735、无 GCD、单线程、5 秒中止为条件，关闭总属性缓存时评估 `308,533,509` 个后缀向量；开启 `suffixTotalDamageCache` 后仅评估 `11,241,844` 个，命中 `2,446,069` 次（约 `21.8%`），吞吐下降约一个数量级。开启 `sharedRawPrefixDominance` 时评估 `306,157,133` 个，略低于默认路径，不能抵消支配索引的额外成本。

这说明“总属性组合少”只适用于固定前缀和食物后的局部重复；对不同前缀，总属性是后缀向量的不同平移，精确键仍接近实际评估量。当前保留连续 `Int32Array` 后缀数组和固定属性和分组，未把哈希缓存或全局总属性数组设为默认路径。批量 DPS evaluator 的速度处理改回逐项除法，并增加了与逐状态 evaluator 的分数/状态索引等价测试。
