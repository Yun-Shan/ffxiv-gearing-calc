# 最优装备方案生成系统 — 渐进式实现方案文档

---

## 0. 文档说明

本文档描述最优装备方案生成系统的完整需求与渐进式实现方案，分为三个版本：

- **V1**：核心计算逻辑（含食物选择）
- **V2**：GCD 与坚韧约束
- **V3**：多职业联合生成

每个版本在前一版本基础上扩展，保持向后兼容。文档涵盖需求定义、算法设计、数据结构、正确性证明、性能分析与实现要点。

## 1. 背景与问题定义

### 1.1 业务场景

FF14 装备配装系统需要从多个装备槽位（最多 12 个，其中盾槽位仅骑士有）中为每个槽位选择一个装备，并在装备上镶嵌魔晶石，使得最终属性的伤害最大。同时需要考虑食物加成、速度 GCD 阈值、T 职业坚韧减伤等约束。

### 1.2 前置输入

经过前置处理（魔晶石组合生成 + Pareto 剪枝），每个槽位 `i` 得到候选装备列表 `candidates[i]`，其中每个候选装备 `EquipInfo` 包含：

- `baseParams`: `[属性id, 属性值][]`，已按属性 id 升序排序
- 元数据（`itemId`、`itemLevel`、`key` 等）

总属性向量是所有槽位选中装备属性的逐分量之和。

### 1.3 伤害函数性质

伤害函数 `Damage(attrs)` 满足：

- **单调非递减**：若属性向量 `A ≥ B`（逐分量），则 `Damage(A) ≥ Damage(B)`
- **非线性阶梯式**：属性达到阈值才给予阶梯式伤害增益
- **食物加成单调**：食物加成后属性 `final_f(base)` 关于 `base` 单调非递减

### 1.4 组合规模

槽位数 `S ≤ 12`，每槽位候选数 `K_i` 经剪枝后约 10~15，全组合可达万亿级，无法穷举。必须使用保证全局最优的高效算法。

### 1.5 算法选型

采用**分支限界法（Branch and Bound）**：通过乐观上界剪枝，保证全局最优，同时大幅缩减搜索空间。所有版本均基于此框架。

## 2. 算法核心：分支限界框架

### 2.1 搜索树

深度为槽位数 `S`，每个节点代表前几个槽位已选定装备，子节点表示对下一个槽位的选择。

### 2.2 上界计算

对当前节点（已选部分槽位，属性总和 `currentAttrs`，剩余槽位集合 `R`），构造**逐分量最大属性向量**：

```
U[d] = currentAttrs[d] + Σ_{j∈R} maxAttr[j][d]
```

其中 `maxAttr[j][d] = max_{equip ∈ candidates[j]} equip.baseParams[d].value`。

对任意实际可行方案的基础属性 `B`，有 `B ≤ U`（逐分量）。由伤害函数单调性，`Damage(B) ≤ Damage(U)`。因此 `Damage(U)` 是该节点所有方案伤害的上界。

### 2.3 剪枝条件

```
若 upperDamage ≤ best.damage → 剪枝
```

上界有效性保证了剪枝不会丢失全局最优。

### 2.4 正确性

**定理**：分支限界法返回全局最优解。

**证明**：搜索树完整枚举所有组合；上界 ≥ 实际伤害；剪枝条件保证被剪分支不含优于当前最优的解；搜索完成后 `best` 必为全局最优。 ∎

## 3. V1：核心计算逻辑（含食物选择）

### 3.1 需求

**V1 目标**：在无 GCD 约束、无坚韧约束、单职业场景下，为每个槽位选择装备并选择一种最优食物，使伤害最大。

**输入**：

- `slots`: `EquipInfo[][]`，每个槽位的候选装备列表
- `foods`: `Food[]`，候选食物列表（通常 2~5 种），每种食物包含每个属性的百分比加成 `p_d` 和上限 `cap_d`
- `damageFn`: 伤害函数
- `attributeCount`: 属性维度数（≤ 7）

**输出**：

- `{ damage: number, selection: EquipInfo[], food: Food }`

### 3.2 食物模型

对属性 `d`，食物 `f` 加成：

```
final_f(base)[d] = base[d] + min(base[d] * p_f[d], cap_f[d])
```

**单调性**：对固定食物 `f`，`final_f` 关于 `base` 单调非递减。

### 3.3 搜索树设计（食物作为第一层）

```
深度 0：选择食物 f ∈ foods
深度 1..S：依次选择各槽位装备
```

**为什么用食物作为第一层**：便于与其他约束（V2）、多职业联合（V3）统一集成；可在食物层提前剪枝。

### 3.4 上界计算

#### 3.4.1 已选定食物（深度 ≥ 1）

```
U[d] = currentAttrs[d] + Σ_{j∈R} maxAttr[j][d]
upperDamage = Damage(final_f(U))
```

#### 3.4.2 未选定食物（根节点）

```
U[d] = Σ_{j∈所有槽位} maxAttr[j][d]
upperDamage = max_{f ∈ foods} Damage(final_f(U))
```

#### 3.4.3 食物层剪枝

对每种食物 `f`，先计算其全局上界（所有槽位未选时的上界）。若 `Damage(final_f(U_all)) ≤ best.damage`，直接跳过该食物的完整搜索。

### 3.5 算法流程

```javascript
function findBestV1(slots, foods, damageFn) {
  // 1. 预处理：每个槽位每维最大值 maxAttr[j][d]
  // 2. 按候选数升序排序槽位（优化剪枝）
  // 3. 初始化 best = { damage: -Infinity, selection: null, food: null }
  // 4. 可选：贪心生成初始 best（每槽位选总属性最高，食物选全局最优）
  // 5. dfsFood(0)：
  //    对每个食物 f：
  //      计算全局上界，若 ≤ best.damage 跳过
  //      dfsSlot(0, new Array(D).fill(0), [], f)
  // 6. 返回 best
}

function dfsSlot(slotIndex, currentAttrs, currentSelection, food) {
  if (slotIndex === slots.length) {
    const dmg = damageWithFood(currentAttrs, food, damageFn);
    if (dmg > best.damage) updateBest(dmg, currentSelection, food);
    return;
  }
  for (const equip of slots[slotIndex]) {
    add(equip, currentAttrs, currentSelection);
    const U = computeUpperAttrs(slotIndex, currentAttrs);
    const upperDamage = damageWithFood(U, food, damageFn);
    if (upperDamage > best.damage) {
      dfsSlot(slotIndex + 1, currentAttrs, currentSelection, food);
    }
    remove(equip, currentAttrs, currentSelection);
  }
}
```

### 3.6 关键优化

1. **伤害函数缓存**：`Map` 缓存 `(foodId, attrsKey) → damage`，避免重复计算。
2. **槽位排序**：按候选数升序，先处理约束强的槽位。
3. **候选排序**：每槽位内按总属性降序，尽早找到较优解。
4. **贪心初始解**：使用贪心快速获得一个可行解，初始化 `best`，增强剪枝。
5. **食物剪枝**：若食物 `f1` 在每个属性上的加成均弱于 `f2`，剔除 `f1`。

### 3.7 正确性

- 食物加成单调 → 复合伤害函数 `Damage(final_f(base))` 关于 `base` 单调。
- 上界 `Damage(final_f(U))` 对所有实际方案伤害成立。
- 剪枝安全，全局最优性得证。

### 3.8 性能

- 单次搜索节点数：典型场景数百至数千。
- 耗时：< 400ms（JavaScript）。
- 食物数量（2~5）影响为常数倍。

## 4. V2：GCD 与坚韧约束

### 4.1 需求

**V2 目标**：在 V1 基础上，支持以下可选约束：

1. **GCD 约束**：要求 GCD 恰好等于指定值 → 速度属性落在对应阈值区间 `[minSpeed, maxSpeed]`。
2. **坚韧下限约束**：要求坚韧属性 ≥ 指定值。
3. **最高坚韧约束**：先最大化坚韧值 `T_max`，再在 `T_max` 下最大化伤害。

速度属性 id（技能速度或咏唱速度，因职业而异）、坚韧属性 id（仅 T 职业）由调用方提供。

调用层可以直接传入以秒为单位的 `gcd`（例如 `2.48`），V2 通过与伤害计算完全相同的逐层截断公式反查含食物速度的闭区间。坚韧下限也可以通过 `toughnessMinPercent` 传入减伤百分比（例如 `5` 表示 5.0%），V2 反查达到该减伤档位所需的最低含食物坚韧。`speedMin` / `speedMax` / `toughMin` 仍作为直接指定属性值的底层接口保留；同时指定时取约束交集。

### 4.2 约束建模

统一表示为一组属性的下限/上限：

| 约束类型 | 属性 | 下限         | 上限     |
| -------- | ---- | ------------ | -------- |
| GCD      | 速度 | minSpeed     | maxSpeed |
| 坚韧下限 | 坚韧 | minToughness | ∞        |
| 最高坚韧 | 坚韧 | T_max        | T_max    |

所有约束基于**含食物的最终属性**判断。

### 4.3 节点可行性检查

在节点 `(slotIndex, currentAttrs, food)`，对每个约束：

**下限约束** `final_d ≥ minVal`：

```
若 final_f(currentAttrs + Σ_{j∈R} maxAttr[j])[d] < minVal → 不可行
```

**上限约束** `final_d ≤ maxVal`：

```
若 final_f(currentAttrs + Σ_{j∈R} minAttr[j])[d] > maxVal → 不可行
```

其中 `minAttr[j][d] = min_{equip ∈ candidates[j]} equip.baseParams[d].value`。

### 4.4 上界调整（收紧）

若属性 `d` 存在上限约束 `maxVal`，构造上界时裁剪：

```
U[d] = min(U[d], inverseFinal_f(maxVal)[d])
```

其中 `inverseFinal_f(maxVal)` 是使 `final_f(x) ≤ maxVal` 的最大基础值 `x`。由于 `final_f` 单调，可通过二分或解析求解。

### 4.5 最高坚韧约束的两阶段处理

**阶段一：寻找最大坚韧 `T_max`**

- 目标：最大化 `final_f(toughness)`。
- 使用分支限界，上界函数改为坚韧上界：
  ```
  upperToughness = final_f(currentToughness + Σ_{j∈R} maxAttr[j][toughId])
  ```
- 剪枝条件：`upperToughness ≤ bestToughness`。

**阶段二：在坚韧 = T_max 下最大化伤害**

- 添加约束：`toughness ≥ T_max` 且 `toughness ≤ T_max`。
- 运行 V1+V2 的伤害最大化搜索。

### 4.6 算法流程

```javascript
function findBestV2(slots, foods, damageFn, constraints) {
  // constraints: { gcd, speedMin, speedMax, toughnessMinPercent, toughMin, maxToughnessMode }
  if (constraints.maxToughnessMode) {
    const T_max = findMaxToughness(slots, foods, constraints);
    constraints.toughMin = T_max;
    constraints.toughMax = T_max;
  }
  // 与 V1 相同流程，但可行性检查与上界调整按上述规则
}
```

### 4.7 正确性

- 可行性检查确保仅保留能通过剩余槽位满足约束的分支。
- 上界裁剪后仍对所有满足约束的实际方案伤害成立。
- 两阶段处理中，阶段一找到全局最大坚韧，阶段二在坚韧 = T_max 子集中搜索伤害最优 → 全局最优。

### 4.8 性能

- 可行性检查与上界调整复杂度 O(D × |R|)，开销极低。
- 约束通常能缩小搜索空间，提升效率。
- 两阶段最高坚韧增加一次搜索，总耗时仍可控（< 800ms）。

## 5. V3：多职业联合生成

### 5.1 需求

**V3 目标**：在 V2 基础上，支持多个职业联合生成配装。要求：

- 部分槽位（**通用槽位** `G`）在所有职业间共享同一装备；
- 其余槽位（**非通用槽位** `N`）允许各职业独立选择；
- 可选食物共享策略：
  - **策略 A**：食物全局共享（所有职业用同一食物）
  - **策略 B**：食物各职业独立
- 目标：使所有职业的伤害结果相对于各自单独最优伤害的**百分比差距之和最小**。

**等价目标**（加权伤害最大化）：

```
maximize  Σ_{c∈C} w_c · D_c(E_G) ,  w_c = 1 / OPT_c
```

其中 `D_c(E_G)` 是职业 `c` 在通用槽位固定为 `E_G` 后，对非通用槽位和食物进行最优选择的最大伤害；`OPT_c` 是无通用约束下职业 `c` 单独最优伤害。

### 5.2 算法总体设计：双层分支限界

- **外层**：搜索通用槽位（及食物，若策略 A）的组合。
- **内层**：给定外层选择后，对每个职业独立运行 V2 求解器（固定通用槽位，剩余非通用槽位自由），得到 `D_c(E_G)`。

### 5.3 外层搜索树（策略 A：食物共享）

```
深度 0：选择食物 f
深度 1..|G|：依次选择通用槽位装备
叶子节点：对每个职业独立求解非通用槽位
```

### 5.4 外层上界计算

对当前外层节点（已选定部分通用槽位 `selectedG`，食物 `f`），对每个职业 `c`：

```
UB_c = solveSingle(c, selectedG, f)   // 固定 selectedG，剩余所有槽位自由
UB = Σ_{c∈C} w_c · UB_c
```

**关键点**：`UB_c` 允许职业 `c` 为**未确定的通用槽位**独立选择装备，因此是实际可达 `D_c(E_G)` 的上界。

**剪枝**：

```
若 UB ≤ bestValue → 剪枝
```

### 5.5 叶子节点计算

所有通用槽位确定后，对每个职业 `c`：

```
D_c(E_G) = solveSingle(c, E_G, f)   // 固定 E_G，仅非通用槽位自由
value = Σ_{c∈C} w_c · D_c(E_G)
```

更新全局最优。

### 5.6 策略 B：食物各职业独立

外层只搜索通用槽位；内层求解器自行选择最优食物：

```
UB_c = max_{f ∈ foods} solveSingle(c, selectedG, f)
```

或更紧的上界：

```
UB_c = solveSingleAllowFoodChoice(c, selectedG)   // 在求解器内部把食物作为第一层搜索
```

### 5.7 算法流程

```javascript
function findJointOptimalV3(jobs, commonSlots, foods, damageFn, strategy) {
  // jobs: [{ candidates, constraints, optDamage }]
  // commonSlots: 通用槽位索引数组
  // 1. 计算各职业 OPT_c（无通用约束下的单独最优），w_c = 1/OPT_c
  // 2. 按候选数升序排序通用槽位
  // 3. 初始化 best = { value: -Infinity, commonEquipments, jobResults, food }
  // 4. 外层 DFS
  return best;
}

function dfsOuter(gIndex, selectedG, food) {
  // 计算上界
  let UB = 0;
  for (const c of jobs) {
    UB += c.w * solveSingle(c, selectedG, food);
  }
  if (UB <= best.value) return;

  if (gIndex === commonSlots.length) {
    // 叶子：精确计算
    let value = 0,
      results = [];
    for (const c of jobs) {
      const D_c = solveSingle(c, selectedG, food);
      value += c.w * D_c;
      results.push(D_c);
    }
    if (value > best.value) updateBest(value, selectedG, results, food);
    return;
  }

  for (const equip of commonSlots[gIndex].candidates) {
    selectedG.push(equip);
    dfsOuter(gIndex + 1, selectedG, food);
    selectedG.pop();
  }
}
```

### 5.8 缓存优化

内层 `solveSingle` 调用频繁，使用缓存：

- 缓存键：`(jobId, fixedSlotsKey, foodId)`，其中 `fixedSlotsKey` 为固定槽位装备 id 的字符串。
- 存储：`Map<string, number>`。
- 效果：相同前缀 `selectedG` 在不同分支下复用结果，显著降低开销。

### 5.9 正确性证明

**定理**：V3 返回的联合方案使加权伤害最大（等价于百分比差距之和最小）。

**证明**：

- 外层完整枚举所有通用槽位组合（及食物，策略 A）。
- 节点上界 `UB = Σ w_c · UB_c` 中，`UB_c` 允许职业 `c` 独立选择剩余通用槽位，是实际可达 `D_c(E_G)` 的上界，因此 `UB` 是任何扩展方案加权伤害的上界。
- 剪枝条件 `UB ≤ best.value` 保证剪掉的分支不含更优解。
- 搜索完成后 `best.value` 为全局最优加权伤害。
- 因 `w_c > 0`，加权伤害最大 ⇔ 百分比差距之和最小。 ∎

### 5.10 性能

- 外层搜索节点数取决于通用槽位数、候选数和上界紧度，通常远小于全组合。
- 内层每次调用复杂度与 V2 单职业搜索相当（数毫秒）。
- 缓存可将重复前缀的开销降为 O(1)。
- 典型场景总耗时：秒级（可接受）。

### 5.12 边界情况

- 若某职业 `OPT_c = 0`：权重 `w_c` 置为 0 或排除该职业。
- 若通用槽位为空：退化为各职业独立优化。
- 若某固定通用槽位组合导致某职业约束不可行：`solveSingle` 返回 `-∞`，该外层分支被剪。
- 若策略 A 下所有食物均不可行：返回空结果。

## 6. 通用实现要点

### 6.1 预处理

- **属性维度对齐**：所有装备属性数组长度一致（按属性 id 升序，缺失补 0）。
- **maxAttr / minAttr 预计算**：每槽位每维最大/最小值。
- **槽位排序**：按候选数升序，或按边际收益启发式。
- **候选排序**：每槽位内按总属性降序。

### 6.2 伤害缓存

```javascript
const damageCache = new Map();
function cachedDamage(attrs, food) {
  const key = `${food.id}|${attrs.join(",")}`;
  if (damageCache.has(key)) return damageCache.get(key);
  const dmg = damageFn(applyFood(attrs, food));
  damageCache.set(key, dmg);
  return dmg;
}
```

### 6.3 上界紧度优化

- **上限裁剪**：对存在上限约束的属性，裁剪上界。
- **小规模穷举**：剩余槽位数 ≤ 3 时直接穷举得到精确最大伤害。
- **分组松弛**：剩余槽位分组取逐分量最大值，组间独立求和。

### 6.4 初始下界

- 贪心策略：每槽位选总属性最高的装备，食物选全局最优。
- 随机采样：多次随机生成可行解，取最优作为初始 `best`。

## 8. 边界情况汇总

| 场景               | 处理                |
| ------------------ | ------------------- |

| 食物列表为空       | 退化为无食物场景    |

| 通用槽位为空       | 各职业独立优化      |
| 剩余槽位数 ≤ 3     | 穷举得到精确上界    |

## 9. 总结

本方案通过**分支限界法**统一解决装备配装的最优化问题，利用伤害函数与食物加成的单调性构造有效上界，保证全局最优。

- **V1** 引入食物选择作为搜索树第一层，实现核心计算；
- **V2** 通过可行性检查与上界裁剪支持 GCD 和坚韧约束，并用两阶段处理最高坚韧；
- **V3** 采用双层分支限界，外层搜索通用槽位（及食物），内层复用 V2 求解器，通过加权伤害上界剪枝，实现多职业联合最优。

三个版本渐进式演进，正确性有严格数学保证，性能满足实际业务需求（毫秒至秒级）。
