# 项目规则与实现记录

本文档记录本项目必须遵守的业务规则、实现过程中已经确认的问题、对应修复方式，以及后续演进的正确方向。目标设计仍以根目录的《自动配装优化项目设计方案.md》为准；本文档描述当前代码的事实状态。

## 1. 数据规则

### 1.1 数据来源优先级

- 生产数据不得手写、随机生成或使用演示回退。
- 游戏资料以对应 MCP 服务器为首选事实来源；能从 MCP 获取的目标版本数据必须使用 MCP。只有确认 MCP 缺少目标 Sheet、字段、行、类型、成员或必要查询能力后，才允许回退到 `https://github.com/Asvel/ffxiv-gearing.git`，并记录缺失项和回退位置。
- FFXIV 游戏数据 Sheet 主要通过 `ffxiv-mcp-lumina` 查询；`Dalamud.*` API 和 `FFXIVClientStructs.*` 底层结构分别通过 `ffxiv-mcp-dalamud-api` 与 `ffxiv-mcp-clientstructs` 查询，三类资料不得混用。
- MCP 与参考项目不一致时，必须核对目标游戏版本、MCP 数据/文档版本和参考仓库 commit。版本一致且 MCP 能覆盖目标资料时以 MCP 为准；版本无法对齐时必须失败或隔离数据，不能静默混合。
- 进入生产数据的 MCP 查询结果必须保存为可复现、可校验的导入产物，并至少记录服务器、Sheet/类型/成员、查询范围、查询或导入时间及可取得的版本信息。参考项目数据必须记录仓库 URL、精确 commit、导入时间和源文件清单。
- 所有来源最终都必须由 `scripts/update-data.mjs` 统一生成 `src/data/generated-data.json`，禁止手工编辑生成文件。
- `Item.Name` 为空或仅含空白的物品视为游戏中已移除，导入时排除，不进入装备、食物候选及任何后续计算；不得使用参考项目旧名称恢复该物品。名称字段缺失或格式错误属于数据错误，必须明确失败。
- `scripts/query-mcp-lumina.mjs` 负责启动环境提供的 Lumina MCP stdio 服务器并生成 `src/data/mcp-lumina.snapshot.json`；查询结果不得由聊天文本或手工复制构造。默认查询参考项目中的全部可用装备、战斗食物、职业分类、22 个受支持职业的 `ClassJob` 行、食物效果、`ItemLevel`、`BaseParam`、`Materia` 和 `MandervilleWeaponEnhance` 行（当前已知的一类自定义参数武器表）。职业行须先用 `ClassJob.Abbreviation` 通过 `search_rows` 发现，再以 `get_rows` 批量读取；不得写死或凭记忆录入 row ID。
- 职业原生等级属性修正和职业名称使用 `ClassJob` 的 MCP 字段；职业角色、主副属性、GCD/特性/队伍公式、等级上限及默认品级范围使用参考项目 `src/game.ts` 中对应职业 schema，并按职业记录各字段来源。青魔法师 `BLU` 属于受支持职业，MCP 行用于名称、原生 modifiers、限职和盾牌能力核验，等级上限及默认品级范围来自参考 schema。
- 青魔法师每点 INT 对应的魔法武器伤害加值表在 Lumina MCP 的 Sheet 清单和 `ClassJob` 字段中均不存在。只有在当前 MCP 快照保存了 `list_sheets` 与 `ClassJob` 的 `describe_sheet` 结果并确认没有对应表/字段时，才允许从参考项目读取映射；来源文件为 `data/out/bluMdmgAdditions.js`、`data/in/bluMdmgAdditions.txt` 与 `data/convert.ts`。更新器必须逐项校验导出与原始测量文本一致，且所有数值均为非负安全整数，禁止缺失兜底、截短或近似。
- `scripts/update-data.mjs` 读取 MCP 快照并优先覆盖参考项目中的同 ID 数据；MCP 未返回的字段或行才保留参考项目值，并在 `dataSources` 中记录缺失范围和回退位置。当前统一更新器仍解析参考仓库的以下原始导出作为补缺和领域常量来源：
  - `data/out/gears-*.js`
  - `data/out/foods.js`
  - `data/out/jobCategories.js`
  - `data/out/levelCaps.js`
  - `data/out/slotCaps.js`
  - `data/out/roleCaps.js`
  - `src/game.ts`
- 当前快照游戏版本为 `2026.09.15.0000.0000`，服务器验证版本为 `2026.08.05.0000.0000`，版本警告及通用查询可用性声明保存在快照中，覆盖 21964 件可用战斗装备、420 种战斗食物、22 个职业、230 个 `ItemLevel` 行、12 个 `BaseParam` 行、1417 个 `Materia` 行及 62 个 `MandervilleWeaponEnhance` 自定义参数武器行。`ItemFood` 行 1800 在该版本动作表中被引用但不存在；参考项目没有把 1800 用作该类食物效果参数，因此它不是必需的食物效果行。导入器只记录该查询缺口，并继续使用同一食物动作中其余 MCP 效果字段，不虚构缺失行。
- MCP 与参考项目均缺少装备、食物、职业、魔晶石或属性上限表时必须直接失败，不能用虚构、近似或内置兜底数据继续运行。
- `ClassJobCategory` 只负责判断装备是否适用于目标职业，必须以实时 `ffxiv-mcp-lumina` 的 `Item.ClassJobCategory` 和对应 `ClassJobCategory` 行作为生产依据；参考项目中的分类映射不再作为该用途的事实来源，也不再要求两边分类 ID、显示文字或职业集合逐项一致。
- 分析 `ClassJobCategory`、`ClassJob` 等 MCP 数据时，必须实时调用 `ffxiv-mcp-lumina` 的 `describe_sheet`、`search_rows`、`get_row` 或 `get_rows`；不得把本地 `mcp-lumina.snapshot.json` 当作 MCP 实时查询结果。实时结果必须记录服务器、Sheet、字段、行 ID、查询范围、游戏版本和查询时间。
- 参考项目的 `jobCategories.js` 仍可用于确定待查询/导入的参考装备 ID，但不能用于覆盖或校验 MCP 的 `ClassJobCategory` 职业适用性。

### 1.2 更新方式

通用查询可接受服务器的验证版本滞后，但仅限健康信息明确声明 `get_row` / `get_rows` 等通用工具不受 `GameVersionMismatch` 影响、且没有其他降级原因的情况。必须保存原始警告及可用性声明，导入器再次检查该声明。所有批次采用同一检测游戏版本；便捷接口不适用此例外，也不得将不同版本的快照静默合并。

```bash
npm run data:update
node scripts/update-data.mjs --offline
```

默认参考仓库位于 `reference/ffxiv-gearing`。可通过 `FFXIV_GEARING_ROOT` 指向其他本地检出。联网模式执行 fast-forward 更新；离线模式只解析已有检出。

## 2. 属性与战斗规则

### 2.1 基础属性

最终属性不是装备属性的简单总和。计算顺序为：

1. 根据 `jobLevelModifiers` 取得等级基础参数。
2. 使用职业 `statModifiers` 计算主属性和耐力等基础值。
3. 加入族群属性。当前 UI 未提供族群选择，逻辑层默认使用上游索引 0，即“人族 - 中原之民”。
4. 累加装备及实际生效的魔晶石属性。
5. 最后应用食物的百分比加成和固定上限。

以 100 级武士为例，基础力量为：

```text
floor(440 * 112 / 100) + 2 = 494
```

遗漏基础属性会使伤害评分和已知配装产生数量级明显的偏差。

### 2.2 单件装备属性上限

魔晶石必须在单件装备上逐颗应用，不能先汇总全套后统一截断。上限完全复刻参考项目：

```text
cap = round(levelCaps[stat][itemLevelIndex]
            * slotCaps[stat][rawSlot]
            * roleCaps[stat][roleId]
            / 100000)
```

每颗魔晶石应用后的属性值为：

```text
effective = min(cap, current + materiaValue)
```

UI 中的 `+54` 表示魔晶石标称值；实际增加量可能因单件属性上限而小于 54。优化评分必须使用截断后的实际值。

### 2.3 魔晶石等级

- 数值来自上游 `materias`。
- 可用等级来自上游 `materiaGradeRequiredLevels`。
- 根据装备品级选择满足要求的最高等级，禁止写死“十二型”或固定 `+54`。
- 仅生成全部可用孔填满的候选；不可禁忌镶嵌装备填满普通孔，可禁忌镶嵌装备填满五孔，不提供关闭禁忌镶嵌选项；普通孔和首个禁断孔使用最高可用等级，其余禁断孔使用上游允许在限制孔使用的最高等级。限制等级规则由更新器从参考项目导入，不在领域层写死；不优化镶嵌成功率或成本。

### 2.4 伤害期望

`calculateEffects` 必须与参考项目 `equippedEffects` 的取整顺序一致，尤其包括：

- 暴击率与暴击伤害；
- 信念倍率、直击率、坚韧伤害与减伤；
- 职业主属性修正后的武器伤害；
- 默认 5% 队伍主属性加成，或职业显式提供的 `partyBonus`；
- 职业攻击主属性、特性倍率及 GCD 修正；
- 每一步规定位置的 `floor`，不能把取整统一移到公式末尾。

截图中的 7.55 武士基准已固化为回归测试：STR 6501、CRT 3605、DET 2533、DHT 1847、SKS 420、VIT 7467、武器性能 158，结果约为 101.8633，GCD 为 2.17 秒。

### 2.5 槽位规则

- 骑士使用主手和盾牌两个槽位。
- 其他战斗职业使用组合武器槽位。
- 两戒指槽内部表示为 `ring` 和 `ring2`；同 ID 仅在来源明确证明装备不是 unique 时允许。
- 双戒指读取同一原始槽位 12，候选配对必须遵守 unique 装备不能重复、非 unique 装备可以重复的规则。

### 2.6 前端结果展示规则

- 单职业采用四步向导：选择职业、选择目标、设置候选范围、检查并开始。职业无预选，每步由用户明确确认后前进，最后手动启动搜索；推荐默认值来自现有职业配置和生成数据。
- GCD、速度与坦克坚韧条件在目标步骤展开，来源和装备限制在范围步骤展开；高级限制默认折叠，收起后显示当前值或已启用数量，不清空配置。返回修改保留其他步骤输入。
- 搜索结果保留该次配置快照，不能将旧条件的结果显示为当前推荐。单职业重新配置时不混排旧结果、不展示新旧条件对照；第一步提供逐次搜索记录，载入指定成功结果不触发新搜索。每次单职业与联合搜索均在当前浏览器本地数据库记录时间、完整条件、状态和成功结果，刷新、重置配置或离开页面不删除记录；结果载入要求数据版本匹配，版本不匹配时明确说明，禁止用当前数据静默重新计算为旧结果。联合重新配置时同样隐藏旧结果并显示准备搜索状态，旧结果仍可从历史记录载入。搜索中、取消、无解、失败与完成状态必须有可辨识的标题和下一步提示。
- 搜索中显示估算进度条与阶段、已用时间、已准备装备方案和食物候选、求解器已报告核验量等小字信息。百分比由阶段与耗时估算，不能声称已知完整组合总数或精确候选完成比例；运行中最多显示 95%，未完成求解与复核时不得显示完成。候选计数使用领域层实际报告，不从示意数据构造；联合候选数量注明为各职业合计。
- 视觉方向使用用户选定的第一张方案：浅色工作台、青绿色强调、横向进度、右侧流程指引。装饰资产只作界面背景，不作为游戏数据。职业名称和可选职业集合由生成数据决定。
- 桌面优先通过重排信息与缩减间距尽量一屏呈现，不靠裁切、隐藏必需明细或不可读字号消除滚动。职业图标按用户指定的 XIVAPI 资产接口下载，职业行编号先通过 Lumina MCP 核对并保留来源记录；不得凭记忆添加职业编号。
- 本轮设计和验收按用户要求仅面向正常电脑视口（1440×900、1440×1024）；现有窄屏回退保留，不列入验收范围。不得隐藏必需属性、魔晶石、来源或品级。多职业保留独立入口，折叠的每职业配置显示当前摘要。

- 配装结果保持固定单列，顺序为武器、盾牌、头、身、手、腿、脚、耳坠、项链、手镯、戒指1、戒指2；多职业搜索的共享槽位选择双列左侧为武器、头、身、手、腿、脚，右侧为盾牌、耳坠、项链、手镯、戒指1、戒指2。无盾牌职业在结果单列省略该行，共享槽位选择无法共享盾牌时保留不可见的布局占位，不添加盾牌说明。
- 用户可见的固定文案必须使用中文；`GCD` 是唯一保留的业务专有名词，原始装备名称和来源名称可以保留上游语言。
- 属性名称必须使用以下中文映射：力量、灵巧、智力、精神、耐力、暴击、信念、直击、技速、咏速、坚韧、信仰、物理基本性能、魔法基本性能、攻击间隔。
- 指标名称统一使用“每威力伤害期望”，其数值直接来自与参考项目 `equippedEffects.damage` 同取整顺序的 `calculateEffects`。
- 推荐配装、装备逐行属性、食物、配装总属性和约束必须在同一结果页连续展示，不得通过标签页隐藏总属性。
- 每个装备行显示该装备最终实际属性，包括普通孔受单件上限截断后的结果；魔晶石标签显示上游标称数值。
- 装备行的副属性达到单件上限时加粗，判定复刻参考项目 `statHighlights`：只对参考项目标记为可高亮的副属性判断装备未镶嵌原生值是否达到上限，不把“镶嵌后刚好达到上限”误显示为原生满属性。

## 3. 优化搜索规则

正式算法位于 `src/domain/search`。单职业使用 `findBestLoadoutExactMip`；联合搜索使用 `findBestJointLoadoutV3`，领域适配负责由生成数据构造完整的装备、镶嵌及食物候选。详细设计见 [最优装备算法](最优装备算法.md)，实现证明与数值边界以 [V3 正确性与验收](V3正确性与验收.md) 为准。

- 不按启发式评分限制每槽装备数量，不设置固定宽度的中间状态截断。保留每件装备的全部合法普通孔属性方案，并按最终属性及共享所需完整身份去重。
- 使用 HiGHS 混合整数模型表示装备、食物的离散选择、食物取整及封顶、属性阶梯和约束。以具有误差界的固定点对数组织候选，再用整数伤害因子、BigInt 乘积或有理数复核所有仍可能改善目标的签名。
- 单职业目标支持每威力伤害期望和按 GCD 折算的目标。联合目标为各职业目标值除以各自单独最优基线的比例之和；不能用乘积最优替代比例总和最优。基线与联合模型采用同一目标和各职业约束。
- 各职业独立配置 GCD 单值或离散多值、速度上下界、最低坚韧、最低减伤百分比及最高坚韧。离散 GCD 的速度区间必须保持并集，不得填成包含未选档位的连续区间。
- 最高坚韧先在完整候选集合中求得，再将该值作为联合搜索的硬约束；不能固定共享方案后降低要求。
- 共享部位按名称对齐，包含同一装备及同一完整属性方案。共享戒指1与戒指2可分别选择或同时选择，匹配各自完整装备与镶嵌身份；完整戒指对仍用于校验整套配装的唯一性。联合 MIP 仅在有序 pair 候选恰好构成完整合法笛卡尔积、属性可加且 unique 元数据齐全时，才可内部拆成两个单戒指槽并按 `itemId` 添加跨槽 unique 约束；共享完整戒指对时必须保持同一无序身份多重集。条件不成立就回退 pair 模型，返回结果仍映射为原戒指对。共享食物取各职业可用食物身份交集，独立食物分别求解。
- 技速/咏速按角色读取：坦克、力量和灵巧职业使用技速，治疗和智力职业使用咏速。可行 GCD 查询与正式求解使用相同候选、食物、镶嵌与硬约束，输出档位必须能正式求解。
- 装备锁定约束装备 ID；锁定装备的普通孔仍参与优化。锁定 ID 缺失或与来源、品级、穿戴等级、排除条件冲突时返回无可行配装，不自动改选其他装备。等级同步先处理装备属性上限，并禁用被同步普通装备的魔晶石；自定义参数武器保留参数分配并按同步上限截断。
- 浏览器搜索在工作线程中执行，支持进度、取消和总时限保护；取消和超时不得返回未完成的结果。运行时缓存有界，不读取预先打表文件。
- 只有求解器报告最优且复核完成才返回结果，无法完成时明确失败，不返回近似配装。最优性限定于输入候选及约束；HiGHS 使用浮点求解，不提供独立形式化有理数证书。
- Node 验收入口的进程 RSS 保护与浏览器能力分别描述；浏览器无法取得进程 RSS，不能把不可用统计伪称为实测内存。
- Node 测试与验收包装集中在 `scripts/node-tests`。该目录只放 Node 测试、进程/Worker 启动和结果输出等调用层代码；搜索、候选生成、公式和游戏规则必须复用 `src/domain`，不得在脚本目录实现或复制算法。
- 当前多职业 Node 验收读取经过来源校验的生成数据，并调用 `runJointOptimizationLocally`；它不连接独立 MCP 客户端，也不导入参考项目脚本。
- `scripts/archive` 仅保存旧探索代码、测试记录和日志，不参与构建类型检查、不提供 npm 入口，也不得由生产代码或当前 Node 验收包装调用。需要手动复现历史探索时按该目录内的说明操作。
## 4. 正确性约束

- 生产数据必须具有可追溯来源，缺失必需字段时明确失败。
- 装备与魔晶石逐件按上游上限计算，允许最后一颗魔晶石部分生效；不得以局部伤害排名截断候选。
- 基础属性、职业武器伤害修正及队伍主属性加成必须进入正式公式。
- 公式拒绝未支持的等级与缺失的职业主属性、生命值修正，不以其他等级或默认修正替代必需资料。
- 食物百分比以基础属性、装备与实际镶嵌属性的合计计算，整数模型与结果展示必须一致。
- 速度上下界和最低坚韧值指包含基础属性与食物的最终值。最低减伤百分比通过领域公式换算。
- 盾牌使用独立副手槽，双戒指受装备唯一性限制。戒指1与戒指2的共享分别匹配各自装备和镶嵌方案，另一枚戒指仍须满足唯一性。

## 5. 当前边界

- 数据更新器已接入脚本化 `ffxiv-mcp-lumina` 查询产物；当前快照覆盖全部 21964 件可用战斗装备、420 种战斗食物和 22 个职业（包括 80 级上限的青魔法师）。`ClassJob` 原生职业属性修正来自 MCP；参考项目继续提供 GCD/特性/队伍公式、等级与默认品级 schema、族群常量及其余领域边界数据。仅青魔法师 INT 对应的魔法武器伤害加值表在 MCP 中缺失，使用已逐项核对的参考项目原始测量导出。
- 支持装备品级同步，同步普通装备按同步品级属性上限压缩且魔晶石失效；自定义参数武器保留参数分配并封顶。
- 支持合法禁断属性组合与等级限制，不计算成功率或镶嵌成本。
- 单职业与多职业联合搜索为独立页面；联合搜索支持共享完整装备与镶嵌，以及共享或独立食物。
- 强制装备当前锁定装备 ID，并不支持逐孔强制魔晶石；锁定装备仍会参与普通孔魔晶石优化。
- 族群目前固定为“人族 - 中原之民”，尚无 UI 选择。
- GCD 目标初始支持任意手动输入；点击“计算可行 GCD”后，UI 会按当前职业、品级、来源、强制装备、食物和坚韧约束切换为真实可行档位选择器。该查询使用正式候选生成器，覆盖同步和所选镶嵌规则。
- 生成数据直接打包进前端，主包较大；后续可按品级或职业拆分加载，但不能因此改变数据语义。

## 自定义参数武器

- 业务定义：装备带 `customizable: true`，且其自定义参数能从已确认的上游参数表读取。当前已知来源包括 `MandervilleWeaponEnhance`，但不能将其当作唯一类型；其他自定义参数武器可能在其他表中，必须分别确认来源后才能接入。
- 生产主键：每个已确认参数表中的有效 Item 主键。参考项目 `customizable: true` 集合仅作为别名溯源记录，不能替代未确认的参数表；不同参数表之间不能因共享字段结构就默认可合并。
- 参数语义：每件武器 4 个 Materia 槽，参数取值由 `Materia[i]`（Materia 行 ID）+ `MateriaBigValueIndex[i]` / `MateriaSmallValueIndex[i]` 决定；候选生成阶段必须按 Materia 行读取实际 stat/value，不得使用 12/24/54 等固定数值。
- 上游可选规则：4 个槽位中必须选 1 small + 2 big + 1 空槽，每个槽至多被选一次；候选数 C(4,1) × C(3,2) = 12。
- 候选生成实现：领域候选构造器 按"先选 1 small、再从剩余 3 槽选 2 big、1 槽留空"生成 meld；若 `customParameters.length !== 4` 显式抛出异常，禁止静默兜底。
- 当前快照（MCP 2026.09.15）记录 `MandervilleWeaponEnhance` 的 62 个有效参数行，所有 Item 主键与查询范围保存在快照。参考项目的别名只作溯源，不代替 MCP 主键；其他自定义参数武器仍须分别确认参数表。
- 当前已确认参数表缺失或与参考项目别名完全无交集时，导入器必须显式失败；不允许把参考项目 `customizable: true` 装备作为未确认参数表的生产信源。
