## M01：食物效果与利用率

### 已确认决定

用户确认领域层返回的食物结果包含：每项属性的加成上限、加成比例、实际生效加成，以及按参考项目公式计算的利用率。UI 不再自行计算该比例，也不再以固定 100% 冒充实际利用率。

### 结果契约

`OptimizationResult.food` 使用 `FoodResult`：

| 字段 | 含义 |
| --- | --- |
| `stats` | 原始食物各项属性的加成上限 |
| `statRates` | 原始食物各项属性的加成比例，百分数口径沿用既有数据 |
| `actualStats` | 本职业本配装中各项实际生效增益；原始食物中对该职业不生效的属性记录为 0 |
| `utilization` | 整数百分比，计算方式如下 |

```text
utilization = floor(sum(actualStats) / sum(stats) × 100)
```

分子、分母均遍历原始食物的属性集合；不是逐项百分比的算术平均。取整沿用项目与上游的浮点边界容差。上限总和为 0 时利用率定义为 0，避免无定义数值。

`src/domain/food-result.ts` 从既有 `applyFood` 计算前后取得属性差值并生成快照，不重复食物公式，不改变候选、镶嵌、目标、约束、求解与证明。`optimizer/result-assembly.ts` 是正式组装入口；单职业、联合搜索的各职业结果和各单职业基线均使用这一入口。同一共享食物的效果仍按各职业分别保存。

### UI 与历史

- 食物属性行优先显示 `food.actualStats`；利用率直接展示 `food.utilization`。
- 项目尚未上线，本次重构不考虑旧历史数据的 schema 兼容性。`actualStats` 和 `utilization` 为领域结果必填字段，历史校验要求提供完整字段；不提供旧数据回退、迁移或重算。
- 移除先前 UI-only `actualFoodStats` 扩展字段和“利用率未记录”展示分支。
- 历史保存/恢复和 Comparison 传递保存的食物快照；Comparison 食物身份包含实际增益与利用率，避免同一食物在不同职业/方案中的不同效果被合并。
- 未来固定配装导入计算应返回同一食物效果契约；本项没有提前接入 M04。

### 验证范围

- 新食物快照模块：封顶、未封顶、按总量加权而非平均、职业不适用属性、零增益、零上限及输入不变性。

## M02：职业上限与同步等级

### 已确认决定

用户确认严格按职业当前上限处理，移除低等级角色配置。三个概念保持独立：职业上限控制可穿戴性，同步品级控制装备属性 cap，公式等级控制基础属性、食物所依赖的基础值、伤害与 GCD 参数。

```text
wearableLevel = jobMaxLevel
calculationLevel = syncLevel 存在
  ? min(syncLevel 映射出的等级, jobMaxLevel)
  : jobMaxLevel
```

- 上限来自真实职业规则，未单独指定上限的职业使用运行时已支持最高等级；不固定为 100。缺少职业规则或必需等级参数时失败。
- 同步映射沿用真实数据：优先查同步品级分组，再查职业等级对应品级的精确映射。不支持的映射明确失败，不猜测邻近等级。
- 即使只搜低品级装备，未同步时仍按职业上限计算。来源、装备排除、强制装备及候选品级范围不改变公式等级。
- 低等级同步不排除职业上限内可穿戴的高等级装备；装备同步、普通镶嵌失效、自定义参数武器规则沿用既有实现。无候选仍返回无可行结果，不捏造配装。
- 移除 `OptimizationConfig.jobLevel` 和 UI 编译/GCD 查询中的对应配置。保留既有 `syncLevel` 字段名，其语义仍为同步品级；外部配装器分享格式中的等级字段属于该协议，保留读取和编码能力，不提供低等级角色搜索配置。
- 项目未上线，本轮不迁移或兼容旧历史 schema；成功结果仍保存本次实际 `calculationLevel`，恢复结果不重新计算。

移除角色等级字段后，已有求解器策略场景判断也删除该字段条件；求解器、目标、硬约束和证明逻辑保持原实现。为使 Node 正式入口及联合基线 Worker 能运行，将领域数据的二进制解码器导入改为相对路径，消除对 Vite 路径别名的依赖。

本次已确认契约取代领域规则文档中旧的“候选派生公式等级”语义；用户此前要求的跨目录规范同步仍留待后续处理。

## M03：同步 Single 的同属性替换

### 用户确认

- 按对应装备类型的最终生效属性逐项完全相同判定，包含武器性能和攻击间隔；候选满足原搜索条件。
- 完整保存普通镶嵌、固定槽自定义参数和义军武器整数参数分配。
- 槽位通过 key 引用完整替换数组，数组包含所有项及当前项，不因选择而交换或重建。
- 戒指分别引用完整主数组与唯一子集数组；另一槽已选同 ID 唯一戒指时，由 UI 显示禁用候选，不隐藏。

该决定覆盖原规范“不包含当前项、切换时交换数组”和此前提出的“领域重新过滤另一戒指列表”建议。详见[结果与实验室](04-结果与实验室.md#同步-single-的同属性替换)。

### 接入

`ResultGear` 提供 `replacementGroupKey` / `uniqueReplacementGroupKey`，`OptimizationResult.equivalentGear` 集中保存完整 `MeldedGear` 数组。同步 Single 求解后由 `optimizer/equivalent-gear.ts` 收集；Joint 和非同步 Single 不启用。

重新使用原始合法池与既有装备方案生成器，避免 Pareto 剪枝丢失同属性不同物品。保留原来源、排除和强制约束；义军武器根据目标差值反推唯一的有效分配，检查单项/同步上限/总量，不枚举全部整数域。求解目标、搜索候选、硬约束与最优性证明不变。

UI 只读取完整主数组展示，唯一子集数组仅参与冲突判断，当前项保留选中样式，唯一冲突显示禁用。选择只更新该槽装备并保留组 key，数组保持不变；回写同一历史记录，恢复时校验引用与完整快照。固定配装导入采用下文 M04 的独立计算入口。

## M04：分享链接的固定配装计算

### 已确认决定与实现

- 分享解析仍在 UI service；默认 `resolveImportedGearset` 调用领域 `calculateFixedGearset`，按当前数据版本返回完整对比快照。
- 始终以职业上限检查穿戴及装备同步规则；公式等级由统一等级规则推导，链接携带等级必须与之相同。低等级角色配置不恢复，同步链接的公式等级可以低于职业上限。
- 必须包含完整且无重复部位的同职业配装和当前目录可识别的食物。检查装备唯一性、职业/穿戴条件、普通孔和禁断孔的等级限制、装备品级对应的魔晶石可用等级，以及自定义参数合法性。缺少资料或非法配置明确拒绝，不自动补齐。
- 固定配装允许合法空孔及低等级魔晶石，不填孔、不优化。解析器保留 `null` 空孔，普通魔晶石的 `slotIndex` 保留物理孔位，用于禁断显示和再次分享。
- 搜索结果的魔晶石数组按属性聚合，无物理孔位承诺。仅在分享导出时将受限等级稳定排在安全孔及首个禁断孔；不修改原结果数组和表格顺序。有显式孔位的输入原样保留。
- 自定义参数是参考分享协议中的绝对属性值。曼德维尔类武器验证 2 大 + 1 小合法分配；义军武器验证原始单项/总预算，允许零分配。先覆盖原始装备属性，再应用同步上限，合法原始分配超过同步 cap 时截断而非拒绝。分享导出使用原始分配，不能从已封顶结果反推。
- 属性、食物、伤害和 GCD 使用正式领域公式链。食物结果包含上限、比例、实际增益及真实利用率；UI 读取领域百分比，不设固定 100%。
- 此入口仅计算指定配装，不启动搜索，不产生搜索记录、搜索耗时或可替换数组。相同显式孔位与默认顺序在 Comparison 合并，实际孔位不同则独立展示。

### 验证
