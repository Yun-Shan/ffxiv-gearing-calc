# 冲突与修改边界

[返回入口](README.md)。本页记录本轮用户指示与尚待确认项，不修改现行规则。确认状态只来自用户，不由代理复核代替。

## 本轮已明确的适用方式

- 本次是重构设计，不能假定与现行规则一致；冲突部分逐项向用户确认。
- Penpot 尚未按本次方案修改，仅作为风格参考。结构、内容、布局、流程以重构设计及用户确认作为依据，浏览器仍需真实验证。
- 规则文档在重构完成后更新，不在设计阶段提前覆盖现行规则。
- 本次重构范围明确限定为 `src/ui/**`。需要 domain 修改的部分先做 mock 完成组件测试；全部 UI 完成后、最终 Playwright 测试复核前，才提交具体 domain 方案，由用户确认后修改。其它目录外修改仍须单独确认。

## src/ui 以外的修改确认

先提供具体文件/目录、必要性、行为变化、备选方案及验证范围，再等待用户确认。只读检查可继续；UI 依赖 domain 新能力时先 mock 完成组件测试，不修改真实 domain，也不能将领域公式复制到 UI 规避授权。

| 可能涉及的范围 | 原因 | 当前状态 |
| --- | --- | --- |
| `src/domain/**` 及目录外测试 | 等级策略、结果携带等价候选、固定配装计算契约等 | 先 mock 完成全部 UI；最终 Playwright 前由用户确认具体方案后才修改 |
| `src/data/**`、更新脚本、运行时格式 | 仅在确认确有数据或契约缺口时提出，不能预设需重生成 | 未授权修改 |
| `src/styles/**`、`src/main.*` 等 UI 外入口 | 全局 token、全局 @media、样式入口等可能需要协调 | 未授权修改；不能因样式清理跨出 src/ui |
| package 文件、构建/测试配置、public 资源、其它 scripts | 依赖、工具、资源等调整 | 未授权修改 |
| `docs/**`、README、AGENTS.md、项目 skill | 完成后的规则/证明/入口同步 | 需另行确认；本轮只授权修订本组重构设计文档 |

`src/ui` 内同样不得未经确认实施规则冲突。规则变化的确认与外部文件修改的确认是两个边界，不能互相替代。UI 可通过测试替身继续完成；真实 domain 集成保留到指定确认阶段，具体顺序与 mock 边界见[实施与验收](06-实施与验收.md)。

## 对照 Issue 的覆盖与未决项

本次实际重新读取 Issue #2 正文及全部 7 条评论。以下未决项来自来源缺口，不通过代理选择补成产品规则：

| 未决项 | 影响与确认时点 |
| --- | --- |
| Joint shared/job 跨 scope 的 force 与 exclusion 冲突 | 来源只给出通用清理规则，未说是否改动另一 scope/其它 Job；在实现相关事务前确认；详见条件文档 |
| Comparison 多方案展开与无滚动/无裁切的冲突 | 未确定容量和溢出承载方式；在完成比较页布局前确认，不能自行截断或加分页/滚动 |
| Comparison 删除基准、主动切换职业及方案数量 | 第一方案为基准已确定，其它操作未定；若实现这些操作，先确认具体行为 |
| Comparison 基准值为零的相对差展示 | 公式未定义零分母显示，需确定实际可达性及对应展示，不输出 NaN/Infinity |

这些 UI 行为问题可以在对应组件实现前集中确认，不提前要求批准 domain 方案。等级、等价判定、固定配装计算仍按既定 mock → 全部 UI 完成 → 用户确认 domain → 最终 Playwright 顺序处理。
