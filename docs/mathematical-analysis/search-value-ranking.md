# 装备搜索优化价值排序（基于当前定理与测量）

> **范围与诚实边界**：本文件把 `docs/mathematical-analysis/` 现有定理与候选池测量，整理成**面向装备搜索实现的工程价值排序**。
> 所有"预期效果"都是**工程估算**，不是测量结果；本轮**没有**接入生产搜索、没有跑 MILP/benchmark、没有性能验收。
> 定理状态以各目录 README 为准；测量数字来自 [measurements/substat-sum-bounds.md](measurements/substat-sum-bounds.md)。
> 排序依据是"**预期可减少的搜索工作 / 实现与接入成本 / 风险**"，不是定理的数学深度。
> **本版已按同域比较修正"界之间的支配关系"，并按生产现状修正"联合判据是否已实现"的判断。**

## 1. 评价口径

对每条定理/工具，按四个量做工程判断：

1. **可剪对象**：候选、partial branch、共享方案、MIP 变量/分支、还是仅几何/证书；
2. **强度**：上界/必要条件的紧度（越贴近真实最优越强）；
3. **单位成本**：`O(·)` 与常数（BigInt 次数、预计算规模、是否每候选重算）；
4. **命中率与风险**：前提失效频率、tie/坐标/数据依赖、回退成本。

排序的经验法则：

```text
价值 ≈ (可剪对象的规模 × 强度带来的剪枝比例) / (单位成本 × 实现风险)
```

### 1.1 关键修正：不同界的强度只在**同一约束域**内可比

**不能**写"`U` ≥ frontier 半空间 ≥ 和割"这样的全序。三者保留的约束不同：

- `U(b,R,κ)` 只保留三副属性乘积 + **总和**预算 + 逐属性 caps；它**不保留**加权资源约束、main/weapon/TEN/GCD 的相关性；
- frontier 的半空间 `w·x ≥ K_w` 保留任意方向 `w` 的**加权**约束；
- 和割保留的是 `w=(1,1,1)`。

因此存在"frontier 能整支排除、`U` 不能"的实例（见 §2.2 的 同域比较 反例），也存在"`U` 是精确乘积界、比半空间更紧"的实例。**实践中应取所有合法界的交集/更紧值（取 min），不能假设某个界支配另一个。**

同样，生产 `prepareResourceBudgetCandidateBounds`（`loadout-finder-exact-mip.ts:1222–1285`）已覆盖 `main/weapon/det/ten/crt/dht/gcd` 与加权资源支持，并调用 `prepareFactorResourceBudgetUpperBound`（`:1267,1353`）；三副属性 `U` 是**另一个松弛**，应作为**额外**上界与其取更紧，不能直接宣称替换或更强。

### 2.2 两处关键修正（同域比较与联合判据）

**frontier 与 `U` 不可比较，二者互补；PR6 是同类能力。** 反例（L100 普通公式）：真实可达贡献只有 `(100,0,0)`、`(0,20,0)`；取 `b=0`、`R=100`、`κ=(100,20,0)`、`B=Φ(100,0,0)=4,092,796,000,000`。自由预算域含 `(84,16,0)`，其乘积 `4,094,012,208,000>B`，故 `U>B`，`U` 无法排除严格改善；但取 `w=(1,5,0)`，真实加权最大值为 `100`，而盒域支撑阈值 `K_w(B)=128`（DHT 档位最小 H 的枚举：`C+5H` 最小 128），`100<128` ⇒ frontier 半空间可整支排除。原因是 `U` 未保留加权资源约束。**"同域"必须指实际使用的松弛约束（目标、预算、caps、加权资源、TEN/GCD 等）完全一致**，不能只指"研究同一个真实候选问题"。**PR6（任意方向半空间）属于 frontier 同类能力**：可以包含能排除而 `U` 不能排除的加权方向，因此不能与 PR4/5（和割/候选和割）一起被笼统判为"被乘积界支配"；要么逐方向证明冗余，要么按排名 3 评估。**结论**：`U`、frontier、PR6、和割没有全序；实施时必须"取 min/交集"。

**(联合判据) 联合损失和判据已在生产实现。** `src/domain/search/loadout-finder-exact-mip.ts:3316–3340` 的 `ratioSumAtOrBelowThreshold`、第 `4070` 行的共享前缀剪枝、以及 `:4091–4126` 的必要子集割（`addRatioUpperNecessaryCuts`）已实现 `Σ u_j` 族的精确 BigInt 剪枝。**本定理不是"待新增"的联合能力**；新增空间仅是用更紧的 `U_j` 改进既有判据的输入，增量必须单独测量。排序已相应下调并标注"增量"。

## 3. 第一梯队详解（排名 1–3）

### 3.1 排名 1：`U(b,R,κ)` 精确 tier-triple 预算上界

**原理**：自由资源松弛的三属性因子乘积最大可精确写成

```text
U(b,R,κ) = max { Π_i F_i(t_i) : t_i ∈ T_i,  Σ_i θ_i(t_i) ≤ R } ，
T_i = 每属性可达档位，θ_i(t) = max(0, g_i(t) − b_i)
```

对 `(C,D)` 档位对做排序/前缀最大（`P=|T_C||T_D|`），再枚举 `T_H` 二分查询；是**精确等式**，不是启发式界。

**实现方向**

1. 复用 `prepareSubstatFactorBudgetQuery`（`src/domain/search/substat-factor-budget.ts:71-171`）；它已经实现类表、配对、排序、前缀最大、查询。
2. 接入点：与生产 `prepareResourceBudgetCandidateBounds`（`loadout-finder-exact-mip.ts:1222–1285`，覆盖 main/weapon/det/ten/crt/dht/gcd 与加权资源）**取更紧**；在 `candidateUpperBoundCannotImproveIncumbent`（`exact-mip-candidate-upper-bound.ts:96-140`）中作为额外上界。不可直接替换生产界。
3. 缓存：`(level, job, b, κ)` → 查询器；候选/分支的 `b,κ` 不同，需评估“每候选重算预计算”的成本；分层策略：
   - 分支级（`b` 相同、`R` 递减）缓存一次、逐分支只查询；
   - 候选级若预计算过贵，退回现有完整资源界/粗上界（排名 9）。
4. 保持 BigInt/交叉乘法语义；`P1–P8` 前提（公式域、baseline、R/κ、因子域、精确算术、其它乘区乐观上界、查询可用）。
5. 失败回退：查询 `undefined`（`maxWork` 超限/非法）→ 现有 `prepareFactorResourceBudgetUpperBound`；不得把“无结果”当“不可改善”。

**预期效果（估算）**：作为**额外**三副属性上界，理论上能加强候选/分支上界（与现有界取 min），L100、`G=3000` 时精确查询计算量比三维枚举小 2–3 个数量级。但端到端增量取决于：现有完整资源界有多松、每候选预计算成本、MIP 的 LP 界。**未测量，不能给提速数字**。

**风险**：`R/κ` 构造错误 ⇒ 低估（不安全）；`b` 不是已提交下界 ⇒ 不安全；每候选重算可能吃掉收益；与生产界的关系需同域证明（不能用 U 替代完整资源界）。必须先接排名 2 的 `R/κ` 构造。

### 3.2 排名 2：更紧的 `R/κ` 构造（substat-sum-upper-bound）

**原理**：`U` 的输入 `R` 是“剩余来源对三属性贡献**总和**的严格上界”（相对 baseline 的增量）；`R_sep = Σ_i Σ_s max x_i` 是合法但松的构造。更紧的是逐槽对 `S3=CRT+DHT+DET` 取 max 再求和、戒指唯一性精确配对、义军武器精确和（只统计目标属性，见 义军目标属性 修正）、食物上界族、约束 Lagrangian 界。

**测量支撑（这是测量，不是估算）**：

- 验收 18 case / 52 职业行：`R_gear^uniq` 相对 `R_sep` 收紧 **12.44–28.22%**（均 25.30%）；食物族相对 `R_food_naive` 收紧 **12.01–27.43%**。
- 戒指唯一性 gap 在部分 case 为正（坦克 case 7、治疗 case 88），忽略会高估。
- `R_food` 在基线 18/36、验收 52/52 个实例被合法完成精确达到（高品级食物 cap 饱和）。

**实现方向**：候选池构造后，对每个槽取 `max S3`（义军武器用 `S3(x0)+min(T,Σ_{i∈{CRT,DHT,DET}}m_i)`）、戒指用精确配对（生产已有 `buildRingPairEquipInfos` 可复用配对候选）、食物按 B1–B4 族；每分支/候选只对“剩余槽”重算（增量滚动），成本 `O(Σ|C_s|)`。`κ_i` 仍用逐属性上界。

**预期效果（估算）**：**中高**。它本身不剪枝，但把排名 1 的 `U` 直接收紧；`U` 对 `R` 只阶梯变化，因此乘积界收紧幅度小于和界百分比，需要按档位阈值评估。成本低、风险低，应作为排名 1 的前置工作包。

### 3.3 排名 3：incumbent frontier / `K_w` 半空间（strict-improvement-frontier）

**原理**：`K_w(B)=min{w·x: Φ(x) 的其它因子乐观乘积 > incumbent}` 给出必要半空间；任意方向 `w`，候选/分支若 `w·x<K_w` 即整支不可严格改善。`Ω_slab`（加了 `L≤Σ≤R`）**不是坐标上集**：D_min 不再单调、tier 单元不再常值，盒域代表元/最小反链算法不能直接继承；正确计算需按 `D_min_slab(C,H)` 全枚举或重新推导 breakpoints。

**实现方向**：每 `B` 计算一次 `D_min`/最小反链（或 slab 上的全枚举），之后候选检查 O(1)；选择方向 `w`（轴、和、加权资源方向）是性能 policy，不改变正确性。**加权资源方向是它在 `U` 之外的独立价值**（加权反例）；不能假设 `U` 支配它。

**预期效果（估算）**：**中**。在 `U` 可用时，同域内通常被精确乘积界支配；但在保留加权资源/其它约束、或 `U` 查询不可用时，可整支排除。收益取决于接入点与方向选择，未测。

## 4. 第二/三梯队（排名 4–9）

- **排名 4 联合损失和（增量）**：判据本身已在生产实现（见 §2.2 联合判据；`ratioSumAtOrBelowThreshold`、子集割）；本定理只提供数学表述与 `u_j` 概念。新增空间是用更紧的 `U_j` 加强既有判据；**不能**把同一求和判据计为独立收益。预期中低，需增量 A/B。
- **排名 5 pairwise 关键集**：把 2D 切片求值从 `O(D)` 降到 `O(D·a/q)`（L100 约 5–7%）；主要价值是加速 frontier 的 2D 子问题、部分归约证书和独立 2D 精确最大；对三维 `U` 查询本身不是必需。
- **排名 6 顶点/部分归约**：证书通过时精确 `U` 可换成 O(1)/四类 facet 的 2D 求值；但端点最大全域失败、证书在真实区间大量失败（见 [simplex-vertex-reduction](theorems/simplex-vertex-reduction/README.md)，且其 caps 绑定时部分归约必须用四 facet 版），命中率低；精确查询必须保留。
- **排名 7 slab/和的下界剪枝**：PR1 可把 `Ω` 收紧为 `Ω∩{L≤Σ≤R}` 并让 `K_w` 在集合意义上不减；但 `Ω_slab` 非上集，D_min 非单调、tier 代表元失效，需要全枚举/重新推导。**PR4/5**（和割/候选和割）在同域内被乘积界支配；**PR6** 是任意方向半空间族（含加权方向），与 `U` 互补，必须逐方向按排名 3 评估，不能笼统排除。slab 仍宽（测量 `R_food−L1` 约 0.76k–4.5k）。预期低（PR6 的增量则取决于实际方向）。
- **排名 8 坐标 box（`e_i` 支撑）**：与 frontier 的 3 个轴支撑等价，不增剪枝强度；可作显式证书/存在性推理，`T` 幂等且低 B 常停滞。不放在高价值区。
- **排名 9 `U_m`/保守 majorant**：只在精确 `U` 查询不可用时作安全回退；`U_16` 对 CRT-DHT 仍 ~49bp、DHT-DET ~228bp 的 gap，远松于精确查询。

## 5. 推荐实施路线（按依赖与收益）

**阶段 A（上界层，最高优先）**
1. 实现排名 2 的 `R/κ` 构造（一次候选池扫描，可先只在现成 `candidatePools` 结果上做）。
2. 接入排名 1 的 `U` 查询（先分支级/相同 `b` 缓存；候选级用成本阈值决定是否启用）；**与生产 `prepareResourceBudgetCandidateBounds` 取更紧，不做替换假设**。
3. 验收指标（实现侧，不是本轮）：候选上界调用次数、`U≤incumbent` 比例、MIP 节点/耗时——**需要单独 pilot，当前未做**。

**阶段 B（单职业预过滤）**
4. 排名 3：frontier `K_w` 预过滤（尤其是加权资源方向；`U` 查询超限/不可用时作回退）。

**阶段 C（联合层，增量）**
5. 排名 4：用更紧的 `U_j` 加强**既有**联合 ratio-sum/子集割判据；只测量增量剪枝，不把判据本身计为新收益。

**阶段 D（细粒度/回退）**
6. 排名 5 pairwise 关键集，作为 frontier/部分归约的 2D 求解器。
7. 排名 6 caps 感知证书；排名 7–9 仅作回退。

**阶段 E（正确性门，先于任何真实候选删除）**
8. [marginal-comparison](theorems/marginal-comparison/README.md)/[attribute-swap-criterion](theorems/attribute-swap-criterion/README.md)：松弛内 ≤/交换只能用于松弛状态；真实装备删除必须满足三条安全路径之一。否则“优化”会改变最优解（已有分离反例）。

| --- | --- | --- | --- |

## 7. 风险、回退与正确性门

- **坐标**：全部使用贡献坐标（面板 = base + 贡献；CRT/DHT/TEN 减 `sub`、DET 减 `main`，不可统一平移）。
- **界的同域比较（同域比较）**：`U`、frontier、和割保留的约束不同；不能写全序支配。合并方式是取更紧值/交集，且必须保证各界的定义域、目标、tie 语义一致。
- **前提失败**：`R/κ` 无法认证、`U` 查询不可用、`b` 不是下界、`B` 不是同域下界、共享/戒指/食物耦合无法认证 → 回退到现有安全上界（完整资源界/现有精确求解器）；不得用经验系数替代。
- **slab**：`Ω_slab` 非上集，不能沿用盒域 D_min 单调/代表元算法；K_w 必须按点或重新推导的 breakpoints 计算。
- **tie 语义（非严格域/同分点可达性）**：`B=P*` 时非严格域非空；`O|P_inc` 不保证同分点（还需商可达）；严格/非严格核不能混用。
- **真实候选删除**：只允许显式合法替代、严格乐观上界、全坐标支配三条路径；松弛内交换不得删除真实装备。
- **数据/版本**：数据版本变化后必须重跑 `verify-canonical-model.mjs` 与相关定理 `verify.mjs`；`R/κ` 构造依赖候选池，需按输入重算。
