## 3 符号、量词与定义域

### 3.1 因子与坐标

沿用参考模型的整数档位/因子：对 `sigma ∈ {C,H,D}`（CRT/DHT/DET）与贡献 `g >= 0`，

```text
t_sigma(g) = 档位函数（参考模型 §3）
F_C(t) = 1_000_000 + t(t+b_C),  b_C = 350（普通）/150（BLU）
F_H(t) = 4000 + t,   F_D(t) = t
Phi_sigma(g) := F_sigma(t_sigma(g)) > 0
```

**坐标是贡献 `g`（不是面板总值）**：面板 CRT/DHT/TEN = `sub` + 贡献，面板 DET = `main` + 贡献；基础属性归约（`equipped-effects.ts:127`、`getBaseStats` `:178-203`）与换算式见参考模型 §2.1，可达域内 `g >= 0` 与截断等价的结构性依据见 §2.2。交换算子移动的是**贡献** `delta` 个单位；因为偏移在每对坐标上是常数，交换的差分/判据对坐标平移不变（面板与贡献下判据相同；但绝对阈值需换算）。完整坐标审计见 §13。

### 3.2 自由资源松弛

```text
Omega_R = { c >= 0, h >= 0, d >= 0 : c + h + d <= R }   （或带逐属性 cap：c <= kappa_C 等）
baseline b = (C0,H0,D0)                                   （贡献基线：装备+食物已计入的初始贡献）
x = (C,H,D) = (C0+c, H0+h, D0+d) ∈ Omega := b + Omega_R       （松弛状态空间，贡献坐标）
V_R(x) := Phi_C(C) * Phi_H(H) * Phi_D(D)                       （副属性乘积；比较目标）
```

松弛还允许其它目标乘区取乐观上界（见 [strict-improvement-frontier](../strict-improvement-frontier/README.md) Lemma 0），但**交换判据只作用于三个副属性因子**，其它因子在交换中不变，故判据只需比较副属性乘积（约去正因子）。

### 3.3 交换算子

对方向 `i != j ∈ {C,H,D}` 与整数 `delta >= 1`（`delta` 是**贡献**单位；面板差分同为 `delta`，因偏移为常数）：

```text
Swap_{i <- j, delta}(x) = x + delta * e_i - delta * e_j
```

**松弛内可行**的条件：

```text
x_j >= delta（保证 j 坐标非负）且 x_i + delta <= kappa_i（盒式 cap；simplex 无此条）
```

（simplex 的 `c+h+d = R` 在交换下不变；`c+h+d <= R` 型松弛中交换也不改变总和。）

记

```text
F0 := Phi_i(x_i),   F1 := Phi_i(x_i + delta)
G0 := Phi_j(x_j),   G1 := Phi_j(x_j - delta)
```

交换前/后的副属性乘积（其余因子固定为正，约去）：

```text
V_before = F0 * G0 * R(x)      （R(x) 为不变的第三副属性因子与其它乘区）
V_after  = F1 * G1 * R(x)
```

### 3.4 边际比较中的「转移」

当比较的不是一次等量交换，而是两个**独立转移**（例如相邻 tier step）：

```text
转移 P：F0 -> F1，成本 cF > 0（原始属性单位）
转移 Q：G0 -> G1，成本 cG > 0
```

其中 `F0,F1,G0,G1` 均为正整数，`cF,cG ∈ Z_{>0}`。此时比较的是单位成本相对增益 `ln(F1/F0)/cF` 与 `ln(G1/G0)/cG`。注意这与 §3.3 的「一次交换」不是同一对象：交换的两侧成本按定义相等（都是 `delta` 个原始单位）。

### 3.5 真实装备模型

一个真实模型 `M` 包含：槽位集合 `S`、每槽可用物品集合 `I_s`（每件物品给出非负整数属性向量）、每槽镶嵌/魔石上限、食物规则、共享身份/唯一性约束 `U`（同一物品不能以相同身份重复占用、两枚戒指只有明确非 unique 时可同 ID）、硬约束 `H`（GCD 档位集合、最低坚韧、最低减伤、同步 cap 等）。记

```text
Gamma(M)          = 满足全部规则与硬约束的真实配置集合
sigma: Gamma -> Z_{>=0}^3,  sigma(gamma) = (C,H,D) 贡献三元组     （真实 stat 映射）
phi_img = sigma(Gamma) ⊆ Omega = b + Omega_R                    （取 Omega 足够大）
V(gamma) = 完整伤害/DPS 目标值
```

对任意真实模型，`V` 在 `gamma` 与 `sigma(gamma)` 上通常不能只由 `V_R` 决定（其它乘区随物品/食物/速度变化）；本文在反例模型里固定其它乘区以把问题压缩到副属性因子（这不影响分离结论的一般性，见 §6.5）。

## 4 假设

- **(P1) 因子正性。** 参与比较的因子 `F0,F1,G0,G1` 均为正整数值（production `safeDamageFactors` 的同等前提，`exact-mip-candidate-upper-bound.ts:96-106`）。该前提在 `g >= 0` 上由 canonical 参数保证（[tier-log-curvature](../tier-log-curvature/README.md)）；若因子可能为 0/负，`ln` 与比值均无定义，判据必须禁用（反例 §7.3）。
- **(P2) 精确整数运算。** 交换判据只用整数乘积比较（BigInt），不使用浮点 `log`；`ln` 只出现在**证明**中，不出现在运行时判定。
- **(P3) 松弛可行性。** 被消除的状态必须在松弛 `Omega` 内；交换目标 `x'` 必须满足 §3.3 的可行性条件。退出 `Omega` 的「交换」不是松弛移动，不能用于消除。
- **(P4) 真实删除独立认证。** 从真实模型删除物品/镶嵌/食物候选，必须另行满足 Theorem 3.2 的 (a)/(b)/(c) 之一；交换判据本身不构成删除理由。真实域的约束（共享身份、戒指唯一性、共享食物、GCD 与最低坚韧）必须保留（`docs/rules/领域与搜索规则.md:18,34-40,45-46`）。**「只触及 CRT/DHT/DET」的交换判据仅在 SKS/SPS（速度）、TEN、主属性与全部硬约束固定或不受影响时才成立**；否则交换会带动其它乘区变化，`R(x)` 不再是常数。
- **(P5) 目标语义。** 「严格改善」与「同分/tie 保留」是不同模型（Theorem 2.2）；「找任一最优」与「枚举全部最优（含身份）」也不同。
- **(P6) 截断语义。** `g >= 0` 上 `Math.trunc(v+1e-7)=floor(v)`（[raw-tier-transform](../raw-tier-transform/README.md)）；`g >= 0` 由基础属性归约 + 候选贡献非负结构性成立（参考模型 §2.2）。

## 5 精确命题

### 5.1 Theorem 1.1：两状态交换的精确判据

设 `x ∈ Omega`、`Swap_{i<-j,delta}(x) = x' ∈ Omega`，因子定义如 §3.3，第三副属性因子与其它乘区在 `x, x'` 上相同且为正。则：

1. 交换结果的符号完全由整数乘积决定：

```text
V_after > V_before  <=>  F1 * G1 > F0 * G0
V_after = V_before  <=>  F1 * G1 = F0 * G0
V_after < V_before  <=>  F1 * G1 < F0 * G0
```

2. 该判定是精确、可终止的：`F1*G1`、`F0*G0` 为整数（生产用 BigInt）；比较结果与浮点无关。
3. 平台的正确处理：

```text
若 t_i(x_i + delta) = t_i(x_i) 则 F1 = F0；若 t_j(x_j - delta) = t_j(x_j) 则 G1 = G0。
因此：两个因子都不变 => tie；只有 i 变而 j 不变 => 严格改善（F1>F0）；只有 j 变而 i 不变 => 严格恶化；
两个都变 => 由精确乘积比较决定净方向。
```

4. 边界：`x_j < delta` 或（盒式 cap 下）`x_i + delta > kappa_i` 时该交换在松弛内不可行，不能作为消除依据；但「不可行」本身不构成任何结论。

### 5.2 Theorem 1.2：单位成本边际比较的交叉指数判据

对正整数 `F0,F1,G0,G1` 与正整数成本 `cF,cG`：

```text
ln(F1/F0) / cF  >=  ln(G1/G0) / cG
        <=>  F1^cG * G0^cF  >=  F0^cG * G1^cF
```

且该式两边均为整数，可用 BigInt 精确判定。等号/严格/反向关系同理成立。

> 该式是评论 02 §七 给出的**更正后**形式。issue 正文旧形式在 `cF != cG` 时不等价（§7.2 给出数值反例）。

### 5.3 Theorem 1.3：交换判据 = 等成本边际比较（归约）；不等成本形式不能替代交换判据

1. **归约。** 在 §3.3 的交换中取「转移 P = i 的前向因子变化 `F0 -> F1`，成本 `cF = delta`」与「转移 Q = j 的**反向**因子变化 `G1 -> G0`，成本 `cG = delta`」（后者表示「从交换后状态回退到交换前状态」），则 Theorem 1.2 的比较式变为

```text
F1^delta * G1^delta  >=  F0^delta * G0^delta
<=>  F1 * G1 >= F0 * G0          （两边开 delta 次方；因子全正且 delta>0）
```

即恰为 Theorem 1.1 的精确交换判据。反之，Theorem 1.1 的判据也可写成 Theorem 1.2 在 `cF=cG=delta` 时的形式。因此「等成本交换」是边际比较的特例，两者不矛盾。

2. **不等成本形式不能替代交换判据。** 当 `cF != cG` 时，Theorem 1.2 回答的是「哪个独立转移的单位成本相对增益更大」；它**不**回答「把 `delta` 个原始单位从 j 移到 i 是否改善」。后者只能由 Theorem 1.1 判定。§7.4 给出一个抽象数值例子：单位成本比较判定 F 侧更优，但真正的等量交换严格恶化。

### 5.4 Theorem 2.1：严格改善交换 ⟹ 松弛内非最优

设 `x ∈ Omega`、`x' = Swap_{i<-j,delta}(x) ∈ Omega` 且 `V_after > V_before`（精确判据）。记 `OPT = argmax_{Omega} V_R`（`V_R` 与 `V` 在同一组因子坐标上一致）。则

```text
V_R(x) < V_R(x') <= max_{Omega} V_R   =>   x ∉ OPT.
```

因此对「计算松弛最大值/最优解」的用途，从 `Omega` 的状态集中删除 `x` 是安全的：`max_{Omega} V_R` 与 `OPT` 都不变。

### 5.5 Theorem 2.2：tie 交换不授权删除

设 `x, x' ∈ Omega` 且 `V_after = V_before`（tie 交换）。则：

1. **若只关心最大目标值**：`x` 与 `x'` 的目标值相同，删除 `x` 不改变 `max V_R`；这只在「输出值」层面安全。
2. **若保留 tie / 身份语义**：`x` 可以是最优解（`x ∈ OPT`）；tie 交换只保证 `x' ∈ OPT`，不保证 `x` 非最优。删除 `x` 会改变 `OPT` 集合（或改变按身份/并列枚举的输出）。**tie 交换不给出任何删除许可**。
3. **若只搜索「严格改善 incumbent」**：tie 状态本身不严格改善，故不会进入严格改善候选集；但这与「可以用 tie 交换删除最优集合中的点」是不同命题，不能混用。

精确逻辑形式：

```text
严格： ∃ x'∈Omega, V(x') > V(x)  =>  x ∉ OPT
同值： ∃ x'∈Omega, V(x') = V(x)  =/=>  x ∉ OPT       （x 仍可能在 OPT 中）
```

### 5.6 Theorem 3.1：分离定理（松弛 vs 真实装备）

**陈述。** 存在真实模型 `M` 与物品候选 `c`，使得：

1. 存在合法真实配置 `gamma ∈ Gamma(M)` 使用 `c`，其松弛像 `x = sigma(gamma) ∈ Omega` 在松弛内存在**严格改善的自由交换** `x -> x'`（`x' ∈ Omega`，`V_R(x') > V_R(x)`）；
2. 但不存在任何合法真实配置 `gamma'` 实现 `x'` 或改进 `gamma`；
3. 因此「存在理论有利交换」**不蕴含**「存在合法真实替代」；用该理由删除真实候选 `c` 会改变真实最优（甚至删除唯一最优解）。

**一般引理（分离的结构原因）。** 真实像集 `phi_img = sigma(Gamma(M))` **不保证**交换封闭性：

```text
x ∈ phi_img  =/=>  Swap_{i<-j,delta}(x) ∈ phi_img
```

没有任何规则强制该封闭性；§7.1 的模型就是它的具体见证。即使 `x'` 恰好在 `phi_img` 中，也可能没有合法配置同时满足共享身份、戒指唯一性、食物、GCD/坚韧等约束；因此「交换有利」既不能保证存在替代配置，也不能保证替代配置合法。唯一安全的删除理由必须直接作用于真实模型（Theorem 3.2）。

**证明。** 显式反例见 §7.1（ring 唯一性模型：真实最优 `A+B = (500,30,0)`；松弛交换到 `(530,0,0)` 严格更好；但 `(530,0,0)` 需要两枚同 ID 的 A 或额外镶嵌，被唯一性与 meld cap 排除；删除提供 DHT 的物品 B 会把真实最优从 `4,153,084,875,000` 降到 `4,147,900,000,000`）。一般引理由 `Gamma(M)` 的定义直接得到：像集不是交换封闭集，且 §7.1 的模型已是其具体见证。

### 5.7 Theorem 3.2：三条安全的真实删除路径

删除真实物品/镶嵌/食物候选 `c` 只能在下列条件之一成立时进行：

**(a) 显式枚举合法替代集。** 若对每个使用 `c` 的合法配置 `gamma ∈ Gamma(M)`，都存在一个不使用 `c` 的合法配置 `gamma'`（显式构造/枚举，且满足全部共享身份、唯一性、食物、GCD/坚韧约束）使 `V(gamma') >= V(gamma)`，则删除 `c` 不改变真实最优值。若要求 tie/身份输出，则还需 `>=` 的并列处理说明。

**(b) 严格乐观上界（推荐与 frontier 联动）。** 取一个**包含真实可行域**的松弛/上界 `Sup ⊇ phi_img`（例如自由资源松弛 `U(b,R)`、或 [strict-improvement-frontier](../strict-improvement-frontier/README.md) 的 `G_>(B)` 超集），并证明

```text
max_{gamma ∈ Gamma(M), c ∈ gamma} V_upper(gamma) <= incumbent     （严格改善模型）
max_{gamma ∈ Gamma(M), c ∈ gamma} V_upper(gamma) <  incumbent     （tie/身份保留模型）
```

则不存在使用 `c` 的严格改善解（严格模型），或在保留 tie 的模型里连同分点也不会被删除；注意路径 (b) 一定要用与目标语义匹配的那一档比较（frontier 定理 Theorem 3.3）。

**(c) 全坐标支配（超出本文范围，仅登记）。** 若存在不使用 `c` 的合法配置在**全部目标与硬约束坐标**上不劣于每个使用 `c` 的配置（且保留共享身份/可配对集合/跨槽唯一性），才能删除；这条路径不能只比较副属性乘积（`docs/rules/领域与搜索规则.md:45-46`）。

### 5.8 Corollary 3.3：松弛内部使用的安全性（使用契约）

在 `U(b,R)` 的求解、`K_w(B)` 的查询、或任何**只以松弛最优值/上界为目的**的计算内部，使用 Theorem 2.1 删除「存在严格改善交换」的状态是安全的：因为被删除的状态都不是松弛最优，松弛最大值与最优值不变，故由它导出的上界/必要半空间仍然安全。

使用契约（全部满足才允许）：

1. 域必须是松弛（`Omega_R` 或其子集），不能混入真实可行性判断；
2. 交换目标必须在松弛内（§3.3 可行性），否则该「交换」不成立；
3. 因子必须为正（(P1)）；
4. 删除决定只用于松弛最大值/最小值/上界计算，不用于真实候选的输出过滤；
5. 严格 vs tie 语义显式声明（Theorem 2.2）；
6. 最终真实候选的保留/删除仍由 Theorem 3.2 与精确比较（`candidateUpperBoundCannotImproveIncumbent`）认证。

## 6 证明

### 6.1 Theorem 1.1 证明

设 `R(x) > 0` 为交换中不变的其余因子乘积。则

```text
V_after - V_before = R(x) * (F1*G1 - F0*G0)
```

`R(x) > 0`，故差值符号等于 `F1G1 - F0G0` 的符号；三项判定成立。`F1*G1`、`F0*G0` 为整数，BigInt 比较可在有限步内精确结束。平台情形由 `t_sigma` 的单调性：`F1 >= F0`、`G1 <= G0`（贡献增加/减少），且相等当且仅当 tier 不变；于是若只有 i 变化则 `F1G1 > F0G0`，只有 j 变化则 `<`，两者都变时必须比较乘积。边界条件由松弛定义直接给出。∎

### 6.2 Theorem 1.2 证明

因所有因子与成本为正，`ln(F1/F0)`、`ln(G1/G0)` 有定义。由 `cF,cG > 0`：

```text
ln(F1/F0)/cF >= ln(G1/G0)/cG
<=> cG*ln(F1/F0) >= cF*ln(G1/G0)                （两边乘 cF*cG>0）
<=> ln((F1/F0)^cG) >= ln((G1/G0)^cF)           （对数幂律）
<=> (F1/F0)^cG >= (G1/G0)^cF                    （ln 严格单调递增）
<=> F1^cG / F0^cG >= G1^cF / G0^cF
<=> F1^cG * G0^cF >= F0^cG * G1^cF              （两边乘 F0^cG * G0^cF > 0）
```

最后一步是正数交叉乘法，所有中间量都是整数幂，可用 BigInt 精确比较。等号情形同理。∎

### 6.3 Theorem 1.3 证明

1) 取 `cF = cG = delta`，转移 P 取 `F0->F1`，转移 Q 取反向 `G1->G0`（即 `Q0 = G1`、`Q1 = G0`）。代入 Theorem 1.2：

```text
F1^delta * G1^delta >= F0^delta * G0^delta
<=> (F1*G1)^delta >= (F0*G0)^delta
<=> F1*G1 >= F0*G0                        （正数；delta>0 时 x -> x^delta 严格递增）
```

即 Theorem 1.1。2) 不等成本时 `cF != cG`，上述等价链在「交换两侧成本同为 `delta`」处失效；Theorem 1.2 的式子是 `(F1/F0)^{cG}` 与 `(G1/G0)^{cF}` 的比较，不含「两侧各消耗相同原始单位」的约束。因此只能用于独立的单位成本排序，不能替代交换判定。§7.4 给出具体反例。∎

### 6.4 Theorem 2.1 证明

`x' ∈ Omega` 且 `V(x') > V(x)`，故 `max_{Omega} V >= V(x') > V(x)`，所以 `x` 不是最大值点，`x ∉ OPT`。删除非最优状态不改变 `max` 与 `OPT`：`OPT ⊆ Omega \ {x}`，且 `max_{Omega \ {x}} V = max_{Omega} V`（因为达到最大值的点未被删除）。∎

### 6.5 Theorem 2.2 证明

`V(x') = V(x)`。若 `x ∈ OPT`，则 `max V = V(x) = V(x')`，故 `x' ∈ OPT`；`x` 仍是最大值点。因此「存在同值替代」不否定 `x` 的最优性；若输出集合需要包含全部最优（或按身份输出），删除 `x` 会改变结果。若只输出最优**值**，则删除不改变值——这是唯一的弱结论。逻辑形式由 `argmax` 定义直接得到。∎

### 6.6 Theorem 3.1 证明

用 §7.1 的显式模型：

- 槽位：两个戒指槽；物品 `A` 提供**贡献** `(CRT,DHT,DET)=(500,0,0)`，`B` 提供贡献 `(0,30,0)`（贡献 = 面板 − `(sub,sub,main)`，见 §13；下文所有数值都是贡献坐标）；meld cap 为 0；共享物品身份约束：同一非空物品不能同时占两个戒指槽（戒指唯一性规则的最简形式，`docs/rules/领域与搜索规则.md:18`）；其余乘区固定。
- 合法真实配置：`{}`、`{A}`、`{B}`、`{A,B}`（以及顺序无关的两槽排列），贡献三元组分别为 `(0,0,0)`、`(500,0,0)`、`(0,30,0)`、`(500,30,0)`。
- 真实最优：`(500,30,0)`，`V_R = 4,153,084,875,000`。
- 松弛：`Omega` 含 `(530,0,0)`（把 30 点 DHT 全部转给 CRT）；`V_R(530,0,0) = 4,154,176,000,000 > 4,153,084,875,000`，严格改善。
- 任何真实配置都不能实现 `(530,0,0)`：需要两枚 `A`（被唯一性禁止）或额外 30 点 CRT 镶嵌（meld cap=0）；其它真实配置的乘积都 `<= 4,153,084,875,000`（`{A}` 为 `4,147,900,000,000`，`{}`、`{B}` 更低）。
- 若按「理论交换有利」删除提供 DHT 的物品 `B`，合法配置只剩 `{}`、`{A}`，真实最优降为 `4,147,900,000,000`，输出改变。

一般引理：`phi_img` 的交换封闭性不成立（上例中 `(500,30,0) ∈ phi_img` 而 `(530,0,0) ∉ phi_img`）；即使像点仍在 `phi_img`，真实约束也可能使所有实现它的配置非法。因此分离成立。∎

### 6.7 Theorem 3.2 证明

**(a)** 对每个 `gamma`（使用 `c`）取合法 `gamma'`（不使用 `c`）且 `V(gamma') >= V(gamma)`。则 `max_{Gamma} V <= max_{gamma'∈Gamma, c∉gamma'} V <= max_Gamma V`，故删除前后真实最优值相同；若需要并列解，还需对每个最优 `gamma` 构造 `gamma'` 保持同值。注意：同时删除多个候选时必须保证每个替代配置不依赖其它同批被删候选（否则须对整批做统一论证）。
**(b)** 对全部使用 `c` 的真实配置，`V_upper(gamma) <= incumbent`（严格语义；tie 语义用 `<`）。则不存在使用 `c` 的严格改善配置；在只搜索严格改善解的模型中删除 `c` 不改变结果。注意 `V_upper` 必须来自 `Sup ⊇ phi_img` 的**乐观**上界（例如自由资源松弛或 frontier 区间），不能来自真实域内的近似。
**(c)** 支配性证明：若每个使用 `c` 的配置都被某个不使用 `c` 的合法配置在全部目标与硬约束坐标上不劣地替代，则 `c` 可从候选中删除；该命题需要全坐标与共享身份论证，本文不展开。∎

### 6.8 Corollary 3.3 证明

由 Theorem 2.1，在松弛内部删除的状态都不是松弛最优；`U(b,R)` 的精确最优值（或其严格上界、`K_w` 查询）只依赖松弛的 `max/min`，被删除状态不参与极值，故结果不变。契约条件的必要性分别来自：域混用会破坏 2.1 的前提（真实约束下交换可能不可实现）；退出 `Omega` 的交换不满足 2.1 的 `x' ∈ Omega`；非正因子破坏 1.1 的约去（tie/严格语义见 2.2）。∎

## 7 反例与边界退化

### 7.1 分离反例（ring 唯一性；精确数值）

见 §6.6 与 [`verify.mjs`](verify.mjs) 的 `B5.separation`。模型：两个戒指槽；`A=(500,0,0)`、`B=(0,30,0)`（均为**贡献**；level=100 WHM 下对应面板 `A=(920,420,440)`、`B=(420,450,440)`）；meld cap=0；唯一性禁止两枚同 ID 戒指。level=100 WHM 的 canonical 因子（CRT/DHT/DET 档位与 `F_C/F_H/F_D` 见 §3.1；偏移见 §13）：

| 真实配置 | 贡献 (C,H,D) | 副属性乘积 |
| --- | --- | --- |
| `{}` | (0,0,0) | 4,080,000,000,000 |
| `{A}` | (500,0,0) | 4,147,900,000,000 |
| `{B}` | (0,30,0) | 4,085,100,000,000 |
| `{A,B}`（真实最优） | (500,30,0) | 4,153,084,875,000 |
| 松弛点（不可实现） | (530,0,0) | 4,154,176,000,000 |

松弛内 `(500,30,0) -> (530,0,0)` 是严格改善的自由交换；真实域没有 `(530,0,0)`。删除 `B` 后真实最优变为 `{A}` 的 `4,147,900,000,000`，改变输出。**结论：理论交换有利不是删除真实物品/镶嵌/食物的理由。**

### 7.2 issue 正文旧边际比较形式不等价（已被评论 02 §七更正）

取 `F0=10, F1=80, cF=3; G0=1000, G1=2000, cG=1`。真值：`ln(80/10)/3 = ln2 = ln(2000/1000)/1`，两侧单位成本 log 增益**相等**；交叉指数判据给出 `F1^cG·G0^cF = 80*10^9 = 8e10 = F0^cG·G1^cF`，同样相等。而 issue 正文旧形式（两种可能读法）分别给出 `(80*1000)^1 = 80,000` vs `(2000*10)^3 = 8e12`，以及 `(80*1000)^3` vs `(2000*10)^1`，均**严格不等**。因此旧形式在 `cF != cG` 时不等价于真值/更正判据；运行时必须使用 Theorem 1.2 的交叉指数形式。

### 7.3 正因子前提不可省

抽象例子：`F0=1, F1=2, cF=1; G0=0, G1=5, cG=1`。两状态乘积 `0 -> 10` 严格改善（若允许 0 因子）；但交叉指数式变成 `F1^cG·G0^cF = 2*0 = 0` vs `F0^cG·G1^cF = 1*5 = 5`，判为不改善——错误。负因子时 `ln` 无定义，交叉乘法也不再保序。故 (P1) 必须由运行时检查（参照 `safeDamageFactors`），不满足时禁用交换判据、不删除任何东西。

### 7.4 单位成本边际比较不能替代交换判据（不等成本）

抽象模型（说明逻辑差异，不映射到具体等级）：当前状态因子 `F=10`、`G=100`；F 的下一个 tier step 成本 1，`F:10 -> 20`；G 的相邻 tier step 成本 3，`G:100 -> 40`（反向下降）。单位成本：`ln(20/10)/1 = ln2 ≈ 0.693`；`ln(100/40)/3 ≈ 0.305`，判据说「把资源投入 F 更划算」。但真正的等量交换（从 G 移 3 个原始单位给 F）是：F 只用了 1 个单位跳到 20，多余 2 个单位在平台内浪费；G 从 100 掉到 40；乘积 `10*100 = 1000 -> 20*40 = 800`，严格恶化。**结论**：`cF != cG` 的单位成本排序不能回答「交换是否改善」；交换必须用 Theorem 1.1。该反例同时说明为什么 Theorem 1.3 的归约只在 `cF = cG = delta` 时成立。

### 7.5 tie 删除反例（松弛内部）

level=100 WHM，盒 `[0,5]×[0,3]×[0,10]` 全落在首个 tier 平台内（CRT tier 50 在贡献 `0..13` 不变、DHT tier 0 在 `0..5` 不变、DET tier 1000 在 `0..19` 不变），`264` 个状态乘积完全相同、互为 argmax；其中 `262` 个存在 tie 交换。若按「有同值替代即可删除」的规则，argmax 集合会从 `264` 缩为 `1`——在保留 tie/身份语义时输出改变。**结论**：tie 交换不授权删除（Theorem 2.2）。

### 7.6 边界退化

- `delta > x_j`：交换目标坐标会变负，交换在松弛内不可行；不能用于消除。
- 盒式 cap：`x_i + delta > kappa_i` 时不可行；若松弛是 simplex 的 `c+h+d <= R` 形式，交换保持总和，通常不触发 cap。
- `delta` 跨多个 tier：Theorem 1.1 仍精确成立（只比较交换前后两点）；但 Theorem 1.3 的「单步转移」叙述需要把 `delta` 视为该次转移的完整成本，不能把多档跳变拆成多个不同成本的子转移后错误套用。
- `F1 = F0` 且 `G1 = G0`（平台内交换）：tie；不改善，也不恶化。
- 因子为 0/负：判据禁用（§7.3）。
- 速度/TEN/主属性随真实物品改变时：交换判据的「其它因子不变」前提失效；此时 §3.3 的 `R(x)` 不恒定，必须回到完整乘积比较或先认证其它坐标不受影响。

## 10 应用前提与安全回退

### 10.1 松弛内部（`U(b,R)`、`K_w`、frontier 计算）

1. 域确认：当前计算是自由资源松弛（允许任意 `c,h,d >= 0` 分配，或其在册的子域），不是真实装备可行域；状态坐标必须是**贡献**（若数据是面板值，先按 §13.1 减 `sub`/`main`）；
2. 交换可行：`x_j >= delta`、`x_i + delta <= kappa_i`（盒式）；simplex 的 `c+h+d` 约束保持；
3. 正因子：`Phi_i`、`Phi_j` 在涉及区间为正（`g>=0` 且参数在支持表内即成立；运行时仍应检查 `safeDamageFactors` 等价前提）；
4. 只用于松弛极值/上界：删除状态后仍可精确得到 `max/min` 或严格上界（Corollary 3.3）；
5. tie 语义：只对松弛最大值计算使用；若计算还要保留同值/身份，不做 tie 删除（Theorem 2.2）。

### 10.2 真实装备候选删除

1. **不得**仅依据交换判据删除任何真实物品/镶嵌/食物候选（Theorem 3.1）；
2. 使用路径 (a)：显式枚举合法替代集并验证全部约束（共享身份、戒指唯一性、共享食物、GCD 档位、最低坚韧、同步 cap 等）；物品属性按**贡献**核对（面板换算见 §13.1，禁止用面板值直接替代贡献）；
3. 使用路径 (b)：以自由资源松弛/严格乐观上界（[free-budget-upper-bound](../free-budget-upper-bound/README.md)、[strict-improvement-frontier](../strict-improvement-frontier/README.md)）证明该候选不可能严格改善 incumbent；tie 保留模型需切换为非严格界；
4. 路径 (c)：全坐标 + 硬约束支配（本文不展开）；
5. 最终认证：`candidateUpperBoundCannotImproveIncumbent`（`exact-mip-candidate-upper-bound.ts:127-140`）的精确 BigInt 比较；本判据不得替代。

### 10.3 安全回退（按顺序）

1. 因子可能非正、cap/budget 未知、`delta` 会退出域、速度/坚韧/主属性耦合、或共享身份无法认证 → **不删除任何东西**，退回完整精确路径；
2. 真实候选删除无法按 (a)/(b)/(c) 认证 → 不删除；使用现有 exact upper bound；
3. 松弛内部删除若破坏「上界/极值不变」的用途（例如需要枚举全部最优或按身份计数）→ 不做删除；
4. 不得把「理论交换有利」升级为经验剪枝（无 magic value：不引入固定 CRT/DHT/DET 阈值或固定交换比例）。

## 12 未解决问题

1. **真实域可交换性条件。** 本文只给出分离反例；在什么充分条件下真实可行域 `phi_img` 对某类交换封闭（例如同槽位、同镶嵌预算、无唯一性冲突的自由替换）尚未形式化。若有这样的条件，路径 (a) 可以弱化为「检查若干局部条件」。
2. **共享身份的形式化。** 戒指唯一性、共享食物、共享方案的「无序身份多重集」约束（`docs/rules/领域与搜索规则.md:37-39`）如何进入分离定理的模型，需要与联合搜索的共享表示对齐；本文只用最简 ring 唯一性模型。
3. **不等成本交换。** 真实域中一次替代可能对应不同数量的原始属性（不同物品/镶嵌混合），此时 Theorem 1.3 的等成本归约不适用；是否需要「单位预算交换 + 余量」的组合判据未研究。
4. **食物百分比/上限的非线性。** 食物对每个属性分别应用百分比与 cap（`docs/rules/领域与搜索规则.md:20`），跨属性「交换食物」不是简单的坐标转移；本文的交换算子不覆盖食物重分配。
5. **tie 语义的完整契约。** Theorem 2.2 只给出逻辑形式；若系统需要「同值但身份不同」的全部输出，删除规则与身份传递闭包如何组合未形式化。
6. **与 frontier 半空间的组合。** 路径 (b) 与 [strict-improvement-frontier](../strict-improvement-frontier/README.md) 的 `L <= K_w` 半空间组合时的最优组合顺序/冗余消去，本文未展开（frontier §12 有对应开放问题）。
7. **多职业联合下的共享交换。** 联合搜索中同一交换可能同时影响多个职业的松弛；Corollary 3.3 是否可逐职业独立使用、还是需要联合身份证明，未研究。
8. **运行时定点 log 的可选路径。** 评论 02 §七 提到「运行时可用有上下界证明的定点对数运算」；本文只用精确整数判据，定点 log 的正确性证明不在本文范围（见 [marginal-comparison](../marginal-comparison/README.md)）。

## 13. baseStat 影响审计（贡献坐标 vs 面板总值）

本节是第二轮坐标审计：逐条核对交换算子、ring 唯一性分离反例、全部 Theorem / Lemma 的坐标是**贡献**还是**面板总值**。**审计结论：未发现面板/贡献混用**。交换判据对坐标平移不变，分离反例的数值必须且已经是贡献坐标；本节把坐标声明、归约链、逐命题判定、数值复核与运行契约显式登记，并在 §3/§6/§7 补充了贡献标注。

### 13.1 坐标声明与换算

本文全部坐标 —— 松弛状态 `x=(C,H,D)`、基线 `b=(C0,H0,D0)`、交换量 `delta`、交换目标 `x'`、真实模型的 `sigma(gamma)`、以及 §6.6/§7.1 的全部数值 —— 都是**贡献** `g`，不是面板总值：

```text
面板 CRT/DHT/TEN = baseStats(sub)  + 贡献
面板 DET         = baseStats(main) + 贡献
```

由参考模型 §2.1（基础属性归约；`equipped-effects.ts:127`、`getBaseStats` `:178-203`）：

| 属性 | 基础属性 | 贡献 = 面板 − 基础属性 |
| --- | --- | --- |
| CRT | `sub` | `C = 面板CRT − sub` |
| DHT | `sub` | `H = 面板DHT − sub` |
| DET | `main` | `D = 面板DET − main` |
| TEN | `sub` | 本文不把 TEN 作为交换坐标（它是固定前提，见 (P4)） |

本文数值示例使用 level=100 WHM：`sub = 420`、`main = 440`。

**交换判据的平移不变性。** 偏移只依赖 `(level, job, stat)` 且在同一状态内是常数；因此

```text
x' = x + delta*(e_i - e_j)   ⟺   panel(x') = panel(x) + delta*(e_i - e_j)
```

两者的差分相同，因子只由贡献决定，所以交换判据在贡献/面板两种表述下给出同一个符号。需要换算的只有**绝对阈值**（如与 [strict-improvement-frontier](../strict-improvement-frontier/README.md) 的 `w·x >= L` 联用时），换算公式见 frontier §13.5。本文的交换判据本身不产生绝对阈值。

### 13.2 归约链（为什么档位/因子只吃贡献）

1. `equippedAttributeTier` 先算 `value = baseStats[stat] + gearAndFoodValue`，再减偏移 `sub`（CRT/DHT/TEN）或 `main`（DET）后进入 floor（`equipped-effects.ts:127-149`）。
2. 由 `getBaseStats` 的当前数据：`baseStats.CRT = baseStats.DHT = baseStats.TEN = sub`、`baseStats.DET = main`，故 `value − 偏移 = gearAndFoodValue = g`；档位 `t_sigma(g)` 只依赖贡献（参考模型 §2.1）。真实装备/镶嵌/食物数据在模型中叠加的也是贡献增量；面板值 = 基础属性 + 贡献。
3. 正式候选路径贡献逐项非负（参考模型 §2.2），故 `g >= 0`；四个分支 floor 实参恒 `>= 0`，`Math.trunc(v+1e-7)=floor(v)` 在可达域无条件成立。
4. 因此交换中的 `F0,F1,G0,G1` 必须由 `t_sigma(贡献)` 计算；把面板值直接喂给 `t_sigma` 会重复计入基础属性。meld/food 的数值同样是贡献增量，可直接与物品贡献相加。

### 13.4 数值复核（全部按贡献复算；面板等价仅作说明）

level=100 WHM，`sub=420`、`main=440`；`verify.mjs` 的 `B8.baseStat-audit` 用 canonical 档位按贡献重算并断言与文档数值相等：

| 真实配置/松弛点 | 贡献 `(C,H,D)` | 面板 `(CRT,DHT,DET)` | 副属性乘积（`F_C F_H F_D`） |
| --- | --- | --- | --- |
| `{}` | `(0,0,0)` | `(420,420,440)` | 4,080,000,000,000 |
| `{A}` | `(500,0,0)` | `(920,420,440)` | 4,147,900,000,000 |
| `{B}` | `(0,30,0)` | `(420,450,440)` | 4,085,100,000,000 |
| `{A,B}`（真实最优 q） | `(500,30,0)` | `(920,450,440)` | 4,153,084,875,000 |
| 松弛点 r（不可实现） | `(530,0,0)` | `(950,420,440)` | 4,154,176,000,000 |

要点：

1. 若把 `q=(500,30,0)` 解释为面板值，则贡献 = `(500−420, 30−420, 0−440) = (80,−390,−440)`，含负分量，超出正式候选 `g >= 0` 定义域；故这些数值只能是贡献。
2. 交换差分 `(ΔC,ΔH,ΔD) = (30,−30,0)` 在贡献坐标与面板坐标下相同（偏移相消）；B1 的精确比较 `4,154,176,000 vs 4,153,084,875` 是交换涉及的两个因子（`F_C F_H`，第三个因子 `F_D(0)=1000` 约去），同样是贡献坐标值。
3. 分离反例的结论 `4,154,176,000,000 > 4,153,084,875,000 > 4,147,900,000,000` 按贡献复算一致；删除 `B` 后真实最优降到 `{A}` 的值，与坐标标签无关（因为所有配置的其它乘区固定）。
4. 与 frontier 联用时：交换判据不需要换算；只有 `w·x >= L` 型绝对阈值需要按 frontier §13.5 加 `Σ w_i·offset_i`。

### 13.5 应用契约（防止坐标混用）

1. 松弛状态、基线、交换量、乐观上界输入都必须是**贡献**；若内部数据是面板值，先按 §13.1 减 `sub`/`main`。
2. 物品、镶嵌、食物的属性增量按贡献汇总（面板 = 基础属性 + 贡献）；共享身份/唯一性约束作用在物品层面，与坐标无关，但删除/替代验证必须保留。
3. 交换判据的因子乘积只依赖贡献；禁止把面板值直接喂给 `t_sigma` 或与贡献阈值比较。
4. 与 [strict-improvement-frontier](../strict-improvement-frontier/README.md) 联用时，阈值换算在同一 `(level, job)` 上完成：`w·panel >= L + Σ_i w_i·offset_i`。
5. 真实删除路径 (a)/(b)/(c) 的输入（真实配置值、严格乐观上界、支配关系）必须是完整目标值/贡献，不能在坐标之间混用。
6. 无法确认输入是贡献时：禁用交换判据、**不删除任何东西**，回退 exact upper bound（§10.3）。

### 13.6 结论

- **未受影响**：交换判据对坐标平移不变，Theorem 1.1/1.2/1.3、2.1/2.2、Corollary 3.3 的陈述与证明不需要改变；分离定理 Theorem 3.1 的结论与数值在贡献坐标下成立且已按贡献复算。
- **修正与澄清**：§3.1/§3.2/§3.3/§6.6/§7.1/§9/§10 增加「贡献」标注与参考模型 §2.1/§2.2 引用；新增本节与 `verify.mjs` 的 `B8.baseStat-audit`（PASS）。
- **无面板混用**：§7.1 的 `(500,30,0)`、`(530,0,0)` 等全部是贡献；若按面板解释会产生负贡献，不满足正式候选定义域。若 `baseStats`/`clanStats`/`statModifiers` 变化（参考模型 §2.1），必须重核偏移与本节换算；`B8` 会在偏移不再等于 `sub/main` 时失败。
