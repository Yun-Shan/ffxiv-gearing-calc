## 3. 符号、量词与定义域

### 3.1 坐标声明（贡献坐标 vs 面板总值）

本文全部坐标 `x_i`、`G_i`、`g_i`、`S`、阈值 `L/R/K_sum`、示例数值都是**贡献**（装备 + 镶嵌 + 食物对属性的贡献），**不是面板总值**：

```text
面板 CRT/DHT/TEN = baseStats(sub)  + 贡献
面板 DET         = baseStats(main) + 贡献
```

由参考模型 §2.1（`equipped-effects.ts:127-149`、`getBaseStats` `:178-203`）：`baseStats.CRT = baseStats.DHT = baseStats.TEN = sub`、`baseStats.DET = main`，档位函数 `t_i(g)` 的输入就是贡献 `g`；正式候选路径贡献逐项非负（§2.2），`g >= 0` 且 floor 实参恒非负，`Math.trunc(v+1e-7)=floor(v)` 在可达域无条件成立。因此：

- `L`、`R`、`S` 必须按贡献求和；把面板值当贡献会把 `Σbase` 重复计入（见 §7.2 的数值反例：level 100 时 `Σbase = 420+420+440 = 1280`）。
- 食物加成公式的 `G_i` 是**食物应用前的贡献**，`base_i` 是等级基础属性（参考模型 §2.2 的 canonical 公式）。

### 3.2 统一模型

单职业、固定 formula level、同步已应用。所有贡献为整数。

- **槽位集合** `Slots`；槽 `s` 的候选集合 `C_s`，候选 `c` 的贡献向量 `x(c) = (x_C, x_H, x_D) ∈ Z_{>=0}^3`（已含固定镶嵌/参数）。可选槽允许空选择，空选择记零向量 `0`（`S3(0)=0`）。记 `S3(c) = x_C + x_H + x_D`。
- **戒指唯一性**：两个戒指槽共享 `itemId` 时，仅当该物品明确 non-unique 才允许；否则同一 unique `itemId` 不得在两个槽（或更一般地任意两个槽）重复出现。
- **食物集合** `F`（可空）；若食物可选，则允许「无食物」`f = ∅`。对食物 `f` 与食物应用前贡献 `G_i >= 0`：

```text
bonus_i(f, G) = min(cap_i^f, trunc((G_i + base_i) * r_i^f + 1e-7)),   r_i^f = statRate_i^f / 100 >= 0
bonus_i(∅, G) = 0
```

- **可选硬约束**：速度贡献带 `[v_lo, v_hi]`（GCD 约束）与 TEN 贡献带 `[t_lo, t_hi]`；本模型把它们视为对槽贡献（视实现还包括食物贡献；见 §10 前提）的附加约束。约束只会缩小可行域。
- **配置/完成** `γ`：每槽选一个候选（或空）+ 一个允许的食物；满足戒指唯一性与硬约束。
- 记

```text
G_i(γ)   = Σ_{s} x_i(c_s)                  （食物应用前的贡献和）
g_i(γ)   = G_i(γ) + bonus_i(f(γ), G_i(γ))  （最终贡献，= frontier 坐标 C/H/D）
S(γ)     = g_C + g_H + g_D = ΣG_i + Σbonus_i
Γ        = 全部合法完成的集合（真实可达域）;  Reach = { g(γ) : γ ∈ Γ } ⊆ Z_{>=0}^3
```

- 本文所有量词 `∀合法完成` 指对 `Γ`；所有剪枝安全性的最终依据是 `Reach ⊆ 被保留区域`。

### 3.3 上下界对象

- **安全下界** `L`：整数，满足 `∀γ∈Γ: S(γ) >= L`。
- **安全上界** `R`：整数，满足 `∀γ∈Γ: S(γ) <= R`。可由槽候选上界 + 食物上界给出（Theorem 2 的对称式），也可来自 free-budget 侧的预算 `R`（`U` 的预算参数）。
- **slab**：`Ω' = Ω ∩ {L <= Σ <= R}`，其中 `Ω` 是 `strict-improvement-frontier` 使用的贡献盒（或真实可达集的外接盒）。
- **滚动界**：已提交槽集合 `P`、已提交和 `s_P = Σ_{s∈P} S3(c_s)`、剩余下界 `L_rem(P)`、剩余上界 `R_rem(P)`。
- **incumbent 和割**：`K_sum(B) := K_{(1,1,1)}(B)`（[strict-improvement-frontier](../strict-improvement-frontier/README.md) 的 `K_w` 取 `w=(1,1,1)`），即任何 `Φ > B` 的点必须满足的必要和。
- **free-budget 松弛记号**（来自 [free-budget-upper-bound](../free-budget-upper-bound/README.md)）：baseline 贡献 `b`、预算 `R`、caps `κ`、`K = Σκ`、`S* = min(R,K)`、`A(b,R,κ) = {x >= 0 : Σx <= R, x_i <= κ_i}`、`U(b,R,κ) = max_{x∈A} Π_i f_i(b_i+x_i)`。它与本文槽模型是**两个不同对象**（见 §5.1 禁止混用）。

## 4. 假设

- **(A1) 坐标与定义域**：全部量是贡献坐标，`g >= 0` 整数；由参考模型 §2.1/§2.2 结构性成立；面板数据必须先换算（§3.1、§10）。
- **(A2) 槽候选原子性**：每个候选贡献向量非负且含全部固定镶嵌/参数；槽之间除戒指唯一性/共享身份外相互独立。候选集合非空；可选槽含空向量。
- **(A3) 食物 canonical 公式**：`bonus_i` 按 §3.2 公式计算，`r_i^f >= 0`、`cap_i^f >= 0`、`base_i >= 0`；`trunc` 为生产 `Math.trunc`。由此 `bonus_i(f, ·)` 对 `G_i` **非减**（§6 引理 3），这是 `L_food` 与 `R_food` 安全性的依据。
- **(A4) 唯一性/硬约束**：戒指唯一性与可选硬约束按当前规则（`docs/rules/领域与搜索规则.md:18,34-40`）。约束只会缩小 `Γ`。
- **(A5) 精确整数**：`S3`、`L`、`R`、`K_sum`、乘积等都用整数/BigInt 精确比较；`Math.log`/浮点不参与判定（§9、§10）。
- **(A6) free-budget 侧前提**：引用 `U` 时须满足 [free-budget-upper-bound](../free-budget-upper-bound/README.md) §4 的 (A1)–(A6) 与 §10 的 P1–P8（baseline/预算/caps 是可证明的界）。
- **(A7) 最终认证**：任何真实候选/分支/区域的删除最终仍由精确比较 `candidateUpperBoundCannotImproveIncumbent`（`exact-mip-candidate-upper-bound.ts:127-140`）或精确枚举认证；本文剪枝是必要过滤，不替代最终认证。
- **(A8) 语义显式**：调用方必须声明模型是「只搜索严格改善」还是「保留 tie/身份」；两者不可混用（§5.6 PR8、§10）。

## 5. 精确命题

### 5.1 Lemma 0/1：坐标、`U` 不变性与禁止混用

**Lemma 0（坐标一致性）。** 在 §3.2 的模型与 (A1) 下，`S(γ) = Σ_i g_i(γ)` 是贡献坐标下的三属性贡献和；`Reach` 中每条贡献三元组的坐标和就是 `S(γ)`。这不是定义面板值的函数。

**Lemma 1（下界不能改变 `U`；独立复核）。** 在 [free-budget-upper-bound](../free-budget-upper-bound/README.md) 的松弛 `A(b,R,κ)` 中，`U` 由三因子坐标单调（其定理 1(3)）且存在满预算最优解 `x*` 满足 `Σ x*_i = S* = min(R,K)`（其定理 2）。因此：

1. 对任意整数 `L <= S*`：`max { Π_i f_i(b_i+x_i) : x ∈ A(b,R,κ), Σx >= L } = U`。**限制到 `Σ >= L` 不改变 `U`**。
2. 更一般地：下界 `L` 只把「所有坐标和不足以达到 L 的分配」排除；由于满预算最优解的和为 `S*`，只要 `L <= S*` 就不会排除它。若 `L > S*`，限制后的区域为空——这不是「更紧的 U」，而是丢失整个免 `U`。
3. 对 slab 的上侧：任何 `R'' >= S*` 的 `Σ <= R''` 也不改变 `U`。
4. **安全下界不会改变 `U`**：若 `L` 是真实可达集的安全下界且真实可达集非空，则对任一真实完成 `γ` 有 `S(γ) >= L`；在 free-budget 的分配坐标下 `Σx <= S*`，故 `L` 对应的下界不会超过满预算面（`L - Σb_i <= S*` 的类似关系）。**结论：下界只能用于删除不可能区域/收紧必要区域（真实可达集的超集区域），不能用来「缩小 `U` 的值」。**

**禁止混用（重要）。** 由 Lemma 1 与 §3.1：

- `slab` 的包含关系是「**真实可达集 ⊆ Ω'**」，因此它可用于：(a) 收紧 `strict-improvement-frontier` 的 Ω、`D_min`/`K_w`（计算的是真实可达集超集上的必要区域）；(b) 判定分支/区域是否可能含真实完成（空则可剪）；(c) 枚举真实可达区域时跳过不可能区域。
- **不能**把 slab 当作 `U(b,R,κ)` 的额外约束来「缩小 `U`」：`U` 是松弛最大值，限制到 slab 不改变 `U`；更不能因为**某切片没有真实点**就跳过它来减少 `U` 的计算——`U` 的最大值仍可能在满预算面上（其最优解未必对应真实可达点）。
- **PR3 的切片跳过**只允许用于「真实域可行性/枚举」；若用于**顶点/部分归约证书**（该证书为松弛最大值服务），跳过切片会破坏证明：顶点/边界归约的证书必须覆盖**所有**切片，包括没有真实点的切片（因为松弛最大值可能由这些切片上的候选取得）。反例说明见 §7.4：free-budget `U=4,082,040,000,000` 的最大值出现在满预算面 `Σ=15` 上；而真实域 slab `[L,R]=[59,96]` 与松弛分配和 `Σx∈[0,15]` 不相交——若用真实域 slab 做切片跳过，会把 `U` 的满预算最大值面整个跳过。

### 5.2 Theorem 2：安全下界 L1

在 §4 假设下：

1. **装备/镶嵌下界**：

```text
L_gear = Σ_{s∈Slots} ℓ_s,   ℓ_s = min_{c∈C_s} S3(c)     （可选槽的空向量计入 C_s）
```

则对任意合法完成 `γ`（每槽选一个候选）：`Σ_s S3(c_s(γ)) >= L_gear`。证明：逐槽 `S3(c_s) >= ℓ_s`，求和。戒指唯一性/共享身份只会减少合法选择，不影响该不等式（对每个真实选择的逐项下界仍成立）。

2. **食物下界**：定义

```text
L_food = min { Σ_i bonus_i(f, 0) : f ∈ F_allowed }
```

其中 `F_allowed = F`（食物必选）或 `F ∪ {∅}`（食物可选；`bonus_i(∅,0)=0`）。则对任意合法完成的食物选择与任意 `G_i >= 0`：`Σ_i bonus_i(f,G_i) >= L_food`（由 (A3) 单调性，`bonus_i(f,G_i) >= bonus_i(f,0)`；再取允许食物的最小）。

3. **总下界**：

```text
L1 = L_gear + L_food,     ∀γ∈Γ: S(γ) >= L1.
```

4. **安全方向**：`L1` 对候选池、食物集合、槽模型的变化保持安全，只要 `ℓ_s` 与 `bonus_i(f,0)` 按当前输入精确计算；约束（唯一性/速度/TEN 带）只会缩小 `Γ`，因此**无约束下界在约束下仍安全**（不会失效）。
5. **可达性/tightness**：若所有槽相互独立（无唯一性/共享耦合），逐槽取 `argmin` 可同时取到，`L_gear` **精确等于**装备侧最小和；`L_food` 与食物依赖 `G_i`，`L1` 一般不是 `min S` 的精确值（数值实例：`L1=59` 而 `min S=67`，见 §7.6）。有戒指唯一性时 `L1` 仍安全但可能不紧。

### 5.3 Theorem 3：更紧的安全下界

1. **独立槽**：无唯一性/共享耦合时，`L_gear = min { Σ_s S3(c_s) }` 精确（逐槽 argmin 同时取到）。有耦合时只能保证 `L_gear <= min`；此时用下一条。
2. **戒指唯一性的精确最小合法配对**：设两个戒指槽 `A, B`，候选集合 `C_A, C_B`。合法配对集合 `P_legal = {(a,b) : (a,b) 不违反唯一性}`。则

```text
L_gear(rings) = min_{(a,b) ∈ P_legal} (S3(a)+S3(b))
```

算法：对每个 `a ∈ C_A`，在 `C_B` 中取与该 `a` 合法的、`S3` 最小的 `b`（若唯一性只涉及 itemId，则先按 `S3` 排序，取最小合法者；带 itemId 时用「每个 itemId 的最小/次小」O(|C|) 或最坏 O(|C_A||C_B|) 全枚举）。证明：合法配对的集合就是 `P_legal`，取最小即定义。数值实例：朴素逐槽 min `=32`（X+X 非法），精确最小合法配对 `=39`（X+B2 或 A2+X），精化 `L1' = 66`（§7.6）。
3. **约束只会缩小可行域**：对任意约束集合 `K`，`Γ_K ⊆ Γ`，故 `min_{Γ_K} S >= min_{Γ} S`。所以任何在 `Γ` 上证明的下界在约束下**仍安全**（但可能更松）。若要更紧，可用下一条。
4. **可选：约束下界的 Lagrangian 提升（条件成立）**。设附加约束是可加统计量（例如 TEN 贡献和 `ten(c)`；速度同理）。对 `ten >= t_lo`：对任意 `ν >= 0`，

```text
LB_ν = Σ_s min_{c∈C_s} (S3(c) − ν·ten(c)) + L_food + ν·t_lo  <=  min_{ten>=t_lo} S
```

对 `ten <= t_hi`：对任意 `μ >= 0`，

```text
LB_μ = Σ_s min_{c∈C_s} (S3(c) + μ·ten(c)) + L_food − μ·t_hi  <=  min_{ten<=t_hi} S
```

因此 `max_ν LB_ν`（或 `max_μ LB_μ`）是更紧的安全约束下界。**方向必须正确**：下侧约束配 `−ν·ten + ν·t_lo`，上侧约束配 `+μ·ten − μ·t_hi`；符号反了会得到不安全的值。注意这要求约束在槽间可加；若约束含食物非线性项（食物加成依赖总 `G`）或跨槽共享身份，则该分解不成立，只能使用安全但更松的 `L1`。数值：`TEN>=2` 时约束下 `min S=67`，`max_ν LB_ν=64`；`TEN<=1` 时 `min S=67`，`max_μ LB_μ=59`（§7.7）。

### 5.4 Theorem 4：部分分支/滚动下界

对部分提交 `P`（每槽已选候选或未提交）与任意合法完成 `γ` 扩展 `P`：

```text
s_P = Σ_{s∈P} S3(c_s)                                  （已提交贡献和）
L_rem(P) = Σ_{s∉P} ℓ_s + L_food,  R_rem(P) = Σ_{s∉P} u_s + R_food
=>  s_P + L_rem(P) <= S(γ) <= s_P + R_rem(P)
```

其中 `R_food = max_{f∈F_allowed} Σ_i bonus_i(f, G_i^max)`、`G_i^max = Σ_{s∉P} max_{c∈C_s} x_i(c) + Σ_{s∈P} x_i(c_s)`（食物对 `G` 单调，故用逐属性独立乐观最大；忽略唯一性只会更大，安全）。证明：`S = s_P + Σ_{s∉P} S3 + Σbonus >= s_P + Σℓ_s + L_food`；上界同理。

**增量更新（O(1)/槽）**：提交槽 `s` 选候选 `c` 时：

```text
s_P      += S3(c)
L_rem(P) -= ℓ_s          （食物下界不变；若该步提交的是食物，则 O(1) 重算 L_food）
R_rem(P) -= u_s          （并收紧 R_food 的 G^max；可用单调更新）
```

**戒指唯一性/共享身份下**：提交一个戒指槽可能排除另一戒指槽的某些候选；此时把 `u_s`/`ℓ_s` 替换为「与 P 合法相容的候选集」上的 min/max（重算该槽 O(|C|)），其余增量规则不变；`ℓ_s` 变小或变大方向都只会使区间更松/更紧但仍安全（min/max 用合法子集计算本身就是安全界）。

### 5.5 Theorem 5：单调性与滚动区间

1. `s_P` 随 P 增大非减（`S3(c) >= 0`）。
2. `L_rem(P)` 随 P 增大非增：提交一个槽会把它的 `ℓ_s` 从剩余和下界中移除。
3. 分支下界 `s_P + L_rem(P)` 随 P 增大非减：新增 `S3(c)`，移除 `ℓ_s`，而 `S3(c) >= ℓ_s`。
4. `R_rem(P)` 随 P 增大非增；`[s_P + L_rem, s_P + R_rem]` 是逐步收紧的滚动区间，且始终包含全部扩展完成（Theorem 4）。

### 5.6 剪枝定理族 PR1–PR8

每条给出：精确陈述、证明要点、删什么/不删什么、适用对象、tie 语义。完整证明见 §6。

#### PR1 slab 包含（收紧必要区域）

**陈述。** 设 `L <= min_{γ∈Γ} S(γ)`、`R >= max_{γ∈Γ} S(γ)` 是经认证的界，`Ω` 是 `strict-improvement-frontier` 的贡献盒且 `Reach ⊆ Ω`。令 `Ω' = Ω ∩ {(C,H,D) : L <= C+H+D <= R}`。则：

1. `Reach ⊆ Ω'`（真实可达集仍在 slab 内）；
2. **可继承的集合安全**：任何在 `Ω'` 上**正确计算**的 `K_w(Ω')` 给出的半空间仍对全部真实可达改善点必要；`K_w(Ω') >= K_w(Ω)`（小集合上的 min 更大；若 `G_> ∩ Ω' = ∅` 则 `K_w = +∞`，结论是「Ω' 内无改善点」，比剪枝更强，而不是剪枝失效）；
3. **不可继承的算法**：`Ω'` 一般不是坐标上集，`D_min` 关于 C/H 的单调性、tier 单元常值、最小反链/档位代表元枚举（frontier Theorem 1.2/1.3/1.4/2.2/2.3）**都不能直接搬到 `Ω'`**（slab 非上集）。必须使用 frontier Theorem 1.5 的逐点公式与 `(C,H)` **全枚举**：

```text
K_w(Ω') = min_{ (C,H) ∈ [0,κ_C]×[0,κ_H] } [ w_C*C + w_H*H + w_D*D_min'(C,H) ]    （跳过 +∞ 截面）
```

它是精确公式，但成本为 `(κ_C+1)(κ_H+1)` 个格点查询（`D_min` 可查盒域 tier 单元表），**不是** `|A_C||A_H|` 个 tier 代表元；紧凑 breakpoint 表示需另行推导（frontier §12）。若误用盒域代表元会得到偏大（不安全）的 `K_w`：反例 `L100, κ=(1,1,1), L=R=1, B=1` 中真实 `K_w(0,1,1)=0`，代表元算法给出 `1`（frontier §7.6、§11 A13）。
4. 更强的剪枝：用 `K_w(Ω')` 的**已证明值或下界**作半空间阈值比用 `K_w(Ω)` 删得更多且仍安全（前提是第 2 条的「正确计算」）。

**D_min 的 slab 重定义（显式逐点公式）。** 对固定 `(C,H)`，`slab ∩ Ω` 上重新定义

```text
D_min'(C,H) = max( D_min(C,H), max(0, L−C−H) )       若 D_min(C,H) 有限；
截断上界：D <= min(κ_D, R−C−H)；
若 D_min(C,H)=+∞，或 max(D_min(C,H), max(0,L−C−H)) > min(κ_D,R−C−H)，则 D_min' = +∞（空集）。
```

**证明**：`G_> ∩ Ω'` 在 `(C,H)` 截面上是 `{D : D_min(C,H) <= D <= κ_D, L−C−H <= D <= R−C−H}`；它的最小元就是 `max(D_min, max(0,L−C−H))`，非空条件即公式；其余为定义。∎ **注意**：这是**逐点公式**；§11 E 的 3721 格点验证只验证该公式与暴力逐点一致，**不证明**盒域 tier 代表元/最小反链枚举可继承——后者已被 frontier §7.6 的反例否证（同 tier 单元内 `D_min'` 不同值、`D_min'` 非单调）。

**适用对象**：Ω 是真实可达集的超集（松弛域），因此本规则用于收紧「真实域的必要区域/上界计算域」。**禁止**把 `Ω'` 当作 free-budget `U` 的额外约束去缩小 `U`（Lemma 1、§5.1）。

#### PR2 分支不可行

**陈述（全局界形式，字面版）。** 设 `[L,R]` 是同一上下文下的全局有效界（所有合法完成 `S∈[L,R]`），分支 `P` 的保证区间由 Theorem 4 给出。若 `s_P + L_rem(P) > R` 或 `s_P + R_rem(P) < L`，则该分支没有合法完成。

**证明**：若存在扩展完成 `γ`，则 `S(γ)` 同时满足分支区间与 `[L,R]`；两个区间不相交则矛盾。∎

**限制（必须写入适用范围）**：在 `[L,R]` 为**同一上下文的全局有效界**时，任何**非空**分支的保证区间必与 `[L,R]` 相交（因为它的完成同时落在两者中）。所以该字面形式只能用于「由界推出某分支为空」；它对**非空**分支不会触发。本文给出两个精确命中：非法完全提交分支（唯一性冲突）的保证区间落在 `[L,R]` 外（`branch.lower=200 > R=110`；`branch.upper=10 < L=105`），且这些分支确实无合法完成（§7.3）。离散不可行（如戒指唯一性导致某槽无候选）需要单独的候选集可行性检查，不能只靠区间。

**陈述（目标窗口形式，可用版）。** 设 `[W_lo, W_hi]` 是**保留解必须满足的目标窗口**（例如严格改善模型：`W_lo = K_sum(B)`、`W_hi = R`；tie 模型：`W_lo = K_sum^{>=}(B_nonstrict)`）。若分支区间与 `[W_lo,W_hi]` 不相交，则该分支不含保留解；在严格改善模型中可安全剪除（不是「无合法完成」，而是「无严格改善完成」）。数值命中：`W_lo = K_sum = 71` 时 2 个分支被剪且均无严格改善完成（§11 G）。

**适用对象**：真实域分支搜索；目标窗口形式只在对应目标语义下使用（tie 模型换非严格阈值，见 PR8）。

#### PR3 区域/切片排除（必须限定范围）

**陈述。** 设区域 `Q ⊆ Z_{>=0}^3`（可以是固定第三坐标的 pairwise 切片、tier 盒、分支子区域），且可计算其可达和区间 `[σlo(Q), σhi(Q)]`（安全界：`σlo` 用逐坐标/区域下界，`σhi` 用上界；例如 `σlo = Σ` 的下界）。若 `[σlo,σhi] ∩ [L,R] = ∅`（`L,R` 为全局有效界），则 `Q` 不含任何真实完成（`Reach ∩ Q = ∅`），可跳过/删除该区域的真实域枚举与候选搜索。

**pairwise 切片特化。** 固定第三属性贡献 `d0`、另两属性预算（坐标和）`S_pair` 的切片上，任意点的总和为 `Σ = S_pair + d0`。若 `S_pair + d0 ∉ [L,R]`，则该切片不含真实完成，可跳过。数值：`S_pair+d0 ∈ [L,R]` 对全部可达改善点成立，并且构造的不相交切片确实无真实完成（§11 H）。

**证明**：`Reach ⊆ slab`（PR1 的 1），故任何真实完成的总和在 `[L,R]`；若区域上所有点的总和都不在 `[L,R]`，区域与 `Reach` 不交。∎

**适用范围（重要，来自用户约束）：** PR3 只允许用于「真实域可行性/枚举」。**禁止**用于：(i) 为 `U(b,R,κ)` 的切片计算做跳过——`U` 的最大值仍可能在满预算面上，且该面未必有真实点；(ii) 顶点/边界/部分归约证书——该类证书为**松弛最大值**服务，必须覆盖所有切片。反例：free-budget 实例 `U=4,082,040,000,000` 在满预算面 `Σ=15` 取到，而真实域 slab `L=59` 与该面不相交；按真实域「无真实点」跳过切片会丢掉 `U` 的 argmax（§7.4）。

#### PR4 incumbent 和割

**陈述。** 令 `B>0` 为严格改善阈值（[strict-improvement-frontier](../strict-improvement-frontier/README.md) Lemma 0），`K_sum(B) = K_{(1,1,1)}(B) = min { C+H+D : Φ_C(C)Φ_H(H)Φ_D(D) > B }`（`G_>` 为空时 `+∞`）。则任何严格改善点满足 `Σ >= K_sum(B)`。因此：

```text
若分支的“最大可能和” s_P + R_rem(P) < K_sum(B)  =>  分支内无严格改善完成（严格模型可剪）；
若与 slab 组合得到空交集 => 同理。
```

证明：`x ∈ G_>(B) => Σx >= K_sum(B)`（[strict-improvement-frontier](../strict-improvement-frontier/README.md) Theorem 3.1，`w=(1,1,1)`）；分支任何完成 `Σ <= s_P+R_rem`。∎

**支配关系（必须说明）**：`K_sum` 规则是**必要条件和**，比精确乘积界弱：若某分支的精确最大乘积 `<= B`（或 `U <= incumbent`），则它删得比和割更多；和割可删的分支一定也被精确乘积界删去（数值：和割命中 2 个分支，全部被乘积界覆盖；另有 28 个分支「乘积界可删但和割不触发」）。因此和割只登记为**廉价早筛/一致性检查**，在无法计算乘积上界时作为替代；不声称更强。tie 模型用非严格阈值 `K_sum^{>=}(B_nonstrict)` 或禁用（PR8）。

#### PR5 候选级必要和可达性

**陈述（严格模型）。** 对槽 `s` 的候选 `c`，用 `c` 的分支最大可能和 `maxΣ_using(c) = s_P + S3(c) + Σ_{s'≠s} u_{s'} + R_food`（并收紧戒指唯一性/食物上界）。若 `maxΣ_using(c) < K_sum(B)`，则 `c` 不可能参与任何严格改善完成，可在严格改善搜索中删除。

证明：任何使用 `c` 的完成 `Σ <= maxΣ_using(c) < K_sum`，而严格改善需 `Σ >= K_sum`，矛盾。∎

**数值命中**：小实例 M4 中 `tiny` 候选 `maxΣ=50 < K_sum=96`，命中且该候选不参与严格改善完成（§11 J）。M1 中命中 0 个（该实例所有候选都参与最大乘积完成），同时给出 4 个「乘积界可删但和可达性不触发」的候选。

**支配关系**：同 PR4，被精确乘积界支配；只在无法计算乘积上界时作廉价替代。**tie/身份保留模型不可用 `<=`/`<` 删除**（PR8）；戒指唯一性下用 `c` 可能排除同槽其它候选组合，但删除 `c` 只移除使用 `c` 的完成，不影响不使用 `c` 的完成，故严格模型下安全。

#### PR6 半空间组合/多方向

**陈述。** 和半空间 `Σ >= K_sum(B)` 是 [strict-improvement-frontier](../strict-improvement-frontier/README.md) 支撑族中的一个方向 `w=(1,1,1)`（阈值 `K_{(1,1,1)}(B)`）。对已认证的方向族 `(w_i,K_i)`：

1. 任意子集 `S` 的联合删除 `∪_{i∈S}{w_i·x < K_i}` 都不删除任何严格改善点（任一条都是必要条件）；
2. `w=(1,1,1)` 与其它方向可任意组合，正确性不依赖方向数量；
3. 冗余判据：若 `w_j = λ w_i`、`K_j >= λ K_i`，则第 `i` 条被第 `j` 条蕴含；一般判据为 `min_{x∈∩_{j≠i}H_j} w_i·x >= K_i`（`H_j={w_j·x>=K_j}`）时第 `i` 条冗余。

证明：与 [strict-improvement-frontier](../strict-improvement-frontier/README.md) Theorem 5.1/5.2 相同（逐条必要条件；蕴含则冗余）。∎

**数值**：5 个方向、31 个非空子集均不删可达改善点；`(2,2,2)` 且 `K=2K_sum` 蕴含和半空间；`K_{(1,1,1)}(Ω')=max(K_sum,L)=71`（§11 K）。**适用对象**：真实域必要区域（Ω 为真实可达集超集）；不是松弛域的 U 约束。

#### PR7 复合/多职业

**陈述（离散可行性，无条件安全）。** 多职业联合搜索中，共享槽/共享物品的选择必须对每个职业 `j` 都存在合法完成。若对某共享部分提交与某职业 `j`，职业 `j` 的候选集可行性检查失败（例如共享的 unique 物品占用了职业 `j` 必需槽的唯一候选、或戒指唯一性使剩余槽无候选），则该共享分支可安全剪除（联合模型下不存在合法完成）。

**陈述（目标窗口，条件安全）。** 若联合模型**明确要求每个职业独立严格改善**（例如 `Σ_j` 归一化损失模型中对每个职业有单独 incumbent 要求时），则对职业 `j` 使用 PR2 目标窗口/PR4 和割：分支对职业 `j` 的最大可能和 `< K_sum,j(B_j)` ⇒ 职业 `j` 无严格改善完成 ⇒ 联合分支可剪。**若联合目标允许职业间 trade-off（如 [joint-loss-sum-bound](../joint-loss-sum-bound/README.md) 的归一化损失和），则不能**仅因某职业不能改善就剪掉整个联合分支（其它职业可能补偿）；此时必须使用联合损失界。

**证明**：离散版由「联合合法完成 ⇒ 每职业合法完成」；条件版由「联合模型要求每职业改善 ⇒ 该职业无改善即非保留解」。∎

**数值**：共享戒指 X 与职业 1 专属唯一候选同 `itemId`：联合合法完成中含 X 的 `=0`，共享方案 `(X,B2)` 联合完成数 `=0`（离散剪枝）；条件目标窗（要求每个职业严格改善）剪掉 2 个 job1 分支且均无合法完成（§11 K）。

#### PR8 tie/身份保留语义

| 剪枝 | 严格改善模型 | tie/身份保留模型 |
| --- | --- | --- |
| PR1（slab 包含） | 安全（只收紧必要区域） | 安全：slab 只排除**无合法完成**的区域；同分方案仍在 slab 内（L/R 对全部合法完成成立） |
| PR2（全局界形式） | 安全（只证空分支） | 安全（同上，删的是无合法完成的分支） |
| PR2（目标窗口）/PR4/PR5 | 用严格阈值 `K_sum(B)`，安全 | **失效**：必须换成非严格阈值 `K_sum^{>=}(B_nonstrict)`，否则会删除同分方案；身份/并列枚举模型下建议只做可行性剪枝 |
| PR3（区域/切片） | 安全（只排除无真实完成的区域） | 安全（只删无真实完成的区域） |
| PR6（半空间） | 安全（必要条件） | 必须用非严格支撑阈值；否则同分点可能被删 |
| PR7（可行性部分） | 安全 | 安全（只删无合法完成的联合分支） |

**反例（PR8）**：抽象正因子乘积模型 `Φ=x1x2x3`、`B=8`、tie 点 `(2,2,2)`（`Φ=8`、`Σ=6`）；`G_>(8)` 的最小和 `K_sum=7 > 6`。严格改善模型不保留该 tie 点是正确的；tie/身份保留模型若用「`Σ<K_sum`」剪枝会删掉这个同分点——规则失效（§11 K）。数值/一般性论证见 §7.5。

### 5.8 方向规则（低估安全、高估不安全）

1. **`L` 必须 `<= min_{γ∈Γ} S(γ)`**：低估（更小的 L）安全但更弱；高估（L 大于真实最小值）会删除合法完成（§7.2 的 `L=68 > min S=67` 删掉 2 个合法完成；`L=R=96` 更严重）。
2. **`R` 必须 `>= max_{γ∈Γ} S(γ)`**：高估安全但更弱；低估（小于真实最大值）会删除合法完成（§7.2 的 `R=95`）。
3. **逐属性 min 相加是安全但更弱的 L**：`Σ_i Σ_s min_c x_i(c) <= Σ_s min_c S3(c) = L_gear`；数值 `44 <= 59`（§7.2）。反过来「逐槽 min 之和」比「逐属性 min 之和」更紧。
4. **面板值不能当贡献**：L 会被抬高 `Σbase`（level 100：`1280`），数值 `L1+1280=1339 > max S=96`，直接删光（§7.2）。
5. **Lagrangian 方向**：下侧约束 `ten>=t_lo` 用 `−ν·ten + ν·t_lo`；上侧 `ten<=t_hi` 用 `+μ·ten − μ·t_hi`；方向反了不安全（§5.3、§7.7）。

## 6. 证明

### 6.1 Lemma 1（`U` 不变性，独立复核）

引用 [free-budget-upper-bound](../free-budget-upper-bound/README.md)：

- 定理 1(3)：`U` 对 `R`、`b_i`、`κ_i` 非减（由 `f_i` 单调）。
- 定理 2：存在最优分配 `x*` 满足 `Σx*_i = S* = min(R,K)`。

于是对 `L <= S*`：`x* ∈ A` 且 `Σx*_i = S* >= L`，故 `x*` 在限制域 `{Σ>=L}` 中；限制域的 max `<= U`（子集）；又 `x*` 达到 `U`，所以相等。若 `L > S*`，任何 `x∈A` 都有 `Σx <= S* < L`，限制域为空。`Σ<=R''` 同理。**独立复核的有限证书**：§11 F 在 `b=0,R=15,κ=20` 上对 `L=0,1,7,14,15` 断言最大值不变、`L=16` 为空、满预算面 `Σ=15` 取到 `U`。∎

**禁止混用的证明**：slab 的包含关系只对**真实可达集**成立（`Reach ⊆ Ω'`）；`U` 的定义域是 `A(b,R,κ)`（松弛分配），其满预算最优解一般不对应真实完成，也不要求 `S∈[L,R]`。把真实域 `[L,R]` 强加给 `A` 会改变 `U` 的定义域（若 `L>S*` 直接清空）。PR3 的切片跳过若用于顶点/归约证书，会删除松弛最大值的候选切片；[simplex-vertex-reduction](../simplex-vertex-reduction/README.md) 的证书要求覆盖所有切片（其定理 2/4 的量词为「所有定第三坐标切片」），因此跳过会破坏证明。§7.4 给出数值反例。∎

### 6.2 Theorem 2 证明

逐槽：`c_s(γ) ∈ C_s`，故 `S3(c_s(γ)) >= ℓ_s`；求和 `Σ_s S3 >= L_gear`。食物：由 (A3) 引理（下）`bonus_i(f,G_i) >= bonus_i(f,0)`，故 `Σ_i bonus_i >= Σ_i bonus_i(f,0) >= L_food`。相加得 `S(γ) = ΣS3 + Σbonus >= L1`。约束：`Γ_K ⊆ Γ`，逐点不等式在子集上仍成立。∎

**引理 3（食物加成对 G 非减）**：`G -> (G+base)*r + 1e-7` 非减（`r>=0,base>=0`）；`trunc` 非减；`min(cap,·)` 非减；复合非减。因此 `bonus_i(f,G) >= bonus_i(f,0)`。∎

### 6.3 Theorem 3 证明

(1) 独立槽：逐槽 argmin 的笛卡尔积是可行选择（无视耦合时），其和等于 `L_gear`，故 `min = L_gear`。
(2) 戒指：合法配对集合 `P_legal` 有限，定义取最小可达；算法枚举/排序取最小合法即得定义值。
(3) 约束：子集最小值不小于全集最小值。
(4) Lagrangian：对 `ten >= t_lo`、`ν>=0`，可行点满足 `t_lo − ten <= 0`，故 `S >= S + ν(t_lo − ten)`（右边更小）；对全部点取下确界得 `LB_ν <= min_{ten>=t_lo} S`。`ten <= t_hi`、`μ>=0` 同理（`S >= S + μ(ten − t_hi)`）。由于槽独立时 `min` 可分解，`LB_ν` 的计算是逐槽 min 求和（加食物下界）。注意：若食物贡献也进入约束或约束在槽间不可加，该分解不成立，此时只保留 Theorem 2 的安全下界。∎

### 6.4 Theorem 4/5 证明

Theorem 4：对扩展完成 `γ`，`Σ_s S3(c_s) = s_P + Σ_{s∉P} S3(c_s) >= s_P + Σ_{s∉P} ℓ_s`；食物同理（`bonus_i(f,G_i) >= bonus_i(f,0) >= L_food`）；上界用 `u_s` 与 `R_food`。区间包含。增量更新是代数恒等式；合法子集 min/max 仍是安全界。∎
Theorem 5：`s_P` 增量为 `S3(c)>=0`；`L_rem` 增量 `−ℓ_s <= 0`；分支下界增量 `S3(c)−ℓ_s >= 0`；`R_rem` 增量 `−u_s <= 0`。∎

### 6.5 PR1 证明

`Reach ⊆ Ω`（Ω 是外接盒）且 `∀γ: L<=S(γ)<=R`（L/R 有效），故 `Reach ⊆ Ω'`。**集合/安全方向**可继承：`G_> ∩ Ω' ⊆ G_> ∩ Ω`，故 `min` 更大（或空集 → `+∞`）；任何在 `Ω'` 上**正确计算**的 `K_w(Ω')` 半空间对 `G_> ∩ Ω'` 安全，而真实可达改善点都在 `G_> ∩ Ω'` 中。

**但算法/结构不继承（slab 非上集）**：`Ω'` 不是坐标上集，`D_min'` 不再关于 C/H 单调、不再在盒域 tier 单元内常值；因此 frontier 的 tier 代表元/最小反链枚举不能直接套用。`D_min'` 的公式由 §5.6 的截面最小元论证（逐点）；上界截断 `D <= min(κ_D,R−C−H)` 是因为 slab 上侧约束；`+∞` 是空集语义。`K_w(Ω')` 必须按 §5.6 PR1 的 `(C,H)` 全枚举公式计算（或使用已证明的下界）；§11 E 的 3721 格点只验证**逐点公式**与暴力一致，不构成对盒域代表元算法继承性的证明。∎

### 6.6 PR2 证明

全局形式：设分支有扩展完成 `γ`，则 `S(γ) ∈ [s_P+L_rem, s_P+R_rem]`（Theorem 4）且 `S(γ) ∈ [L,R]`（全局有效界），两区间相交；故条件（不相交）成立时不存在扩展完成。限制：若分支非空则存在 `γ`，故两区间都包含 `S(γ)`，必相交；因此全局形式只能对空分支触发（要证非空需额外结构/离散检查）。目标窗口：`γ` 若为保留解必满足 `S(γ) ∈ [W_lo,W_hi]`；分支区间不相交则无保留解。∎

### 6.7 PR3 证明

`Reach ⊆ slab`（PR1 的 1）；若区域 `Q` 的所有点满足 `Σ ∉ [L,R]`（由 `[σlo,σhi]` 与 `[L,R]` 不交），则 `Q ∩ Reach = ∅`。pairwise 切片特化：切片点满足 `Σ=S_pair+d0`，故条件直接化归。∎ 关于**禁止混用**见 §6.1 的证书覆盖论证。

### 6.8 PR4/PR5/PR6/PR7/PR8 证明

- PR4：`x∈G_>(B) => Σx >= K_sum`（frontier Theorem 3.1）；分支完成 `Σ <= s_P+R_rem`；若后者 `< K_sum` 则无改善完成。支配：若精确最大乘积 `<=B`，则无改善完成，故和割可删的分支也被乘积界删；反之不成立（数值 28 个反例）。
- PR5：同上，将「分支最大和」替换为「使用该候选的最大和」，并注意删除 `c` 只移除使用 `c` 的完成。
- PR6：任一方向都是必要条件；`w=(1,1,1)` 即和割；冗余判据证明同 frontier Theorem 5.2（`H_i` 被其它 `H_j` 蕴含则删除集不变）。
- PR7：离散版由联合合法完成 ⇒ 每职业合法完成；条件版由联合保留解定义要求每职业满足目标窗口。
- PR8：见 §5.6 PR8 表与 §7.5 反例；严格模型的 `<` 剪枝对 tie 点不成立（tie 点不满足严格阈值），tie 模型必须使用非严格区域或不做目标类剪枝。∎

## 7. 反例与边界退化

数值全部来自 [`verify.mjs`](verify.mjs)（level=100 WHM，`sub=420`、`main=440`；所有坐标为贡献）。

### 7.1 合成实例 M1 与安全界

M1：head 4 候选、两个戒指槽各 2 候选（X 在两个戒指槽同 ID 且 unique）、2 食物；共 24 个合法完成。`S∈[67,96]`；`L_gear=47`（逐槽 min）、`L_food=12`、`L1=59`；`R_gear=78`、`R_food=18`、`R=96`；可达坐标最大 `(49,48,37)`。所有完成满足 `L1=59 <= S <= R=96`。

### 7.2 方向错误的不安全反例（L/R/逐属性/面板值）

1. **L 太大**：`L=68 > min S=67`，会排除 2 个合法完成（`S=67` 的完成）。
2. **把上界当 L**：`L=R=96`，排除全部非最大完成。
3. **R 太小**：`R=95 < max S=96`，排除 `S=96` 的完成。
4. **逐属性 min 相加（安全但更弱）**：`Σ_i Σ_s min_c x_i(c) + L_food = 44 <= L1 = 59`；两式都是安全下界，但逐槽 min 更强。
5. **面板值当贡献（不安全）**：level 100 的 `Σbase = 420+420+440 = 1280`；把面板最小值当 L 得到 `L=59+1280=1339 > max S=96`，会删光全部完成。
6. **戒指唯一性 naive vs 精确**：朴素逐槽 min `=32`（两槽都取 X，但 X unique 不能重复）；精确最小合法配对 `=39`（X+B2 或 A2+X）；精化 `L1'=54+12=66 <= min S=67`，比朴素 `L1=59` 显著更强（§7.6）。

### 7.3 PR2 的精确命中与限制

- **全局界形式的限制**：45 个部分提交分支中 40 个非空；非空分支的保证区间全部与 `[L,R]=[59,96]` 相交（不相交 0 个）。这与定理一致：非空分支必与全局有效界相交，因此该形式只能命中空分支/由界推出为空的分支。
- **上界方向命中**（非法完全提交）：两戒指槽都选 `Xbig`（同 unique itemId），合法范围 `[20,110]`，非法分支保证区间下界 `200 > R=110` ⇒ 剪枝；该分支确实无合法完成。
- **下界方向命中**：两戒指槽都选 `Xsmall`（同 unique itemId），合法范围 `[105,200]`，非法分支保证区间上界 `10 < L=105` ⇒ 剪枝；确实无合法完成。
- **目标窗口形式**：`W_lo=K_sum=71`，2 个分支被剪且均无严格改善完成。

### 7.4 PR3 禁止混用的反例（真实域 vs 松弛域）

free-budget 松弛 `b=0, R=15, κ=20`：`U=4,082,040,000,000`，且最大值在满预算面 `Σ=15` 上（满预算最优解存在）。真实域 slab 的 `L=59`（甚至最小合法完成 `S=67`）与松弛分配和 `Σx∈[0,15]` 不相交。若把真实域 slab 用于：
1. **给 `U` 加约束**：限制 `Σx >= 59` 后 `A` 为空——不是更紧的 `U`，而是丢失 `U`；
2. **跳过切片**：按「该切片无真实点」跳过所有分配切片，`U` 的满预算 argmax 被跳过，顶点/部分归约证书失效。

因此 PR3 的切片跳过只在「真实域可行性/枚举」成立；对 `U`/顶点归约证书，必须保留全部切片（§5.1、§6.1）。

### 7.5 PR8 的 tie 反例

抽象正因子乘积模型 `Φ=x1x2x3`、`B=8`：tie 点 `t=(2,2,2)`，`Φ(t)=8=B`、`Σt=6`；`G_>(8)` 的最小和 `K_sum=7`（例 `(1,3,3)`，`Φ=9`、`Σ=7`）。严格改善模型不保留 `t` 是正确的；但 tie/身份保留模型若套用「`Σ < K_sum` ⇒ 剪」会删除 `t`——tie 模型必须使用非严格阈值（`K_sum^{>=}(B_nonstrict)`）或只做可行性剪枝。§7.3 的 PR7 与 §7.2 的 PR1/PR3 只删除无合法完成/无真实完成区域，因此对 tie 安全。

### 7.6 戒指唯一性：朴素 vs 精确

§7.2 第 6 条；`L_gear` 精确值 `54`、精化 `L1'=66`；真实 `min S=67`。差距 `1` 来自食物依赖 `G`（`L_food` 用 `G=0` 的 `bonus`，而最小完成的食物 `G>0` 使 bonus 略高）。这说明 `L1` 安全但未必紧；更紧的联合 slot+food 下界是开放问题（§12）。

### 7.7 约束下的下界与 Lagrangian 方向

约束 `TEN>=2`：约束下 `min S=67`；`max_ν LB_ν=64 <= 67`（安全）。约束 `TEN<=1`：约束下 `min S=67`；`max_μ LB_μ=59 <= 67`。方向反写（`+ν·ten − ν·t_lo` 或 `−μ·ten + μ·t_hi`）会给出可能大于真实最小值的「伪下界」，不安全。

### 7.8 空改善区域/空 G 语义

- `B=P*`（盒内最大乘积）时 `G_> = ∅`，`K_{w}(Ω')=+∞`；正确结论是「Ω' 内无改善点」（比任何半空间都强），不是剪枝失效。
- `G_> = ∅` 时 PR4/PR5/PR6 的目标窗口为空真：此时应直接返回「无严格改善解」，不再叠加阈值。
- `L > R`（非法 slab）或 `L` 超过全下界/`R` 低于全上界：视为输入错误，必须禁用本层而不能用它剪枝。

### 7.9 食物边界

- 食物可选时 `F_allowed = F ∪ {∅}`：`L_food = min(0, min_f bonus(f,0)) = 0`（bonus 非负），安全但弱；食物必选时 `L_food = min_f Σbonus(f,0)`。
- 若某项 `bonus_i(f,0) = cap`（基础属性已足以触发封顶），则 `bonus_i` 对 `G` 为常数，`L_food = R_food` 侧都紧；数值实例中 f1 的 C/D 与 f2 的 H 在 `G=0` 附近未封顶，需用单调性。
- 多个食物/食物与共享食物交集：`L_food` 只依赖**允许食物集合**；共享食物约束（`docs/rules/领域与搜索规则.md:39`）只会缩小 `F_allowed`，在其上取 min 仍安全（若交集为空则无合法完成，属 PR2/PR7 可行性剪枝）。

### 7.10 slab 不继承盒域档位算法（反例；与 frontier §7.6 一致）

取 L100 WHM、`Ω=[0,1]^3`、`L=R=1`、`B=1`（所有点 `Φ > 1`）。`Ω' = Ω ∩ {Σ=1}` 内改善点恰为 `(1,0,0),(0,1,0),(0,0,1)`。逐点公式给出

```text
D_min'(0,0)=1, D_min'(1,0)=0, D_min'(1,1)=+∞
```

`D_min'` 在 H=1 方向随 C 从 0 增到 1 由 `0` 变为 `+∞`（违反 frontier Theorem 1.2 的单调不增）；`(0,0)` 与 `(1,0)`（以及 `(0,1)`/`(1,1)`）在贡献 0/1 属于同一 tier 单元，却取不同 `D_min'`（违反单元常值）。取 `w=(0,1,1)`：

```text
真实 K_w(Ω') = 0（由 (1,0,0)）
盒域 tier 代表元 (0,0) 算法 = 0+0+D_min'(0,0) = 1   （偏大、不安全）
```

因此 PR1 的 `K_w(Ω')` 必须按 §5.6 的 `(C,H)` 全枚举公式计算（或使用已证明的下界）；§11 E 的 3721 格点只验证**逐点公式**，不证明代表元/最小反链枚举可继承。同一反例在 [strict-improvement-frontier](../strict-improvement-frontier/README.md) §7.6/§11 A13 中独立复现。

## 10. 应用前提与安全回退

### 10.1 输入前提（全部满足才启用对应层）

1. **坐标**：所有输入是贡献坐标；若内部是面板值，先按 §3.1 减 `sub/main`（CRT/DHT/TEN 减 `sub`、DET 减 `main`），不得统一平移。
2. **候选与槽**：每槽候选非空且含固定镶嵌；可选槽显式含零向量；戒指唯一性/共享身份按真实规则编码。
3. **食物**：canonical 公式与参数可认证（`rate/cap/base` 非负、`trunc` 语义正确）；`F_allowed`（含可选无食物）明确。
4. **约束**：速度/TEN 带按真实规则；下界允许忽略约束（安全），但 PR2 目标窗口/PR3 可行性/PR7 若使用约束，必须使用**实际约束**（不能忽略）。
5. **上下界方向**：`L <= 真实最小值`、`R >= 真实最大值` 由精确输入计算/证明；`K_sum(B)` 由 frontier 的精确算法或安全下界给出（不得用未证明的上界）。
6. **语义**：严格改善 / tie 保留 / 身份保留显式声明（PR8 表）。
7. **精确算术**：`S3`、`L`、`R`、`K_sum` 与乘积全部整数/BigInt；浮点仅用于诊断。

### 10.2 使用对象（禁止混用）

| 用途 | 允许的规则 | 禁止 |
| --- | --- | --- |
| 真实域分支/候选剪枝 | PR1（收紧必要区域）、PR2 全局/目标窗口、PR3（真实域可行性）、PR4/PR5（严格模型）、PR6、PR7 | 用真实域 slab 去限制 `U`；用 target 窗口删 tie 方案 |
| 真实域枚举/区域跳过 | PR3（区域/切片） | 用于顶点/部分归约证书（必须覆盖所有切片） |
| free-budget `U` 计算 | 无（Lemma 1 只说明不变量） | 给 `U` 加 slab 约束缩小 U；因无真实点跳过切片 |
| frontier 必要区域 | PR1（Ω→Ω'）、PR4/PR6 的阈值 | 用面板值求 `Σ`；用未认证的 L/R |

### 10.3 安全回退（按顺序）

1. 任一输入前提失败（坐标不确定、食物公式不可认证、唯一性未建模、L/R 方向错误）→ **不删除任何东西**，回退精确求解/现有上界。
2. `L1` 无法计算（槽候选集为空、食物集合为空且食物必选）→ 说明模型无合法完成或输入非法，交由精确枚举/求解判定。
3. PR2/PR3/PR7 的可行性检查无法认证 → 只保留 Theorem 2 的下界（用于安全界的「不能改善」判定），不做可行性剪枝。
4. 目标类剪枝（PR4/PR5/PR6）在 tie/身份模型下自动禁用或切换非严格阈值；否则不剪。
5. 最终认证：任何保留/删除的候选/分支最终以 `candidateUpperBoundCannotImproveIncumbent` 或精确枚举核对；本文剪枝不替代最终认证。
6. 禁止经验阈值：所有 `L/R/K_sum` 来自当前输入与已证明公式；不能因为「剪得不够」引入 magic value（Issue 正文「不依赖 magic value」）。

## 12. 未解决问题

1. **`L1` 的紧致性**：`L1=59` 与真实 `min S=67` 的差距来自「逐槽 min」与「食物依赖 G」的联合优化；如何给出 slot+food 联合的精确最小和（非线性 `bonus_i(f,G_i)`）尚无一般算法/闭式界（本文只给安全下界与 ring 精确化）。
2. **约束下的 Lagrangian 对偶间隙**：§5.3 的 `max_ν LB_ν` 对可加约束安全但可能不紧；整数/非线性约束（食物贡献参与 TEN、速度带与 GCD 阶梯）下的更好下界未研究。
3. **PR2 的实用强度**：全局界形式只能证空分支；如何在分支上得到独立于全局界的**更紧**界（例如分段上下界、共享身份下的局部界）未研究。
4. **PR7 与联合目标的一般耦合**：本文只给可行性/条件目标窗；在 [joint-loss-sum-bound](../joint-loss-sum-bound/README.md) 的一般 trade-off 目标下，如何把逐职业「和」的下界转成联合损失界未研究。
5. **共享身份的形式化**：戒指唯一性/共享食物/共享方案的无序身份多重集如何在 `L/R` 与 PR 中精确定义（与联合搜索表示对齐）仍不完整（本文只用最简 ring 唯一性模型）。
6. **与 frontier 的组合**：PR1 的 slab 与 frontier 的 `D_min`/`K_w` 更新顺序、与 support 族的冗余消去未展开（frontier §12 有对应问题）。
7. **多个 `L` 来源的比较**：`L_gear`、约束下 Lagrangian、动态 `L_rem` 的取舍（哪个更紧、何时组合）没有理论最优选择，只是运行时 policy。
8. **性能**：本文不声明任何剪枝收益；实际剪枝量、预处理成本未评估（需按 issue 的 benchmark 清单另做）。
9. **食物可选/必选与共享食物的边界**：`F_allowed` 为空、共享食物交集为空等退化情形的精确失败语义需与生产规则核对。
10. **slab 上的紧凑 frontier**：PR1 的 `K_w(Ω')` 目前只能按 `(C,H)` 全枚举（成本 `(κ_C+1)(κ_H+1)`）；引入 `C+H=L−D`、`C+H=R−D` 反对角线后的最简 breakpoint 表示未推导（frontier §12 有对应开放问题）。
11. **数值实现边界**：BigInt/安全整数切换、`1e-7` 容差在食物加成与阈值反查中的复核属于实现侧验收（本文只登记前提）。

## 13. baseStat 影响审计（贡献坐标 vs 面板总值）

- **本定理的坐标**：`S3(c)`、`S`、下界 `L_gear/L_food/L1`、slab `[L,R]`、`K_sum` 全部是**贡献**坐标；面板总值 = 基础属性（CRT/DHT/TEN 为 `sub`、DET 为 `main`）+ 贡献，换算见 [canonical-evaluator-reference.md](../../canonical-evaluator-reference.md) §2.1。
- **baseStat 的影响**：下界/上界/剪枝全部作用于贡献和或贡献三元组；`baseStat` 只经 `value = baseStats + gearAndFoodValue` → `value − offset = G` 归约进入。正式候选路径 `G >= 0` 与档位实参非负是结构性事实（参考模型 §2.2），因此剪枝定理无需额外的面板坐标处理；食物下界 `bonus_i(f,0)` 中的 `0` 是**贡献 0**（面板值为 `base_i`），已在 `verify.mjs` 中按 canonical 食物公式断言。
- **误用风险**：把面板值当贡献计算 `L/R` 会得到错误方向（通常 `L` 过大 ⇒ 删合法点，不安全；`R` 过小 ⇒ 删合法点）；`verify.mjs` 的 `A.sum-bounds`/`L.direction` 段包含"面板值当贡献会删光"的反例（`L=1339>96`），以及逐属性 min 相加的安全但更弱对比（`44<=59`）。
- **结论**：本定理**不受** baseStat 影响（坐标本来就是贡献）；无定理/数值需要重证或重算。
