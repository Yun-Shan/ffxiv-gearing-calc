# 多职业联合搜索：模型与验收边界

## 目标和搜索范围

对职业 `c`，先在其完整输入候选和约束内求独立最优值 `OPT_c`，再最大化联合方案的归一化目标

\[
\sum_c \frac{D_c}{OPT_c}.
\]

`D_c` 与 `OPT_c` 必须采用相同目标及职业约束：`damage` 使用每威力伤害期望，`dps` 使用该值除以 GCD。不能把原始职业分数或对数目标相加来代替归一化和。候选域、领域约束及公式的来源见[领域与搜索规则](rules/领域与搜索规则.md)；最优性论证见[当前搜索算法最优性证明](当前搜索算法最优性证明.md)。

共享装备的模型表示必须能还原为各职业共同使用的同一物品及完整属性方案。只匹配各职业总属性而无法还原共同身份时不等价；能证明并还原共同身份的属性等价压缩可以使用。共享食物按物品身份绑定，但每个职业仍按自己的基础属性及规则计算效果。双戒指保留合法成对候选和 unique 身份约束；仅当戒指域满足等价条件时，联合模型才可把它表示为两个内部槽位。数学条件见证明文档的[戒指约束与可行域等价](当前搜索算法最优性证明.md#戒指约束与可行域等价)。

归一化求和只对正基线职业定义；底层入口不将零基线作为分母，其对应职业仍保留可行性和共享约束，且整数伤害因子与 GCD 仍须通过有效性校验。这不是用户可配置的职业权重。

联合问题可以通过连接各职业共享选择的整数模型求解，也可以固定共享身份后逐职业精确求解。共享装备组合单一或共享域能完整枚举时，无需联合 MIP；只有全部组合完成或达到已证明的全局上界时才能结束。没有共享槽位或存在未参与归一化求和的职业时，采用外层分支限界，以放宽尚未确定共享约束后的归一化上界之和剪枝。两种表示都必须保持相同目标与可行域。

固定点对数仅用于安全缩小仍可能改善当前方案的因子签名集合；返回前仍按实际候选重建装备与属性，并用 BigInt 精确比较归一化目标之和。

## 证明和数值边界

搜索的全局最优结论以三个条件为前提：候选集合和模型表达同一有限问题；共享身份、游戏约束及属性重建一致；整数模型求解器的最优/不可行状态正确。因子误差带、联合比例和的必要条件、支配剪枝和戒指域等价的推导见[当前搜索算法最优性证明](当前搜索算法最优性证明.md)。

HiGHS 在浮点数上求解。实现会校验整数解、模型约束、重建属性及因子，并以 BigInt 比较最终目标；这些检查证明返回方案可行且目标计算一致，不能独立证明求解器没有漏掉更优解。因此当前结果是以求解器状态可信为前提的条件最优性结论，没有独立可验的最优性证书。小规模穷举对照用于验证模型和实现，不能替代大规模实例的形式化证书。

## 验收计时

Node 验收在全部职业的装备候选准备完成后开始搜索计时，计入职业独立基线、共享方案构造、联合搜索、食物选择和最优性复核。验收入口对 Worker 启动及结果传输施加总时限；超时或证明未完成必须标为未完成，不得作为近似最优结果返回。正式前端搜索没有固定搜索时限，用户可以主动取消。

当前验收场景、具体参数、命令、资源保护及性能判定均以[搜索耗时优化说明](search-optimization/README.md)和其验收记录为准；本文不维护另一份场景清单或时限数字。
