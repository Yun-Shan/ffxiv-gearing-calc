回调形态因搜索阶段而异：HiGHS 通常较快报告首个可行 incumbent；CP-SAT 在 RPR、SAM 和 VPR 基线更早抵达最终 incumbent，但 MCH 更晚。RDM/PCT 因精确 GCD 区间，限制后的额外 MIP 也参与总时长。VPR/MCH 联合不可行性证明阶段，HiGHS 每秒级中断回调持续提供界和节点数据，共 104 次 bound 事件，并最终报告不可行；CP-SAT 8 workers 在耗尽总时限前没有发出该阶段的 solution 或 best-bound 事件，且本次关闭了日志事件。两者回调次数不能直接互相比较：HiGHS 有周期性进度快照，CP-SAT 的 best-bound 事件由界改善触发；HiGHS 的节点数和 CP-SAT branches 也不是同一个计量单位。

本轮性能对照当时保留 HiGHS 作为正式默认后端，并把 CP-SAT 留作同候选集的可选验收后端。CP-SAT 单 worker 对 RDM/PCT 与 RPR/SAM 有优势，但 VPR/MCH 的联合尾段更慢且八 worker 峰值内存约为 HiGHS 的 2.7 倍。上述耗时和内存是含回调的单次实测，不构成对其他硬件、候选或运行次数的性能保证。

## 2026-10-03：联合 MIP 内部拆分戒指槽

在 VPR/MCH 同候选场景中，将联合 MIP 内部的一个 pair 槽拆为两个戒指 one-hot 槽，并用每个 unique `itemId` 的跨槽和约束排除重复 unique 戒指。只有 pair 域通过完整有序笛卡尔积、属性可加性和完整 unique 元数据检查时才启用；其余情况仍使用 pair 模型。UI、单职业候选和最终返回结构继续使用原戒指对。

新候选哈希为 `ca933fce10153366ee043fa43b7ae62b83e4cd991bd6be81b5f242cf45570efd`。与旧哈希 `bd75ded55d9522e7e68b1f9c72682074c72ff89cf958e0a7b9cc3a4e0cdde450` 的候选导出逐字段相同，差别仅为新导出增加了 `ringUniqueByItemId` 元数据；去掉此字段后 JSON 完全一致。目标、候选组合、共享槽、食物、DPS 及计时方式均相同，HiGHS 归一化目标仍为 `4742535/2371792`。

这组实测说明，pair 拆分减少戒指选择变量并缩短了 HiGHS 的联合证明阶段，但总变量反而增加，说明拆分会扩大部分属性线性化范围，不能只凭变量数预测速度。HiGHS 从 133.848 秒降至 118.775 秒，改善约 11.3%；CP-SAT 8 workers 把单职业阶段提前到约 48 秒，但联合无改进证明仍超出总时限。新结果通过同一新候选缓存的 HiGHS 与 CP-SAT 重放得到。

## 2026-09-29：精确 MIP 搜索

本节记录的是目录拆分前的旧单 worker HiGHS 精确 MIP 验收。该模式把每个槽位和食物建成离散选择变量，按 V2 规则约束食物取整/封顶、GCD、坚韧及最高坚韧目标；伤害因子使用固定点对数作为 MIP 目标，并用 BigInt 精确复核候选，直到剩余因子签名低于可证明的误差界。旧求解器未证明最优、超过时限或触及 RSS 保护线时会停止且不返回近似结果。旧运行材料与手动复现说明保存在 `scripts/archive`。

- 旧搜索时限默认 `115000ms`，参数名为 `DATA_TEST_EXACT_TIMEOUT_MS`，上限为 `115000ms`。
- 旧搜索进程 RSS 达到 `3.5 GiB` 时停止；MIP 在独立 worker 中运行，V8 老生代限制为 `2560 MiB`。
- 不生成或读取预先打表文件；候选因子区间在运行时构建。
- 显式设置 `DATA_TEST_ALGORITHM=v2` 会运行旧 V2 搜索；它仍是近似搜索，不能据此声称严格全局最优。多 worker 也仅支持 V2。
