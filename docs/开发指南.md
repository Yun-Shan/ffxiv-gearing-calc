# 开发指南

本文面向开发与维护；产品介绍和在线使用入口见 [README](../README.md)。下文命令均在仓库根目录执行，源码路径也以仓库根目录为基准。

## 实现概览

纯前端的 FFXIV 自动配装优化器，使用 React、Base UI、TypeScript 与 TanStack Router。单职业与同组多职业联合搜索支持装备/食物筛选、同步、装备锁定、GCD 和坚韧约束，以及共享装备与镶嵌。联合目标按各职业单独最优基线归一化；搜索完成最优性复核后返回结果，支持进度、取消及本地历史。仅成功完成并进入结果页的搜索保存到本地历史，进行中、取消、失败及无可行结果的搜索不计入历史。历史记录支持单条删除，以及按单职业或多职业类型清空。

业务行为与候选域见[领域与搜索规则](rules/领域与搜索规则.md)；界面方向和文字版风格参考见[前端设计总览](前端设计总览.md)。

领域计算支持装备特殊效果 `ItemSpecialBonus=11`：当前驯兽师固定启用，其他职业不启用；调用方传入的效果启用列表暂由该职业规则覆盖，不提供界面设置。

强制装备支持只锁定物品 ID、逐孔固定魔晶石并自动优化其余孔位，或固定完整的自定义参数。曼德维尔及义军参数在确认后进入搜索条件，随条件快照保存和恢复；自动设置继续由搜索分配。

## 页面与功能

- 装备选择框支持按名称、品级或来源搜索。
- 装备表的物品名称可点击，浮层提供中文维基和 Garland 数据链接。
- 导航“支持与反馈”和常见问题中的“反馈入口”打开同一个反馈弹框，提供 GitHub Issues 入口。
- 强制装备支持从 Asvel 配装分享链接识别、预览并确认导入，保留合法镶嵌和自定义参数；联合条件按共享或职业私有槽位自动筛选。
- 排除来源支持在选择框中直接输入来源路径搜索，弹层保留树形分类；筛选时的分类勾选只作用于匹配来源，并保留其他已选来源。
- `/`、`/single`：同一单职业选择页；单职业条件、进度和结果分别位于 `/single/conditions`、`/single/progress`、`/single/result`。同步结果支持同属性装备替换并回写同一历史记录。
- `/lab`：实验室入口；`/joint` 为多职业联合选择页，条件、进度和结果分别位于 `/joint/conditions`、`/joint/progress`、`/joint/result`。种族、装备品级范围与同步目标为全职业共享条件，各职业单独设置 GCD、食物与坚韧条件。
- `/gear-comparison`：同职业最多四方案对比，可从 Single/Joint 已完成历史或完整 Asvel 分享链接添加。导入按当前数据计算固定配装，保留合法镶嵌与自定义参数，不启动搜索或新增历史；链接中不在当前数据目录的装备按空槽处理，拒绝整套导入。装备表区域允许滚动查看全部内容。
- `/faq`：常见问题；每条问答使用同一组件展示，列表在容器内滚动。
- `/about`：关于；列出项目使用的参考项目、数据与图标来源以及主要依赖。
- 结果页“分享配装结果”可复制链接或图片。分享链接使用部署根路径并附带 `?s=...`，地址栏保持部署根路径和查询参数，页面内部显示普通单职业或联合结果；刷新时优先读取分享 token。离开分享结果进入条件、选择或其他页面时移除分享参数；分享结果不重跑优化器或新增历史，未知来源沿用确认流程；解析或恢复失败时显示与启动外壳同样风格的独立错误页，在淡色框内直接显示灰色、自动换行的错误详情，并提供返回首页操作。
- 结果食物包含各项上限、比例、实际增益和真实利用率；单职业与多职业高级设置共用同一对话框，目前无实际设置项。

界面结构与滚动边界见[前端设计总览](前端设计总览.md)，交付验收要求见[工程规则](rules/工程规则.md)。四方案容量合成预览仅在开发环境 `/gear-comparison?ui-preview=comparison-capacity` 启用。

## 路由与刷新

所有环境使用浏览器 History 路由，不支持旧 hash 地址。`/` 与 `/single` 都显示单职业选择页且不相互跳转；未知路径回到 `/`。工作台阶段进入浏览器历史，成功搜索以结果页替换进度页，取消或失败回到条件页。离开进度页会取消搜索，浏览器前进或后退不会自动重启搜索。

单职业和联合工作台使用 `sessionStorage` 恢复当前工作台当前页面的已提交条件或完成结果；同一工作台切换阶段保持连续，离开工作台后清除恢复数据。浏览器前进或后退进入条件页时优先保留现有条件 Draft；缺失时从当前结果对应的冻结条件快照重建，不读取可能已被覆盖的最新历史记录。“调整条件”按钮仍从当前结果快照建立新的条件草稿。刷新进度页回到条件页，不保存或恢复运行中的搜索；没有对应状态数据时回到该工作台的选择页。损坏或 schema／数据版本不匹配的数据会清除并提示；存储失败不阻止使用或搜索，并提示刷新恢复不可用。常见问题、关于、实验室和装备对比等非工作台页面不恢复工作台状态。

## 开发

```bash
npm install
npm run dev
npm run build
npm run preview
```

页面与浏览器计算 Worker 由同一次 Vite 构建输出，公共模块复用同一份 JS。`scripts/vite-compute-worker.ts` 负责 Worker 入口 URL、共享动态导入的环境兼容和预取资源清单。清单自动覆盖构建后的异步 JS、Worker 及其关联 CSS、WASM 和其他导入资源，包括分享图片模块。正式页面成功挂载后空闲、低优先级预取，跳过已加载资源；此文件预取不执行 JS、应用 CSS 或初始化 WASM，开发服务保持原生按需加载。截图模块和分享图片布局另在单职业或联合结果页完成路由渲染后的空闲时间导入执行，生产与开发环境共用；同一页面运行期间复用初始化任务，失败静默处理并允许后续重试。升级 Vite 时需运行该插件的回归测试，并验证生产构建的 Worker 加载、分享图片模块与样式、WASM 按需初始化、后台预取和 Pages 子目录路径。

文件路由由 `@tanstack/router-plugin` 从 `src/ui/app/routes` 生成 `src/ui/app/routeTree.gen.ts`；不要手工编辑生成文件。`npm run build` 先运行 Vite 以生成路由树，再运行 `tsc -b`，因此干净检出也会先生成 TypeScript 所需的路由类型。当前不启用路由自动代码拆分，现有 Worker 构建与预取行为保持独立。

## GitHub Pages 部署

部署流程由 [GitHub Pages 工作流](../.github/workflows/deploy-pages.yml)管理。首次使用需在仓库 Settings → Pages 将 Source 设置为 GitHub Actions。

流程使用 Node.js 24、`npm ci` 和 `npm run build`，构建后将 `dist/index.html` 复制为 `dist/404.html`，再上传 `dist` 并部署到 `github-pages` 环境，无需个人访问令牌。所有环境均使用浏览器 History 路由，静态站点 fallback 支持刷新和直接打开页面。

部署基路径统一由根目录 `index.html` 中的 `<base href="/">` 设置，默认部署在 `/`。需要部署到子目录时，由部署方在构建前手动改为例如 `<base href="/ffxiv-gearing-calc/">`，然后重新构建；GitHub Actions 不会自动推导或覆盖该路径。基路径必须以 `/` 开头和结尾，不得包含域名、查询参数或 hash。Vite 开发服务、构建资源路径、页面路由、刷新恢复存储和分享链接均使用这一配置。

## 验证与性能验收

按[工程规则](rules/工程规则.md)选择与改动相关的检查：

```bash
npm test
npm run test:coverage
npm run test:domain:coverage
npx vitest run src/ui
npm run test:data
npm run test:v3:runner
npm run data:test:v3
```

`test:domain:coverage` 对领域生产代码的语句、分支、函数和行执行 90% 门槛；仅排除类型声明、测试及 Worker/环境传输适配器，具体范围由 `vitest.domain.config.ts` 固定。覆盖率门槛与正式搜索验收是不同检查，不能用测试命令成功代替覆盖率达标或完整证明。Node 测试和多职业验收的配置见[运行说明](../scripts/node-tests/README.md)。

全场景性能验收：

```bash
node docs/search-optimization/tools/run-acceptance.mjs
```

场景筛选、时间保护、计时边界、历史对比和产物说明见[性能验收说明](search-optimization/README.md)。浏览器正式搜索不设时限，Node 验收的保护时限不等于产品性能目标。

## 更新数据

来源、回退条件和版本要求见[数据规则](rules/数据规则.md)。统一命令先准备并固定参考项目 commit，再查询 MCP，在内存中校验和合并资料，直接生成最终二进制文件：

```bash
npm run data:update
```

首次更新数据前，将仓库根目录的 [`local.env.example`](../local.env.example) 复制为 `local.env`，填写 Lumina MCP 可执行文件、游戏目录与 EXDSchema 目录。`local.env` 已被 Git 忽略，本机实际路径仅保存在该文件中；不要提交它。

```powershell
Copy-Item local.env.example local.env
```

更新器和 MCP 查询模块会自动从仓库根目录加载 `local.env`，无需手动导入；已有系统/进程环境变量优先于文件，调用方显式传入的查询选项优先于环境变量。必需路径缺失或为空时会明确报错，不再使用机器专属的默认目录。普通开发、构建和离线测试不要求该文件。

查询启动顺序固定为 `initialize → refresh_schema → health → Schema／数据查询`；只有刷新明确返回 `refreshed: true` 才继续，失败时保留原产物。游戏版本直接取同批 MCP 检测结果，不手工改写版本文字。

| 环境变量 | 用途 | 默认值 |
| --- | --- | --- |
| `FFXIV_MCP_LUMINA_COMMAND` | Lumina MCP 可执行文件路径 | 必填 |
| `McpLumina__GamePath` | 游戏安装目录 | 必填 |
| `McpLumina__SchemaPath` | EXDSchema 目录 | 必填 |
| `FFXIV_GEARING_ROOT` | 参考项目检出目录 | 仓库内 `reference/ffxiv-gearing` |
| `FFXIV_MCP_LUMINA_CONCURRENCY` | MCP 批量查询并发数 | `4` |
| `McpLumina__LanguageDefault` | MCP 默认语言 | `chs` |

路径包含空格或 `#` 时用引号包裹；Windows 路径可使用正斜杠，避免转义歧义。脚本使用 Node 原生环境文件和 TypeScript 加载，需使用支持这些功能的现代 Node（部署构建使用 Node 24）。

参考项目默认检出到 `reference/ffxiv-gearing`，可用 `FFXIV_GEARING_ROOT` 指定其他本地检出。查询和编码在同一次更新中使用相同 commit；所有必需资料及完整产物校验通过后才替换原 bin，失败保留原产物。只保存最终 bin，不再保存查询 JSON、支持旧快照离线重生成或增量补字段。开发、构建及部署直接使用已提交的 bin，不启动 MCP。

装备是否采用 HQ 属性以同版本 MCP `Item.CanBeHq` 为准，伤害类型按适用职业的 `ClassJob.PrimaryStat` 选择。领域统一使用该字段生成的 `mainStat`，不再保存独立 `attackStat`；角色分组取自 `ClassJob.JobType`，未知类型要求先定义新的 Type 类型。受支持的 `ItemSpecialBonus=11` 附加属性仍独立保存并按领域规则启用。

同步面板支持仅等级或具体品级目标，按品级/副本共享生成目录，自定义品级至少 90 且须有完整属性上限。来源与目录生成见[数据规则](rules/数据规则.md#同步等级与副本目录)，计算语义见[领域与搜索规则](rules/领域与搜索规则.md)。

运行时产物为 `src/data/generated-data.bin`，包含十个业务段，保留装备获取途径和全局摘要（游戏版本、参考仓库、commit、导入时间）。逐项溯源、查询范围、版本警告及资料缺失核验证据仅在生成时于内存中核验，不写入 bin。格式字段由 `src/data/binary` 下的 TypeScript Schema 定义，见[格式规范](运行时数据二进制格式.md)。`npm run data:format` 生成字段文档，`npm run data:format:check` 检查文档与 Schema 一致；`npm run data:benchmark` 测量数据加载与解码。

装备、食物与职业图标统一使用 `GameIcon` 组件，调用方只传物品 ID 或职业 ID 和样式类。组件读取 bin 中物品的 `icon`，或职业数字 ID 加 `62100`，从 XIVAPI CDN 跨域加载 PNG。没有独立图标 JSON 或本地职业 PNG。
