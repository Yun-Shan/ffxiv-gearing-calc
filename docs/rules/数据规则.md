# 数据规则

## 事实来源与查询时机

- 禁止在生产中虚构、合成、近似或使用演示游戏数据。合成对象仅可用于隔离测试，生产代码不得访问。
- 游戏资料优先使用对应 MCP 的目标版本结果；只有确认服务器缺少目标资料或必要查询能力、且不是名称或方法错误时，才可回退到 [Asvel/ffxiv-gearing](https://github.com/Asvel/ffxiv-gearing)。记录缺失项和回退位置，不能因参考项目更方便而跳过 MCP。
- 新增或改变对游戏数据、字段语义、外部 API 或底层结构的理解，以及更新生产数据前，必须查询对应 MCP。纯重构、文档整理和不改变事实依据的回归维护可复用已确认且版本适用的来源；有版本疑点时重新核实。不得凭记忆编造字段、行 ID、枚举、签名或偏移。
- 本地快照是带来源的查询产物，不能冒充实时 MCP 结果。实际查询保留服务器、查询范围、字段和行、时间及版本。
- 全量生成 bin 时，连接 Lumina MCP 后必须先调用 `refresh_schema`，等待工具明确返回刷新成功，再执行 `health`、Schema 与数据查询；刷新失败或未明确成功时中止，不继续查询或替换原产物。

| 资料归属 | 查询服务器与方式 |
| --- | --- |
| `Lumina.*` 游戏 Sheet | `ffxiv-mcp-lumina`；结构用 `describe_sheet` / `list_sheets`，行及枚举用 `get_row` / `get_rows` / `search_rows` 或便捷查询 |
| 实际引用的 `Dalamud.*` API | `ffxiv-mcp-dalamud-api`；服务、类型与成员查询 |
| 实际引用的 `FFXIVClientStructs.*` | `ffxiv-mcp-clientstructs`；类型、命名空间及字段布局查询 |

先确认归属，不确定时先搜索；三类资料不得相互替代。职业行须通过职业缩写查询发现，再批量读取，不能硬写记忆中的 row ID。

## 版本与可追溯性

- 生成阶段按数据项核验来源。MCP 至少在内存中提供服务器、Sheet/类型/成员、查询范围、查询或导入时间及可取得的游戏/文档版本；参考项目至少提供仓库 URL、精确 commit、导入时间和源文件清单。最终 bin 只保留全局摘要（游戏版本、参考仓库 URL、精确 commit、导入时间），不保存逐项溯源字段或查询证据；装备获取途径属于业务字段，继续保留。
- 来源不一致时，先核对游戏版本、MCP 数据/文档版本和参考 commit。同版本且 MCP 可覆盖时以 MCP 为准；版本无法对齐时失败或隔离，禁止静默混成一批生产数据。
- `GameVersionMismatch` 仅因验证版本滞后时，只有服务器明确声明通用查询不受影响、Schema 可用且没有其他降级原因，才可用同一检测游戏版本的通用查询更新快照。保留检测/验证版本、原始警告和可用性声明，并由导入器复核；该例外不适用于便捷接口。
- MCP 与参考项目都缺少必需资料或格式错误时明确失败，不以内置默认值、旧值或近似数据继续运行。

## 导入与运行时产物

- MCP 查询由 `scripts/query-mcp-lumina.mjs` 作为更新器的模块在内存中返回，经完整校验后投影为运行时业务数据并直接编码；不保存查询 JSON 或其他原始查询档案，不能从聊天文本手抄查询产物。查询范围、字段、版本、时间、警告及必要的能力核验证据仅用于本次生成校验，因此不支持旧查询结果的离线重放或增量补字段。
- 上游解析、校验与生成由 `scripts/update-data.mjs` 统一编排。参考项目先准备并固定 commit，再查询同次所需 MCP 资料；所有生产来源经该入口统一生成 `src/data/generated-data.bin`，禁止手工编辑生成文件。
- 运行时使用单一无压缩二进制快照，浏览器、Worker 和 Node 共用解码契约。布局与校验以[二进制格式规范](../运行时数据二进制格式.md)为准，不在其他规则中复制字段和索引结构。
- 运行时编码保留装备 ID、物品图标 ID 的 u32 范围；装备普通与特殊属性、品级上限及食物固定加成使用 u16，食物比例直接使用 u8。生成阶段遇到负数、小数或超范围值明确失败，不截断、近似或钳制。去重仅改变存储表示，必须完整恢复原业务字段和数值。
- 装备和食物的 `icon` 来自同版本 MCP `Item.Icon`，随物品写入 bin；职业基础目录保存同版本 `ClassJob` 的数字 ID、`Name` 和 `Abbreviation`，职业图标 ID 按数字 ID 加 `62100` 获取，不维护独立图标 JSON。
- 同步规则与副本目录使用同版本 MCP 全量查询统一生成；筛选与合并规则见下文。运行时只保存等级规则及分类后的名称和同步目标，不保存原始类型 ID、成员 ID、排序 ID、分类枚举或独立品级及说明表。原始资料、查询范围与逐项来源仅用于本次内存校验。
- 生成阶段校验业务字段、来源、引用和排序；读取阶段拒绝文件损坏、不支持的格式或越界结构，并统一检查属性上限表完整性，不重复维护同步分类名称及顺序，不读取旧 JSON 或演示数据兜底。
- 游戏数据 bin 的数据版本号直接保存生成所用 MCP 游戏版本，不拼接参考提交、策略或结构标签；参考提交等溯源信息单独保留在 provenance 中。界面版本值统一读取该 bin 的版本，仅在结果页显示，不用于历史记录的业务判断。
- `Item.Name` 为空或仅含空白时视为已移除，导入时排除，不参与后续计算；不得用参考项目旧名称恢复。名称字段缺失或格式错误必须失败。
- 参考装备标记 `obsolete=true` 时，来源统一映射为“已废弃”，覆盖原来源或缺失来源。装备二进制生成使用最终归一化的穿戴等级与品级，排除同时满足穿戴等级低于 50 且品级低于 90 的装备；等于任一阈值时保留。不为此迁移旧历史记录。
- 参考项目原始来源包含“古董系列”或“军票”的装备一律排除；按来源映射前的原始文字判断，即使标记 `obsolete=true` 也排除。
- 来源映射优先处理 `obsolete=true`；其余来源以“→诗学”或“/诗学”结尾时统一为“点数/诗学”，以“→战利品”“→兵团”“→同盟”结尾时依次映射为“怪物狩猎战利品”“兵团徽章”“同盟徽章”。其他来源保持原文。
- 来源以“→雇员探险”结尾时映射为“雇员探险”；完整来源“点数/哲学→无限城古迹、日影地修炼所、野营地”映射为“迷宫挑战/无限城古迹、日影地修炼所、野营地”。同样保留 `obsolete=true` 的优先级。
- 运行时保留完整食物目录，供分享链接导入与固定配装计算使用；只在搜索候选生成时保留暴击、信念、直击三项至少包含其一的食物，并按固定值与比例的全属性支配关系做帕累托剪枝。速度坐标（技速/咏速的固定值与比例）不同的食物互不支配，避免在速度上限或精确 GCD 条件约束下丢失可行候选。
- 装备的 HQ 选择由同版本 MCP `Item.CanBeHq` 决定，不再读取参考项目的 `hq` 标记。`CanBeHq=true` 时，将 `BaseParamSpecial` / `BaseParamValueSpecial` 的附加属性与基础属性合并为装备 `stats`，候选只保留这一 HQ 版本；为 false 时只保留基础属性。字段缺失或不是布尔值时生成失败，逐件来源必须包含同版本 `Item.CanBeHq` 查询记录。运行时二进制与历史结果不保存 `hq` 标志，因此不能再区分或标注 HQ。下述受支持特殊效果沿用独立属性规则。
- 职业主属性统一来自同版本 MCP `ClassJob.PrimaryStat`，按 BaseParam ID `1/2/4/5` 分别生成领域 `mainStat=STR/DEX/INT/MND`，不再保留独立 `attackStat`。缺失、不是整数或不支持的 PrimaryStat，以及缺少同版本 Schema、职业行和查询范围来源时生成失败；不从参考职业或装备属性推断。装备的伤害类型由 MCP 职业分类确定适用职业，再按其主属性判断：`INT/MND` 对应 `MDMG`，`STR/DEX` 对应 `PDMG`。需要选择伤害类型的装备若同时适用物理和魔法职业，必须明确报错并列出物品 ID 与职业，要求添加该物品的硬编码伤害类型映射；无伤害属性的通用防具不涉及类型选择。武器原生伤害、BaseParam 中的伤害属性、HQ 附加伤害与独立特殊效果使用同一类型选择，选中类型的原生零伤害必须保留。
- 角色分组来自同版本 MCP `ClassJob.JobType`：`1` 为防护，`2/6` 为治疗，`3` 按 PrimaryStat 分为力量或灵巧近战，`4` 为灵巧远程，`5` 为智力远程；青魔法师与驯兽师遵循其实际 JobType，不设限职兜底。仅支持 `1` 至 `6` 六种已定义类型，缺失、非法或超出范围时明确报出职业与原值并要求先定义新的 Type 类型；已知 JobType 与 PrimaryStat 不相容时也必须失败。角色不从参考属性列表推断，原始 JobType 只用于本次生成与来源核验，不另存运行时字段。
- MCP `Item.ItemSpecialBonus` 当前仅支持 ID `11`。生成时为该 ID 保存 `ItemSpecialBonus`、`ItemSpecialBonusParam`，并按 HQ 使用的 `BaseParamSpecial` / `BaseParamValueSpecial` 字段提取独立 `specialStats`；ID 和参数来自同版本 Item 查询，ID 11 的描述通过 MCP `ItemSpecialBonus` 行查询核验，查询范围与来源仅用于本次内存校验。ItemSpecialBonus 为 11 的属性不并入普通 `stats` 的 HQ 合并，避免启用该效果时重复累加；其他装备继续使用既有 HQ 合并规则。所有 Item 行都必须带有有效的 ItemSpecialBonus ID 和参数，缺少字段时生成失败，不能默认按 0 处理。

## 同步等级与副本目录

- 同步资料使用同版本 MCP 的完整 `ContentFinderCondition`、`ContentType`、`ContentUICategory`、`ParamGrow` 和 `ItemLevel` 查询。支持等级取项目公式参数，等级默认品级取 `ParamGrow.ItemLevelSync`；同步映射不与参考项目分组或预测值逐值核对。
- 等级下界从完整有效 `ContentFinderCondition.ItemLevelSync/ClassJobLevelSync` 与 ParamGrow 对应值生成，不用 `ItemLevelRequired`，不受副本展示筛选影响。50 级下界固定为 90；来源中低于 90 的品级不纳入支持域，不因此判为坏资料。生成时拒绝品级归属冲突及区间顺序与观测等级不一致。
- 副本目录要求名称非空、`JournalGenre` 非零且同步等级受支持。根据 `ContentType`、`HighEndDuty` 和 `ContentUICategory` 识别极神、幻巧与零式，纳入绝境战、诛灭战和斗兽奇弈；排除普通讨伐、普通八人和普通 24 人任务。`AllowUndersized=true` 的排除只用于特殊迷宫探索。
- 特殊场景探索按 `ContentLinkType=3`、`ItemLevelSync>0` 及基础展示条件识别，统一归入“特殊场景探索”，不维护区域类型白名单。显式同步品级大于零时生成品级目标，否则生成仅等级目标，包括最高等级；低于 90 的显式品级不进入目录。
- 仅在目标类型和值均相同时合并：讨伐歼灭战的仅等级项目合并为“XX级极神”，显式品级项目保留；大型任务零式按首个普通空格前的名称合并；特殊迷宫探索去掉开头“零式”后按完整名称合并，组内包含零式时加“(零式)”前缀；特殊场景探索按 `ContentType.Name` 合并。
- 分类内按最高成员 ID 倒序，生成后丢弃 ID；大分类顺序由生成器统一维护。输出名称和目标已是展示成品，UI 不重新解释游戏字段或执行名称合并。属性上限完整性与运行时格式校验见[二进制格式规范](../运行时数据二进制格式.md)。

## 必须保留的来源边界

- 装备适用职业以 MCP 的 `Item.ClassJobCategory` 及对应分类行作为依据；参考分类可帮助确定待查询装备，不能覆盖该职业适用性，也不要求参考分类 ID、文字或集合与 MCP 一致。
- 职业名称、角色、主属性和原生属性修正取自 MCP `ClassJob`；副属性、GCD/特性/队伍公式、等级上限及默认品级范围由参考职业 schema 补齐，按字段记录来源。限职也须核验其职业与盾牌能力，不能沿用旧职业总数限制。族群基础属性表同样来自参考项目 `clanStats`，种族与族群名称按同一索引顺序保存。
- 青魔法师 INT 对应的魔法武器伤害加值映射，只有在生成阶段于内存中核验 Sheet 清单及 `ClassJob` 结构证据、确认 MCP 无对应资料后，才可从参考导出和原始测量文本导入；须逐值一致且为非负安全整数，不可截短、近似或缺失兜底。
- 自定义参数武器必须分别确认其参数表。参考项目的 `customizable` 标记只作别名溯源，不能代替 MCP 参数主键；不能因字段相似而合并不同参数表。已确认必需表缺失、或有效主键与参考别名完全无交集时明确失败。
- 查询与导入必须涵盖已接入的参数表及其引用物品。非必需查询缺口可记录后继续，但须有引用关系依据，不能凭空补行或忽略必需参数。

更新命令和环境配置见 [README](../../README.md)；运行时版本与全局摘要以最终生成产物为准。查询范围、缺口和逐件来源在本次生成中核验，不在规则或长期产物中维护副本。
