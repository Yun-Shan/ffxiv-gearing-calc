# 工程规则

## 架构与编辑

- React、Base UI 和浏览器服务不进入 `src/domain`。除模块加载时的严格数据校验外，领域函数保持确定性、无副作用；UI 复用领域结果，不重写游戏公式。
- 上游数据解析归统一更新脚本；Node 测试与验收包装调用正式领域逻辑，不另写搜索算法。`scripts/archive` 不作为当前入口，不参与生产构建或正式验收调用。
- 优先扩展已有类型与纯函数，仅在消除真实重复或隔离稳定规则时增加抽象。保留无关用户改动，避免大范围格式化；注释解释不直观规则和取舍。
- 新增或修改 Base UI 用法前查阅[官方 AI 文档索引](https://base-ui.com/llms.txt)及对应组件文档，确认实际 API。

## 前端代码组织

- `src/ui/app` 放应用容器、应用样式和测试；`pages/<page>` 放页面和私有组件；`components/<component>` 放跨页面共享组件；`services` 放浏览器存储、前端状态保存及应用配置等非领域服务。
- 各组件模块使用独立目录，入口、样式及私有资源相邻。仅供页面或单一组件使用的子组件放其 `components` 子目录，可继续嵌套，不提升为全局共享组件。任何 `components` 目录不直接堆放组件文件。
- 页面和组件样式使用所属目录的 SCSS Modules。
- 全局 SCSS 仅放基础规则、设计 token 和确实共享的样式，避免用 `:global` 穿透其他组件。
- 编译期颜色、字号 token 放 `src/styles/_tokens.scss`，以 Sass `@use` 引入且不输出 CSS；需要运行时继承或覆盖的值使用 CSS 自定义属性。
- 文字版视觉风格参考见[前端设计总览](../前端设计总览.md)；界面交付与浏览器验收按本文的界面契约、验证要求及用户确认执行。

## 界面与滚动契约

- 页面结构、内容和流程以[前端设计总览](../前端设计总览.md)、本文界面契约及用户后续确认为准，局部视觉风格参考[前端设计总览](../前端设计总览.md)的文字描述。
- 工作台用 phase 区分选择、条件、进度和结果；Draft 仅在条件阶段可变，搜索及结果使用冻结 Snapshot。页面专有 controller/组合留 page-local，跨页条件、装备事务和历史语义放 features。
- 输入、选择、Field、Tabs、Checkbox 与浮层优先复用项目通用组件及 Base UI；UI 不复制领域计算。高级设置入口统一打开应用层同一个 modal。
- 应用壳拥有视口高度，子页面继承剩余空间。History、超长 tabs、选项列表及装备限制列表按自身语义滚动；装备对比的装备表允许滚动，完整保留最多四方案的行列，不以完整 fit 作为容量通过条件。不得靠裁切隐藏数据或主要动作。
- 不恢复旧全局控件 class、`:global` 穿透或遗留 `@media` 补偿布局。表格与指标容器字号是已确认的动态字号用途，可使用容器单位及 `clamp()`；不因此扩展未确认的响应式设计。

## 验证按影响选择

| 改动 | 所需验证 |
| --- | --- |
| 纯文档、规则重组 | 规则一致性、相对链接、阅读入口；skill 另做结构和触发范围校验 |
| 数据来源、导入器、运行时格式 | 重生成受影响快照，数据校验、相关回归与构建；全局数据/格式变化须验证完整产物与消费者 |
| 公式或领域规则 | 确定输入输出的回归、受影响领域测试与构建；涉及候选或搜索时增加对应验收 |
| 搜索实现 | 小模型穷举或等价性回归、受影响正式场景；公共候选、目标、共享身份或证明路径变化须覆盖相关组合，广泛影响时运行全场景验收 |
| 搜索性能策略 | 公平的正式路径对照，保持候选、约束、输入版本及证明口径一致；全局策略变化运行全场景性能验收 |
| 前端实现 | 受影响交互、状态和构建；较大界面变更按界面契约、文字版风格参考及用户确认核对真实浏览器交互、几何与截图，小修复采用相称检查 |

- 无关的数据与逻辑不变时，不要求重新查询 MCP 或重生成游戏快照。需要再生成时的命令见 [README](../../README.md)。
- 纯领域逻辑的语句、分支、函数、行覆盖率门槛分别为 90%。报告实际统计范围、排除项和未达项；命令成功不等于覆盖率达标，不沿用某次合并的临时豁免。公式测试不能只断言结果大于零。
- 相关检查通过后不机械重复扩大全套验证；新增失败或未解决风险时再扩大。未完成的测试、搜索或证明必须明确报告，不能以超时保护或已有可行解充当通过。
- 重大或高风险改动采用独立复核；普通小改动无需固定的多代理审批链。多人编辑时划清文件所有权，主代理负责整合与最终核验；具体协作方式见 [Astra skill](../../.agents/skills/astra-orchestrator/SKILL.md)。

## 性能验收

- 跟踪目标为每职业 30 秒，单职业也计入，即 `30 × 职业数` 秒；它是优化目标，不改变候选、约束、最优性要求或前端运行时限。
- 结果合法性、完整证明、输入一致性、历史结果下限、耗时比较与超时保护分别判断。历史运行保留当时口径；不把不同输入或未完成运行宣称为公平提速结论。
- 计时边界、保护参数、场景与历史基准以[性能验收说明](../search-optimization/README.md)及受版本控制的运行配置为准。当前场景阈值不复制到一般项目规则中。

## 文档维护

- 当前规则分别在数据、领域与搜索、工程文档维护；`AGENTS.md` 仅保留入口和全局底线，README 维护能力摘要与命令。改变规则、来源或边界时更新对应规范；改变命令或用户能力时更新 README。
- 顶层设计说明稳定职责、关键契约和取舍；格式规范保留消费者需要的精确契约；证明保留假设、论证和数值限制。函数清单、逐步调用、策略常数及能直接从代码读出的说明不另建副本。
- 历史决定无后续解释或验证价值时删除；仍支撑基准、回归或取舍的证据保留，并标注范围。生成验收产物不手改，不为了文档整理删除仍被验收引用的基准。
- 用户要求与当前规则有实质冲突时，说明冲突和影响并确认；用户已明确要求改变该规则时，说明调整后即可实施，不重复索取相同授权。尚未澄清的实质冲突保持原行为。
