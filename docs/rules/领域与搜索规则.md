# 领域与搜索规则

## 计算等级与属性

- 职业唯一主属性 `mainStat` 采用 MCP `ClassJob.PrimaryStat`：力量、灵巧、智力或精神；坦克也使用力量，不保留独立攻击主属性字段。坦克专用攻击力与生命值系数按 `role=tank` 判断。装备及特殊效果的 `main` 占位属性按此主属性解析，`secondary` 仍按职业副属性解析；装备读取索引随职业主属性重建，并按装备适用职业精确筛选，不能因坦克与力量 DPS 共用力量索引而混用候选或联合分组。
- 单职业、联合搜索与可行 GCD 查询采用相同的候选、计算等级和规则。装备穿戴限制始终按职业当前上限处理，不提供低等级角色配置，与公式计算等级分开；允许高等级装备参与低等级同步。
- 非同步公式等级取职业当前上限，不依赖候选装备的品级或穿戴等级；不同职业的上限按真实职业规则解析，不固定使用 100 级。
- 同步目标区分仅等级与具体品级。仅等级取目标等级与职业上限的较小值；品级取不超过输入的最后一个等级下界所属等级，再与职业上限取小。50 级下界固定 90，显式同步品级在所有入口须为至少 90 的安全整数；其他下界由完整同版本 MCP 同步资料生成。最高档不设人工品级上界，但必须存在完整属性上限。缺少参数或资料时失败。
- 同步可不启用；领域配置只接收 SyncTarget（jobLevel 或 itemLevel）。界面配置与历史快照另存用户实际选择的副本名，仅用于恢复选择和摘要展示，不传入领域或参与计算缓存；按品级选择不保存副本名，不按目标值反推副本。不保存分类或浏览状态。按品级与按副本共享一份生成目录，品级及悬浮说明仅由该目录派生；等级默认品级取 ParamGrow，仅用于既有装备等级同步规则及辅助范围调整，不把仅等级目标转换成统一品级上限。
- 单职业、联合共享范围、GCD 查询、固定配装、自定义装备、等价装备、分享、历史、摘要与缓存使用同一同步目标语义；目标类型和值共同决定身份，最高等级的仅等级目标也与未启用区分。当前同步能力不包含 `FixedItemLevelSync` 强制上下同步或特殊场景专属属性修正。
- 装备自身的同步计算沿用参考项目 `Gear.syncedLevel`：先比较显式同步品级与装备品级；未直接同步时，再以同步映射等级（不是职业可穿戴上限）与装备穿戴等级比较并取同步品级与装备品级的较小值。穿戴资格仍按职业当前上限筛选。同步后装备属性按该品级封顶，普通魔晶石失效。
- 属性依次由等级基础参数、职业修正、族群基础属性、装备与实际生效的镶嵌合并，最后应用食物百分比、取整和固定上限。合并总属性时忽略不属于职业属性结构的装备属性（例如驯兽师可穿戴装备上的坚韧、信仰），与参考实现 `equippedStatsWithoutFood` 只合并 schema 属性的行为一致；该规则适用于搜索结果、固定配装计算、可行 GCD 与搜索内部求值。族群由搜索范围的种族选择决定，界面默认人族·中原之民；种族只改变基础主属性，不改变副属性与其它规则。联合搜索的种族属于共享搜索范围，所有职业使用同一族群。
- 公式必须与已确认上游在数学上完全一致，包括每个 `floor`、`round`、倍率及顺序。伤害期望包括职业武器伤害修正、攻击主属性、特性和队伍加成；不得把中间取整移到末尾。缺失必需职业修正或超出已验证的职业专用映射范围时失败。
- 可变等级装备保留为候选；`main` / `secondary` 按职业解析。其目标品级为显式同步品级与已钳制计算等级对应默认品级的较小值；没有显式品级时只用后者，低于原品级时应用同步属性上限并禁用普通魔晶石。

## 装备、镶嵌与食物

- 装备特殊效果目前仅支持 `ItemSpecialBonus=11`。领域按职业固定启用效果：驯兽师启用，其他职业不启用：匹配时先按参考实现完成同步封顶与魔晶石封顶，再把装备保存的 `specialStats` 按职业解析后追加到最终属性；追加值不再封顶，也不占用镶嵌可用量。未启用时不追加，`ItemSpecialBonusParam` 仅保留原始参数，不作为属性倍率。领域配置不暴露启用列表；单职业、联合搜索、可行 GCD 与固定配装计算保持一致。
- 搜索路径的普通装备填满全部可用孔，可禁忌镶嵌装备填满五孔，不提供关闭禁断的选项。自动孔中，普通孔及首个禁断孔使用最高可用等级，后续禁断孔使用上游允许在限制孔使用的最高等级；不枚举自动孔的较低等级，不写死型号或数值，不优化镶嵌成功率或成本。固定孔按用户指定的合法魔晶石参与候选生成，只有自动孔可以变化。
- 魔晶石逐件、逐颗应用，按上游 `levelCaps`、`slotCaps`、`roleCaps` 封顶，不能汇总全套再截断；允许最后一颗部分生效，评分使用实际增加量。
- 同步普通装备先按同步品级封顶，普通魔晶石失效；自定义参数武器保留独立参数分配并按同步上限截断。
- 骑士和驯兽师使用独立盾牌槽。两枚戒指同 ID 仅在来源明确证明该装备非 unique 时允许；不同镶嵌方案不能绕过同一物品的唯一性。
- 每槽强制值支持纯数字物品 ID、`{ id, melds }` 或 `{ id, customStats }`，三种形式的 ID 均须为正安全整数。纯 ID 仅锁定物品；`melds` 按孔位排列，`null` 表示自动，其余项固定属性、等级和值；`customStats` 固定完整的绝对自定义参数。候选生成必须满足这些限制，不能只锁定 ID 后重新优化已指定的值。合法 ID 不存在或与其他筛选冲突时无可行解，不自动换装；非法 ID 或参数明确失败。
- 固定自定义参数只生成对应方案。固定义军参数在生成候选时已合并属性并移除可变分配建模信息，不再创建该候选的义军分配变量或约束；自动义军方案继续使用原有整数分配模型。此差异不改变求解算法、目标或完整性要求。
- 求解候选身份保留魔晶石属性、数值、等级与重数，不包含孔位排列。固定孔在候选生成时限制合法组合，结果还原时按各槽位配置恢复固定孔并填充自动孔；同 ID 的两枚戒指分别还原。共享槽位的逐孔配置须在各职业中一致，不能借助结果重排把不一致的共享限制当成同一件装备。
- 食物必须在基础、装备与有效镶嵌属性合并后应用；整数搜索模型与领域公式的食物取整、封顶结果必须一致。

## 自定义参数武器

不同参数表按各自已确认规则解释，不套用统一的普通孔假设：

- `MandervilleWeaponEnhance` 的四个参数槽按对应 Materia 行及大小值索引读取，每次选 1 small、2 big、1 空槽，槽位不重复；四槽结构不成立时明确失败，不硬写参数数值。
- 80 级义军武器按 `ResistanceWeaponAdjust` 的有效属性、单项上限、总量上限和整数步进 1 分配。不能枚举所有合法分配为静态候选；通过整数分配变量表达，结果还原实际分配供属性、镶嵌展示及分享使用。
- 可行 GCD 查询使用相同分配范围，保留每个可达速度及该速度下最大可达坚韧，不能漏掉步进为 1 的速度档位。

## 搜索目标与硬约束

- 当前执行配置必须显式提供 `objective` 和 `clanIndex`；初始界面负责选择默认值，领域与历史入口不补值。装备来源排除、物品排除与强制装备可省略，分别等同于空数组、空数组与空对象。条件编译、领域请求及历史读取使用同一当前配置契约，不迁移旧字段或接受未知配置字段。
- 装备品级下限至少90；速度边界及最低坚韧只接受非负安全整数，最低减伤百分比最多一位小数。同步辅助下调同样不得低于90。
- GCD 仅使用离散档位列表或速度范围，两种模式互斥；单值使用单元素档位列表。坚韧条件只能选择不限、最低坚韧、最低减伤比例或最大化之一，编辑中的空数值须在搜索前补齐。共享部位使用具体槽位，包括独立的 `ring` 与 `ring2`；领域内部可使用已证明等价的戒指对模型。
- 单职业目标支持每威力伤害期望，以及该值除以 GCD 的目标。联合目标为各职业目标与其单独最优基线的比例之和；基线与联合求解使用相同目标和职业约束，不能用原始伤害和、乘积或对数和替代。
- 联合搜索仅接受同组职业：防护、治疗各一组，DPS 按力量、灵巧、智力分组；候选生成前拒绝跨组组合。防护与力量 DPS 即使攻击属性相同也不属于同组。
- 各职业可分别限制 GCD 单值或离散多值、速度上下界、最低坚韧、最低减伤和最高坚韧。速度与坚韧限制针对含基础与食物的最终值，减伤由领域公式换算。
- 联合搜索的装备品级范围与同步目标为全职业共享条件；编译时同一范围写入每个职业的执行配置。各职业仍独立设置 GCD、速度与坚韧条件，不提供职业级搜索范围。
- 联合配置的共享范围、种族、目标、来源排除及共享食物选择必须一致，共享部位的完整强制值也须一致；不一致时领域入口与历史读取均拒绝，不合并或扩展条件。
- 离散 GCD 的速度范围保持区间并集，不能加入未选档位；坦克、力量、灵巧职业使用技速，治疗、智力职业使用咏速。
- 最高坚韧先在原始完整候选域求得，再作为正式优化与联合共享搜索的硬约束；不能固定共享方案后降低要求。
- 共享指同一装备和完整镶嵌/参数身份，按部位名称对齐，不能只匹配属性总和而无法还原共同物品。共享槽位的强制装备与逐孔限制统一设置，并写入各职业执行配置，不另设职业级共享槽位限制。主手及副手/盾牌始终各职业独立选择。
- 两枚戒指可分别或同时共享，未共享的另一枚仍须满足唯一性。完整共享戒指对使用无序身份多重集时必须保留重复非 unique 戒指的重数；存在位置锁定或不对称约束时不能擅自交换。
- 共享食物使用各职业可用物理身份的交集；独立食物允许分别选择。同一食物在不同职业中可有不同的实际属性贡献。
- 可行 GCD 查询必须采用正式搜索同样的候选、食物、同步、镶嵌和硬约束，返回真实可求解的档位。当装备品级范围、来源/指定装备排除或强制装备导致某槽位没有候选时，查询明确返回错误并列出没有候选的槽位，不能返回空档位列表。

## 完整性与优化边界

- 不按启发式排名限制每槽数量、不以固定宽度截断中间状态；必须覆盖全部已支持的合法方案。义军武器的整数参数域也属于完整候选域。
- 支配替换必须覆盖全部目标与硬约束坐标，并保留共享身份、可配对集合和跨槽唯一性。有精确/离散 GCD 或速度上限时，不能用更高速度直接宣称支配。单职业基线的支配候选池不能代替联合候选池。
- 因子可达性、资源上界或共享组合剪枝须证明保守覆盖；未知坐标、元数据不完整、数值溢出或预算不足时保留候选或退回完整路径，不能截断状态后继续声称精确。
- 可选加强行、热启动和启发式只能改善求解效率，不能改变可行域或代替最优性证明。禁止将品级单调、平均斜率或经验权重当成安全剪枝依据。
- 固定点对数须有误差界，最终目标以整数伤害因子、BigInt 乘积或有理数比较；接近代理目标最优值的可行签名不能遗漏。回调可行解不构成证明；对偶界用于结束搜索前必须还原缩放单位并保守取整。
- 只有求解器完成所需最优/不可行判定且目标与身份复核结束才返回结果；取消、超时或未完成不能返回近似推荐或声称证明完成。
- 最优性限定于输入候选及约束，并依赖求解器判定可信。HiGHS 的浮点最优状态不等于独立可核验的形式化有理数证书。数学依据见[条件最优性证明](../当前搜索算法最优性证明.md)。

## 运行与结果边界

- 正式前端搜索在 Worker 中执行，提供实际进度和取消，不设置搜索时限；时限保护只用于 Node 测试和验收。
- Worker 初始化就绪后再发送搜索请求；并发任务共享截止时间和取消信号，结果按输入职业关联，结束、取消或异常时清理。具体并发数和缓存大小由实现管理，不固化为业务规则。
- 运行时缓存有界，不依赖预先打表；离线预计算不能藏在不计时的运行缓存中。
- 历史结果保留原计算值；载入成功结果不启动新搜索。版本号仅为结果页展示元数据，不参与历史记录的校验、去重、载入、编辑或方案对比判定，不因版本差异增加提示或确认。
- 单职业与联合搜索在领域搜索入口开始计时，完成候选准备、求解、结果还原及资源清理后，在返回前将完整耗时写入结果 `statistics.elapsedMs`，单位为毫秒。联合结果及其职业结果使用同一次搜索的完整耗时；求解器内部阶段统计保留各自的诊断含义。界面、历史与 Node 报告直接使用该值，不另行计时、校验、截零或补值；历史仅保存开始时间，不保存结束时间。
- 浏览器无法取得进程 RSS 时不得伪称测得进程内存。性能目标与超时保护、结果合法性及证明状态分别报告。


## 固定配装与结果展示契约

- 分享导入计算完整指定配装，不搜索、不填孔、不优化；保留合法空孔、低等级魔晶石及显式孔位，检查职业、穿戴、部位完整性、唯一性和镶嵌限制。链接的公式等级必须与当前统一等级解析一致。
- 外部分享沿用已有等级与品级协议并准确转换同步目标；仅等级分享的编码等级以同步目标为准，不能被另传的公式等级覆盖。
- 分享链接中的装备若不在当前运行时目录中，视为该槽位为空，按槽位不完整拒绝整套导入；不补装或继续计算部分配装。
- 自定义武器参数按绝对属性值覆盖原始装备后再同步封顶，验证曼德维尔合法分配与义军单项/总预算；结果保留原始分配供分享使用。合法原始值超过同步 cap 时应用截断。
- 食物结果返回各项加成上限、加成比例、实际生效增益及利用率；利用率为实际增益总和除以上限总和后乘 100 向下取整（沿用边界容差），零上限时为 0。
- 同步单职业结果可提供同属性装备池：按对应装备类型的最终生效属性逐项完全相同，包括武器性能及攻击间隔；候选符合原搜索条件，保留完整镶嵌/参数。凡设置强制装备的槽位一律跳过等价候选生成，不提供替换组，包括纯 ID、逐孔魔晶石与自定义参数三种形式。其他槽位的数组包含当前项，按品级、物品 ID 升序；单候选不生成 key。两戒指槽的完整替换池相同、池内恰有两枚不同的唯一戒指且当前两槽各佩戴其中一枚时，两槽均不生成替换 key 或对应数组。其他戒指池用完整主数组展示、唯一子集判断另一槽冲突。替换不重新搜索或更改指标与耗时。
