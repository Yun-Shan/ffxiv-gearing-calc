# 前端设计总览

本文定义整个项目的前端设计方向、跨页面视觉与布局原则，以及设计视口的验收方式。具体页面结构、组件、字段、文案、尺寸、交互状态和实现细节，以 [Penpot 设计文件](https://design.penpot.app/#/workspace?team-id=71b39894-c9c5-81cd-8008-bc8b2a6ce976&file-id=71b39894-c9c5-81cd-8008-bc8f0497fe39&page-id=385a202b-2e30-80ff-8008-bcd1dbe5cc0b&layout=layers) 中对应画板为准；如与本文表述不一致，以 Penpot 为准。本文不复制具体画板细节。

## 范围与设计视口

设计范围覆盖整个项目的前端页面、功能流程和状态。新增页面与流程沿用本总览中的项目级设计原则，并以 Penpot 中对应画板确定具体内容。

项目目标桌面视口包括 1440 × 695 和 1920 × 1080；具体画板支持的尺寸以 Penpot 标注为准。验收使用对应画板的实际视口。Penpot 未定义的视口或状态不声明与设计稿精确匹配，也不从桌面设计自行推导移动端布局。

## 整体风格

- 以沉稳的深蓝色建立导航与品牌区域；内容区域使用柔和的白色和灰绿色中性色，青绿色承担主要交互强调，橄榄绿用于状态和重点标记。
- 采用克制、清晰、偏工具型的视觉表达。通过留白、轻量边框、浅色底面和明确的文字层级组织信息，避免强烈阴影、装饰性渐变或过多高饱和颜色。
- 保持较高的信息密度，同时让配装条件、搜索过程和结果易于扫描。数据表和数值区域强调对齐与可读性。
- 中文内容以清晰的无衬线字体为主；数字、计时和指标采用更适合读数的字形。具体字族、字号和层级查看 Penpot。
- 以低对比度的航海图、罗盘或星图意象作为背景装饰，保持其辅助地位，不遮挡信息。

## 跨页面一致性

- 全项目页面沿用一致的品牌识别、全局导航、颜色语义、文字层级和信息组织方式。
- 各功能流程清楚呈现操作阶段和状态；配置、搜索、结果与历史信息保持稳定、可追溯。
- 对齐、间距、文字、状态和具体交互以 Penpot 对应画板及其状态为依据。遇到本文与 Penpot 不一致时，以 Penpot 为准。

## `src/ui` 目录组织

`src/ui/app/App.tsx` 是应用级容器，负责连接应用入口与页面流程；它的应用级样式和测试放在相邻的 `App.module.css`、`App.test.tsx` 中。应用容器不属于普通共享组件，不放入 `src/ui/components`。

除应用容器外，`src/ui` 的前端代码按组件复用范围和职责放入 `components`、`pages`、`services` 三个目录：

```text
src/ui/
├── app/                         # 应用容器、应用样式和应用级测试
│   ├── App.tsx
│   ├── App.module.css
│   └── App.test.tsx
├── components/                 # 多个页面共享的组件
│   └── <component>/             # 每个组件模块独立放在自己的目录中
│       ├── <component>.tsx
│       ├── <component>.module.css
│       └── components/          # 仅供该组件使用的子组件，可继续嵌套
├── pages/                       # 页面及页面专属组件
│   └── <page>/
│       ├── <page>.tsx
│       └── components/          # 仅供该页面使用的组件
└── services/                    # 非 domain 的前端服务
```

- `components` 根目录只放多个页面共享的组件目录；任何 `components` 目录中都不直接放组件文件，每个组件模块都必须使用自己的子目录组织。
- 页面组件及仅由该页面使用的组件放在对应 `pages/<page>` 目录内。页面专属组件放入页面的 `components` 子目录；若组件只被另一个组件使用，则将其放入该组件目录下的 `components` 子目录。私有组件可以按需继续嵌套，避免把只在一处使用的实现提升为全局共享组件。
- 组件入口、样式和仅供该组件使用的资源放在组件自己的目录中，保持相关实现相邻。子组件采用相同规则，各自使用独立目录。
- 页面与组件的样式放在所属目录的 CSS Module 中；`src/ui` 不使用 Tailwind 工具类或 `@apply`。全局样式仅保留全站基础规则、设计 token 和确实被多个组件共享的样式，避免用 `:global` 穿透其他组件的实现细节。
- `services` 放置非 `domain` 的前端服务，例如 React 状态的保存与读取、浏览器存储和前端应用配置。游戏规则及纯领域逻辑仍归 `src/domain`；组件目录不承担服务或领域逻辑的集中存放职责。
