# 前端 UX 重设计思路：面向新手的单职业配装向导

> 本文是设计提案，不包含代码实现。建议先重做单职业入口和配置流程，再将同一套信息层级延伸到多职业联合搜索。

## 1. 设计方向

把当前“所有条件集中在侧栏、由用户自己理解并填写”的搜索页面，调整为“逐步说明要做什么、展示建议值、由用户确认后继续”的配置向导。

首要用户是第一次使用单职业优化的新手。他们应能先理解职业、优化目标和候选范围，再决定是否增加更细的限制。熟练用户仍可在对应步骤展开高级选项，不必进入另一套功能残缺的简化版。

访谈确认的设计基线：

- 以单职业新手为第一优先用户。
- 采用分步流程，依次处理职业、目标和限制。
- 每一步可展示推荐值，但必须由用户明确确认后才能前进。
- 高级限制留在相关步骤内，默认折叠；已设置的内容要在折叠状态下可见。
- 视觉气质兼顾专业工具的清晰度与少量《最终幻想14》氛围，不复刻参考站点。

## 2. 参考站点观察与借鉴边界

观察对象：[Asvel 最终幻想14配装器](https://asvel.github.io/ffxiv-gearing/)，通过 Codex 内置浏览器查看首页和武士配装页，观察日期为 2026-10-03。页面当时显示资料版本 7.56；此版本信息仅记录观察快照，不作为本项目的数据依据。

### 可借鉴的体验做法

- **先按职业角色组织入口。** 首页把职业分为防护、近战、治疗、远程物理、远程魔法等组，用户可以直接进入职业页。新设计可以借鉴这种分类，让职业选择更容易扫描，避免把职业藏在长下拉菜单里。
- **让比较围绕装备部位发生。** 职业页按部位列出装备候选，并把品级与属性放在相邻列。自动优化器不需要开放同样的逐件手选，但可以借鉴其按部位阅读结果、并排查看关键数值的方式。
- **给数值一个决策语境。** 食物列表展示属性利用率，页面也把伤害、GCD 和属性摘要放在配装信息附近。新设计可用简短解释和摘要帮助用户理解输入与结果的关系，避免只堆数值。
- **把高频工具入口放在职业工作区。** 参考页提供筛选、品级同步、魔晶石、分享、导入和设置入口。对本项目的启发是按任务顺序组织入口，并把少用的控制收进分组，而不是照搬同一排工具按钮。

### 不直接照搬的内容

参考工具围绕手动挑选每个槽位的装备组织页面；本项目要自动搜索整套配装。若复制其逐部位候选长表，会把用户重新带回“逐件挑选”的工作量，也会遮住自动优化的核心价值。因此只借鉴职业分类、数值比较和上下文提示，不复制其表格密度、布局、配色、图标或交互结构。

## 3. 当前产品基线

当前顶部导航将单职业搜索和多职业联合搜索分成独立页面。单职业页把职业、等级、同步品级、候选品级、GCD、速度、食物、坚韧以及来源和装备限制放在侧栏中；结果位于主区域。多职业页在侧栏配置参与职业和共享策略，在主区域展开各职业条件。

这套结构功能完整，但新手需要先理解多个领域概念，才能判断哪些条件必须填写、哪些可以保留默认值。建议把配置条件拆成有顺序的步骤，并在每一步说明“当前要决定什么”“建议值是什么”“展开后还能调整什么”。

## 4. 建议的信息架构与单职业流程

保留清晰的单职业 / 多职业入口。单职业页以四步向导为主：

| 步骤 | 用户要做的决定 | 默认呈现 | 折叠的高级选项 |
| --- | --- | --- | --- |
| 1. 选择职业 | 选择要优化的职业与等级 | 按职业角色分组显示职业；等级使用项目已有的职业数据默认值，并清楚标出 | 职业相关的特殊说明 |
| 2. 选择目标 | 决定优化目标和战斗节奏 | 提供带简短说明的推荐目标；清楚区分“每威力伤害期望”和“按 GCD 折算” | 单个或多个 GCD、可行档位查询、速度范围；坦克显示坚韧和减伤条件 |
| 3. 设置候选范围 | 决定参与搜索的装备与食物范围 | 使用项目当前已有的品级范围、自动食物等真实默认值；说明同步品级的影响 | 来源排除、强制装备、排除装备以及其他可用限制 |
| 4. 检查并开始 | 核对整组条件并启动搜索 | 汇总职业、目标、品级范围、食物与已启用限制；每项可返回对应步骤修改 | 不新增计算参数；仅提供编辑入口 |

每步都提供明确的“上一步”和“确认并继续”；最后一步使用“开始搜索”。推荐值可以先呈现出来，但不能自动跳过确认，也不应悄悄启动搜索。职业由用户明确选择；其他默认值必须来自现有职业配置、生成数据和领域规则，不为界面体验虚构品级、食物或战斗数值。

### 步骤交互

- 顶部显示简短进度，例如“第 2 步，共 4 步”，同时标记已完成步骤。用户返回修改时保留其余已填写内容。
- 每步聚焦一个主要问题；说明文字尽量回答“这个选择会影响什么”，不要在首屏展示完整规则手册。
- “推荐”值需要有简短理由；用户改变推荐后，在最后的条件摘要中显示实际选择。
- 每个高级折叠区的标题显示已启用数量或当前值，例如“来源限制 · 已排除 2 项”。展开后不清空已设置内容，关闭后摘要仍可见。
- 只显示适用于当前职业的选项。技速 / 咏速和坦克坚韧条件继续依照领域层规则呈现；不要要求非坦克用户理解坚韧，也不要把职业专用字段伪装成通用条件。
- 需要查询可行 GCD 时，用计算得到的真实档位供选择；说明查询使用当前职业和限制，不把不可行档位作为推荐项。
- 魔晶石填满规则作为说明显示，不提供关闭填孔或关闭禁断的开关。等级同步对魔晶石的影响也应在相应设置旁说明。

## 5. 结果页层级

向导负责减少开始前的决策负担；搜索结果仍要提供足够信息来核对优化器做出的选择。建议结果页按“结论 → 配装 → 属性明细”的阅读顺序组织：

1. **结论摘要：** 明确展示“每威力伤害期望”、GCD 和用户选择的优化目标；其他指标作为次级信息，不用多个同等强调的数字争夺注意力。
2. **推荐配装：** 按武器、盾牌、头身手腿脚、饰品顺序逐行展示装备。每行保留实际最终属性、魔晶石、来源和品级；原生副属性达到上限时继续按既有规则高亮。
3. **食物与总属性：** 在同一结果页面展示实际食物及其生效属性、配装总属性和相关效果。可以用分区、锚点或清晰的卡片层级帮助浏览，但不能把必需明细藏到其他标签页。
4. **条件回看：** 保留本次搜索条件摘要与返回编辑入口，帮助用户理解结果是由哪些选择得出的。

搜索进度、已取消、无可行配装、失败，以及“配置已修改但结果尚未更新”等状态要有可辨识的状态标题与下一步建议。只有求解与复核完成时才将结果标记为完成；无法完成证明时明确说明，不展示近似配装为最终推荐。

## 6. 视觉方向

采用“清晰的分析工作台，加少量游戏氛围”的混合方向：

- 以高对比的中性表面承载配置表单和结果数据，保持较宽的行距和明确的标题层级。
- 用一套克制的主强调色标记推荐值、当前步骤和主要操作；游戏氛围放在职业身份、轻量图形细节和局部标题区域，不铺满数据表。
- 数值使用易对齐的数字样式，属性标签使用清晰的中文名称。颜色只作辅助，不能成为识别装备状态、上限或搜索状态的唯一方式。
- 保持按钮、状态、输入框和折叠区的样式一致；焦点、错误、禁用和进行中状态都要与普通状态区分。
- 视觉元素应与 Asvel 页面保持独立，不沿用其具体配色、图标、表格布局或品牌表达。

桌面端宽屏作为首要场景是基于现有侧栏和数据表布局的设计假设，并非访谈确认；同时要保留窄屏完整操作能力。窄屏下逐步呈现单个步骤，避免继续压缩成两列小输入框；结果表格应有清晰的横向浏览或卡片化方案，不能静默隐藏用户必须核对的属性信息。如果实际主要使用场景是移动端，应优先重新评估向导和结果的排布。

## 7. 多职业联合搜索的延伸

首期聚焦单职业新手流程。多职业仍保持独立入口，但后续可复用职业角色选择、每职业条件分组、条件摘要和结果状态样式。共享装备 / 食物策略与每职业限制要分开解释，并在开始前汇总共享槽位和各职业使用的目标；各职业详细条件可以折叠，但展开状态和已配置摘要都应明确。

联合搜索是高级场景，不应挤进单职业向导的默认步骤，也不应因优化单职业而丢失当前能力。共享身份、戒指唯一性和每个职业基线等规则继续由现有领域逻辑负责。

## 8. 优先顺序与验收标准

建议按以下顺序推进设计落地：

1. 重新安排单职业配置：四步向导、推荐值确认、相关高级选项折叠、可回看的条件摘要。
2. 梳理结果页：突出优化结论，同时保持装备逐行属性、食物和总属性同页可见。
3. 统一加载、无解、失败、取消和过期结果等状态表达。
4. 将可复用层级扩展至多职业页面，并完善窄屏与键盘操作。

设计验收时检查：

- 新用户能看懂每一步要做的决定；推荐值清楚可见，但必须主动确认才能前进。
- 默认状态不要求填写全部限制；展开高级条件后，用户能识别哪些值已生效。
- 变更职业时只显示适用的速度、坚韧等条件，且术语、属性映射与实际计算保持一致。
- 搜索状态不会让用户误把未完成或旧条件的结果当作当前推荐。
- 推荐配装、逐件最终属性、食物和总属性在同一结果页面展示；伤害指标沿用领域层计算结果。
- 用户可见固定文案使用中文，属性使用项目的中文映射；数据和推荐默认值只来自项目认可的真实来源。
- 视觉效果有适度游戏氛围，但数值对比、输入焦点和状态信息始终清楚。

## 9. 明确不在本提案内的事项

- 不修改搜索公式、候选生成、魔晶石规则、数据来源或优化目标定义。
- 不在 UI 层复制领域公式，也不为了降低表单复杂度删除现有约束能力。
- 不开放违反项目规则的选项，例如关闭普通孔或禁断孔填充。
- 不复制参考站点的手动逐件选装流程和具体视觉样式。
- 本提案只描述设计方向；代码和项目规则尚未修改。
