# 自动配装成功案例迁移清单

## 历史已验证且推荐迁移的定理与方法

本清单覆盖本次讨论的四项主要成功案例，另列一个尚未成功的高压力补充场景。这里的“推荐迁移”指历史实验已有价值，**不等于已通过当前 main 的上线验收**。编号沿用原数学研究文档。

1. **T49 职业等价压缩**：在候选、约束、因子与目标归一化结构满足等价条件时，将等价职业折叠为带重数的代表职业。必须保留目标权重、原职业结果恢复和所需独立基线。四坦案例在 T48 流程上已有明显收益。
2. **T11 速度与食物可达范围投影**：从真实离散候选计算可达速度，再结合食物取整和 GCD 条件施加必要范围。只做安全外包络或精确可达性排除，不以连续范围代替实际可行性。
3. **T34 完整伤害乘积食物上界**：用普通合法起点作为下界，结合完整伤害因子的保守上界排除不能追平的食物。不得只看暴击、直击、信念三因子而遗漏其它乘区的取舍。
4. **T14／T15 精确共享状态搜索及配套必要条件**：共享部分聚合，私有部分独立求值，同时保留食品、速度、物品身份和唯一性约束。历史三坦案例已有成功记录；规模和成本依赖实际候选域。
5. **T54／T57 等已验证结构压缩组合**：作为 BLM 等历史强对照的组成部分迁移；不得把组合总收益全部归于其中一个定理，也不得不检查适用条件就全局启用。

**配套方法而非独立剪枝定理**：从原输入生成较好可行起点，再以可证明上界进行精确搜索。起点质量影响速度，但不能改变搜索目标或把启发式结果称为最优；起点生成成本必须计入。

推荐分级规则：纯明显收益优先；若部分场景有明显收益，其他场景的退化须满足“绝对差距不超过 1 秒”或“相对差距不超过 2%”之一。任何漏解、错误最优性声明都不能用性能收益抵消。

## 共同搜索条件

除各案例另外说明外：

- 种族参数 `clanIndex=0`，目标为 `damage`，不额外最大化坚韧。
- 装备范围包含上下界；排除自定义属性武器，不设置强制装备，不排除装备来源。
- 食物自动选择，不预先锁定某种食物；使用准备流程生成的合法镶嵌候选。
- 联合搜索共享头、身、手、腿、脚、耳、颈、腕、两枚戒指及食物；各职业武器独立，骑士盾牌独立。
- 保留 unique 限制、完整装备身份、实际食物取整与全部伤害因子。两枚戒指不是忽略唯一性约束的任意重复选择。
- 不固定共享装备，不向性能测试注入已知最优配装。历史最佳方案只用于运行后的独立结果核对或正确性审计。
- main 本轮排除列表由当前数据中自定义参数武器／义军属性调整标记生成。数据更新后应重新生成，不复用旧 ID 列表当作完整排除规则。

## 案例 A 四坦等价职业压缩

### 搜索参数

PLD／WAR／DRK／GNB；100 级；装备 780–785；无同步；四职业 GCD 均为 2.50；共享规则见上。

### 历史成功

在 T48 流程基础上启用 T49：

- 第一组：82.927 → 14.616 秒。
- 第二组：82.435 → 14.423 秒。
- 四职业压成三个带权代表类，权重为 1／2／1；该域 WAR 与 DRK 等价。
- 共享状态从 458,793 降为 13,787；私有求值从 11,011,032 次降为 248,166 次。

该历史流程从配置出发，不输入已知独立最优值。但 T48 的输出契约是提供一套认证最优方案；当前 main 还要求每个职业的独立最优基线 `optima`。迁移不能通过删除这些输出成本获得不公平提速。

### 本次 main 情况

原流程约 106.110 秒返回，并报告证明完成；联合值为：

`199728672037235712 / 49962146079560975 ≈ 3.9975999373442197`。

历史物理配装重新按当前 main 数据、公式和候选合法性验证后，得到更高联合值：

`9297538159 / 2324486470 ≈ 3.999824597387`。

因此这次 main 返回不能作为正确完成基准。反例已核验 45 个职业槽位选择及镶嵌属于当前候选池，且共享、戒指与 GCD 条件合法。它证明“main 本次返回不是最优”，**没有证明反例本身是最新 main 的全局最优**，也不是迁移流程新发现的方案。

完整反例已另行提供于《四坦更好配装-搜索条件与完整结果.md》和《四坦更好配装-完整数据.json》。本清单不重复打包装备数据。

### 迁移及验收重点

T49 尚未完成 main 集成。必须先查明错误完成的来源，区分模型、适配层和求解器数值问题；再验证等价判定、目标重数、每职业基线与物理方案恢复。不能用较差结果的快速返回证明优化成功。

## 当前状态与统一验收标准

本次记录的是案例信息和迁移清单，不是完整实现文档，也不是已完成验收报告。目前没有任何一项可以宣称已完整复现历史强组合并通过 main 推广验收。

1. **固定可比输入**：记录提交、数据散列、职业、品级、同步、GCD、共享槽位、食品范围和排除规则；main 更新后重新建立原流程基线。
2. **先正确后提速**：重建物理配装，验证合法性和精确目标值；超时仅报告未完成。求解器 Optimal／Infeasible 状态与独立最优性证据分开表述。
3. **完整计时**：包含候选准备、独立基线、可行起点生成、投影／上界构造、实际搜索、结果重建和核验。阶段时间只用于解释瓶颈。
4. **重复且换序**：同机、同预算、无并发干扰，多轮交换原流程与新流程执行顺序；单次改善只作为初步观察。
5. **优先长场景**：A 正确性排查与 D／C 超时转完成优先；B 用于单职业长场景验证。十几至二十秒案例只做退化检查。
6. **按既定阈值推荐**：有明显收益，且其它场景退化不超过 1 秒或 2% 之一；正确性不作妥协。纯明显收益列更高优先级。
7. **交付分层**：案例清单、具体实现原理与适用条件、逐项性能和正确性验收分别记录。不提供复现包；结论中保留搜索参数。
