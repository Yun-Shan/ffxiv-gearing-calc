## 3. 已核查的职业机制

### 武僧：两种暴击收益必须一起考虑

暴击属性影响普通攻击的暴击概率、暴击倍率和部分战技触发的斗气。必暴战技仍受暴击倍率影响，但自然暴击概率不再提高该攻击是否暴击的概率；相应斗气触发不能再按普通暴击概率计算。38/74 级的触发率不同，六合星导脚有不触发斗气的例外；义结金兰额外引入自身、队友事件与资源上限变化。[官方武僧指南](https://na.finalfantasyxiv.com/jobguide/monk/)

因此“所有武僧伤害乘一个暴击收益系数”不成立；必暴和斗气两种遗漏甚至可能部分抵消。影响依动作构成、等级、时间窗、暴击增益及溢出而变，不能给出通用百分比。

### 按机制扩展，比逐职业堆系数更有价值

| 机制 / 代表职业 | 应进入模型的内容 | 建议次序 |
| --- | --- | --- |
| MNK：必暴＋暴击触发斗气 | 必暴条件、可触发动作、等级概率、斗气消耗及额外攻击；结义和溢出另定场景 | 首个专门 profile |
| WAR：必暴必直；SAM：必暴 | 按动作/状态区分，不把全职业套成保证命中 | 通用命中语义完成后接入 |
| MCH：Reassemble、Wildfire、自动机 | 保证命中、禁止暴直、独立或宠物类缩放 | 拆分伤害类型后接入 |
| DNC：保证命中动作、Devilment、资源与舞伴 | 命中增益、动作数和 Esprit 场景 | 内置场景 profile |
| 暴击/直击概率增益窗口 | 普通概率封顶；保证命中时增益转换；联合窗口分布 | 按来源和时间区间处理 |
| DoT、自动攻击、宠物 | 各自基础公式、取整、速度/间隔、快照及事件频率 | 后续机制层，影响面较大 |
| BRD 资源与团队贡献 | 当前版本的机制，不能复用旧版 DoT 暴击触发说法 | 独立验证后扩展 |

此表是模型分类，不宣称所有职业已完成覆盖。当前 BRD 歌曲 Repertoire 为固定概率触发，与早期基于 DoT 暴击的模型不同。[官方诗人指南](https://na.finalfantasyxiv.com/jobguide/bard/)

**保证直击不等于直击属性没收益。** xivgear 区分自动直击属性补偿、DET 合并取整、命中倍率及外部直击率增益；不能只令 `h=1`，也不能再乘一次普通直击期望。保证暴击也须区分裸暴击属性与概率增益转伤害。实施时需逐项核对精确公式，不能把示意式当已验证公式。[xivgear 数学实现](https://github.com/xiv-gear-planner/gear-planner/blob/f771f2bceedde6c73b851563266dba6eb65db6bf/packages/xivmath/src/xivmath.ts#L294)

### Etro：已确认是通用静态指标

[官网](https://etro.gg/)显示版本 `v20260812.1`，列出 7.55 物品。读取其部署[脚本](https://etro.gg/public/js/main.d39b10b7.chunk.js)与公开 [source map](https://etro.gg/public/js/main.d39b10b7.chunk.js.map)后确认：

- `views/Gearset/GearsetHelpers.js:1045–1064` 将 100 威力乘武器、主属性、信念、普通暴击/直击期望、坚韧及特性；`SidebarTables.js:129–139` 调用它显示 expectedDMG。
- `HelpDialog.js:45–64` 说明该指标不计技速、咏速、自身及团队增益，并提示不同 GCD 的循环差异。

因此 **Etro 的这个 100 威力指标不包含斗气反馈、必暴技能占比或职业循环模拟**。没有进行完整全站审计，不扩张为“Etro 永远没有其他相关功能”。source map 原始字节 SHA-256 为 `3ba5a4dac28c5a0a60f85b6a7f4d5088dcd5c86a23e4badea2d0623443d9179e`。

## 5. 前序探索：公式与搜索边界

脚本：[job-objective-feasibility.mjs](../../../scripts/experiments/job-objective-feasibility.mjs)。结果：[job-objective-feasibility-results.json](../job-objective-feasibility-results.json)。复现：

```powershell
node --experimental-strip-types scripts/experiments/job-objective-feasibility.mjs
```

脚本读取正式 bin、调用正式公式及现有 MIP，合成对象只存在于研究脚本。没有新增生产候选，也没有接入职业修正后的求解器。

### A. 修正能反转排序

固定其他属性，枚举 4,001 个 `CRT+DHT=4000` 的装备与食物贡献向量。测试设 75 次普通战技、25 次必暴战技、每次 300 威力，5 斗气兑换 400 威力。这些是**隔离测试权重，不是推荐循环或经过验证的动作占比**。

| 候选（CRT / DHT 贡献） | 普通模型 | 25% 必暴模型 | 再计入斗气期望 |
| --- | ---: | ---: | ---: |
| A：2 / 3998 | **62.37055324** | 68.17957535 | 72.96131777 |
| B：28 / 3972 | 62.36066801 | **68.18036338** | 72.98629219 |
| C：0 / 4000 | 62.38357423 | **68.19380908** | 72.97654977 |
| D：14 / 3986 | 62.37207731 | 68.18706295 | **72.98139662** |

A/B 证明必暴混合可以改变排序，C/D 证明计入必暴后漏算斗气仍能改变排序。使用统一分母 BigInt 比较，并检查展示公式、向量求值、显式分项和与合并因子一致。

完整网格的最优点在三个测试模型中恰好相同。**反例证明存在受限候选集合会选错，不证明所有域的最终最优都会改变。** 这些向量没有通过实际完整装备的可达性验证，不能据此量化真实 BiS 损失。

### B. 只改求值回调，搜索仍按旧目标选

使用两个合成候选测试现有 MIP，属性顺序为 `[PDMG,STR,CRT,DET,DHT,SKS,TEN]`：

- A = `[160,3000,0,1500,500,500,0]`
- B = `[160,3000,50,1450,500,500,0]`

普通目标 A 胜；纯必暴测试目标 B 胜（58.83449391 > 58.81811863）。将回调改为纯必暴后，MIP 仍返回 A，并报告 `signatureBandProof=true`。它完成的是**旧六因子目标**的证明，不是新目标的证明。纯必暴仅为集成反例，不是武僧模型。

### C. 同一旧签名可以有不同新伤害

固定其他属性，技速贡献从 42 增到 43，GCD 都是 1.99，六因子与 GCD 签名完全相同；`ssDamage` 却从 1.001 变为 1.002。引入吃速度倍率的伤害项后，旧签名不再足以确定分数，原 no-good 排除可能漏掉更优解。

### D. 平均斗气除以 5 不等于有限时间技能次数

设 5 点确定斗气，加上 15 次独立事件、每次 25% 获得一点；假设立即消耗、无溢出。精确二项分布计算：

\[
E[\lfloor(5+X)/5\rfloor]=1.3143090084,
\quad E[5+X]/5=1.75.
\]

即使没有溢出，结束余数也使有限战斗与长期平均不同。固定时长 DPS 必须定义初始斗气、消耗时机、尾段与上限，不能直接用平均资源除以成本。

前序研究执行的定向公式、签名带及并行基线测试为 3 文件、23 项通过，其中公式一致性 7 项另在主代理执行通过。此处保留当次测试记录，不表示本轮文档拆分重跑了全部测试。未运行改造后搜索、真实战斗模拟或全场景性能验收，未提出性能达标结论。

## 6. 新增探索：多 GCD 与统一基线

脚本：[multigcd-objective-feasibility.mjs](../../../scripts/experiments/multigcd-objective-feasibility.mjs)，结果：[multigcd-feasibility-results.json](multigcd-feasibility-results.json)。该脚本读取正式 bin 和当前职业/GCD公式，但所有动作权重与候选向量都是隔离合成测试，不代表真实循环或完整装备。

```powershell
node --experimental-strip-types scripts/experiments/multigcd-objective-feasibility.mjs
```

### 6.1 分档并集与全域枚举

构造三个 GCD（1.94、1.96、2.00）各五个 CRT 向量，共 15 个方案；每档速度下界从正式 `equippedSpeedRangeForGcd` 获取，实际 GCD 用正式求值器复核。各档使用不同合成系数，最终分数按统一时间单位计算。

脚本以 BigInt 有理数直接枚举全部 15 个方案，再分别选出每档最优后比较，两种途径的最终精确分数及方案 ID 相同。另用显式分项计算核对有理系数重建。此实验是有限域 oracle，**没有调用新目标的分档 MIP 或联合因子 MIP**，不能写成两种生产后端已经验证等价。

### 6.2 可分离性反例

取普通与必暴两条合成函数，在两个 CRT 状态上的值（公共分母均为 1,000,000）：

| 函数 | 状态一 | 状态二 |
| --- | ---: | ---: |
| 普通 N | 1,020,000 | 1,195,000 |
| 必暴 K | 1,400,000 | 1,650,000 |

交叉乘积差为 `10,000,000,000`，不等于零，因此这张正数表不能拆成一个行系数乘公共列函数。将第二行换成第一行的两倍则交叉乘积差为零。这里验证的是[01](01-模型数学与多GCD系数.md)中的精确有限域判据，并非声称某个真实 GCD 是纯普通或纯必暴循环。

### 6.3 时间分母不能丢

两个合成周期的总分为 400、300，时长为 5、3。只比较总分会选前者；真实速率是 80、100，应选后者。各固定分支内部可以约去其恒定分母，但跨 GCD 比较时必须恢复。

### 6.4 每档独立归一化会反转联合选择

职业一在全部允许 GCD 中的独立最优为 110，某一档单独最优为 90；职业二独立最优为 100。两个可行共享方案分别给出 A=[90,100]、B=[108,90]。

| 归一化方式 | A | B | 选择 |
| --- | ---: | ---: | --- |
| 全部允许 GCD 的职业基线 | 1.8181818182 | 1.8818181818 | B |
| 错用 A 所处 GCD 自己的 90 作为基线 | 2.0000000000 | 1.8818181818 | A |

全部比较在脚本中使用精确分式。它证明了[04](04-多职业联合搜索.md)的统一基线要求；没有测量真实多职业损失。
