# 真实候选搜索方法与正确性

状态：隔离研究实现与方法说明；核查日期：2026-10-24。本文说明真实装备候选如何进入三档合成职业目标，以及搜索、穷举和结果重建各验证什么。
阅读入口见[专题总览](README.md)，目标推导见[模型数学](01-模型数学与多GCD系数.md)，完整耗时与实施取舍见[第 11 章](11-真实候选完整耗时与实施建议.md)。
性能与独立复核结果见第 11 章；研究进程的成功状态不表示生产功能已经交付。

## 1. 本轮把哪部分从合成向量推进到真实候选

前序有限向量实验验证了代数和反例；本轮由正式 `prepareSearch` 生成真实装备、镶嵌、食物候选，再调用现有 Exact-MIP 完成每档搜索。
装备资料、同步属性、普通孔及禁断政策、食物取整、族群基础与伤害公式来自当前运行时 bin 和领域代码。
动作系数仍是人为构造的合成 profile；真实装备不等于真实循环，结果不能作为武僧正式配装推荐或实战 DPS。
本轮没有实现 GCD×CRT 联合块、一般分项和后端、有限时窗资源状态或多职业联合目标。

| 场景 | 装备品级范围 | 同步 | 食物 |
| --- | --- | --- | --- |
| `sync-fixed` | 790—795 | 品级 735 | 固定物品 49245 |
| `sync-foods` | 790—795 | 品级 735 | 当前生成的全部可用食物候选 |
| `meld-fixed` | 790—795 | 不启用 | 固定物品 49245 |
| `meld-foods` | 790—795 | 不启用 | 当前生成的全部可用食物候选 |
| `wide-fixed` | 780—795 | 不启用 | 固定物品 49245 |

共同输入为 MNK、当前解析的计算等级 100、`clanIndex=0`、无额外来源/物品排除、无强制装备、无最高坚韧要求。
请求允许的 GCD 明确固定为 `[1.94, 1.96, 2.00]`；三个分支使用同一原始候选池，只改变实际 GCD 硬约束和对应目标系数。
`prepareSearch(config, {}, false, true, undefined, false)` 保留独立戒指槽，不预先执行槽位 Pareto 或 Top-K 截断。
候选的完整性仍限定于项目既有合法生成政策，例如自动镶嵌的允许等级；不扩张为游戏中任意低级镶嵌也全部枚举。
未同步时的合法镶嵌产生更多具体身份；研究入口不靠固定每槽数量缩小这部分域。

**“完整域”指本次输入允许的三个 GCD，不是所有自然可达 GCD。** 固定食物 oracle 的原始合法组合观测到 11 种 GCD，另外八种被明确的输入条件排除。
全部 17 食物的 oracle 实际观测到 14 种 GCD，也只对上述三档评分；不能将“11 档”泛称所有场景的可达域。
未选档位不属于本次目标，而不是被性能策略暗中舍弃；也没有为这些档位验证默认循环。
`profileForGcd` 对未知档位复用合成 anchor 的工具行为，不是已验证插值，本轮三档实验不调用它来扩充声明域。

## 2. 三档合成系数与整数多项式

每档固定 `T=120`，定义自然暴击概率 `c`、暴击倍率 `k`、普通暴击期望 `N=1+c(k−1)`。
合成动作因子为：

\[
F_g=\alpha_gN+\beta_gk+\gamma_gcN,\qquad S_g=Base\times H\times F_g/T.
\]

`α`、`β` 表示合并后的普通与必暴贡献，`γcN` 表示受暴击概率影响的额外普通攻击贡献；它们不是实测动作次数或完整资源模拟。

| 实际 GCD | α | β | γ | 多项式约分公因子 d |
| --- | ---: | ---: | ---: | ---: |
| 1.94 | 13040 | 4000 | 3200 | 3200 |
| 1.96 | 12200 | 4500 | 2880 | 320 |
| 2.00 | 11360 | 5000 | 2640 | 80 |

令 `w=CRT整数档位−50`，在本轮非负支持域上 `c=(w+50)/1000`、`k=(w+1400)/1000`。
[runtime.mjs](../../../scripts/experiments/real-job-model/runtime.mjs)把 `10⁹F_g` 展开为整数三次多项式，再除以所有系数的最大公因子 `d_g`，得到正整数因子 `Q_g(w)`：

\[
10^9F_g=d_gQ_g(w),\quad
10^9F_g=(1020000000\alpha+1400000000\beta+51000000\gamma)
+(450000\alpha+1000000\beta+1042500\gamma)w
+(1000\alpha+500\gamma)w^2+\gamma w^3.
\]

编译时先用 BigInt 算系数、公因子，再检查约分系数可安全转为 Number；Horner 求值逐次检查乘法、加法和最终正整数。
不能因为最终乘积用 BigInt，就放任此前系数或 `Q_g` 超出 Number 安全整数范围。
系数非负且 `w≥0`，因此 `Q_g` 单调不减；这是本轮候选界复用的数学条件，不是所有职业模型的普遍性质。

## 3. 新因子如何进入完整搜索链路

研究 runtime 在任何领域导入前注册 Node `registerHooks`，只转换进程内加载的 `equipped-effects.ts` 源码，不写生产文件。
转换先核对完整源 SHA-256，再要求两个插入/替换点各恰好匹配一次；源码漂移时失败，不能继续套用旧审计结论。
第一个插入点在整数因子工厂创建时捕获当前不可变 profile；第二个将返回的 `critical` 因子改为 `Q_g`。
后续切换全局 active profile 不会修改已创建求值器捕获的定义；缓存的参考求值器也按 profile 身份区分。
脚本顺序执行各 GCD，不能在同进程并发切换这个研究全局入口并假定它天然安全。

| 链路 | 本轮传播方式 | 保证范围 |
| --- | --- | --- |
| 向量评分 | `scoreVector` 显式动作和与整数有理数互查 | 同一 profile、同一最终属性贡献 |
| MIP 因子建模 | `model-preparation` 内部创建的整数工厂也经过 hook | CRT 因子类和可达映射采用新 `Q_g` |
| 对数代理 | 因子类对新值执行正式 `roundedLog` | 保留区间量化与当前误差带框架 |
| 签名检查 | 相同因子组记录新整数值 | 固定档位、仅 CRT 新依赖的目标可由签名确定 |
| 最终比较 | `exactProduct/betterFactors` 乘入新 `critical` | 分支内按新乘积比较，不是旧目标重排 |
| 候选及资源界 | 内部调用的新因子工厂捕获同档 profile | 仍须逐项满足对应单调/资源假设 |

每档约束 `gcd=g` 且 `gcdChoices=[g]`，目标选 `damage`，因为合成评分已经有时间分母 `T`，不能再除一次 GCD。
本轮没有引入 DoT、AA、武器间隔收益或其它隐藏速度依赖，所以固定档位后仍可用单 CRT 因子，而不需增加二维签名。
这不同于只替换 `evaluationFunction`：那个做法只改返回数值，不能让内部 CRT 类、对数及证明跟随变化，前序实验已给出反例。
本轮 hook 的传播是窄模型的研究接入，不是已建成可接收任意目标的生产 API。
现有签名带证明仍以可信 MILP 最优/不可行状态为条件，不是独立机器可验的形式化最优证书。

跨 GCD 不能直接比较三个约分后的整数乘积。令 `P_g=WMDTQ_gH`，特性倍率 `τ=τ_int/10⁶`，实际评分恢复为：

\[
S_g=\frac{P_g\,d_g\,\tau_{int}}
{40000000000000\times10^9\times T_g\times10^6}.
\]

`d_g` 在三个分支分别不同，忽略它会改变跨档排序；时长或分母变化时也必须完整恢复。
runner 用 BigInt 分数交叉相乘选全局赢家，浮点 approximate 只用于展示与显式公式容差互查。
只有所有允许档位均完成最优或不可行证明，`globalOptimalityProven` 才为真；否则只记 `bestObservedIncomplete`。

## 4. 独立 oracle 枚举什么，以及独立到什么程度

[oracle.mjs](../../../scripts/experiments/real-job-model/oracle.mjs)针对同步场景遍历每个命名槽位的原始笛卡尔积，再遍历所有允许物理食物。
两枚戒指保留有序位置，只依据 unique 冲突拒绝非法装备组合；不按同属性合并物理身份，不先剪掉低分组合。
正式向量合并负责装备与食物贡献，oracle 自己用 BigInt 实现等级基础、队伍主属性取整、武器、DET/TEN/DHT、暴击和实际 GCD 计算。
目标直接算 `αN+βk+γcN` 的有理动作和，不调用 hook 的整数因子或三次多项式来决定 oracle 排名，也不调用 MIP。
它仍共用运行时数据、正式候选生成、基础属性与向量/食物准备，因而是独立评分与枚举路径，不是完全独立的数据导入器。
每个不同允许属性向量都与研究 runtime 分式精确相等互查；同属性的其它物理组合复用该值，仍全部计入枚举与身份统计。

| oracle 范围 | 原始装备组合 | unique 合法组合 | 合法装备×食物 | 满足允许三档的评分对 |
| --- | ---: | ---: | ---: | ---: |
| [固定食物](real-candidate-results/oracle-fixed.json) | 16384 | 8192 | 8192 | 3776 |
| [全部 17 食物](real-candidate-results/oracle-foods.json) | 16384 | 8192 | 139264 | 58688 |

这里的 `16384` 不是 unique 合法数；`3776/58688` 是满足输入允许 GCD 后的装备食物对数，也不是唯一属性向量数。
oracle 的计数恒等式检查原始枚举完整、unique 拒绝与合法总数相加一致、全部食物对恰好分为 GCD/速度拒绝与已评分集合。
每档和全局分别保存精确最优分式、全部并列命名槽位身份的数量及排序后摘要，另保留少量可读样例。
与 MIP 比对首先核对 bin、候选及输入/profile 指纹，再比较各档与全局精确最优值；不同并列最优身份不构成错误。
oracle 还同时统计旧 `damage/dps` 与新模型的赢家，供研究排序差异；不能把不同目标的耗时当作策略效果。
这两个穷举结果不覆盖未同步巨大镶嵌域；其它场景的求解器证明与回归须分别报告。
后续逐候选证书核验、跨模式结果汇总及独立代码复核的完成状态，以第 11 章和对应保存产物为准。

## 5. 固定配装复核负责真实身份和属性，不能代替最优性证明

[run-case.mjs](../../../scripts/experiments/real-job-model/run-case.mjs)对每个已返回的分支赢家执行以下检查：

1. 逐槽确认完整候选身份属于原始未剪枝池，物理食物也属于原始许可集合。
2. 还原 11 件 MNK 装备；检查 unique，保留实际魔晶石/自定义参数身份。
3. 构造正式 `calculateFixedGearset` 输入，以原同步目标、食物与装备重新计算。
4. 比对全部职业属性及 PDMG、MDMG、DLY 与“基础属性＋搜索贡献”一致，确认实际 GCD。
5. 固定配装通用伤害与普通向量公式互查；新动作和另与恢复单位后的精确分式互查。

固定配装入口仍输出原通用伤害，不能因为属性复核通过就称生产计算器已支持新职业评分。
这组检查证明返回身份可还原、属性与评分一致；不存在更优解仍由完整 oracle 或条件 MILP/签名证明承担。
自动义军分配不在本轮兼容审查范围，不能把脚本保留的通用参数还原代码当作该范围已验证。

## 6. `off`、`on`、`certificate` 的实际含义

| 模式 | 显式配置 | 保留的共同部分 |
| --- | --- | --- |
| `off` | 不继承 canonical 信任标记；primary/main 资源支持设 false；conditional 与资源候选界 profile 均 disabled | 合法候选、真实公式、新 CRT 因子、整数模型、精确乘积和签名带证明 |
| `on` | 通过本轮兼容检查后继承标记；primary/main 设 true；conditional 选 `compact-weighted`，资源候选界 profile 为 default | 同一候选域、profile、档位和最终证明 |
| `certificate` | `on` 配置＋合法贪心 seed＋额外候选上界证书预处理 | 剩余候选仍执行同一完整 Exact-MIP，不靠 seed 返回推荐 |

`off` 不是关闭全部数学优化或证明的穷举后端；`on` 也不是每一个设置名对应的机制都必然执行。
例如 primary 已启用时独立 main-only 分支不另开；canonical 候选界还有候选数量等 gate，小场景标记为 true 但 gate 可为 false。
应读取保存的 `optionalPolicy`、模型统计与 PROFILE 事件确认实际执行，不能仅凭 mode 名称归因。
兼容检查限定 MNK、非负三次系数、`w≥0`、正安全因子以及无自动义军参数；未覆盖其它目标形态。
`certificate` 同时包含独立坐标乘积界与 DET-DHT AM–GM/CRT 支持界，不能把整组模式的收益都称为单独 AM–GM 的贡献。

## 7. 候选证书的全乘积上界

[certificates.mjs](../../../scripts/experiments/real-job-model/certificates.mjs)固定待测槽位候选 `e`，对其余槽位求补全上界。
第一层逐属性取其余槽位最大贡献，再加食物逐属性最大 cap，得到 `upperVector(e)`。
所有因子在本轮支持域单调，因此 `P(upperVector)` 覆盖任何真实补全；这可能组合了不能同时取得的属性，属于有意放宽。
若这个完整乘积已经严格低于同档合法 seed 的 `P₀`，候选可安全删除；否则再尝试相关性更强的第二层。
原始 seed 的各槽候选明确保留，确保同时删候选后仍保有该合法下界。

第二层选择 seed 的正因子 `D₀/H₀` 作为尺度，令 `D/H` 为任意补全的 DET/DHT 因子：

\[
L=D/D_0+H/H_0,\qquad DH\le D_0H_0(L/2)^2.
\]

这是正数 AM–GM；不假定真实最优恰好满足 `D/D₀=H/H₀`，尺度只影响松紧，不影响安全性。
对装备＋食物贡献 `a_D/a_H`，脚本使用并逐整数范围核对连续仿射包络：

\[
D\le1000+140a_D/det,\quad H\le4000+550a_H/div.
\]

因此 `L` 的上界可写为 `(I+w_D a_D+w_H a_H)/A`，其中：

\[
w_D=140H_0div,\quad w_H=550D_0det,\quad
I=(1000H_0+4000D_0)det\,div,\quad A=D_0H_0det\,div.
\]

层级参数与当前贡献范围内若有真实因子超过包络，就跳过整个可选策略；不能把未验证的连续近似当安全界。
将每个其余槽位候选映成 `(CRT贡献, w_D DET贡献+w_H DHT贡献)`，构造分段凹上包络支持函数。
支持查询在给定总 CRT 区间内求线性资源的连续放宽上界，保留负斜率；不按平均收益只留若干候选。
unique、戒指配对和精确 GCD 耦合在这个上界中放宽，不从正式模型删除；放宽扩大集合，因此不低估真实可行补全。

## 8. 食物 cap 的 CRT 平移为何仍保守

令 `b̄` 为各属性跨全部食物分别取得的最大 cap；这些 cap 不必来自同一个物理食物。
对固定候选 `e` 与其它槽位总贡献 `z`，定义平移后 CRT 坐标 `t'=e_C+z_C+b̄_C`。
真实食物 CRT 增益不超过 cap，所以 `t'` 不小于真实 CRT；`Q_g` 单调，允许用 `t'` 给真实 CRT 收益作上界。
支持区间 `[lo,hi]` 按这个平移坐标划分，查询时减去固定偏移 `e_C+b̄_C`，因此每个真实装备补全都有对应区间。
DET/DHT 的仿射常数也加入 `e` 与 `b̄` 的贡献，再加该区间内其余装备的支持上界，得到 `L≤L̄_[lo,hi]`。
不能在 CRT 使用 cap 平移，却让查询约束真实食物 CRT 后的坐标；两种坐标混用可能把补全排除在区间之外。

其它因子取逐坐标独立上界 `K̄=W̄M̄T̄`，则该区间内完整新乘积满足：

\[
P\le \overline K\,Q_g(tier(hi)-50)\,D_0H_0
\left(\overline L_{[lo,hi]}/2\right)^2.
\]

这一式同时覆盖 CRT、DET、DHT 和其它因子，不是只证明某个二因子子乘积较小就删除装备。
食物的身份、百分比、取整、封顶仍在正式 MIP 中按原规则处理；证书只用 cap 放宽，没有删除食物候选。
区间端点、支持值及乘积比较以整数/BigInt 有理数进行，不靠浮点误差容差判定严格小于。
同一食物上界向量里各属性来自不同食物会使界变松，不能据此声称找到了一份实际食物配置。

## 9. 严格平局、工作预算与失败语义

对某候选覆盖的全部 CRT 区间，只有每个非空叶区间的全乘积上界都严格小于 `P₀` 才删除；相等时保留。
不能闭合的区间继续二分；单点仍不能严格排除、数值安全检查失败或支持原语不能处理时，保留候选。
这避免把并列最优候选误删，也避免只检查部分区间后把未检查部分当作不可达。
证书支持构建量、查询次数、单候选节点数及预处理时间都有预算；达到预算只跳过未证完的剪枝，不截断候选尾部。
先前已严格证明的删除可以保留；当前未闭合候选和后续候选进入完整求解，失败/跳过原因进入统计。
证书中的 `removedCandidates` 保存身份、方法、上界分子分母和 seed 乘积，可供后续逐候选独立审计；保存记录不等于该审计已经完成。

runner 从冷 bootstrap 前建立全局 deadline，三个 GCD、候选准备、证书、求解和复核共用该预算，不每档重新领取完整时限。
`run-suite` 另有进程 watchdog；触发、取消、错误或未完成分支都不能把已有最好结果标成全域最优。
可选证书预算耗尽而完整 MIP 仍完成，正确性可以成立；全局搜索预算耗尽则必须记录未完成。
精确一致性、候选合法、签名证明、独立 oracle、一致输入与耗时效果分开报告；具体运行完成状态和性能归因留给[第 11 章](11-真实候选完整耗时与实施建议.md)。

本轮方法支持“真实候选＋三档合成收益目标”的有限域研究。它没有修改生成数据、生产源文件、默认职业目标或界面，也没有解除[当前条件最优性证明](../../当前搜索算法最优性证明.md)的求解器可信前提。
