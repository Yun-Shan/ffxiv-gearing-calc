# 通用建模与耗时优化：按依赖与证明能力复用

状态：研究设计，未接入生产；已有真实候选隔离后端验证。入口见[研究导航](README.md)。
模型公式与多 GCD 系数见[模型数学](01-模型数学与多GCD系数.md)，资料及场景身份见[数据与循环预设](02-数据与循环预设.md)。
本文回答“职业模型能否与通用耗时优化共用底座”；结论是可以，但必须按数学依赖和已证明能力接入。

依据新增数学探索档案的深入迁移分析见[08](08-数学探索成果迁移与新证明.md)，实际复现见[09](09-新增验证与复现记录.md)。其中三次曲率端点证书、共同多 GCD 弦线可继续探索；旧二次单峰段算法已被 MNK 反例否定，不能直接复用。

2026-10-24 补充的[真实候选方法](10-真实候选搜索方法与正确性.md)和[完整耗时](11-真实候选完整耗时与实施建议.md)已把窄模型接入正式 Exact-MIP 的隔离进程。40 次计时均完成且最优分数一致；正式资源行在部分场景退化，候选证书也有正负收益。本页的能力复用条件仍成立，但不得据其正确性直接默认启用全部策略。

## 1. 当前实现事实与建议接口分开

当前工作区没有统一的 `strategies/` 目录或 `auto/on/off` 策略层，不能把历史分支设计当成已启用能力。
现有控制分布于 Exact-MIP 选项、canonical evaluator 的 WeakSet 信任标记、[候选资源策略](../../../src/domain/search/candidate-resource-support-policy.ts)及共享饰品支配策略。
[单职业协调](../../../src/domain/search/exact-mip/single-search.ts)与[模型准备](../../../src/domain/search/exact-mip/model-preparation.ts)仍按当前六因子目标组织精确搜索。
传入新伤害回调不会自动改掉内部整数因子、候选界、签名排除或联合评分。

正式可达性路径使用 `reachableFinalAttributeValues`，再由 `retainReachableFactorClasses` 筛除不可能的因子类。
正式资源目标界是 [factor-resource-budget-upper-bound.ts](../../../src/domain/search/factor-resource-budget-upper-bound.ts)，由候选界模块调用。
`joint-substat-reachability.ts`、`substat-factor-budget.ts` 有可研究原语，但本次源码核查未发现生产路径外部调用；不计作已启用的加速。
建议的“目标描述”是受限编译契约，尚非现有公开 API；首步不要求建设宏大的策略注册框架。

目标描述至少要使以下事实可检查：精确评分及分母、依赖坐标、合法档位、足够签名、因子/联合块、可用保守界。
规则版本、profile、等级、场景和允许 GCD 也须固定；只有职业名称或一个任意函数远远不够。
基础后端必须完整支持该目标，才谈得上按能力启用额外优化。
不兼容时关闭旧优化，不能修复一个仍然证明旧六因子的后端。

## 2. 三类机制的复用条件不同

| 分类 | 例子 | 新模型接入要求 | 资料、预算或证明不足时 |
| --- | --- | --- | --- |
| 可行域事实 | one-hot、食物整数取整、unique、共享物理身份、原始属性可达性 | 保持完整依赖和身份，原规则等价 | 必需规则缺失则失败；可选加强不确定则保留域 |
| 依赖目标的加强 | 属性支配、因子压缩、候选目标界、资源收益界、pair/triple cuts、比例包络 | 用新目标重建收益、单调性、区间及保守界 | 跳过该加强，进入同目标的完整基础路径 |
| 正确性与证明路径 | 精确目标比较、足够签名、量化误差带、求解状态、重建复核 | 新目标须逐项成立，不能作为可选策略 | 拒绝不支持模式；未完成不得返回近似推荐 |

可行域事实也有适用域：旧属性投影遗漏 AA 间隔后不再完整；未知 unique 元数据不能默认为非 unique。
属性相等压缩只有在所有目标与约束依赖、共享身份和合法配对都等价时安全。
支配关系还依赖新模型单调性；有 GCD 离散约束或速度上限时，速度更高不能直接宣称更优。
原始单轴可达集可以给出安全超集，但各轴分别可达不代表它们的组合可达。
超集只会使界变松；把未验证相关性当不可达而删掉组合才会损害完整性。

## 3. 先代数合并，再选择最小依赖块

固定 profile 的动作权重已经确定时，应先合并重复公式和恒定系数，不为每个动作新建装备决策变量。
窄 MNK 模型在特定假设下可将普通、必暴及斗气反馈合成 `C_g(CRT)`，并保留公共基础因子和普通 DHT 因子。
多项式阶数提高不必增加依赖维数；“更真实”也不等于必须构造所有属性的联合表。
但逐技能 floor、保证直击补偿、DoT/AA 或状态期望会破坏某些分离，必须从实际公式而非职业名称判断。

若各 GCD 的表为 `F(g,c)`，只有存在正函数 `a(g)`、`b(c)` 使 `F(g,c)=a(g)b(c)`，才可拆为独立档位与 CRT 因子。
对于完整矩形且元素为正的有限精确表，这相当于矩阵秩为 `1`，可用所有二阶子式为零检验：

\[
F(g,c)F(g',c')=F(g,c')F(g',c).
\]

例如 `[[1.00,1.10],[1.20,1.32]]` 可拆，右下角改为 `1.33` 就不可拆；应交叉相乘精确分式，不能设浮点近似容差。
含不可达空洞的域不能将缺项填 `0` 后直接套这个判据；应证明支持域上存在一致分解，或保留联合块。
系数表未成比例不等于必须使用一般分项和后端，可保留 `(g,CRT)` 块，在固定 `g` 后也可退化为单 CRT 因子。
同理，若保证直击造成 CRT×DHT×DET 耦合，仅将真正耦合的坐标放入块；不必牵连全部主属性和武器坐标。

优先提取公共正因子与精确常数，再在剩余表达式中找最小依赖块。
不同块仍须与同一套真实属性变量绑定，不能为了分离求值而允许矛盾的属性选择。
若表达式无法变成正因子乘积，应研究非负分项和的完整后端；`log(Σ项)` 不等于 `Σlog(项)`。
BigInt 能比较分项和，只解决数值排序，未解决代理目标、签名搜索和全局排除证明。

## 4. 多轴资源支持：原始预算可共享，目标收益要重建

对非负权重向量 `w` 和真实装备/食物属性贡献 `a`，可从每槽最大值构造安全预算：

\[
w\cdot a\le B_w=\sum_s\max_{e\in E_s}w\cdot a(e)
+\max_f w\cdot b_f^{upper}.
\]

这里按原模型一致处理基础偏移，`b_f^{upper}` 是食物实际贡献的保守上界。
各槽最大值及食物最大值可能不能同时达到，因而该式是放宽，不是实际最优属性估计。
现有资源支持用因子对数斜率选择若干非负权重方向，右侧仍由真实候选构造。
斜率影响约束紧度，不把经验斜率直接当作伤害上界；换目标后可重选方向，但任意新方向都要守住原始预算。

若联合块状态 `z` 覆盖多个原始坐标，需为每个方向计算保守最低成本：

\[
c_w(z)\le\min_{a\in A_z} w\cdot a.
\]

`A_z` 是该状态允许的全部属性元组，成本必须不高估；不知道相关性时，可用逐轴下界之和形成更松的下界。
对 `(g,CRT)` 块，成本应同时含该 GCD 对应速度区间的最低贡献及 CRT 最低贡献。
但若速度成本已计入该块，就不能再把旧 GCD 组的同一成本加一次；CRT 也同理。
预算坐标与目标因子不是同一概念：一个 CRT 同时影响自然暴击、必暴和斗气，不能为三项收益各收一次 CRT 成本。
若多个块依赖同一原始坐标，要么合并，要么通过共同属性变量/经证明的成本分配计费，不能直接累加各块最低成本。
目标对数也须每个乘法块计一次；重复计收益会产生另一种错误的上界。

设块覆盖互不重复的资源，`q_b(z)` 是其精确量化对数贡献，`λ≥0`。
由资源约束可构造拉格朗日上界：

\[
\sum_b q_b(z_b)\le\lambda B_w+
\sum_b\max_z\{q_b(z)-\lambda c_w(z)\}.
\]

这解释现有单预算支持包络为何可安全放宽相关性；多轴可取非负价格向量，但必须重新证明成本与偏移。
上界返回整数时向保守方向取整，既不能低估对数代理，也不能忘记代理到真实分数的误差转换。
旧 `ResourceBudgetFactorClass.min` 是单一标量成本，不能未经适配就拿来表达任意二维状态。
一般分项和可研究各非负分项安全界之和；它通常更松，不能继续调用只证明乘积/可加对数的旧界。
条件资源行只有在其条件域也正确映射到新块时可沿用；旧 CRT 区间不能直接当新联合块的区间。

## 5. 签名充分性与数值位宽是性能底线

任何被 no-good 一次排除的签名，都必须确定真实目标；同签名不能藏有更高分方案。
新模型至少检查：所选 GCD 系数、CRT/DHT 联合值、DoT 速度倍率、AA 间隔、buff 场景和动态资源状态是否已确定。
“显示 GCD 相同”不保证这些量相同：已有合成例中 SKS 贡献 `42→43` 时 GCD 同为 `1.99`，但 `ssDamage` 为 `1.001→1.002`。
若新目标使用该倍率，旧六因子＋GCD 签名就不充分。
如果固定档位内所有依赖已被其它因子或联合块完整确定，才无需额外保存原始速度值。

正因子改变后，应重新生成精确值、量化对数、组数与误差带；联合块计一个量化组并不代表其资源只占一个坐标。
按档约掉的常数必须保留恢复信息，跨档比较与联合基线都使用恢复后的共同单位。
当前 `FactorClass.value` 和 `roundedLog` 接收正安全整数 Number，后续 BigInt 乘积不能补救此前的失真。
有理权重可统一分母并约公因子，但不能舍弃小差值；超安全整数时要扩展表示和证明，或拒绝该 profile。
一般分项和、零因子及负项不自动满足现有正因子对数前提，不能悄悄沿用签名带。

## 6. 缓存、静态共享与 Worker 的边界

稳定规则、动作分类、profile 的有理系数编译及候选结构可在同一冻结请求内共享。
按 `g` 分解时，可复用目标无关的槽位合法性、食物描述和静态矩阵；不能复用仍含旧系数的可变目标行。
候选域仍须覆盖全部允许 GCD，不能先用某一档的支配结果删池，再供其它档使用。
排除签名、当前最优、动态 cuts、求解器行和阶段工作预算归各次搜索所有，不跨任务共享可变对象。

| 缓存内容 | 必须决定缓存身份的输入 |
| --- | --- |
| 编译后的模型规则 | 规则/profile 定义、游戏版本、职业、等级、场景、计分单位、精确参数 |
| 因子或状态求值 | 实际所有依赖坐标、GCD、暴击反馈、buff/初始资源/时长等动态输入 |
| 受限搜索结果 | 候选与约束指纹、完整目标身份、允许 GCD 集合、固定共享装备/食物及逐孔/参数身份 |
| 上界 | 同一目标与候选域、条件节点、缩放、已证明适用范围；精确结果与保守界分开存储 |

当前[受限缓存](../../../src/domain/search/joint-loadout/restricted-search.ts)属于单次调用，键为职业、固定共享身份和食物；其它输入由闭包冻结。
局部键在此作用域内成立，不应无条件推广成跨请求全局键。
未完成/取消不是不可行，不能写成表示无解的缓存项；父结果复用也须区分已证明最优与仅可行。
缓存保持有界；冷启动必须计入准备成本，不靠离线大表或隐藏预热获得性能结论。

[并行执行器](../../../src/domain/search/parallel-baseline-executor.ts)已有 Worker 池、就绪后发请求、结果归属和取消清理机制，可研究复用。
新 profile 必须可序列化重建，不能假定函数闭包或 WeakSet 信任标记随消息传输自动保留。
职业并行与档位并行应共用一个有界调度预算，避免每职业再独立开启最大并发而成倍超配。
全部阶段共用搜索截止时间和取消信号，排队、构建、基线、档位与联合阶段都消耗同一总预算。
正式浏览器搜索继续不设搜索时限；Node 测试/验收的保护预算另算，不能每档重新获得一份完整时间。
取消须停止排队与活动求解并清理，不能只取消 UI 的等待；取消后晚到的结果不得进入新请求或历史。

## 7. 结构规模不是耗时基准

既有合成实验记录旧 CRT 因子 `288` 类，合并 MNK 因子也是 `288` 类，DHT 为 `792` 类。
独立域相加为 `1,080` 个值，朴素 CRT×DHT 表为 `228,096` 个组合。
若假设每个 GCD 仍有 `288` 个 CRT 类，三档为 `864` 项、十档为 `2,880` 项。
这些是说明依赖维数的结构计数，不是生产变量数、可达联合状态数或新目标求解实测。
实验的固定资源网格不能达到所有笛卡尔组合；真实生成还受候选、食物、动态参数和约束影响。
即便类数不变，新收益曲线也可能改变上界紧度、量化间隔、签名带密度及 MILP 分支数。
因此不能据这些计数承诺耗时不变、线性增长或满足每职业 30 秒目标。
原始实验与版本限制集中见[来源与探索证据](07-来源与探索证据.md)。

## 8. 性能实验分三组，先过正确性门槛

| 实验 | 固定的内容 | 可回答的问题 |
| --- | --- | --- |
| 模型成本 | 真实候选与硬约束；分别明确 legacy 与新 profile 目标 | 排序差异、编译与求值成本；目标不同，不能归因为策略提速 |
| 策略效果 | 同一新目标、profile、输入 bin、候选域、后端和证明要求 | 完整基础路径与兼容优化的端到端耗时差异 |
| 后端选择 | 同一多 GCD 数学目标、候选、共享身份与证明范围 | 按 `g` 分解与联合块后端的构建、求解及内存取舍 |

正确性 gate 包括：同签名同值、小域完整穷举一致、所有补全下上界不低估、分解/联合相同最优值、重建合法且证明完成。
还须覆盖 legacy 无变化、各 GCD 系数缩放、相同显示 GCD 下不同速度倍率、共享食物和不可行档位。
有并列最优时比较精确目标和合法性；不把不同合法身份误报为不一致。
未过 gate 的更快运行不进入提速结论；超时、无完成证明及错误结果分别记录。

策略与后端计时采用同机 ABBA 顺序，固定 Node/浏览器、HiGHS、并发、保护条件及完整输入指纹。
冷缓存与热缓存分组，预热与编译有明确计时边界；候选、动作规则或因子表不能在对照一侧被藏到计时外。
记录候选准备、profile 编译、因子/可达性、资源支持、模型构建、solver、签名证明、联合基线、受限搜索与重建的耗时。
同时记录变量/行/非零项、因子与块状态数、solver runs、签名检查、候选削减、缓存命中、策略跳过原因和实际可测内存。
浏览器无进程 RSS 时明确不可测；不能把 JS 堆或模型数组大小冒充进程内存。
重复样本和机器/数据/目标指纹随报告保存，遵守[正式性能验收说明](../../search-optimization/README.md)，不替换既有基准。

可选预处理达到工作/内存预算时，应丢弃未证明的加强并继续同目标完整路径；fallback 的触发及耗时也计入总时间。
若爆掉的是唯一完整后端、全部签名检查或全局搜索预算，则是未完成，不能 fallback 为旧目标或近似推荐。
分支间共享界可以减少重复工作，但安全界的作用域、证明版本和全局预算必须一致。
实施时先接通 legacy 与经验证的窄 MNK 描述，再逐项测兼容优化，避免同时改模型、策略、候选和并发导致原因不可辨。
单职业路径见[单职业精确搜索](03-单职业精确搜索.md)，联合基线与外层界见[多职业联合搜索](04-多职业联合搜索.md)。
最终交付条件和待确认范围见[实施与验收](06-实施与验收.md)；本页没有声称新目标已获得生产性能或最优性验收。
