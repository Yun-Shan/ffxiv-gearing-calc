## 2. 哪些原脚本可以直接复跑

以下脚本只依赖档案内纯数学原语，本轮从当前仓库根目录直接执行通过，未写入原档案：

```powershell
node 'docs/数学探索-证明与复现/docs/mathematical-analysis/theorems/coupled-product-support/verify.mjs'
node 'docs/数学探索-证明与复现/docs/mathematical-analysis/theorems/coupled-product-support/verify-product-cuts.mjs'
node 'docs/数学探索-证明与复现/docs/mathematical-analysis/theorems/coupled-product-support/verify-axis-radius.mjs'
```

| 脚本 | 本轮通过记录 |
| --- | --- |
| `verify.mjs` | 1000 个乘积仿射上界检查、500 个支持界检查、120 个独立 LP 顶点等值检查 |
| `verify-product-cuts.mjs` | 24 条加强行、1944 个整数取整检查 |
| `verify-axis-radius.mjs` | 12000 个有理损失半径检查 |

另以无写入内联脚本复现原唯一配对验证的 1800 个域、103382 个原始配对和 36000 个价格查询，逐行匹配档案已有 JSON。该次复现只确认原函数行为；新脚本另用按物品 ID 一致的 unique 元数据验证可迁移用途。

以下路径问题阻止直接复跑原始真实候选/完整求解脚本：

- 档案内缺少多个脚本引用的 `docs/mathematical-analysis/verification/canonical-model.mjs`。历史 Git 对象本地可读，可以查看原 helper，但不能仅补 helper 就宣称环境已经一致。
- 原脚本的 `../../../../src/...` 在当前嵌套目录指向**档案根内的 src**；该目录不存在。原材料要求按原仓库相对位置放置，不能原地执行后忽略导入错误。
- 部分内存插桩匹配旧单体 `loadout-finder-exact-mip.ts` 的字符串锚点；当前同名文件仅转发，实际实现已分到 `exact-mip` 模块。修好文件路径仍不保证插桩生效。
- 原插桩只在主线程注册时不一定覆盖 Node 基线 Worker。正式性能实验须证明干预实际执行，并记录每个线程调用数量，不能把未生效实验当作无收益对照。

因此本轮使用档案纯数学核和当前公式写独立适配实验；没有修补原档案、覆写历史数据或启动旧版完整 MIP 基准。

## 4. 新实验二：多职业区域与等价商

脚本：[job-model-joint-certificates.mjs](../../../scripts/experiments/job-model-joint-certificates.mjs)。结果：[job-model-joint-certificates-results.json](job-model-joint-certificates-results.json)。

```powershell
node scripts/experiments/job-model-joint-certificates.mjs
```

固定种子 `1779033703`，精确 BigInt 分式运算，直接导入档案 `uniquePairOracle/uniquePairHull`。所有动作、私有选择和 GCD 标签为一般正目标的合成输入，不是来自真实职业的循环。

| 验证项 | 实际规模与结论 |
| --- | --- |
| 固定共享后的跨 GCD 分解 | 96 个域、73269 个完整联合点；固定共享后各职业独立取跨档最优，与联合完整枚举相等 |
| 职业基线 | 每职业覆盖所有共享状态与允许 GCD，再冻结为联合分母；所有比例处于 `(0,1]` |
| 乘积与稀疏损失区域 | 精确穷举 Pmax 构造上界；两种下界下 37462 个可追平点次全部保留，72368 个管外点次被排除 |
| 等号边界 | 全部比例为 1、只有一个职业有损失时 η=0，仍保留合法同分点 |
| 旧等价商失效反例 | 新函数独立最优 2，错误同特征约束只有 `131/67`，差 `3/67` |
| 等价商正例 | 完整新函数相同时，按共同特征取代表不降低最优值 |
| 唯一戒指线性支持 | 603 个域，20120 个原始配对、18208 个合法配对、16884 个有理价格查询，均与完整合法配对枚举相等 |

脚本共执行 1365701 次精确断言。不同 incumbent 会重复检查同一个点，因此“点次”不能当作更多独立候选；管外排除数量也不是实际配装组合压缩率。

乘积上界来自本有限域的完整枚举。`L/(L−m)` 部分只展示对已知上界的有理保守放宽，未使用 `Math.log`，也没有认证新目标量化代理或 HiGHS 最优状态。按 ID 一致的 unique 元数据、空池、不可行配对及正负线性价格均有覆盖；凸包插值点没有作为物理候选返回。

## 5. 复现一致性与独立复核

新脚本均成功执行并保存结果。数学迁移脚本包含执行时间 `runAt`，复跑比较时只忽略该字段；联合脚本输出确定，不含时间字段。其余内容必须完全相同，包括来源 SHA、所有精确分数、计数和反例。

本轮进行了独立只读复核：检查公式推导、端点判据、双峰反例、整数边界、候选上界、全域基线、损失区域和证据表述；复跑结果与保存文件一致。链接与文档检查是交付验证的一部分，不替代任何数学证明或生产后端测试。

复现命令应检查子进程退出码，不能只因 PowerShell 输出重定向生成了 JSON 文件就视为成功。保存新结果时保留原档案，以便区分不同版本与实验范围。

## 6. 这些验证改变了什么

- 增加了一项便宜的精确能力判定：每个三次 profile/CRT 区间/k 用两个端点决定弦线证书是否可用。
- 给出了多 GCD 的共同安全界，可以先尝试全域证书，再按必要性细化档位，而非一开始展开全部联合状态。
- 找到旧一峰算法的严格失效例，必须从候选实现中排除直接照搬路径。
- 证实若保持新目标的完整依赖，双属性余数消元、支持函数、联合损失不等式和唯一配对支持仍值得继续。
- 证实旧职业等价不能跨目标直接复用；职业模型越丰富，原先可省略的特征越可能需要恢复。

这些结果加强了[06](06-实施与验收.md)的模型与搜索方案，没有完成其中 R0—R5 的生产交付。

## 7. 下一轮正式实验应回答的问题

| 问题 | 所需证据 |
| --- | --- |
| 默认 MNK profile 是否代表实际玩法 | 同版本动作资料、等级规则、固定场景和独立循环对照 |

| 共同弦线还是按 GCD 分界更合算 | 同一允许域、相同完整性下的准备成本、证书查询、模型规模和完整耗时 |

| 新等价商能压缩哪些真实配置 | 全部约束、目标及代理函数验等，合法物理装备还原与正式最优值一致 |
| 唯一戒指增强是否值得启用 | 在同一上界体系内单独开关，保留负收益与超时记录 |

本轮没有新的真实装备最优收益、正式 MIP 加速倍数、浏览器验收或 30 秒性能达标结论。原档案的正负性能结果仍作为选择实验方向的依据，不能当作新职业目标已经取得的收益。
