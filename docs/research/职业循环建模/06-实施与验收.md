# 实施顺序、实验设计与验收门槛

研究提案，2026-10-23。返回[总览](README.md)。本文件负责将分析转成可执行的交付边界，不表示已实施或已批准生产模型。已有证据与缺口见[07](07-来源与探索证据.md)。

## 1. 三条验收线分别给结论

| 验收线 | 回答的问题 | 通过证据 |
| --- | --- | --- |
| 规则与模型 | 公式有无误用？场景假设是否足以支持所声称用途？ | 同版本规则、确定数值、场景说明、合法配装敏感性与独立对照 |
| 搜索正确性 | 是否优化了同一新目标，是否完整覆盖允许域？ | 小域穷举、签名充分性、上界不低估、正式路径完成证明 |
| 算法耗时 | 在同样结果与证明要求下，优化是否节省时间和内存？ | 同机同目标对照、完整阶段计时、结果与证明一致 |

“公式算出合理数值”“求解器返回 optimal”“比旧模型快”都不能同时替代这三条验收。特别是旧目标与新目标的分数和最优装备可能不同，不能把改变目标导致的差异当优化回归，也不能以速度提升抵消证明失败。

## 2. 建议实施阶段

以下 R 编号仅属于本研究的实施提案，与其他搜索重构任务的阶段编号无关。

| 阶段 | 本阶段交付 | 必须满足的退出条件 |
| --- | --- | --- |
| R0：支持范围与目标契约 | 选定游戏版本、最高等级/同步范围、默认单体场景、评分单位、GCD 支持域和模型身份 | 必需资料取得或缺口明确；产品评分及不支持行为确认；不混版本 |
| R1：规则与固定配装 | 命中类型、资源触发、有理系数、按实际 GCD 计算指定配装的分数 | 确定输入输出测试、等级/取整/概率边界、分项与合并一致；实际完整配装对照 |
| R2：统一目标描述 | legacy 和首个 MNK 目标通过同一受限描述提供精确求值、签名及能力 | legacy 数值、候选、排序及证明不变；所有目标消费者都接收同一冻结定义 |
| R3：固定 GCD 搜索 | 一个固定 GCD 下新 CRT 因子进入正式 MIP、签名和上下界 | 与完整小域 oracle 一致；不存在 callback-only 假接入；真实候选完成证明 |
| R4：多 GCD 协调 | 一次请求自动分档、共享安全准备、比较统一分数、整体取消 | 覆盖所有允许可达档位；分支状态明确；时间/倍率恢复；最高坚韧等前置目标全域一致 |
| R5：联合与应用集成 | 全域职业基线、受限搜索、共享身份、Worker、固定导入、历史与确认后的界面 | 联合 oracle 一致；Worker/缓存/快照正确；界面用真实浏览器验证 |
| R6：联合块与更多机制 | GCD×CRT 单模型、CRT×DHT/DET、DoT/AA 等逐项扩展 | 各后端先证明，再与已正确后端同目标比较；性能收益实测后决定启用条件 |

R0—R1 的首要问题是模型依据；R2—R4 的首要问题是目标与证明集成。R6 不应成为支持多 GCD 的先决条件，也不能因为 R6 未做就把 R4 的用户流程限制成只能选一个 GCD。

每阶段只改变当前需要的边界，保留可复现的 legacy 模式用于回归。新目标不支持时，必须报告所选模式不支持；任何切换通用目标的行为须由明确产品契约决定，不能在搜索中途悄悄发生。

## 3. 代码与规范的交付边界

| 边界 | 需要维护的契约 | 不能顺带改变 |
| --- | --- | --- |
| 数据生成与二进制 | 经核实的新业务字段、统一导入及编解码校验 | 不能手改生成文件或另建未经授权的生产来源 |
| 领域规则 | 计分单位、模型范围、等级/同步/资源语义 | 装备资格、魔晶石政策、固定配装完整性保持原规则 |
| 目标与求解 | 显示/向量/整数评分一致，候选与证明依赖完整 | 不得取消强制最优性复核或换成排名截断 |
| 并行与缓存 | 冻结目标、传输场景、全局任务生命周期 | 不复用旧模型或半完成分支值 |
| 历史与分享 | 新目标输入身份及结果解释，旧记录保留原值 | 不以 `dataVersion` 差异阻止旧历史读取或自动重算 |
| UI | 评分解释、支持范围及状态反馈 | 新内容/流程须确认，不在此次研究中直接实施 |
| 文档 | 更新对应领域规则、顶层职责、证明假设与命令入口 | 本专题中的提案不能自动覆盖当前规范 |

具体生产入口集中在 [rules.ts](../../../src/domain/rules.ts)、[equipped-effects.ts](../../../src/domain/search/equipped-effects.ts)、[exact-mip](../../../src/domain/search/exact-mip)、[joint-loadout](../../../src/domain/search/joint-loadout) 及应用结果/历史消费者。实施时先追踪实际调用，不按文档文件清单机械改造。

## 4. 规则与数学测试矩阵

| 编号 | 用例 | 必须断言 |
| --- | --- | --- |
| M01 | 普通、必暴、必直、双保证、禁止命中类型 | 正确倍率与取整，不重复计算普通概率；buff 概率转换与裸属性分开 |
| M02 | MNK 等级、动作资格与例外 | 38/74 等级边界按同版本资料；必暴/非战技/六合等按实际规则处理 |
| M03 | 基础威力、事件次数、频率和时间分母 | 单位一致，事件资格不能由威力占比代替；没有重复除 GCD |
| M04 | 分项和与合并 CRT 因子 | 精确分式相等，包含零权重、边界 CRT 和公共因子约分 |
| M05 | 多 GCD 可分离与不可分离表 | 精确 rank1 判据；基函数相关/有限域退化时不能错误拒绝合法合并 |
| M06 | 同显示 GCD、不同速度衍生量 | 目标依赖存在差异时签名不同，缓存不能碰撞 |
| M07 | 资源上限、结束余数、初始资源 | 长期均值与有限时窗区分；声明不支持的模型不能伪造精确状态 |
| M08 | 有理数缩放和极大整数 | 正分母、准确比较、Number 安全范围；缩放不能抹去分支间差异 |

规则测试必须给确定输入输出或可核验等式，不能仅断言伤害大于零。对于社区模拟器对照，应固定其提交、参数与场景；差异按取整、buff、时间、资源近似逐项解释，不将社区输出直接当唯一真值。

## 5. 单职业、联合与运行测试矩阵

| 编号 | 用例 | 必须断言 |
| --- | --- | --- |
| S01 | 新目标两候选反序 | MIP 选择与新目标穷举一致，不能仍优化旧整数因子 |
| S02 | 单 GCD 与多 GCD 并集 | 所有分支最优的最大值等于全域最优；允许域内每档被完成或安全排除 |
| S03 | GCD 的区间/最终属性绑定 | 食物取整后 GCD、精确速度限制和 one-hot 选择一致 |
| S04 | 不可达、缺模型、取消、超时 | 状态互不混淆；未完成不产生已证明结果 |
| S05 | 最高坚韧等先行目标 | 在原始允许域先确定全局约束，再分档；不能各档使用不同优先目标值 |
| S06 | 候选/资源界与 cuts | 枚举小域全部补全，新上界从不低估；不可用加强保守跳过 |
| S07 | 联合职业全域 OPT | 不使用每档自己的基线；归一化数值和最终共享选择与 oracle 一致 |
| S08 | 共享戒指、食物、义军参数与强制孔 | 保留实体/镶嵌/参数身份、unique、固定约束和食物策略 |
| S09 | 共享分支与受限子搜索 | 基线保持全局不变；受限求解覆盖剩余可达 GCD，安全上界覆盖全部后续选择 |
| I01 | Worker 与串行 | 同一冻结输入得到相同精确值；传输不丢模型参数和依赖 |
| I02 | 缓存切换 | 职业、等级、场景、GCD域、CRT依赖、食物/共享限制改变时没有陈旧命中 |
| I03 | 历史与固定导入 | 原值保留；导入按指定完整装备计算，不搜索、不换档补装 |
| I04 | 全局取消与任务清理 | 已完成分支仅可作内部诊断，剩余未证明时不能当最终推荐 |

小域穷举是研究与回归 oracle，不应替代生产搜索，也不能由一个简化候选生成器漏掉原本承诺的合法选项。正式验收必须使用真实候选及所有适用硬约束。

## 6. 真实配装的模型效果实验

选择同版本实际合法完整配装，覆盖 CRT/DHT/DET 替换、邻近 GCD、食物切换和固定槽位；比较 legacy、新 profile 与固定参数的独立参考模型。记录动作/资源构成和差异来源，而非只记录一个总分。

至少回答：

- 排名变化是否来自预期机制，是否只在取整边界发生？
- 更换合理时长、队伍或默认策略后，排序是否稳定？
- 哪些参数需要用户知道，哪些可以安全作为固定默认？
- 分数差是否小于模型假设变化引起的差异？若是，应说明敏感性，不能用多位小数暗示实战确定性。

不同场景的分数不可直接混在同一最优比较中。若产品要优化多个场景的加权表现，须另行定义目标与权重，不作为多 GCD 支持的默认含义。

## 7. 性能实验与报告

详细方法见[05](05-通用建模与耗时优化.md)。这里规定交付报告至少有三组互不混淆的实验：

1. **模型成本**：legacy 与新模型保持候选、条件和环境一致，解释新增编译/求值/证明成本；目标不同不要求最优分数相同。
2. **策略收益**：同一新目标、同一输入、同一完整后端，对比可选策略关闭/启用；必须精确最优值一致。
3. **后端选择**：同一新目标与允许 GCD 域，比较按档分解和单模型联合块；必须先分别通过 oracle 和完整证明门槛。

采用独立进程的同机 ABBA 多轮，固定 Node/浏览器、HiGHS、堆大小、并发和数据 SHA；冷/暖缓存分别报告，初始化与预处理边界一致。性能预算只能控制可选加强的工作量，不能截断候选或关闭证明。生产前端仍按当前规则支持取消且不设置搜索时限；Node 保护时限用于实验管理，不把超时记成通过。

报告包括全程耗时、中位数和样本范围、各阶段耗时、候选/因子/变量/行/非零项数量、求解及签名计数、峰值 RSS 或明确的浏览器可测内存范围、启用/跳过策略及理由、精确目标与证明状态。只给最快一次或伤害函数微基准不足以选择正式路径。

每职业 30 秒继续作为跟踪目标。只达到速度目标但未完成证明不合格；完成证明但未达到速度目标应分别报告正确性通过与性能未达。

## 9. 必须停止或回退的条件

- 必需数据不全、版本不一致、目标单位未确定：停止该 profile 的生产接入。
- 新目标无法由当前完整后端表示：停止并实现受证明后端，不只关闭 canonical 标记后继续旧搜索。
- 可选加强预算耗尽或无法建立安全界：保留候选，继续同一目标的完整基础路径。
- 任一测试出现目标、身份、档位或基线不一致：先修复正确性，再继续计时。
- 支持域变化：重新验证覆盖与缓存输入，不能仅更新显示标签。

下一项可执行工作是 R0—R1 的数据与固定配装模型验证；在它们完成前，没有依据把合成系数发布为职业默认值。
