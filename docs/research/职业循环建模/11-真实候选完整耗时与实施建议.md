# 真实候选完整耗时与实施建议

研究日期：2026-10-24（Asia/Shanghai）。方法、上界证明与范围见[第 10 章](10-真实候选搜索方法与正确性.md)，入口见[专题总览](README.md)。

**本轮确认：窄 MNK 三次目标可以进入现有完整精确搜索，并与正式资源约束、候选支持界共同工作；但正确的优化并不保证更快。** 五个真实装备场景、两组 ABBA 共 40 次计时运行全部完成，同场景各模式的每档与跨档精确最优值一致。宽域候选证书有明确收益，但与资源约束一起开启仍未胜过该场景的基础路径。

这里的职业动作系数仍是合成输入。完整性针对允许 GCD `[1.94,1.96,2.00]` 和项目正式候选政策，不是对真实武僧循环、所有自然可达 GCD 或多职业联合搜索的验收。

## 1. 环境、输入与计时口径

| 项目 | 本轮实测 |
| --- | --- |
| 机器 | Windows x64，Intel Core Ultra 7 265K，20 逻辑处理器，约 47.4 GiB 内存 |
| Node / HiGHS npm | v26.8.1 / 1.15.3 |
| 仓库 HEAD | `303877be8f57d7b5215bf9d7d97850177372f8a3` |
| 运行时 bin 版本 | `2026.09.15.0000.0000` |
| bin SHA-256 | `4436a1374320e70ab60b8915e9b71a09a55a1a716658b63b43398ba9ca51989b` |
| 研究进程保护 | 全部三档共享 180 秒预算；父进程 210 秒 watchdog；本批没有触发 |
| 样本组织 | 每场景独立冷 Node 进程，串行 ABBA，每个模式在每个对照块中各 2 次 |

“冷”指每次重启 Node、模块与求解器实例；未清空操作系统文件缓存，也未模拟浏览器冷启动。计时期间没有并发求解或穷举任务，未锁 CPU 频率。研究插桩、诊断与精确浮点评分交叉检查的成本都在计时内，不能把这些数字直接当作产品 Worker 耗时。

主指标为父进程 `coldProcessWallMs`，从启动子进程到退出，包含模块加载、bin 解码、来源记录、候选准备、profile 检查、可选证书、三个 GCD 的建模/求解/签名证明、固定配装重建及结果写出。父进程收集完子进程后的摘要整理不计入。`runCase.elapsedMs` 从模块入口开始，和主指标不是同一边界。

每个分支保留模型准备、greedy、solver、签名检查、变量/约束、实际策略开关及 hook 命中。三个分支全部结束后才比较恢复单位的 BigInt 分数，不只计最快分支或首次找到可行解的时间。

| --- | ---: | ---: | ---: |
| 同步固定食物 `sync-fixed` | 36 | 16,384 | 1 |
| 同步全部食物 `sync-foods` | 36 | 16,384 | 17 |
| 非同步固定食物 `meld-fixed` | 157 | 2,290,942,476,288 | 1 |
| 非同步全部食物 `meld-foods` | 157 | 2,290,942,476,288 | 17 |
| 宽非同步固定食物 `wide-fixed` | 445 | 201,088,714,203,463,680 | 1 |

同步场景为装备 790—795、同步品级 735；非同步窄域为 790—795，宽域为 780—795。固定食物 ID 为 49245。装备笛卡尔积只表示完整原始域规模，不表示求解器逐套访问了这么多配装。

## 2. 正确性结果

| 检查 | 结果及覆盖范围 |
| --- | --- |
| 正式搜索 | 40 次计时运行，120 个固定 GCD 分支；每档均为可行最优，跨档比较完成 |
| 核心证明 | 每档一次 solver run、一次签名带检查，`signatureBandProof=true`；未删除签名/no-good/精确重建能力 |
| 开关一致性 | 五个场景中，`off/on/certificate` 的各档与全域有理分数完全相等；不同合法同分身份不判为错误 |
| 最终配装 | 每份返回结果均检查原始槽/食物身份、完整 11 件、unique、实际 GCD；固定配装入口重新计算属性、镶嵌与原通用伤害 |
| 独立 oracle | 固定食物允许域 3,776 套、全部食物允许域 58,688 套，与每档及全域 MIP 分数完全一致 |
| 独立公式 | 两个同步场景的 1,728 / 23,463 个不同允许属性向量，用独立 BigInt 分项公式核对研究 runtime；没有复用被 hook 的暴击多项式充当 oracle |
| 并列最优 | 同步两个场景中，所有原始并列最优身份所需候选均未被新增证书删除；全域均有 2 个按戒指位置区分的原始完整身份 |

验证器共检查 41 份完整 case，包含上述 40 份计时样本和一份不纳入耗时表的证书 smoke；总计 123 个分支。正式 MIP 证据仍承接现有[条件最优性证明](../../当前搜索算法最优性证明.md)对求解器数值状态的假设，不升级为一般 MILP 的形式化精确证书。非同步大域没有独立遍历所有装备组合；其证据是上界定理、正式完整搜索与开关一致性。

删除项不是只检查“最后赢家还在”。[验证脚本](../../../scripts/experiments/real-job-model/verify-results.mjs)重枚举原始同步域，对每个删项检查它在**所属固定 GCD**下的所有合法完成，确认记录上界不低估独立完整因子乘积，且严格低于经重建的可行 incumbent；同时检查各档所有并列身份所需候选都留在剪枝后槽池。正式 MIP 仍使用原有戒指对称性约束取代表，这不表示每个有序戒指身份都满足最终 MIP 的规范顺序。

- 固定食物共有 78 条删除记录（两份计时样本加 smoke 的重复记录），39 条有合法完成，累计 2,208 次完成项上界检查；另 39 条在相应 GCD 无合法完成。
- 全食物共有 12 条记录（两份样本重复），全部属于相应 GCD 的空完成域。因此这部分不能冒充新增的“食物下有效伤害剪枝点”证据。
- 重复记录、同一完成涉及多个删项，均不作为额外独立配装数量。全食物下的分数与并列最优仍经过完整 oracle 检查。

所有场景本次的全域最优都落在 2.00 档。两个可穷举场景没有观察到新旧目标全域赢家的严格排名反转；不能把前序合成反例当作本次真实装备已发生反转。新目标接入的必要性仍来自数学结构和前序反例，本批主要验证兼容性与搜索耗时。

## 3. 对照一：正式资源约束不应全局强开

`off` 保留核心精确后端，关闭可选资源加强；`on` 显式请求主资源支撑、主属性支撑、`compact-weighted` 条件支撑及默认候选预算路径。实际 primary 支撑覆盖了单独主属性行；本批全部候选数小于 2,000，正式候选预算门槛没有触发；条件支撑为 `no-out-of-window-candidates`。因此这里测到的主要干预是新增主/加权资源行，不能宣称所有请求的策略都执行了。

下表单位为秒；样本顺序来自 `off,on,on,off`，均值为同一对照块内两个样本的算术平均。变化按 `on/off−1` 计算，正数表示更慢。

| 场景 | off 两次 | on 两次 | off 均值 | on 均值 | 耗时变化 |
| --- | --- | --- | ---: | ---: | ---: |
| 同步固定食物 | 0.905 / 0.860 | 0.934 / 0.930 | 0.883 | 0.932 | +5.6% |
| 同步全部食物 | 1.349 / 1.356 | 1.563 / 1.561 | 1.353 | 1.562 | +15.5% |
| 非同步固定食物 | 12.013 / 11.902 | 10.612 / 11.001 | 11.958 | 10.806 | −9.6% |
| 非同步全部食物 | 8.914 / 8.586 | 18.029 / 17.123 | 8.750 | 17.576 | +100.9% |
| 宽非同步固定食物 | 12.309 / 12.172 | 20.904 / 20.768 | 12.240 | 20.836 | +70.2% |

宽域每档变量数仍为 1,507，约束从 123 增至 158；窄非同步固定食物为 926 个变量，约束从 122 增至 157。只增加约 35 行也可能改变 MILP 分支和割平面过程，不能用“模型大小几乎没变”推断耗时接近。

非同步全食物反而比固定食物的 `off` 更快，尽管域更大；这同样说明搜索耗时不随组合数单调变化。不能依据候选总数或食物数直接制定必然加速的阈值。

## 4. 对照二：新增候选证书能缩小模型，但收益依赖分支

此组 `A=on`，`B=certificate`，顺序为 `on,certificate,certificate,on`。证书模式在相同资源模式上，增加独立 greedy 下界、坐标上界和 CRT 条件的 DET–DHT AM-GM 支撑界。候选不确定时保留；所有新增准备成本均计入。

| 场景 | on 两次 | certificate 两次 | on 均值 | certificate 均值 | 耗时变化 |
| --- | --- | --- | ---: | ---: | ---: |
| 同步固定食物 | 0.917 / 0.896 | 0.863 / 0.875 | 0.906 | 0.869 | −4.1% |
| 同步全部食物 | 1.536 / 1.568 | 1.577 / 1.550 | 1.552 | 1.564 | +0.8% |
| 非同步固定食物 | 10.568 / 10.574 | 10.831 / 10.730 | 10.571 | 10.781 | +2.0% |
| 非同步全部食物 | 17.785 / 15.008 | 16.641 / 14.603 | 16.396 | 15.622 | −4.7% |
| 宽非同步固定食物 | 20.557 / 20.573 | 14.215 / 14.228 | 20.565 | 14.221 | −30.8% |

非同步全部食物样本波动明显，前后有共同下降趋势，两个样本不足以把 −4.7% 认定为稳定收益；同步小域与 +2.0% 等小差别也只作为本批观察。宽域的两组样本分离较明确，支持继续开发此证书，但仍不是跨机器、跨职业的速度保证。

以下候选保留数在两份证书样本中一致，三个数依次对应 1.94、1.96、2.00。原始池在每档独立使用，所以不能把各档删数相加后当作一个池的压缩率。

| 场景 | 每档原候选总数 | 各档证书后候选 | 三档额外准备合计，两次 ms |
| --- | ---: | --- | --- |
| 同步固定食物 | 36 | 36 / 32 / 14 | 18.2 / 17.2 |
| 同步全部食物 | 36 | 36 / 36 / 30 | 20.4 / 21.5 |
| 非同步固定食物 | 157 | 154 / 148 / 28 | 41.1 / 40.7 |
| 非同步全部食物 | 157 | 157 / 156 / 129 | 43.3 / 37.7 |
| 宽非同步固定食物 | 445 | 436 / 405 / 28 | 80.9 / 81.8 |

本批所有实际删除都由 AM-GM 支撑界完成，快速坐标界删除数为 0；没有耗尽证书预算。宽域三档分别执行 5,776 / 5,991 / 8,361 次上界查询，每档还检查 6,285 个实际 DET/DHT 整数点的连续上包络。准备时间包含这部分守卫和下界寻找，没有把研究成本藏在计时外。

宽域同一对照块第一对样本的分支数据：

| GCD | on 变量数 | certificate 变量数 | on solver 秒 | certificate solver 秒 |
| --- | ---: | ---: | ---: | ---: |
| 1.94 | 1507 | 1497 | 12.070 | 8.993 |
| 1.96 | 1507 | 1433 | 6.875 | 4.543 |
| 2.00 | 1507 | 192 | 0.980 | 0.022 |

最后一档从 445 个候选缩至 28 个，变量下降约 87%；但整次任务仍需前两档的完整证明。不能用最后一档约 44 倍的 solver 比值宣传整次多 GCD 加速，真实端到端下降约 31%。

窄非同步固定食物则出现相反抵消：同一对照块第一对样本中，2.00 solver 从 0.723 秒降至 0.022 秒，而 1.96 从 1.617 秒升至 2.435 秒，最终整次略慢。删候选数与 MIP 耗时之间没有单调保证。

宽域两次 `on` 的进程峰值约 270—272 MiB，证书模式约 249—254 MiB，来自 `process.resourceUsage().maxRSS` 的 KiB 值换算；它是整个 Node 进程峰值，不是 JS 堆、模型数组大小或浏览器 Worker 内存。

## 5. 对实施方案的影响

### 5.1 保留完整分档作为首版可验收后端

当前实验已经把固定分支的三次因子贯通正式整数表、量化对数和签名带，并验证真实候选的三档并集。无需等待一般循环模拟器或 GCD×CRT 联合大表，便能实现一个可逐步验证的后端。

这不意味着三档代价等于一次搜索的三倍；真实分支难度相差很大，完整任务时间必须逐档相加。产品界面也不能把某一档提前完成表示成全域完成。

### 5.2 将正确性能力与自动启用策略分开

能力检查回答“这个目标上是否合法”，性能策略回答“这个输入上是否值得”。本批非负三次模型允许重建资源支撑，不代表应全局强开。

研究选路应至少独立控制正式资源行与候选预剪枝。宽域 `on+certificate` 的 14.22 秒虽优于本组 `on` 的 20.56 秒，仍高于另一组基础 `off` 的约 12.24 秒；不能只选择较慢基线呈现收益。下一项有价值的实验是 `off+certificate` 的同块 ABBA，而不是直接把当前组合设为默认；本轮没有测该组合。

现有按职业/装备范围选择的历史策略不能直接继承到新目标。缓存和测量身份须包含完整 profile、允许 GCD、食物政策、数据/算法版本；不要仅以“MNK”或候选数量判定策略。

### 5.3 优先收紧昂贵分支的相关性

当前支撑保留 CRT 与 DET/DHT 的装备内关联，但为了便宜，放松速度、unique 配对和实际食物组合。2.00 档删得很多，不代表昂贵的 1.94/1.96 也会受益。

下一步优先比较两种加强：用当前 GCD 的速度范围条件化支撑；按食物身份建立支撑后取最大值。全部食物模式使用各属性独立最大 cap，容易组合出不存在的“超级食物”，这是安全但更松的上界。加强必须把增加的查询、缓存和建模成本一起计量，不能只比较删除比例。

### 5.4 共同多 GCD 界继续保留为研究方向

[第 08 章](08-数学探索成果迁移与新证明.md)的共同弦线仍有数学依据，但本次实际后端使用逐 GCD 支撑及整数区间细分，没有实现共同弦线、旧二次一峰内核、CRT–HD 余数消元或多职业损失管。

跨 GCD 共用下界必须先恢复时间和约分尺度，分支上界必须覆盖其完整候选域。只有安全上界严格低于全局 incumbent 才能整档跳过；不能因为本批五个赢家都为 2.00，就把其它档位省略。

## 6. 复现与交付边界

在仓库根目录执行；每条命令均应检查 `$LASTEXITCODE`。先创建新的输出目录，例如 `tmp/real-job-repro`，保留本批结果。suite 会拒绝覆盖已有同名 summary、case 或日志。

```powershell
New-Item -ItemType Directory -Force tmp/real-job-repro
node scripts/experiments/real-job-model/oracle.mjs --output tmp/real-job-repro/oracle-fixed.json
node scripts/experiments/real-job-model/oracle.mjs --all-foods --output tmp/real-job-repro/oracle-foods.json
node scripts/experiments/real-job-model/run-suite.mjs --scenarios sync-fixed,sync-foods,meld-fixed,meld-foods,wide-fixed --modes off,on,on,off --label resource-abba --output-dir tmp/real-job-repro
node scripts/experiments/real-job-model/run-suite.mjs --scenarios sync-fixed,sync-foods,meld-fixed,meld-foods,wide-fixed --modes on,certificate,certificate,on --label certificate-abba --output-dir tmp/real-job-repro
node scripts/experiments/real-job-model/verify-results.mjs --directory tmp/real-job-repro
```

脚本入口位于[real-job-model](../../../scripts/experiments/real-job-model)，源变换严格检查公式源码 SHA 和两处唯一锚点，数据缺失或公式变动不会静默继续。可选加强预算耗尽只能保留未认证候选并继续完整后端；整次搜索未完成则输出 `incomplete`，不能称为最优。父进程保留子进程完整失败记录，没有用超时或错误结果计算“更快”。

本轮完成了独立源码复核、两个真实小域 oracle、删除证书穷举、40 次同机完整计时和最终结果一致性验证。没有改生产源码、生成数据或 UI，没有运行无关的全量应用验收，也没有宣称已经发布职业模型。

40 次计时都在 30 秒内，只说明这五个当前研究输入满足该数值；不构成全职业、宽域、浏览器或真实循环的 30 秒承诺。达到 2,000 候选门槛时启用的正式资源预算候选界、多职业联合基线、AA/DoT、必直、逐动作 floor、资源余数和更多允许 GCD 仍需单独验证。
