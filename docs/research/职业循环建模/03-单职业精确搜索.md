# 单职业精确搜索

状态：研究提案；核对日期：2026-10-23。本文给出两条多 GCD 搜索路线的证明义务，未实现新生产后端。数学记号承接[模型数学与多 GCD 系数](01-模型数学与多GCD系数.md)，整体阅读入口见 [README](README.md)。

## 1. 当前实现能复用什么

当前属性模型已经支持 `gcdChoices`：用 one-hot 选择允许速度区间，区间绑定含食物的最终属性贡献。公式基础值在转换时统一处理。因此已有能力是“装备只能落在允许档位”，不包含“按档位选择循环目标”。

当前精确目标仍是六个整数伤害因子乘积，DPS 再除 GCD。`evaluationFunction` 并不决定内部整数目标。已有合成反例中，仅把回调换成必暴评分，MIP 仍返回旧目标赢家，并完成旧目标的签名带证明。

只保留与本提案直接相关的实现锚点：

| 入口 | 当前职责与扩展边界 |
| --- | --- |
| [equipped-effects.ts](../../../src/domain/search/equipped-effects.ts) | 正式向量求值与整数因子，必须与显示口径一致 |
| [attribute-model.ts](../../../src/domain/search/exact-mip/attribute-model.ts) | 完整属性、食物、义军参数及 GCD 区间约束 |
| [factor-model.ts](../../../src/domain/search/exact-mip/factor-model.ts) | 单属性取样、因子类和旧乘积比较，尚无联合块 |
| [single-search.ts](../../../src/domain/search/exact-mip/single-search.ts) | 当前代理目标、带内签名排除、重建与终止 |
| [signature-band.ts](../../../src/domain/search/signature-band.ts) | 旧因子名称与乘积结构的保守带宽辅助检查 |

这些是需要核查的边界，不是建议把职业逻辑散写进这些文件。目标无关的属性、候选身份、整数解校验与求解器原语可以复用；目标相关编译应由同一份描述驱动。

## 2. 搜索前置契约：定义域与结果状态

设 `G_allowed` 为本次请求允许的全部 GCD，`X` 为完整候选及硬约束下的合法装备、镶嵌、食物与参数分配。`X_g={x∈X:g(x)=g}`。未指定离散档位时，也要按正式可行 GCD 规则完整得到相应有限域。

预设覆盖检查必须区分以下状态：

| 状态 | 处理语义 |
| --- | --- |
| supported | 该版本、等级、场景及 GCD 有完整、已验证的目标定义 |
| proven-infeasible | 候选/硬约束已证明该档无装备，可从本次域排除 |
| unsupported | 缺少预设或数学能力，不能把该档当不可行删除 |
| incomplete / cancelled / error | 没有完成所需判断，不能发布已证明最优结果 |

首版可要求 `G_allowed` 全部被 profile 覆盖。若以后允许先证明某未覆盖档不可行再排除，须单独实现不依赖缺失目标的可行性证明，不能靠近似速度范围或样本判断。

有任一仍可能可行的允许档 unsupported，则整个请求不能宣称完成该职业模型的全域最优。用户明确选择通用模型是另一个请求；不得在同一次跨档比较中混用通用与职业分数。预设选择契约见[数据与循环预设](02-数据与循环预设.md)。

候选准备不能先用旧目标裁剪新目标需要的装备。速度上限、离散 GCD、武器间隔及资源依赖都属于支配判断坐标；没有新目标下的证明就保留候选。

## 3. 路线 A：固定 GCD 后完整求解

对每个 `g∈G_allowed` 固定速度区间并编译该档目标，求：

\[
OPT_g=\max_{x\in X_g}S(x),\qquad OPT=\max_g OPT_g.
\]

因为 `X=⋃_g X_g`，且每套装备由实际 GCD 归属相应分支，有限并集恒等式给出完整性。分支可为空；每个分支的速度区间必须恰好对应正式公式的该 GCD 原像，不能在边界错误套用邻档系数或遗漏合法速度。

首个实现建议走这条路线，但**每档的新因子后端必须先正确**：例如固定 g 的 MNK 暴击因子、精确比较、完整签名与所有目标相关界都须替换。外层循环调用旧六因子求解器并改回调，仍然是在各档优化错误目标。

各档保持同一冻结候选政策和规则版本；可复用只读候选与目标无关准备。可由有证明的分支局部过滤缩小模型，但不能把某档剪枝后的候选池直接供别档使用。

最高坚韧模式须先按原始完整允许域求得全局最大坚韧，再将其作为所有分支共同硬约束。不能让每档各自最大化坚韧后同时进入伤害比较，否则会纳入未满足全局最高值的分支，改变现有目标语义。

循环平均或频率目标可能写成 `S_g=P_g/D_g`，分支内可约去正常数 `D_g`，但合并结果时必须恢复：

\[
S_a>S_b\iff P_aD_b>P_bD_a.
\]

所有分支都必须最优、证明不可行，或由**新目标、同单位**的保守上界证明不可能改进全局 incumbent 后才结束。未完成分支的可行解不能当 `OPT_g`；代理目标的浮点对偶界也不能未经缩放和误差修正直接作真实分数上界。

以下仅为提案流程，不是现有 API：

```text
prepare immutable full candidate domain and objective identity
verify profile coverage over every allowed g
if maximum-tenacity mode: prove global maximum, then freeze it
best = none
for each allowed g, in a heuristic order:
  if best exists and provenExactUpper(g) <= exactScore(best):
    mark safely-pruned; continue
  backend = compileSupportedFixedGObjective(g)
  result = solveAndProve(backend, domain intersect speedRange(g))
  require result is optimal or proven-infeasible
  compare result and best as exact rational scores
require all branches have a proof-complete disposition
return best with aggregate proof scope
```

启发式顺序可早得到好解；取消与 Node 验收截止时间必须贯穿准备、全部分支及签名检查。有限并行不能使每个分支获得一份独立总截止时间。正式 Worker 搜索仍遵守不设置搜索时限的现有规则。

## 4. 路线 B：单模型 GCD×CRT 联合块

设 `i` 表示允许 GCD，`j` 表示 CRT 函数档位，速度区间为 `[L_i,U_i]`，CRT 区间为 `[A_j,B_j]`。所有区间均按正式取整公式构造，端点为整数。用完整含基础属性的 `s,t` 表述；若模型变量只存装备与食物贡献，则在端点中一致扣除基础值。

建立二元变量 `z_{ij}`，其精确因子是共同分母整数化后的 `C_{ij}`，并建立或复用边际选择 `u_i,v_j`：

\[
\sum_{i,j}z_{ij}=1,\quad
\sum_j z_{ij}=u_i,\quad
\sum_i z_{ij}=v_j.
\]

边际与真实最终属性绑定：

\[
\sum_iL_i u_i\le s\le\sum_iU_i u_i,\qquad
\sum_jA_j v_j\le t\le\sum_jB_j v_j.
\]

`z` 为 one-hot，边际因此恰选一个速度区间和一个 CRT 区间；两轴均不能由装备以外的自由选择替代。已有 `gcd_choice_*` 可作为速度边际复用，但必须按真实区间/档位身份明确映射，不能只按数组位置假定一致。

等价地可直接用 `z` 的加权端点约束两轴。复用已有边际时加等式尤其重要：分别建立一个 GCD 选择和一个目标联合表却不连接它们，会允许“穿慢速装备、拿快速档系数”。

联合目标块对代理目标贡献 `Σ round(L ln C_{ij}) z_{ij}`。若它已吸收原 CRT 倍率与 GCD 时间项，旧两组不再重复贡献目标；保留的边际只用于属性连接及有证明的辅助约束。

CRT 区间应是所有相关行函数的共同细分，或为每行建立相应正确区间。只在旧普通暴击因子处切档可能漏掉 `K` 或 `cN` 的变化。若同 g 内还有 `ssDamage`、技能复唱等速度依赖，必须再细分速度区间，或增加联合轴；显示 GCD 不能替代这些原始依赖。

只能删除有证据不可能实现的联合单元。每轴单独可达不代表两轴组合可达；保留不可达组合并靠完整装备约束排除是安全放宽，不能用不完整可达性表删掉真实单元。

在整数可行解中，装备决定 `s,t`，两者决定合法单元，目标取该单元的 `C_{ij}`；反过来，每个合法装备必须能选择其对应单元。证明双向映射成立后，单模型才与原问题等价。

`factorGroupsForAttribute` 每次只改变一个属性，且假定对应单轴阶梯单调，不能直接采样 `g×CRT` 表。现有 `FactorClass.min/max`、组名映射和资源轴映射也不足以承载二维区间；需要有针对性的联合块描述与编译，而非把联合表伪装成普通 `crt`。

## 5. 正乘积的固定点对数证明如何延续

若目标可写为正整数分子因子与正整数分母因子的乘积/比值：

\[
S=\prod_{a=1}^{p}V_a\big/\prod_{b=1}^{q}D_b,
\quad Q=\sum_a round(L\ln V_a)-\sum_b round(L\ln D_b),
\]

则 `|Q-L ln S|≤m/2`，其中 `m=p+q` 是实际量化项数。新 GCD×CRT 块若已包含时间归一化，会替代旧 CRT/GCD 两项；不能再除 GCD，也不能沿用“固定七项”的误差常数。

联合块非单轴不影响这条乘积误差不等式；前提仍是正值、经整数区间保证的对数量化、正确的目标缩放和求解器精度。零/负目标不能直接取对数，需声明不支持此后端或另作已证明的建模。

令已证明的代理最大值为 `Q*`，所有严格改进真实目标的解均包含在 `Q≥Q*−m` 内。必须遍历带内完整目标签名、精确有理数比较，并证明没有更优可行签名。签名辅助检查容量或时限不足时，返回完整 MIP 处理；不能当作无更优。

共同常数分母可统一约去；选择相关的分母/尺度须统一整数化或成为明确的目标项，其对数量化误差也计入 `m`。每组减去最大系数仅是全域代理目标平移；分支各自的平移量不能用于直接比较跨档真实目标。

共同分母可能使整数位宽增长。BigInt 能精确比较结果，不代表可以把超出安全整数的因子或系数强转 Number 交给现有量化/MIP 接口；必须通过数值边界检查，采用另一条已证明的精确编码，或明确拒绝此后端，不能截断和近似后继续沿用证明。

现有签名带辅助器限制旧因子名称、读取旧 incumbent 字段，不能靠传入新组名自动复用。新实现至少需要接受实际目标因子/分母描述，并重新验证带内笛卡尔放宽与精确比较。

## 6. 签名必须确定完整目标

安全 no-good 的必要性质是：同一个被排除签名下，所有配装具有相同精确目标，或者已对其中可能更优的目标完成另一种完整证明。仅有相同代理 `q` 不够，相同旧伤害因子也不够。

对当前窄联合块，签名应包含目标身份、全部选中因子的精确类与联合单元，及尚未吸收的分母项。联合单元可以在值相同且后续约束仍被正确表达时压缩；是否能压缩必须同时审查资源和共享身份消费者。

目标身份至少区分游戏/规则版本、职业与计算等级、profile 定义摘要、场景与时间口径、允许档位及依赖公式版本。运行缓存还必须包含其实际依赖输入；稳定 profile ID 不能代替内容摘要。

已有同 GCD 异 `ssDamage` 反例说明：新伤害若依赖速度伤害倍率，旧六因子＋GCD 签名会把不同目标放在同一类，第一次 no-good 可能排掉未见过的更优配装。DoT/AA、武器间隔、增益窗口等新增依赖都须做同类审计。

## 7. 资源界与候选上界不能重复收费

现有资源支持把单轴因子区间下界映射到可用属性预算。联合块同时消耗 CRT 和速度，应携带多轴下界，而不是一个模糊 `min`：

\[
cost_{ij}(w)=\min_{(s,t)\in cell_{ij}}(w_s s+w_t t),\quad w_s,w_t\ge0.
\]

矩形且坐标口径一致时可以取 `w_s L_i+w_t A_j`；非矩形时用经证明的下界，允许更松但不可偏高。预算右侧也必须采用同一基础值/装备贡献口径，并覆盖食物取整、封顶和义军参数。

同一个预算行中，每个物理属性只计一次。若 `z` 已收取速度和 CRT，不能再对边际 `u/v` 或旧 `gcd/crt` 组重复收取；否则会错误删掉可行解。边际仍可用于连接约束，是否出现在某条资源式由明确的轴所有权决定。

候选资源界、对数斜率界及签名可行性辅助都须重查联合轴。遇到未知轴或无证明的非单调性，禁用可选加强并保留完整路径；不得将旧目标上界当新目标上界。更广的能力契约见[通用建模与耗时优化](05-通用建模与耗时优化.md)。

## 8. 提议的内部接口与交付门槛

以下是供实施评审的最小契约示意，不是已存在的公共 API，也不要求一次性建立通用插件框架：

```text
CompiledObjective {
  identity, scoreUnit, supportedDomain, rawDependencies
  exactScore(reconstructedInput) -> Rational
  blocks -> positive factors, denominators, domain links
  signature(selection) -> sufficient exact objective signature
  logProof -> quantization, termCount, scaling constraints
  optionalBounds -> only bounds proved for this objective
}
```

单职业所有目标消费者须使用同一编译结果：MIP 系数、热启动排序、真实目标比较、签名/no-good、资源/候选界、结果重算及缓存。独立求值器负责交叉验证，不用另写一套近似公式掩盖差异。

实施门槛为：固定单 g 的新因子先与穷举等价；路线 A 完整覆盖多档且保留尺度；路线 B 与相同域的 A、穷举三方一致；再接入联合搜索。测试必须覆盖食物取整、固定孔、同步与等级、义军连续分配域、最高坚韧、唯一戒指及 unsupported/不可行/取消的区分。

已有[15 点合成实验](multigcd-feasibility-results.json)验证有限并集取最大与全域枚举一致；它未调用改造后的分支或联合 MIP，不能抵扣本节的后端等价性门槛。试验复现与来源边界见[来源与探索证据](07-来源与探索证据.md)。

还需构造不同行分母、非比例系数、跨档赢家反转、速度/CRT 边际错绑、资源重复收费、同 GCD 不同原始依赖及带内真实排序反转。既验返回值，也验允许域是否完整及证明状态，不能只断言“分数为正”。

按[实施与验收](06-实施与验收.md)执行正式领域回归、构建、穷举与性能验收；本文没有新后端的通过记录或耗时结论。[多职业联合搜索](04-多职业联合搜索.md)还必须用所有允许 GCD 的独立最优值作职业基线。
