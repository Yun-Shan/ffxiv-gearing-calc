# 分享链接规格

分享格式号初始为 1。本文定义生产分享功能的 Schema、类型编解码、bin 分享表、恢复行为与验收契约。

完整字段结构、互斥分支、位图、类型及字节公式按下文定义；生产语义类型见[分享类型](../src/share/types.ts)，实际读写见[分享编解码](../src/share/codec.ts)。

## 1. 功能与数据边界

分享以结果页收到的配置及当前选中结果为来源，接收者打开链接即可查看配装、条件及联合概览。引用完整时重建全部信息；来源引用缺失时在应用入口保留未知条件并提示，用户明确忽略后才进入工作台。查看、切换职业、等价替换和再次分享只调用确定性领域辅助，不启动优化器、可行 GCD 搜索、独立基线搜索或求解证明。

接收分享不自动写入搜索历史。应用入口成功反解并完成未知来源确认后，地址栏保留部署根路径及分享查询参数，内部通过路由掩码显示原单职业／多职业结果工作台；文案、导航、布局与操作全部沿用原页面。刷新时优先重新解析地址中的 token，临时替换装备不改动该 token；离开分享结果进入条件、职业选择或其他页面时移除分享参数。用户点击原有“调整条件”后进入条件编辑，再主动开始正式搜索。分享入口统一为“分享配装结果”，打开后选择复制链接或图片；联合概览的图片分享再选择职业。保留参考项目入口。

| 数据 | 保存方式 |
| --- | --- |
| 全部业务条件 | 配置自身保存，可引用前序配置差分；来源未知时保留原分享 ID |
| 当前装备、食物 | 保存实际物品 ID；名称、图标、品级、来源及固有属性从 bin 获取 |
| 普通镶嵌 | 保存物理孔位、属性码和品阶；数值从 bin 获取 |
| 选择型自定义属性 | 保存两大一小选择；具体数值从关联物品的 bin 参数恢复 |
| 任意整数分配 | 保存原分配整数；强制绝对分配与结果相对贡献分别解释 |
| 总属性、食物贡献、effects、当前分数、DPS、GCD | 根据当前 bin、公式和原选择现算 |
| 联合独立基线 | 原 score 按小数点后 7 位保存，逐职业固定 4 B；不保存基线配装，不重新搜索 |
| 联合值 | 原 value.approximate 按小数点后 7 位保存；精确分子、分母不传 |
| 原耗时、原数据版本 | 保存显示精度的 statistics.elapsedMs 及永久版本 ID |
| 替换池 | 不传；按当前 bin、完整条件和原选择生成全部适用替换 |
| 证明、候选计数、其余搜索统计、maximumTenacity 结果 | 不传；最高坚韧配置仍保留 |

工作台结果状态使用展示所需的通用结果类型，不伪造包含证明、完整基线及统计的 OptimizationResult。属性展示采用当前 bin 和公式；原版本及按规定精度保存的原基线、原联合值作为来源信息保留。数据版本变化本身不增加确认流程。

## 2. 链接与基本编码

基址取当前站点 origin 与 `index.html` 中 `<base href="/">` 声明的部署根路径，再追加 `?s=`。默认根目录部署时，从 `/single/result` 分享得到 `/?s=…`；部署方将 base 改为 `/ffxiv-gearing-calc/` 时，生成 `/ffxiv-gearing-calc/?s=…`。参数值是完整二进制的无 padding Base64url；不使用 JSON、gzip、短链服务、格式魔数或辅助表版本号。

令当前基址加 `?s=` 的字符数为 P，完整链接字符数为 `P + ceil(rawBytes × 4 / 3)`。

令 `L(v) = max(1, ceil(bitLength(v) / 7))`。

| 类型 | 编码 | 字节数 |
| --- | --- | --- |
| UInt8 | 无符号单字节 | 1 B |
| U | 非负安全整数，规范最短 unsigned LEB128 | L(v)，1～8 B；u32 子域最多 5 B |
| Z | 有符号差值 d：非负写 U(2d)，负数写 U(−2d−1) | L(ZigZag(d)) |
| ItemD | U(id−Bi)，所有实际物品共用基准 Bi | L(id−Bi) |
| FoodD | 配置自动食物写 U(0)，正固定食物写 U(id−Bi+1) | 自动 1 B，固定 L(id−Bi+1) |
| Q7 | 原值按 toFixed(7) 舍入后乘 10^7，写无符号 UInt32LE；解码除以 10^7 | 固定 4 B，无类型标记 |
| G | x=250−round(gcd×100)，严格检查 (250−x)/100 可逆 | 1 B，x=0..249；0＜GCD≤2.50 |
| Bit | 按语法消费顺序合入公共尾部位流 | 每值 1 bit，整流 ceil(B/8) B |
| Source | 零基来源分享 ID 写 U(id＋1)；无身份的字面文本写 U(0)＋U(UTF8字节数)＋UTF8 | L(id＋1) 或 1＋L(n)＋n |
| Mask | 直接写 U(mask)，各位按 StatCode，不使用结构掩码预设表 | L(mask)，15bit 最多 3 B |
| Allocation | Mask＋按 StatCode 顺序的各非负整数 U | Mask 成本＋ΣL(value) |
| Packed(n,R) | n 个 0..R−1 编号按同一基数打包 | ceil(bitLength(R^n−1)/8) |
| Mixed(ranges) | 各位置使用上下文确定的基数 R[i] | ceil(bitLength(ΠR[i]−1)/8) |

Q7 使用 little-endian。原值必须为有限、非负、非负零且不超过 429.4967295；先检查原值范围，再按 toFixed(7) 的十进制结果取七位定点整数，不能用截断或溢出回绕代替。基线量化后还必须大于 0，避免保留率除零。Q7 明确舍弃第 8 位及以后，不使用 Float32、Float64 或尾数／指数表示，也不为数值额外写类型标记。

Packed/Mixed 使用 BigInt 递推 `A=A×R[i]+digit[i]`，按上表最少字节数以 big-endian 写入，必要的前导零保留；范围乘积为 1 时占 0 B。解码先检查 `A＜ΠR`，再倒序取模、整除。块长不使用浮点对数计算。

U 的范围为 0..2^53−1。ZigZag 后也必须处于该范围，有符号差值范围为 −2^52..2^52−1。不能用 JS 32bit 位运算处理超过 31 位的位图。

## 3. 固定编号

装备物理槽位顺序固定为：

`weapon → offhand → head → body → hands → legs → feet → earrings → necklace → bracelet → ring → ring2`

当前职业的实际槽序取 `slotsForJob` 对应的有效子序列。ring 与 ring2 是不同位置；共享仅允许其中十个非武器槽。

| StatCode／属性位 | 领域键 | 属性 |
| ---: | --- | --- |
| 0 | CRT | 暴击 |
| 1 | DET | 信念 |
| 2 | DHT | 直击 |
| 3 | SKS | 技能速度 |
| 4 | SPS | 咏唱速度 |
| 5 | TEN | 坚韧 |
| 6 | PIE | 信仰 |
| 7 | STR | 力量 |
| 8 | DEX | 灵巧 |
| 9 | INT | 智力 |
| 10 | VIT | 耐力 |
| 11 | MND | 精神 |
| 12 | PDMG | 物理攻击性能 |
| 13 | MDMG | 魔法攻击性能 |
| 14 | DLY | 攻击间隔 |

Allocation 的全局属性存在位直接对应 StatCode，数值按 StatCode 升序写入。普通魔晶石只使用 0..6；选择型参数按四轴的 StatCode 升序排列，其 presenceMask 使用排序后局部轴的 bit0..3。

## 4. 完整流顺序

下表与网页的 13 个区段对应。记录包装、字段名称、说明用的 `_mode`／`_family`／`_encoding` 标签不写入二进制。

| 顺序 | 区段 | 来源与编码 |
| ---: | --- | --- |
| 01 | control | UInt8：bit7=0，bit6 为模式 M，低6位格式号；单职业 0x01，联合 0x41 |
| 02 | dataVersionRef | 原结果数据版本的零基永久 ID，U；0 为第一项，当前 1 B |
| 03 | elapsedTenths | 原 result.statistics.elapsedMs 按页面 0.1 秒显示精度量化，U |
| 04 | itemIdBase | 所有条件和当前选择中正物品 ID 的最小值 Bi，U |
| 05 | patterns | U(非零模式数 P)＋P 条模式；空模式 [] 隐含引用 0 |
| 06 | identities | U(身份数 n)＋物品 ID 排序差分列 |
| 07 | assignments | UInt8(kind)＋身份到完整镶嵌／参数模式的引用列 |
| 08 | configs | U(职业数 J)＋各 U(baseRef)＋完整配置或前序差分 |
| 09 | jointConfig | 联合才有；U11 共享槽与食物策略图 |
| 10 | selectedChoices | Mixed 当前配装选择块，无独立数量／长度 |
| 11 | selectedFoodOffsets | 按配置推导所需数量，逐项写 ItemD，无数量／分支位 |
| 12 | jointTail | 联合才有；J 个基线 Q7，再读一位联合值标记及必要的联合值 Q7 |
| 13 | packedFlags | 全流独立 Bit，ceil(B/8) B，未用高位补 0 |

Bi 包括当前装备、选中食物、强制装备、排除装备及正固定食物；自动 foodId=0 不参与。条件与结果共用 Bi，不分别设装备、食物或条件基准。

耗时量化与页面一致：以 `(elapsedMs/1000).toFixed(1)` 对应的十分秒整数写 U，恢复为该整数乘 100 毫秒。不保存毫秒原值。正式导出不另行计时；联合根与各当前职业行恢复同一显示精度的 statistics.elapsedMs。

主字节流向前读取，独立位流从最后一字节的 bit0 起向高位读取，读满一字节后移到前一字节。总位数由语法决定，不另传长度；结束时主、尾游标必须相接，未使用位必须为零。尾部只包含完整配置的三项可选存在位及联合值标记，B=3×完整配置数＋联合模式标记数。目标／条件模式字节、速度存在字节、强制模式图、联合共享图和列表位置图均在各自主载荷中。

## 5. 模式池、装备身份与引用列

### 5.1 完整镶嵌与自定义分配模式

| 首字节 | 载荷与恢复 | 字节数 |
| --- | --- | --- |
| 0..62 | 普通镶嵌：code=(2^L−1)+M，L=0..5，M 为 L 位非空孔图；按物理孔顺序只为非空孔写 token | 1＋非空孔数 B |
| 144..155 | 选择型自定义：choice=code−144；从关联装备 bin 参数展开 | 1 B |
| 240 | 任意整数自定义贡献：后接 Allocation，grade=0 隐含 | 1 B＋Allocation |

其余首字节非法。普通 token 为 `(StatCode << 5) | grade`：高 3bit 属性码 0..6，低 5bit 品阶 1..31；属性码 7 与品阶 0 无效。普通数值从 bin 恢复。

L 和 M 区分 []、[null] 及尾部 null。普通数组中的 null 在强制条件里表示自动孔，在当前结果里表示实际空孔；查看时不填孔。带 slotIndex 的结果先恢复物理孔数组，再编码；强制数组的显式 slotIndex 必须等于原下标。解码后调用非空 Materia[] 辅助时按非空图位置派生 slotIndex。

选择型参数要求四轴、两大一小一空。smallIndex=0..3，emptyRank=0..2，`choice=3×smallIndex+emptyRank`；emptyRank 从排除 small 的其余三轴中选择空轴，其余两轴为大值。具体 bigValue／smallValue 来自关联物品的 bin 参数。

Allocation 保存原贡献整数及显式存在键，不保存完整总属性。模式池在本链接内去重；不使用全局魔晶石或自定义属性组合预设。

### 5.2 身份列

身份仅包含当前配装实际引用的装备，同物品 ID 不同分配是不同身份；按物品 ID 升序，同 ID 稳定排序。首项写 `U(id−Bi)`，后续写 `U(id−前一id)`，零差值合法。

模式池可包含只用于强制孔的模式；它们不必出现在选中身份的引用列里。

### 5.3 身份到模式的引用

引用范围为 0..P，R=P+1；引用 0 对应空模式 []。数量 n 已在身份列中，不重复写入。

| kind | 引用列载荷 | 成本 |
| --- | --- | --- |
| 0 | n 个 U(patternRef) | 1＋ΣL(ref) |
| 1 | U(defaultRef)＋U(例外数)＋各例外 U(gap)、U(ref) | 1＋L(default)＋L(k)＋Σ(L(gap)+L(ref)) |
| 2 | Packed(n,R) | 1＋ceil(bitLength(R^n−1)/8) |

稀疏分支按身份位置升序，`gap=index−lastIndex−1`，初始 lastIndex=−1。编码器尝试空模式及该列实际引用作为 default，比较完整成本；分支平局按 0→1→2。

## 6. 职业配置

配置不依赖 bin 中的公共条件、职业默认配置或职业组合表。单职业 J=1，联合 J≥2，职业 ID 不重复。每个配置恢复后包含全部业务条件；maxSearchMs、cacheLimit 属于执行参数，不传输。

### 6.1 完整配置固定序列

| 顺序 | 字段 | 编码与来源 |
| ---: | --- | --- |
| 0 | jobId | U，bin ClassJob 数字 ID |
| 1 | clanIndex | U，显式必填，0 也写入 |
| 2 | minItemLevel | U，最低装备品级；业务下限 90 |
| 3 | maxItemLevel | U(max−min)，均为整数且 min≤max |
| 4 | modeBlock | 1 B 控制字节，再按 GCD→同步→坚韧顺序写载荷 |
| 5 | foodId | FoodD，0 为自动 |
| 6 | optionalPresence | 3 个 Bit，依次为 excludedSources、excludedGearIds、forcedGear |
| 7..9 | 三项可选载荷 | 仅存在位为 1 时按上述顺序写入 |

前六项不占存在位图。三项限制缺省与空集合等价，规范为不写；对接领域层时按需要恢复 []／[]／{}。objective 与 clanIndex 不从默认或结果补齐。

### 6.2 目标与模式字节

bit0 为 objective：0 damage，1 dps；bit1..2 为 GCD 模式；bit3..4 为同步模式；bit5..6 为坚韧模式；bit7 固定 0。

| 模式 | GCD 载荷 | 同步载荷 | 坚韧载荷 |
| ---: | --- | --- | --- |
| 0 | 不限，无载荷 | 无同步，无载荷 | 不限，无载荷 |
| 1 | 一个 G；恢复 gcdChoices=[值] | U(等级) | U(minTenacity) |
| 2 | U(档数≥2)＋各 G，顺序保留 | Z(sync.value−minItemLevel) | U(percentTenths)，原百分比乘10 |
| 3 | UInt8(speedPresence)，随后按位写 U(speedMin)、U(speedMax) | U(稳定副本选项ID) | maximizeTenacity=true，无载荷 |

速度存在字节恰 1 B：bit0 最低值，bit1 最高值，其余为 0；只允许 1／2／3。速度与坚韧类数值（含范围端点）只接受非负安全整数，显式零和单边范围保留，上下界有序。现有字段为 speedMin、speedMax、minTenacity，不额外引入新的条件字段。GCD 档位为无重复的非空列表，与速度范围互斥；单值也恢复为 gcdChoices 列表。

副本模式以零基稳定分享 ID 同时恢复 sync 和 syncDuty，0 有效；bin dutyRefs[id] 直接给出原副本表序号。副本无法解析、同步目标不受支持或手动同步无效均提示“无效的分享链接”，不得当作无同步继续。手动同步只恢复 sync。syncDuty 是 UI 侧车，进入领域校验前剥离。坚韧策略互斥，只有坦克可使用。最低减伤比例为 0..100，只允许一位小数；以 Math.round(percent×10) 得到 0..1000 的整数，并检查还原值 ticks/10 与输入完全相等，超精度值拒绝编码，不自行舍入。5.7% 写 U(57)，占1 B；12.8% 写 U(128)，占2 B。

### 6.3 来源与装备排除

excludedSources 写 U(count)＋逐项 Source，excludedGearIds 写 U(count)＋逐项 ItemD，保留顺序。Source 正值先减 1 恢复身份 ID，再经 sourceRefs[id] 直接查询原来源池；数组元素仍为无偏移的原表序号。查询失败时恢复 UnknownSourceRef，保留原 ID 并显示“未知来源（ID）”；不把占位文字作为领域筛选条件。Source 的 0 分支直接恢复无身份的原字符串，即便当前目录没有该文字，也不是未知引用。任何实际装备 ID 都必须存在于当前 bin。

### 6.4 强制装备

强制完整载荷先写 `U(modeMap)`，固定 12 槽每槽 2bit，`modeMap=Σ(mode[i]×2^(2i))`，逻辑 U24，实际 1～4 B。

| 槽模式 | 载荷 |
| ---: | --- |
| 0 | 无强制，无载荷 |
| 1 | ItemD，纯物品 ID |
| 2 | ItemD＋U(patternRef)，固定孔数组；引用 0 仍是 [] 固定孔模式 |
| 3 | ItemD＋选择码或 Allocation，由 bin 参数族确定 |

只为非零槽按固定槽序写载荷，不写每槽存在位或独立 kind。全零顶层强制图规范为省略 forcedGear。

mode 3 的物品必须恰有一类参数族：customParameters 或 resistanceWeaponAdjust，两者同时有／都没有则失败。选择型写 `UInt8(choice+12×presenceMask)`，范围 0..191；四位 presenceMask 按该物品参数的 StatCode 升序排列，区分显式 0 和缺省键。任意分配写绝对 customStats 的 Allocation，空对象／全零仍保持自定义强制语义。

强制 customStats 是绝对分配；结果 grade0 是原贡献。恢复匹配强制自定义装备时先按原绝对值覆盖，保留显式 0，再应用同步封顶，不能仅从非零贡献推断显示值。

### 6.5 前序配置差分

每条配置先写 U(baseRef)：0 为完整；正数为前序已恢复配置下标加 1，禁止向前引用。首条必须完整。编码比较完整及各前序差分的新增字节成本，计入已有尾流合并后的字节变化；平局选完整，再按前序下标升序。modeBlock 是原子值，相同则继承，变化则写完整字节及载荷。

字段序列是六个必填再接三个可选。C 为九字段变化图，R 为六必填变化图，T 为三个可选的三进制状态数，A 为三可选赋值图。T 的状态是 0 继承／1 删除／2 赋值。

| 控制码低 2bit | 编码 | 适用条件 |
| ---: | --- | --- |
| 0 | U(4C) | 没有删除，变化字段直接赋值 |
| 1 | U(4C+1)＋U(A) | 变化字段按 A 区分可选赋值与删除 |
| 2 | U(4×(R+64T)+2) | 必填二态＋可选三态混合；最大 6910 |
| 3 | 非法 | 拒绝 |

比较可用分支的实际字节成本，平局按 0→1→2。必填只能继承／赋值，不允许删除。仅按固定字段顺序写赋值项；删除无载荷。

min 先恢复；赋值的 max 和同步品级相对于该配置当前 min。未变化的 max／sync 继承绝对值，不因 min 改变而再次偏移。

来源／排除 ID 列表差分在该字段位置依次写：新 U(count)、局部位置位图、变化或新增项的载荷。重叠长度 K=min(前序长度,count)，位图为 ceil(K/8) 个原始字节；第一个字节的 bit0 对应下标 0，1 表示赋值、0 表示继承，按下标递增写入后续字节，最后未用高位补 0。先完整读写该位图，再按下标写变化项和新增项；新增位置没有位，缩短由 count 截尾。该位图不进入公共尾流，也不另写位图长度。

前序字段不存在时使用完整列表，不写位置位图；字段整体不变由父配置继承，清空由父配置删除，两者均不写列表载荷。重排仍比较相同下标，不按值查找旧位置。局部位图使用字节数组，不受 JavaScript 32bit 位运算或 53bit 安全整数长度限制。

forcedGear 被赋值时，前序 wire 记录没有该字段则用完整 U24 图；已有该字段则用 `U(changeMap)`，每槽 3bit，逻辑 U36，实际 1～6 B。该判断发生在补默认 {} 前，不额外写分支位。

| 3bit 状态 | 含义与载荷 |
| ---: | --- |
| 0 | 继承，无载荷 |
| 1 | 清除此槽，无载荷 |
| 2 | 纯 ID：ItemD |
| 3 | 固定孔：ItemD＋U(patternRef) |
| 4 | 自定义：ItemD＋按 bin 参数族的内容 |
| 5..7 | 非法 |

changeMap=Σ(state[i]×2^(3i))，ring2 从 bit33 起；必须使用安全整数算术或 BigInt。清除整个 forcedGear 使用父配置的可选字段删除。

## 7. 联合配置与结果选择

### 7.1 联合共享图

共同槽与食物策略合成一个最短 U11，实际 1～2 B。bit0 食物策略：0 shared，1 independent；bit1..10 依次为 head、body、hands、legs、feet、earrings、necklace、bracelet、ring、ring2，置 1 表示共享。bit11 及以上非法；值 0／1 分别表示零共享槽及共享／独立食物。

共同槽按固定顺序恢复。联合 objective 从一致的子职业 objective 获取，不单独编码。所有职业必须同组，范围、同步目标、族群、目标及来源排除集合一致；共享食物配置和每个共享槽的完整强制值一致，UI 副本选择也一致。可完全解析的配置复用正式校验，不合并冲突条件。存在未知来源时，联合来源集合按“已知字符串／未知原 ID”分别比较，不把不同未知引用合并。

### 7.2 当前选中装备

按身份表顺序，以 bin 原始槽位将身份分组，ring 与 ring2 使用同一个 ring 身份组。每个职业按固定有效槽序产生选择，各局部基数 R 是该组身份数。

非共享槽保存局部编号；R=1 时零字节选择。共同物理槽只写首职业，后续逐槽引用同一身份。ring／ring2 分别对齐，不交换位置；不一致输入拒绝。全部编号组成一个 Mixed 块，不写组表、数量或块长度。

恢复后验证完整槽位、职业可穿、唯一性及共享完整身份。同物品不同镶嵌／参数仍可作为不同选择，不能仅比较属性总和。

### 7.3 当前选中食物

食物始终使用 ItemD 逐项写入，无字典、分支位、引用块或数量字段。正固定 foodId 从配置直接恢复；共享自动选择只写一个 ID；独立策略为每个自动职业逐项写 ID。数量由配置推导，零项时 0 B。最终选中食物必须为正物品 ID。

### 7.4 原联合概览

按配置顺序固定写 J 个原 `optima[job].score` 的七位小数定点值，每项 Q7、固定 4 B，量化后必须大于 0；相同分数也逐项写，不写字典、差分、数量或逐项类型标记。

先将原 `value.approximate` 按 Q7 量化。若量化值等于职业数 J，写一个 Bit=1 并恢复 J；否则 Bit=0 后写该 Q7，固定 4 B。该标记表示七位量化值是否为 J，不再保留原 Float64 与 J 的相等性；这样解码后再次分享保持稳定。不从当前分数比值之和反推联合值。保留率使用当前重建 score／七位量化后的 baselineScore。

commonGear 从首职业按 commonSlots 逐槽提取，各槽为单元素数组；共同食物从恢复的选择获得，不保存副本。

## 8. bin 分享表设计

### 8.1 原表、分享身份与映射

新增专用 SHARE_TABLES 段，只保存来源引用数组、副本引用数组和版本文本表。原有 GEAR_CATALOG 来源池保存名称；原有 SYNC.groups[].options 按组顺序、组内选项顺序扁平化，保存整理后副本的名称及 target。分享段不复制这些业务内容，不保存公共条件、职业／魔晶石／自定义组合或结构掩码表。

来源、副本和数据版本的分享 ID 都从 0 开始。ID 0 与原表序号 0 均合法，查表必须判断 undefined／越界，不能用真假值判断。映射关系为：

    来源名 = 原来源池[sourceRefs[shareSourceId]]
    副本选项 = 原副本表[dutyRefs[shareDutyId]]
    原版本 = dataVersions[dataVersionRef]

数组直接保存该版原表序号，不做 +1／−1。分享 ID 的含义永久稳定，原表序号不要求稳定。这里的零基约定不改变 baseRef=0 的完整配置语义、patternRef=0 的空模式语义或 FoodD 的自动食物编码。

### 8.2 分享段完整字节布局

令 Ns 为原来源池项数，Nd 为原副本选项数；Ls、Ld、Lv 为三个永久身份表的已分配项数。索引宽度 W(N) 在 N≤255 时为1，N≤65535时为2，否则为4；N 必须≤2^32−1。宽度由同一个 bin 的原表数量推导，不另存类型字节。

| 顺序 | 字段 | 编码 | 当前成本 |
| ---: | --- | --- | ---: |
| 0 | sourceRefCount | U(Ls) | 2 B |
| 1 | sourceRefs | Ls 个无符号 W(Ns) 字节原表序号，little-endian | 216 B |
| 2 | dutyRefCount | U(Ld) | 1 B |
| 3 | dutyRefs | Ld 个无符号 W(Nd) 字节原表序号，little-endian | 31 B |
| 4 | dataVersionCount | U(Lv) | 1 B |
| 5 | dataVersions | 每项 U(UTF8字节数)＋UTF8，按永久版本 ID 排列 | 21 B |
| | 合计 | 216来源、31副本、1版本 | **272 B** |

这是专用段的完整 payload，不再套一层通用段字符串表；版本文字只写一次。该数值不包括新增容器目录项的12 B、现有原表或其他格式更新成本，不等同于生产文件总增量。接入时需升级运行时 bin 容器格式、增加独立读写模块并重生成产物

### 8.3 永久身份账本与生成规则

生成阶段单独维护身份账本：来源身份为完整原文字；副本身份为(name,target.kind,target.value)；版本身份为完整版本文本。账本属于构建输入，不把这些重复身份内容写入运行时分享段。来源按第一个“/”之前的文字识别前缀，无“/”时以全文为前缀。首批来源顺序由人工确认，保留账本中的分组和排列，不将人工排序规则写入生成脚本。

自动生成新增批次时，来源仍先按前缀作确定性的字符串字典序排列，同一前缀内按对应装备的最高物品 ID 倒序，不使用副本 ID 或后缀字典序；最高 ID 相同时才以完整来源文字打破平局。副本按整理后选项包含的最高 ContentFinderCondition 行 ID 全局倒序；合并选项取全部成员的最高 ID，分组展示顺序不影响分享 ID。新增身份缺少原始 ID 依据时生成失败。

以 Git HEAD 中已提交的账本作为永久基准。尚未提交账本时，基准为空，每次全量重建；已有提交时，保留已提交条目，只将本次新增来源和副本按上述规则排序后追加，新的版本按批次追加。工作区内尚未提交的分配不作为下一次生成的基准，因此重复生成不会积累待提交的旧身份或旧版本。已提交 ID 不重排、不删除、不复用；既有来源增加新装备不会重新分配其 ID，名称或同步目标改变时分配新身份。

每次生成按以下顺序处理：

1. 完成正式数据查询、业务归一、来源池及整理后副本目录生成。
2. 读取 HEAD 中已提交账本（不存在则从空表开始），保持已提交条目及顺序；按上述排序规则重建本批新增身份，忽略上次生成但尚未提交的分配。
3. 为全部历史分享身份重新定位本次原表序号，生成 sourceRefs／dutyRefs。
4. 历史身份在本次原表不存在时，将该槽写为本次原表长度 N；这是一个自然越界序号，常规查询得到未知，不占用任何有效序号，也不把0作为未知码。
5. 每次都重新计算这个越界序号，不能沿用旧 N，以免原表增长后指向新记录。
6. 验证数组长度、宽度、原表指向的身份、重复身份和版本完整性，再与原表原子写入同一个 bin。
7. 读取产物并验证解析；失败保留上一份完整 bin，不混用不同批次原表与映射。

分享数组的值可以因原表重排改变；永久不变的是分享 ID 对应的身份。不得把“账本仅追加”误解为运行时序号数组的元素值也必须不变。

### 8.4 缺失引用策略

| 引用 | 缺失行为 |
| --- | --- |
| Source 引用 | 恢复 UnknownSourceRef，保留 ID，显示未知来源，继续恢复当前配装 |
| 副本分享 ID、原副本序号或同步目标 | 提示“无效的分享链接”，不降级为无同步 |
| 数据版本分享 ID | 提示“无效的分享链接” |
| 实际装备／食物 ID、职业或解析必需目录信息 | 提示“无效的分享链接” |

U 整数和数量在定义域内增长会自然增字节。Q7 固定4 B，超出范围明确拒绝；改变精度、扩大固定数值范围、新增字段、改变顺序／编号或打包语义均属于格式变化。格式1发布后，不兼容变化使用新格式号。

## 9. 确定性重建与替换池

1. 解码并检查结构、所有目录引用与完整配置。任一实际装备／食物 ID 在当前 bin 不存在，则整条提示“无效的分享链接”；不部分展示，不用占位图标继续计算。配置 foodId=0 自动哨兵除外。
2. 先验证手动同步或解析副本引用，确保同步目标有效；再从职业及 sync 确定 calculationLevel，从 clanIndex 取基础属性。逐槽恢复物品、孔位及自定义选择；验证装备与职业／槽位匹配、唯一性、孔位／品阶及分配规则。
3. 复用正式单件辅助进行属性具体化、绝对自定义覆盖、同步封顶、普通镶嵌和职业特殊效果计算，保留显式零键。特殊效果由职业规则确定。
4. 通过 calculateBaseStats、addStatsForJob、foodStatsForJob、applyFood、describeFoodResult 汇总最终属性及食物实际贡献，再 calculateEffects 得到效果。按 objective 得当前 score，DPS=damage/GCD。
5. 来源条件完整时按原条件与选中身份生成全部适用等价池；存在未知来源时跳过依赖完整条件的池，仍恢复当前选装、属性与概览。保留原耗时、版本、基线分数及原联合值。

替换池复用领域候选及等价匹配辅助，以单件最终属性和武器性能判断，不按总 score 近似匹配。来源未知的职业不生成依赖完整条件的池，整组共同替换也需完整来源条件；设置任何强制值的槽位不生成池。两戒指同时处理唯一性和重数，按品级、ID、完整身份排序，单成员不形成组；联合页面仅提供正式支持的替换能力。

引用完整的正常链接，完整信息重建目标为 2 秒，包含 Base64url、二进制、冷 bin 初始化、全部属性及适用池、Worker 通信和页面应用；图片加载单列。不得以截断候选或延迟到用户展开后补池来满足目标。任务可取消，路由／选择变化后丢弃过期返回；缓存有界且键覆盖完整条件、选择及当前 bin／规则。

进入工作台后，装备替换沿用原页面逻辑，仅更新当前结果；不维护或回写原分享语义对象。再次分享统一从当前配置、当前选中结果和保存的版本、耗时、基线及联合值重新编码，不回填派生属性或证明。编码器对未解析来源仍保留原数字引用，只有用户在入口明确选择忽略时才移除该条件。

### 9.1 未知来源的恢复与能力

UnknownSourceRef 是解码后的语义对象，不新增 wire 字段：

    type UnknownSourceRef = { unknownSourceId: number };
    type ShareSource = string | UnknownSourceRef;

入口恢复状态保存原条件 token 和未解析 ID 列表，以列表为空判定来源条件完整，不额外保存派生布尔值。已知职业、同步和选择齐全时，未知来源不影响当前装备属性、食物贡献、effects、score、DPS、GCD 及保留率的计算。未知来源不直接投入工作台。入口展示未解析 ID，用户可返回搜索，或选择“忽略未知来源并继续”；确认后仅移除未知来源条件，重新生成完整替换池，再交付正式配置及结果。未确认前不删除条件、不进入工作台、不生成依赖完整来源条件的池。

不能将 UnknownSourceRef 传入只接受 string[] 的领域配置，也不能删除未知条件后伪称完整校验。为检查同步等其他字段，可以构造仅用于校验的已知字段投影；它不是恢复结果、池输入或搜索输入。同步必须始终单独有效，未知来源不能绕过同步检查。联合来源的一致性按已知字符串与未知原 ID 的判别集合验证，不与“未知来源”占位文本比较。

### 9.2 应用入口与工作台接入

分享参数由应用入口识别，在专用 Worker 中反解并完成确定性重建。加载、无效链接及未知来源条件均由入口处理，不创建独立分享结果页。同步无效或必需目录缺失时停留入口错误状态，不将残缺数据投入工作台。

成功后以 replace 方式进入内部单职业／多职业结果路由，并用路由掩码保持地址栏的部署根路径和分享参数，不新增浏览历史项。配置、展示结果和数据版本用于初始化对应工作台的 result 阶段。多职业的 jobResults、原基线分数与共享装备结构由入口适配完成。

业务结果状态不保存分享来源标记、原分享 token 或 ShareDocument；应用路由协调层在当前会话中将结果与 token 绑定，保证前进、后退时显示正确来源。不添加分享专用结果文案、导航、按钮状态或替换流程。结果布局、SCSS、调整条件、重新选择职业、搜索记录及图片／链接分享沿用原页面。结果类型不包含求解证明；正常搜索与历史持久化继续要求完整搜索结果。导入不自动搜索、不新增历史，也不绑定已有记录的持久化回调。

切换路由或分享参数时取消旧 Worker，丢弃过期返回。浏览器前进或后退到分享记录时，复用与 token 匹配的当前结果；结果缺失或来源不符时重新解码，并保留同一工作台已有的条件草稿。刷新带分享参数的地址时优先解码 token；普通工作台地址按当前页面的 sessionStorage 恢复规则处理。

## 10. 空值、输入边界与验收

字段存在由语法或存在位决定，没有全局空值字节。可选缺键与 undefined 合并，数值 0／布尔 false 保留。普通孔 null 由非空图表示；[]、[null] 及尾部 null 可区分。顶层空限制规范为缺省；槽内空固定孔和空／全零自定义仍是有意义的强制值。普通字段不接受任意 null。

patternRef=0 是空模式，baseRef=0 是完整配置，ItemD=0 是物品 Bi，FoodD=0 是自动食物，G 偏移 0 是 2.50 秒；这些零不代表字段缺失。必填差分仅继承／赋值，可选差分另有删除。

读取器必须在循环、分配或 BigInt 范围乘积计算前检查累计资源预算、目录数量、列表长度和块长；验证最短整数、引用范围、保留码、UTF-8、Q7 范围及正基线、互斥字段、截断、尾随、列表局部位图和尾部位流的零补齐。完整链接预算为 32,768 字符；超出时明确提示容量限制，不截断条件，也不将合法超长配置描述为篡改。

不要求签名或额外校验和。会导致设备资源异常或代码执行的问题属于安全边界；其余输入检查用于数据兼容性和正确恢复，不扩展为真实性证明。

验收覆盖单／多职业、盾牌、不同族群、自动／固定食物、各 GCD／同步／坚韧模式、普通固定／自动孔、同 ID 不同分配、选择型及任意自定义、来源／装备排除、强制完整／差分、两戒指独立／共同共享、零值／空值／删除、整数换字节边界、永久表追加、未知 ID、路由取消和再次分享。

已保存的回归材料包含在 `2026.10.06.0000.0000` 版本上完成的 17 份真实搜索结果，以及 5 份单列的同目标副本元数据夹具；按当前类型和七位小数精度投影后，22 份稳定往返，核对 30 份当前配装、20 项原基线和 333 件单件属性／武器性能。真实结果 raw 为 46～109 B、在测量基址 `https://ffxiv-gear.yunshan.dev/?s=`（34字符）下完整链接为96～180字符，共1,205 B；实际链接字符数随部署基址前缀变化。Q7 保留原基线七位小数的显示；联合值同样只保留七位小数，不能承诺原八位小数显示或所有舍入边界上的保留率完全相同。

## 11. 类型编解码设计

本节规定正常业务输入的规范编码；规范编码器输出的字节在纯解码后重新编码应保持相同。读取器也允许通过结构校验的等价布局，重新编码时会规范化。文字直接使用 JavaScript 原生 TextEncoder／TextDecoder 的 UTF-8 编解码行为，不增加自定义文本规范化。业务上的等价不自动意味着 wire 相同：配置列表顺序、孔位空值、自定义显式零键和戒指物理位置在纯 wire 往返中保留。工作台结果用带 slotIndex 的非空魔晶石表示，再次分享会省略结果末尾无实际贡献的空孔；强制孔配置的完整长度不变。编解码不调用搜索器。

### 11.1 整数、精度与字节序

| 类型 | 写入步骤 | 读取步骤与边界 |
| --- | --- | --- |
| UInt8 | 一个0..255整数 | 读1 B；模式／保留码按所在字段校验 |
| U | 反复取最低7位，仍有高位时置bit7；输出最低组在前 | 最多8 B，用BigInt累计后检查≤2^53−1；拒绝截断、非最短表示和溢出 |
| Z | d≥0取2d，否则取−2d−1，再写U | 偶数取z/2，奇数取−(z+1)/2；范围−2^52..2^52−1 |
| Q7 | 先校验原值范围与非负零；取toFixed(7)十进制结果，去小数点得到u32，写4 B little-endian | 用无符号u32读取，除10^7；基线整数必须>0；不写类型位，无Float回退 |
| G | x=250−round(gcd×100)，验证(250−x)/100严格恢复输入，再写UInt8 | x必须<250，恢复(250−x)/100，再执行业务校验 |
| ItemD | 校验真实正物品ID，写U(id−Bi) | 加Bi并核对当前bin；偏移0是物品Bi |
| FoodD | 自动写U(0)，固定写U(id−Bi+1) | 0恢复自动；其余恢复Bi+code−1并核对食物目录 |
| Mask | 按StatCode置位，直接写U(mask) | 验证mask<2^15；按升序读取各置位属性值，显式零键不丢失 |

Q7不得简化为对输入直接执行Math.round(value×10^7)：应保持toFixed(7)的舍入契约，避免二次浮点舍入改变边界结果。4 B定点整数的读写使用无符号接口，不能通过有符号32bit移位意外改变≥2^31的值。

### 11.2 来源引用与字面来源

Source先读U(tag)：

| tag | 内容 | 处理 |
| --- | --- | --- |
| 0 | U(字节数)＋UTF8 | 无身份的字面内容；严格UTF8解码，恢复原字符串，不查词条表 |
| 正整数 | shareId=tag−1，无其他载荷 | 查询sourceRefs[shareId]后直接查原来源池；缺失恢复UnknownSourceRef |

由于tag=ID＋1必须在U的安全整数范围内，来源分享ID的格式范围为0..2^53−2。身份ID 0写U(1)，ID 126写U(127)，ID 127写U(128)；ID 0..126各占1 B。普通已有来源只写数字；字面分支用于原表未包含的来源前缀或字符串，不额外维护重复文字表。未知来源的再次编码仍写U(原ID＋1)，不写“未知来源”字样。

dataVersionRef和dutyOptionId直接写零基U，不使用Source类型的加1偏移。版本ID用于版本表，副本ID用于副本映射数组，来源ID用于来源映射数组，三个编号空间互不混用。

### 11.3 按位字段与局部位置图

公共位流只收集完整配置的3个可选存在位和联合值标记。逻辑第一位在文件末字节bit0；下一位依次bit1..7，再移到倒数第二字节bit0。未用高位必须0。所有主载荷从前向后读取，最终游标须与实际尾部字节相接。

列表位置图保留在列表字段内：写新长度Knew，再写ceil(min(Kold,Knew)/8)B完整位图，最后顺序写变化／新增条目。位图在每个字节中也是低位对应较小下标，但字节按数组正序前向读取；它与文件倒向尾流不是同一个存储区域。父字段继承／删除不进入列表语法，前序无字段则只读完整列表。

模式控制字节、速度存在字节、强制装备U24/U36图、联合U11图、Allocation属性图均在对应主载荷位置。它们的保留位及数值范围在读取时验证。

### 11.4 参数模式与条件差分

模式首字节自行区分普通孔、两大一小、任意整数分配，不能再额外写kind或属性族。普通头部code决定长度与非空物理位置，按顺序读取token；两大一小的值从对应物品bin参数得到；Allocation只保存副属性贡献或强制绝对值，语义由所在字段确定。

配置编码器先按六必填、三可选形成规范记录，空顶层限制省略。首职业完整；后续职业分别试编码完整记录和每个前序基准，实际比较新增主字节及合并尾位后的增量。相同成本选完整，再选较小baseRef；一个基准内的变化码同成本按0→1→2选择。不得只比较原对象长度或忽略位流补齐。

列表、强制装备和modeBlock分别遵循自己的差分语法；min变化时先更新该条上下文，max／sync的赋值才使用新min。继承字段恢复绝对值后不重新套偏移。baseRef是本链接内局部引用，0表示完整，正值仍为前序下标加1；这与零基永久分享ID是不同规则。

### 11.5 范围打包

对于位置i，取0≤digit[i]<R[i]。先令A=0、S=1，每项执行A=A×R[i]+digit[i]、S=S×R[i]。S=1时块长0，否则块长为ceil(bitLength(S−1)/8)，将A按该长度以big-endian写出，包括必要的前导零。

解码按上下文计算相同S和块长，读取A并要求A<S，再从最后一个位置向前取模与整除。同基数Packed是Mixed的特例。数量、基数和块长不另传；不得使用浮点log估算块长。参考编号、槽位分组和真实物品身份先通过校验，才能建立范围。

### 11.6 Base64url与读取预算

仅允许A–Z、a–z、0–9、下划线和连字符，不含padding。编码参数为完整二进制的Base64url；解码校验字符、长度余数和规范尾位，重编码必须等于原参数。链接不使用gzip、JSON、浮点载荷、格式magic或额外校验和。

完整链接预算32,768字符。令当前站点origin与应用部署根路径组成的完整基址加`?s=`的长度为P，参数最多32,768−P字符，对应raw最多floor(3×(32,768−P)/4) B。链接生成和页面恢复均按实际前缀检查预算；纯二进制读取器另设24,576 B绝对分配上限，防止在没有URL上下文时无界分配。读取数量后、分配数组前检查剩余字节和业务上限；职业数量受bin职业目录及不重复要求限制，身份数受职业有效槽位总数限制，模式和列表数量受剩余载荷及业务约束限制。范围乘积、字符串字节和所有循环执行累计预算检查，错误不以静默截断处理。

## 12. 实现分层与验收交付

| 层 | 职责 | 禁止事项 |
| --- | --- | --- |
| 结果投影 | 从冻结配置和当前选择建立分享语义，量化Q7、耗时 | 从controller另取耗时，保存派生属性／证明副本 |
| wire编解码 | 处理上述类型、字段顺序、引用及资源预算 | 读取React状态、调用优化器、依赖对象键枚举顺序 |
| bin分享表生成 | 维护永久身份账本，重建数字映射，与原表原子发布 | 以本次排序当永久ID，复制来源／副本正文 |
| 确定性恢复 | 原表解析、完整已知约束校验、当前属性与适用池 | 未经用户明确忽略便丢弃未知来源，缺失同步时继续 |
| 应用入口与工作台 | 入口反解及处理无效／未知，以路由掩码进入原结果工作台并保留分享参数，取消过期恢复 | 自动启动搜索、自动写入历史、过期任务覆盖当前页面 |

配置与结果保持不可变快照。路由参数变化、用户离开或选择变化后取消旧任务；Worker返回前核对任务身份。完整缓存键包含当前bin／公式、全部原条件、选中完整身份及来源解析状态，避免复用另一版本或缺失条件下的池。缓存和Worker消息有界。

生产接入按“bin生成与读取 → 纯wire → 恢复适配 → 路由与结果页 → 完整浏览器验收”执行。真实结果回归保存正式搜索的原始结果、bin SHA、数据版本和搜索入口，分享查看不调用搜索。边界合成夹具与真实结果分开统计；性能以完整冷启动链路计时，不能把单次热解码当2秒验收。

必须交付：真实配置／选装往返、Q7七位精度、再次分享稳定性、零基首项及空值、bin重排／删除／增长、入口未知来源显示、显式忽略前ID保留及确认后交付、未知来源下同步仍严格失败、未知实际物品失败、完整替换池及取消路径。

生产编解码与恢复回归覆盖22份夹具（17份真实搜索结果＋5份副本元数据派生）、30行当前配装、20项基线及333件属性／武器性能。纯wire实现在`src/share`；专用Worker负责完整属性与适用替换池，返回后终止实例，路由变化或离开时取消并丢弃旧返回；不维护无界恢复缓存。冷启动2秒目标按正式构建、隔离浏览器上下文、完整路由及全部适用池验证，图片加载单列。
