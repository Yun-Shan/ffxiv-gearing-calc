# 已安装算法包的搜索性能分析

> 状态说明（2026-10-03）：本文的 CP-SAT 对照属于历史探索，运行适配器现已移除。当前 UI 与 Node 验收均固定使用 HiGHS；以下保留原始测量和分析供查阅。

## 结论

当前候选域是有限离散优化：每槽选一件装备和食物，再满足属性、取整、封顶、GCD、坚韧及共享身份约束。伤害由六个正整数阶梯因子构成，DPS 再除以正整数 GCD；模型以固定点对数作安全筛选，最终用 BigInt 精确比较。该组合选择问题一般是 NP 难的，精确求解的最坏情况仍随候选数指数增长。求解包决定分支、传播、松弛和并行效率，没有哪一种能仅凭模型类别保证更快。

在相同 VPR/MCH 候选与约束上，本轮 HiGHS 搜索完整证明耗时 **118.775 秒**；CP-SAT 8 workers 在 **235 秒**时仍未完成联合最优性证明。戒指对拆分让 HiGHS 相比此前 133.848 秒的成对变量模型快约 **11.3%**，达到 120 秒目标，但没有把总耗时降到 60 秒以内。CP-SAT 的基线阶段更快，联合证明仍是瓶颈。本轮实验因此保留 HiGHS 为正式后端、CP-SAT 为可选验收后端；后者适配器随后已从运行代码移除。

进一步把生产候选、单职业基线和联合搜索都改为两个单戒指槽后，同场景虽然仍证明了相同目标值，但耗时 **189.414 秒**。相较 118.775 秒的“成对候选基线 + 联合 MIP 内部拆分”慢约 **59.4%**；完整拆槽没有更快，故当前保留成对候选生成，并只在已验证等价时拆分联合 MIP。戒指可行域的一一对应证明以及该选择的数学原因见下文和 [条件最优性证明](当前搜索算法最优性证明.md#戒指约束与可行域等价)。

## 数学适配

| 已安装包 | 对当前模型的适配 | 性能与证明边界 |
| --- | --- | --- |
| `highs@1.15.3` | 混合整数线性模型；用 LP 松弛、分支定界和割处理 one-hot 与属性阶梯 | 当前正式后端。实现会复核整数约束和 BigInt 目标，但 HiGHS 的浮点 `Optimal` 状态不是独立可验的证书。 |
| `or-tools-wasm@1.0.0` | CP-SAT 接受同一有界整数线性模型；布尔传播和多 worker 可并行搜索 | 在较易验收场景实测更快；本次 VPR/MCH 8 workers 超过 235 秒且未证明联合最优，峰值 RSS 为 1,636,487,168 字节。整数状态消除了浮点模型容差，但仍没有独立最优性证书。 |
| `glpk.js@5.0.0` | 同属 LP/MILP，可表达相同离散选择 | 没有理论依据认为它在此实例上必然胜过 HiGHS；须固定候选集实测。 |
| `ipopt-wasm@0.2.0`、`nlopt-js@0.1.1` | 连续非线性优化 | 放松 one-hot 后会产生分数装备选择，局部或连续最优不等于离散最优；只能作试探或启发式，不能替代当前证明流程。 |

HiGHS 与 CP-SAT 在最坏情况下都可能搜索指数规模的树。CP-SAT 的整数传播和并行策略适合离散模型，但增加 worker 只能改变实际搜索速度，不能改变问题复杂度；MILP 的 LP 松弛也可能在某些实例上更有力。`glpk.js` 的相同模型类别同样无法从渐近复杂度推出实例胜负。Ipopt/NLopt 若用于辅助，只能将结果映射回合法完整配装并重新验证。

## 同候选基准与戒指拆分

场景为 VPR/MCH、共享耳饰/项链/手镯/戒指和食物、DPS 目标、无额外 GCD/速度/坚韧限制。新缓存哈希为 `ca933fce…570efd`；与旧哈希 `bd75de…e450` 的候选 JSON 去掉新增的 `ringUniqueByItemId` 元数据后逐字段相同。HiGHS 返回归一化目标 `4742535/2371792`。

| 模型/后端 | 搜索时间 | 联合阶段 #6 | 峰值 RSS | 结论 |
| --- | ---: | ---: | ---: | --- |
| 戒指对 one-hot + HiGHS | 133.848 秒 | 原生约 80.3 秒 | 约 489 MB | 完成 |
| 戒指槽拆分 + HiGHS | **118.775 秒** | 原生 67.051 秒，11,655 节点 | 516,579,328 字节 | 完成，约快 11.3% |
| 戒指槽拆分 + CP-SAT / 8 workers | **235 秒超时** | 未出现 incumbent 或 best-bound 更新 | 1,636,487,168 字节 | 未完成最优性证明 |

本节前述的 118.775 秒方案只拆联合 MIP 表示，pair 候选生成和单职业基线仍保持原样。令两槽候选为 `A,B`，原合法域为

\[
P=\{(a,b)\in A\times B:\neg(\operatorname{id}(a)=\operatorname{id}(b)\land U(\operatorname{id}(a)))\}.
\]

模型分别对 `A,B` 作 one-hot，并对每个 unique ID `g` 加约束

\[
\sum_{a:\operatorname{id}(a)=g}x_a+\sum_{b:\operatorname{id}(b)=g}y_b\le 1.
\]

这保留同一可行域，也允许同 ID 非 unique 戒指重复。只有 pair 域与上述笛卡尔积过滤结果完全相同、unique 元数据一致、pair 属性逐坐标可加时才启用；共享完整戒指对时另用选择变量保持同一无序身份多重集。若任一校验失败就回退原模型。拆分减少了戒指对直接选择变量，却扩大部分线性化域；本次总变量从 4,034 增至 4,817，说明变量数本身不足以预测耗时，实测才是依据。

全流程拆槽试验使用 VPR/MCH、同一职业约束、共享 Ears/Neck/Wrists/Finger 两槽和 shared DPS。新候选哈希为 `07e645f9dacf7321ae60c731e127b2a8c5b37726e8500e08eeaf5619bc3dd670`，共有 29 个唯一单戒指方案进入每个槽。HiGHS 在 **189.414 秒**完成证明，归一化值仍为 `4742535/2371792`，峰值 RSS 为 `515,178,496` 字节。该运行的联合 #6 用 94.227 秒、18,390 个节点；之前部分拆分的 #6 用 67.051 秒、11,655 个节点。这个结果表明，即使同一有限可行域和最优值，单职业 pair 基线及联合模型的变量关联结构也会显著影响求解时间。

CP-SAT 在其它固定候选的较易验收场景曾快于 HiGHS：RDM/PCT 为 8.43–8.59 秒对 16.46 秒；RPR/SAM 为 56.15–62.42 秒对 80.80 秒。对难例却没有完成，故结论是“可能更快，依搜索结构而定”，不是全面替换后端。详细阶段数据、回调和运行环境见 [搜索基准记录](搜索基准记录.md)。
