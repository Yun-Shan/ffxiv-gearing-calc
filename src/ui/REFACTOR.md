# UI 重构交付边界

当前界面规则见[工程规则](../../docs/rules/工程规则.md)，视觉风格与页面边界见[前端设计总览](../../docs/前端设计总览.md)。最初涉及领域层的改动先 mock，后续已按用户逐项确认接入；本页记录交付边界与历史验证结果。

## 已有真实路径与待接入契约

| 能力                                      | 本轮边界                                                                                                            |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Single / Joint 搜索、候选目录、GCD 可行性 | 调用真实 domain API；等级规则已按确认调整，求解器与其它规则保持既有实现                                                                     |
| 职业上限 / 同步等级新规则                 | 已接入统一领域解析；移除角色等级配置及候选派生等级，搜索/GCD/条件摘要共用                            |
| 同步 Single 等价替换                      | 领域生成完整同属性候选组、槽位 key、完整戒指数组及唯一子集；当前项保留，选择与历史回写不改候选数组 |
| 固定配装导入                              | 分享解析属于 UI service；默认适配器调用领域 `calculateFixedGearset`，保留合法空孔和参数，不产生搜索记录/耗时 |
| 历史与对比                                | 使用保存的结果、属性、数据版本；不按当前游戏数据重算旧结果                                                          |
| 食物行                                    | 领域食物结果已提供上限、比例、实际增益及利用率；完整字段必填，本轮不兼容旧历史 schema                                             |

## 开发预览

开发环境的 `/gear-comparison?ui-preview=comparison-capacity` 用于四方案容量检查。装备来自当前数据目录，数值明确为 mock；该入口不会在生产环境启用，不证明固定配装计算或等价关系。

## 源码所有权

页面私有流程、controller、Draft 组合留在平级 `pages/`；跨页条件、装备与历史语义放在 `features/`。Page 组合 Provider 与布局，Main/Aside 读取同一 phase 与 validation。历史存储按 run/historyId 管理，异步写入不阻断搜索或页面流转。

真实 domain 新契约接入后仍需补公式/候选/等价关系/最优性验证；UI fixture 测试不构成这些领域结论。

## 最终验收补充（2026-10-18）

- 计算、历史、导入的 `dataVersion` 统一使用领域 `defaultDataVersion`；`displayedDataVersion` 保留游戏资源目录版本，只校验独立生成的职业与装备图标清单，避免同一游戏数据被误判为跨版本。
- Base UI checkbox 显式关联到自身可见标签，来源树各节点在外层 FormField 上下文中仍有正确可访问名称。

## 已确认的容量处理

用户已确认装备对比允许装备表区域滚动，保留当前实现。四方案不要求全部行同时显示；保留完整行列，不分页或截断数据。此决定替代先前容量暂留要求。

## 初始 UI 交付验证（历史记录）

- `npm run build` 通过；`npx vitest run src/ui`：15 文件、76 项通过；`git diff --check` 通过。
- 真实浏览器执行 Single 搜索、取消、历史结果恢复，以及 RDM/BLM 联合搜索、共享/职业结果和键盘切换；检查 1440×695 与 1920×1080。普通单方案 Comparison 从真实历史添加后完整显示。截图与日志位于 `artifacts/ui-refactor/`。
- 全量 `npm test`：46 文件通过、5 文件失败；364 项通过、11 项失败，另有 7 个 worker 异常。失败均涉及未改动的 domain worker 无法解析 `@/data`，不记为全量通过。
- `src/domain`、`src/data` 无改动；UI 样式未残留 `@media`、`:global` 或 `clamp()`。四方案极端容量不在通过项中。

联合历史真实保存拒绝已修复：`statistics.timeLimitMs` 按领域类型作为可选字段校验；真实 RDM/BLM 搜索完成后刷新并从 History 恢复结果通过。README、规则与总览已获后续授权并完成同步。
